9第 2 节岗位地图：五类岗位（上）① AI 应用 PM：面向 C 端用户 / 需求洞察·体验·增长 ② Agent 与工作流 PM：面向业务流程 / 流程抽象·工具设计·异常兜底 ③ RAG 知识库 PM：面向企业知识 / 数据治理·检索链路·权限更新；每行四列：面向谁、做什么、核心能力、适合什么背景每行 1 分钟，手指沿行移动；让学员在导学案「我的匹配度」列画星岗位地图表（投屏，制作完成前用本页表格版）
10第 2 节岗位地图：五类岗位（下）① AI 行业解决方案 PM：面向 B 端客户 / 行业理解·方案包装·交付协同 ② 大模型平台 PM：面向开发者 / 技术深度·开发者体验·成本模型 ③ 底部念注释区「岗位为市场通用分类，具体职责以各公司 JD 为准」④ 提醒平台岗池子最小、竞争有技术崇拜滤镜讲完五行停 10 秒，让学员自己选；举手统计各列星数，口头播报「这间教室的主攻分布」岗位地图表（投屏，同图 2）
11第 2 节岗位没有高下，匹配才对① 五类是分工不是阶梯，不是鄙视链 ② 三维匹配：熟悉的行业 × 过去的背景 × 想要的职业状态 ③ 熟悉的行业排第一：行业认知是换岗时唯一带得走的积累 ④ 五类岗位市场数量不同，把池子大小也考虑进去本课金句页，放慢语速重复两遍；纠正「平台岗最厉害、解决方案岗是外包」的每届排序紫底白字全屏金句页
12第 2 节双案例对照：匹配对了 / 匹配错了① 正面：B 端售后交付背景，三维同向 → 主攻解决方案岗，把交付异常整理成「流程断点清单」，面试现场分析场景直接对答 ② 反面：零编程内容运营执意投平台岗，硬门槛七八条、差距清单写不下去，W3 纠偏回应用岗 ③ 深化：为什么 / 边界（第一周允许纠偏，过 W2 立项不换）/ 常见误解（迁移最短 ≠ 最简单）④ 这段在面试里怎么答正面讲「三个维度指向同一方向所以省力」，反面讲「站错起跑线不是不行」；各 5 分钟，不贬低任何一类岗位双案例对照图（配图清单图 6）
13第 3 节JD 四区拆解法① 职责区（做什么）② 要求区（硬门槛）③ 加分项区（优先项）④ 隐藏区（团队与阶段）⑤ 口诀前置：写「精通 / 负责过 / 三年以上」是门槛，写「熟悉 / 了解」是加分先定性「JD 是能力翻译信，不是考试大纲」；口诀带全班齐念一遍—
14第 3 节现场示范：拆一份 JD① 教学示例 JD 四区划线结果 ② 职责区四条连起来就是产品全链路 ③ 硬门槛 3 条 / 加分项 3 条对照 ④ 隐藏区：「与算法协作」→ 应用层非模型层 ⑤ 关键词 → 六维归类3 分钟拆解示范，学员导学案同步划；不提问；页脚必须标注「教学示例，非真实招聘信息」教学示例 JD（教案第八节文本）
15第 3 节常见误读对照 + 三处深化① 误读一：把加分项当门槛 ② 误读二：把技术名词当学习大纲 ③ 正解：JD 是对话素材不是考试范围 ④ 为什么：四区法把「恐惧」翻译成「任务」⑤ 边界与常见误解：隐藏区是推断不是写明要求，路线图是一个项目不是八门课两条误读各点一名学员「你中过哪条」；三处深化用「补 why / 补边界 / 补反面」带过，不展开成新课—
16第 3 节八周四阶段总览① 认知筑基 W1–W2 ② AI 核心能力 W3 ③ 产品硬功 W4–W5 ④ 实战与就业 W6–W8 ⑤ 一切为就业服务用手臂画四段；强调 W3 技术浓度最高但全绑在主项目上，不为学技术而学技术八周路线图（课程大纲同款四阶段条）+ 6 节时间轴页眉
17第 3 节八周路线图：每周产出 + 五里程碑 + 全链路① 每周核心课 + 周末产出 + 验收标准 ② 主项目五里程碑：立项 → 原型 → PRD 过审 → 商业验证 → 路演 ③ 全链路七节点：需求输入 → 数据准备 → 模型选型 → 应用开发 → 评测验收 → 上线监控 → 数据回流 ④ 金句「没有评测集的 AI 功能，上线就是开盲盒」强调每周三档 Rubric；预告「每节课都会告诉你在全链路哪个位置」；七节点只讲「产品经理要关心什么」，不展开交互式架构图（AI 产品全链路 Tab，投屏代替，见 07-交互使用说明）
18第 3 节就业全景 + 双案例 + 薪资看结构① 09-就业数据页口径：每个数字标样本量与口径，未填的写「待教务补充」，不口头补数 ② 三条典型转岗路径（A 运营→应用岗 / B 客服交付→解决方案岗 / C 技术→平台岗）③ 四张检查卡 W2/W4/W6/W8 各 5 项；节奏：补作品 → 内推试水 → 批量投递 ④ 双案例：正面「拆成可排序补齐动作」/ 反面「技术名词当考纲」⑤ 薪资与晋升：看结构不看数字，W8 谈薪课发当年数据只讲事实、路径与判断标准，不含结果承诺；「产品经理看数据，先看口径」是这一页的第一课；薪资页用蓝框提示条弱化数字感09-就业数据页（只读投屏）+ 双案例对照图（图 6）；不改动原文件
