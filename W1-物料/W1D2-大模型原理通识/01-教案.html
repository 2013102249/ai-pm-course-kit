教案 · W1 周二《大模型原理通识（产品经理版）》

AI 产品经理就业训练营 · 第一周第二天 · 90 分钟（2 课时）· 讲师版

一、基本信息

项目 内容
所属阶段 阶段一 · 认知筑基（Week 1）
本课主题 大模型原理通识（产品经理版）
课时 90 分钟（2 课时）
授课对象 转行 / 进阶层学员（昨日已完成开营与岗位全景，尚未接触技术细节）
前置知识 无硬性要求；知道「大模型」这个词即可
本课产出 大模型通识一页笔记 + 「懂到什么程度」边界自测 + 模型选型五维清单
教学场地 教室或线上直播，需投屏 + 学员可访问交互工具
教学红线 本课只讲产品经理需要懂的原理；严禁讲数学公式和代码；技术细节以「找算法同事」收口

二、教学目标（可测量）

  1. 能用「超级接话员」类比向外行讲清大模型的本质，并说出预训练、SFT、RLHF 三个阶段各自解决什么问题（对应作业：向一位非技术朋友做 3 分钟科普）。
  2. 能解释上下文窗口是什么、超限会发生什么，并给出两种以上的产品应对手段（对应课堂快问快答 + 习题）。
  3. 能对照「懂到什么程度」边界表，判断 5 个典型技术问题分别属于「必须懂 / 应该懂 / 不必懂」哪一档，并说出「不必懂」的问题该找谁（对应课堂练习）。

三、教学重难点

  • 重点：预训练 / SFT / RLHF 三阶段的产品视角解读——每个阶段「解决什么问题、不做会怎样、产品经理因此多了一个什么决策」。
  • 难点一：Transformer 的科普深度控制。学员背景两极分化——技术背景的容易要求讲公式，非技术背景的容易听不懂。讲法是「一个类比 + 一个类比边界」，明确宣布「今天不碰公式」。
  • 难点二：「懂到什么程度」的边界感。学员要么想全懂（焦虑），要么想全不懂（放弃）。本课用三档边界表给出可执行的取舍标准。

五、教学步骤与时间拆分

时间 环节 教学内容 教学方法 对应产出
0–10 min 导入：你每天都在用，但它只是个「超级接话员」 调查学员昨日/今早用过哪些 AI 产品；抛出核心类比：模型不是百科全书，是超级接话员 提问破冰 + 类比 —
10–30 min 环节一：接话员是怎么练成的 用 LLM原理架构图讲五步链路；Transformer 科普（自注意力 = 让模型学会「看全文再接话」）；预训练 = 读完图书馆但从没被教过怎么答题 讲授 + 图示 + 类比 通识笔记：链路五步填空
30–45 min 环节二：从接话员到助手 SFT = 岗前培训（教它按指令回答）；RLHF = 满意度回访（让它说人爱听的话）；三阶段串成「一个人的成长史」 讲授 + 类比 + 提问 三阶段对比表填写
45–60 min 环节三：两个仪表盘 上下文窗口 = 模型的「桌面大小」；推理成本 = 按 token 计费，输入输出分开算；两个仪表盘如何约束产品设计 讲授 + 交互演示（temperature） 仪表盘笔记 + 选型五维清单
60–72 min 环节四：看得见听得见的模型 多模态能力与边界（能识图不等于能精确数数）；模型家族速览：GPT / Claude / Gemini / DeepSeek / Qwen / GLM 的存在与定位 讲授 + 客观描述 模型家族一栏笔记
72–85 min 环节五：懂到什么程度 讲三档边界表；快问快答：5 个技术问题现场归类；宣布「不必懂的问题找算法同事」 讲授 + 快问快答 边界自测表
85–90 min 总结与作业 三句话收束 + 布置作业 + 预告周三提示词课 讲授 —

六、课堂提问设计（7 问）

# 提问 提问时机 预设答案 / 引导方向
1 「今天早上，有谁用过 AI？用来干什么？」 导入（0–3 min） 破冰。收集 3–4 个真实用途，为「你每天都在用」做证据
2 「接话员为什么会一本正经地胡说八道？」 环节一（约 20 min） 它的本能是「接上话」而不是「答对题」——永远会接话，哪怕不知道答案
3 「预训练完的模型，为什么不能直接上线给用户用？」 环节二（约 33 min） 它只会续写，不会「按指令回答」——需要 SFT 做岗前培训
4 「为什么有了 SFT 还要 RLHF？岗前培训还不够吗？」 环节二（约 40 min） SFT 教「答对」，RLHF 教「答得让人满意」——同一个问题的多个回答，人知道哪个更好
5 「模型聊得越久，产品经理该担心什么？」 环节三（约 47 min） 两件事：上下文越来越挤（窗口预算），每轮都在累计花钱（推理成本）
6 「temperature 调高和调低，分别适合什么产品？」 环节三（约 55 min，配合交互演示） 低 = 严谨客服 / 信息抽取；高 = 创意文案 / 头脑风暴。参数是产品决策不是技术细节
7 「『Transformer 有几层注意力』这个问题，产品经理必须懂吗？」 环节五（约 74 min） 不必懂。必须懂的是「为什么选这个模型」；结构细节找算法同事

七、板书要点

大模型 = 超级接话员：永远会接话，哪怕不知道答案

五步链路：用户输入 → 提示词组装 → 大模型 → 输出后处理 → 回复用户

三阶段成长史：
预训练（读书）→ 学会说话和世界知识，但不会按指令答题
SFT（岗前培训）→ 学会按指令回答
RLHF（满意度回访）→ 学会说人爱听的话

两个仪表盘：上下文窗口（桌面大小）· 推理成本（按 token 计费）

边界口诀：懂边界，不懂公式；能选型，不训模型

八、课堂练习参考答案（快问快答归类）

问题 档位 关键理由
「为什么选这个模型，不选那个？」 必须懂 选型是产品决策，涉及能力-成本-延迟权衡
「上下文窗口超了会发生什么？」 必须懂 直接决定产品能处理多长的文档、多少轮对话
「自注意力大致在干什么？」 应该懂 能听懂算法同事的话，能判断技术方案是否跑偏
「GPT、Claude、DeepSeek、Qwen 各是什么定位？」 应该懂 选型调研的基本功，但不必记参数
「注意力公式怎么推导？」 不必懂 数学细节，遇到时找算法同事
「训练框架用 PyTorch 还是别的？」 不必懂 工程实现，与产品决策无关

九、学员易错点预判与应对

易错点 表现 应对
把大模型当成「百科全书 / 数据库」 认为它「知道」一切，答错就是坏了 用「接话员」类比纠偏：它从不查资料，只负责接话；答错是本能不是故障
想搞懂数学公式才肯往下听 技术背景学员追问公式推导 明确本课红线：今天不碰公式；给「应该懂」清单，让学员知道边界在哪
认为微调是万能的 「效果不好就微调」 讲清顺序：先提示词、再 RAG、最后才是微调；微调改行为不加知识
认为上下文窗口越大越好 「上最大的窗口」 讲成本与延迟：窗口是预算表不是面子工程；按场景选
因「不懂技术」而焦虑 「我是不是学不了 AI 产品」 用边界表收口：必须懂的只有 5 件事，其余有算法同事

十、「懂到什么程度」边界表（本课核心交付，对应环节五）

这张表是全课的「导航仪」：左边是技术世界，右边是产品世界，中间这条线就是产品经理的岗位边界。课堂上投屏逐行过，学员抄进导学案。

档位 定义 具体条目 做不到会怎样
必须懂（能独立决策，说不清就是失职） 直接决定产品决策，面试必考 ① 大模型是概率续写引擎，会幻觉；② 预训练 / SFT / RLHF 三阶段各自解决什么问题；③ 上下文窗口是什么、超限会怎样；④ 推理成本按 token 计费、输入输出分开算；⑤ 模型有能力边界和知识截止时间 选型靠拍脑袋，被算法同事问倒，面试过不了技术通识关
应该懂（能听懂、能提问、能判断方案跑偏） 开会不懵，能和技术同事对话 ① Transformer 自注意力大致在干什么；② 微调不是首选——先提示词、再 RAG、最后微调；③ 多模态的能力边界（能识图不等于能精确数数）；④ 主流模型家族的存在与定位（GPT / Claude / Gemini / DeepSeek / Qwen / GLM）；⑤ 私有化部署与 API 调用是两条成本曲线 评审会只能复读 PRD，无法判断技术方案是否跑偏
不必懂（遇到时找算法同事，学了也是沉没成本） 数学与工程实现细节 ① 数学公式（注意力公式、损失函数推导）；② 代码实现与训练框架细节；③ 模型结构参数（层数、注意力头数、参数规模）；④ 分布式训练与显存优化；⑤ 论文复现 除了焦虑，没有收益——这些不该由产品经理拍板

讲师收口话术：「今天这张表，建议你截图设成手机壁纸。以后每次想钻进技术细节之前，先问自己一句——这件事在『必须懂』还是『应该懂』里吗？不在？关掉页面，去找算法同事喝杯咖啡。」
