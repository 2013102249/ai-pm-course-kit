## 二、教学目标（可测量）

1. 能对任意一款 AI 产品按六大形态给出归类，并说出一条判断依据（验证：习题第一层归类题 + 对应板块当堂拆解报告，归类正确率 ≥80%）。
2. 能用「用户价值 × 技术依赖 × 商业模式」三维完成 2 份产品拆解报告，每个维度至少写 2 条要点（验证：周五前提交的作业，每维要点数逐条可数）。
3. 能完成「业务场景 → 产品形态 → 商业模式」的匹配推理，并给出 2 条理由（验证：对应板块快答 + 习题第二层，理由数逐条可数）。
4. **【术语目标】** 能准确释义当日 12 个术语，并对「Agent vs 工作流」「Copilot vs Agent」两组易混概念各说出 1 条分界判据（验证：对应板块《术语自测表》12 行自评 + 习题第 0 层术语辨析题，正确 ≥10 题）。
5. **【面试目标】** 能在 60 秒内用「产品形态 + 人在回路中的位置 + 价值维度」答完「你平时用什么 AI 产品、它是什么形态」，并承受 2 层追问不跑题（验证：对应板块两两模拟 +《面试模拟记录表》自评分 ≥3/5）。
6. 能说清「形态没有高下，匹配才对」，并从成本结构倒推解释「为什么这个场景不用视频 / 数字人」（验证：对应板块反面案例讨论 + 对应板块面试题 4 的踩分点达成数 ≥3）。
7. 能把当日 3 类产出（拆解报告、术语自测表、面试模拟记录表）按《本日作品集积木》归档到指定位置（验证：对应板块当堂验收，3 项归档齐全）。

## 三、教学重难点

- **重点**：六大形态的边界与判别特征。核心判据只有一句话——看人在回路中的位置：人问一句、人画流程、人只验收，对应三种完全不同的产品。
- **难点一**：形态归类的灰度地带。同一产品常跨形态（对话助手内置知识库、Agent 里嵌工作流），学员容易追求唯一答案。教「主形态 + 副形态」的表述法。
- **难点二**：商业模式与形态的匹配推理。学员容易只背「订阅制」三个字，说不清为什么这个形态适合订阅。用「成本结构 → 收费依据」倒推，四类模式：免费导流、订阅、按量、按席位。
- **难点三【术语混淆】**：零基础学员把「产品形态 / 产品功能」「AI 原生 / 加了 AI 按钮」「Chatbot / 知识库问答」混为一谈，尤其分不清「Agent vs 工作流」（步骤由谁拆）与「Copilot vs Agent」（默认动作是建议还是执行）。应对：对应板块每个术语给「生活类比 + 易混辨析 + 面试说法」三件套，两组重点辨析用对照表反复过。
- **难点四【面试失分】**：学员被问「你平时用什么 AI 产品」时只报产品名、说不出形态；被问「为什么不做视频 / 数字人」时只答「太贵了」不算账；被追问 2 层就跑题或改口。应对：对应板块给「踩分点 + 追问链 + 60 秒标准答法 + 失败答法」逐题拆解，两两模拟时按评分表互评。

## 五、六大形态三维拆解表（本课核心）

| 形态 | 一句话定义 | 用户价值 | 技术依赖 | 商业模式 | 判别特征 |
|---|---|---|---|---|---|
| 对话式助手（Chatbot） | 用自然语言随问随答的通用入口 | 降低信息获取与内容创作门槛，随问随答 | 基础大模型的对话、长上下文与推理能力 | 免费获客 + 会员订阅 + 生态导流 | 人问一句，AI 答一句；交互以对话为主 |
| 工作流编排 | 把多步任务串成可视化流水线 | 重复流程自动化，省人力、少出错 | 工作流引擎 + 工具与插件调用 + 多模型路由 | 平台订阅 / 按量计费 + 开发者生态 | 人先画流程，AI 按节点跑；节点与分支可见 |
| 知识库问答 | 让模型基于指定资料作答并给出处 | 散落文档变成可问答的组织资产，新人上手快 | RAG（Retrieval-Augmented Generation，检索增强生成）技术栈：解析、分块、Embedding、检索、重排 | 订阅 / 席位收费 + 企业按量 | 答案必须带出处；资料边界清晰 |
| 多模态生成（含文生图 / 文生视频 / 数字人） | 生成图片、视频、语音等富媒体内容 | 内容生产成本数量级下降 | 文生图（Text-to-Image）/ 文生视频 / 语音合成模型，算力成本高 | 积分 / 按生成量计费 + 订阅 | 人给创意，AI 出成品；一次生成一次付费 |
| Copilot 副驾（Co-pilot） | 嵌入既有工作流的实时助手 | 不离开主场景，效率增强而不夺权 | 上下文工程 + 与宿主系统集成（文档、日历、代码库） | 按席位订阅，随宿主软件分发 | 人始终在主导位，AI 只做建议 |
| 自主 Agent（Autonomous Agent） | 接收目标后自主规划并执行多步任务 | 端到端交办，人只做验收 | 规划 + 工具调用 + 多步执行 + 错误恢复 | 订阅 + 按任务 / 积分计费 | 人给目标，AI 自己拆步骤；结果导向 |

## 七、课堂提问设计（20 问）

| # | 提问 | 提问时机 | 类型 | 预设答案 / 引导方向 |
|---|---|---|---|---|
| 1 | 「产品形态」和「产品功能」差在哪？ | 对应板块 | 术语辨析 | 形态是整体交互范式（用户怎么把任务交给 AI），功能是单个能力点；如「对话」是形态，「改文案」是功能 |
| 2 | 「AI 原生」和「旧系统加个 AI 按钮」是不是一回事？ | 对应板块 | 术语辨析 | 不是。AI 原生从零围绕模型能力重做流程；加按钮是「+AI 贴皮」，底层流程没变 |
| 3 | Chatbot 和知识库问答，都回答问题，分界在哪？ | 对应板块 | 术语辨析 | Chatbot 靠模型通用记忆随口答；知识库问答答案必须带指定资料出处、资料边界清晰 |
| 4 | **Agent 和工作流，到底谁在拆步骤？** | 对应板块 | 术语辨析（重点） | Agent 自己把目标拆成步骤（AI 临时规划）；工作流是人预先把步骤画成节点、AI 只按节点跑；前者灵活难控，后者死板可观测 |
| 5 | **Copilot 和 Agent，看哪个动作一眼分清？** | 对应板块 | 术语辨析（重点） | 看默认动作：Copilot 默认「建议」、等你采纳；Agent 默认「执行」、等你叫停；副驾与代驾之别 |
| 6 | 「多模态」和「文生图」是同一个概念吗？ | 对应板块 | 术语辨析 | 不是。多模态是能力范畴（含理解与生成、含多种媒体）；文生图只是其中一种生成任务 |
| 7 | RAG 和「微调」差在哪？为什么知识库问答非它不可？ | 对应板块 | 术语辨析 | RAG 检索外部资料再作答、不改模型参数、换资料即换答案；微调改模型本身；RAG 是知识库问答「答案带出处」的最低成立条件 |
| 8 | 「价值维度」写成功能清单为什么不合格？ | 对应板块 | 术语辨析 | 要写成「没有它，用户多花多少时间或多花多少钱」的可计量句式，不是罗列功能 |
| 9 | 同一句「帮我把会议记录整理成待办」，对话助手和 Agent 反应差在哪？ | 对应板块 | 原理理解 | 助手给整理好的文字；Agent 直接查数据、写文档、发通知——差别在交办深度，即人在回路中的位置 |
| 10 | 判断一个产品是什么形态，最快的办法看什么？ | 对应板块 | 原理理解 | 看人在回路中的位置：人问一句、人画流程、人只验收，分别对应对话 / 工作流 / Agent |
| 11 | 豆包和 Kimi 都是对话助手，凭什么一个主打大众、一个主打长文档？ | 对应板块 | 原理理解 | 同形态不同定位：技术特长（长上下文）决定差异化场景；形态相同不等于产品相同 |
| 12 | 知识库问答凭什么敢收企业的钱？ | 对应板块 | 原理理解 | 把散落文档变成可问答资产，省下新人培训与查资料时间——价值可计量，所以敢按席位收 |
| 13 | 多模态生成为什么普遍按积分收费，对话助手却敢免费？ | 对应板块 | 原理理解 | 成本结构不同：一次生成的算力成本远高于一次对话；免费模式要靠流量与生态把钱补回来 |
| 14 | 老板说「给我做一个像 Manus 那样的产品」，你第一句话问什么？ | 对应板块 | 原理理解 | 先问任务边界与容错度：哪些任务能交办、错了代价多大——不是先问用什么模型 |
| 15 | 硬上数字人做制度播报，成本和体验各会翻在哪？ | 对应板块 | 案例复盘 | 成本：逐条生成 + 改字重渲 + 形象合规；体验：口型 / 念错、不能搜索复制、等待抽卡。需求本质是「查得到、带出处」，文本形态就够 |
| 16 | 你平时用什么 AI 产品？它是什么形态？ | 对应板块 | 面试追问 | 先报产品 + 用「人在回路中的位置」给归类依据，再补一句定位或副形态；只报名字是失败答法 |
| 17 | 我说它是 Chatbot，你凭什么说不是？再追一层：它跨形态吗？ | 对应板块 | 面试追问 | 用「主形态 + 副形态」表述，主交互为准；能举出内置知识库 / 插件等副形态特征 |
| 18 | 这个场景你怎么选形态？为什么不上 Agent 全自动？ | 对应板块 | 面试追问 | 先问重复劳动与出错代价，稳定重复用工作流、需追责用知识库；Agent 有错误累积与责任边界问题 |
| 19 | 为什么不用视频 / 数字人？老板坚持要，你怎么劝？ | 对应板块 | 面试追问 | 从成本结构倒推 + 体验账 + 信息可检索性三条算账，回扣「形态没有高下，匹配才对」，给折中方案 |
| 20 | 讲一次你选错形态的经历，损失是什么、复盘出什么判据？ | 对应板块 | 面试追问 | 真实场景 + 成本 / 体验损失 + 判据 + 改进；不甩锅、不编造 |

> 统计：术语辨析 8 问（#1–#8，含 #4、#5 两组重点）、面试追问 5 问（#16–#20）另加 #14、#18 可作追问延伸，合计 ≥18 问，满足「术语辨析 ≥6、面试追问 ≥6」的口径要求（#14、#15、#18 在面试模拟中作为连追层复用）。

## 八、板书要点（按 6 节重排）

```
【对应板块 · 术语】
12 个术语：产品形态 / AI 原生 / Chatbot / Copilot / Agent / 工作流 / 多模态 / 文生图 / 数字人 / RAG / 价值维度 / 技术可行性
两组重点辨析：
  Agent vs 工作流 → 步骤由谁拆？（AI 临时规划 / 人预先画死）
  Copilot vs Agent → 默认动作是建议还是执行？（副驾 / 代驾）
缩写全称：RAG=检索增强生成 / Copilot=副驾驶 / Agent=自主智能体 / Chatbot=聊天机器人 / Text-to-Image=文生图

【对应板块 · 框架】
拆解三维：用户价值（解决什么问题）× 技术依赖（靠什么成立）× 商业模式（凭什么收钱）
判别口诀：看人在回路中的位置（人问一句 / 人画流程 / 人只验收）
金句：形态没有高下，匹配才对
全链路定位：六大形态发生在「应用开发」环

【对应板块 · 后三形态 + 反面案例】
六句话：对话—人问一句 AI 答一句；工作流—人画流程 AI 按节点跑；知识库—答案必须带出处；
        多模态—一次生成一次付费；Copilot—人主导 AI 建议；Agent—人给目标 AI 走完全程
成本结构 → 收费依据：免费导流 / 订阅 / 按量 / 按席位
反面案例：硬上数字人 / 硬做视频 = 成本翻 + 体验翻（双输）

【对应板块 · 实操】
同一需求三款对比：豆包给文字 / Kimi 读长文档 / 扣子自动跑流程
拆解报告三问：解决什么问题 · 靠什么成立 · 怎么收到钱

【对应板块 · 面试】
60 秒答法三件套：产品形态 + 人在回路中的位置 + 价值维度
答题红线：只报名字 / 只说「太贵了」/ 被追问就改口
金句：能用文字说清的事，别用视频烧钱

【对应板块 · 收束】
三句收束 + 作品集积木归档 + 当堂验收
```

## 九、课堂练习参考答案

### （一）形态归类（对应板块抽点）

| 产品 | 主形态 | 判断依据 |
|---|---|---|
| 豆包 | 对话式助手（Chatbot） | 以多轮对话为主要交互，随问随答 |
| Kimi | 对话式助手（长上下文特化） | 交互是对话，技术特长是超长上下文读长文档 |
| 扣子（Coze） | 工作流编排 | 用户先搭建工作流与插件，AI 按设定流程执行 |
| 讯飞星火 | 对话式助手（行业场景特化） | 对话交互为主，叠加教育等行业方案 |
| 数字人播报工具（反面案例用） | 多模态生成（文生视频 / 数字人分支） | 一次生成一次付费，成本与合规风险偏高 |

### （二）商业模式匹配（对应板块快答）

| 场景 | 匹配形态 | 匹配商业模式 | 关键理由 |
|---|---|---|---|
| 面向大众的免费问答入口 | 对话式助手 | 免费 + 会员订阅 + 生态导流 | 对话边际成本趋低，先占入口再变现 |
| 电商自动处理退换货全流程 | 工作流编排（复杂时用 Agent） | 平台订阅 / 按量计费 | 省下的人力可计量，按量或按订阅都说得通 |
| 金融机构内部制度问答 | 知识库问答 | 席位订阅 + 企业按量 | 替代培训与检索成本，按使用人数收费最直观 |
| 短视频团队批量出图 | 多模态生成（文生图） | 积分 / 按生成量计费 | 单次生成算力成本高，按量最公平 |
| 销售团队邮件写作帮手 | Copilot 副驾 | 按席位订阅 | 嵌在现有工作流里，按人头收费最直观 |
| 企业内部制度「播报」（反面案例） | 硬上数字人 / 视频（不推荐） | 按生成量计费（成本失控） | 需求本质是「查得到、带出处、可复制」，文本或知识库问答更匹配 |

### （三）术语小测参考答案（对应板块，10 题速批）

| # | 题目要点 | 标准答案 | 给分 |
|---|---|---|---|
| 1 | 产品形态 ≠ ? | 产品功能（整体交互范式 vs 单个能力点） | 1 分 |
| 2 | AI 原生 与「+AI 按钮」的区别 | 前者重做流程，后者贴皮不改底层流程 | 1 分 |
| 3 | Chatbot 全称 | Chat Robot，聊天机器人 | 1 分 |
| 4 | 知识库问答的最低成立条件 | RAG 全链路（解析/分块/向量化/检索/重排）+ 权限 | 1 分 |
| 5 | RAG 全称与中文 | Retrieval-Augmented Generation，检索增强生成 | 1 分 |
| 6 | Agent vs 工作流分界 | 步骤由 AI 临时拆，还是人预先画成节点 | 1 分 |
| 7 | Copilot vs Agent 分界 | 默认动作是「建议」还是「执行」 | 1 分 |
| 8 | 多模态 与 文生图 关系 | 多模态是能力范畴，文生图是其中一种生成任务 | 1 分 |

### （四）面试评分示例（对应板块两两模拟，5 分制）

**示例题**：「你平时用什么 AI 产品、它是什么形态？」

| 分档 | 表现 | 得分 |
|---|---|---|
| 1 分（失败） | 「我常用豆包，挺好用的。」只报名字，无形态、无依据 | 1 |
| 3 分（合格） | 「豆包是对话式助手，人问一句 AI 答一句。」给对形态 + 一条依据 | 3 |
| 4 分（良好） | 上一档 + 「它卡全场景免费入口，和 Kimi 的长文档定位不同」，补定位差异 | 4 |
| 5 分（优秀） | 上一档 + 主动用「人在回路中的位置」框架 + 补一句「主形态对话式，兼有文档解析副形态」，并承受「为什么不是知识库问答」追问不改口 | 5 |

**追问失分示例**：被问「它跨形态吗」就改口说「那可能算 Agent」——判为框架不稳，扣 2 分；正确答法是坚持「主形态 + 副形态」表述。

## 十、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 追求唯一正确答案 | 纠结某产品到底算助手还是 Agent | 教「主形态 + 副形态」表述法：先定主交互，再补一句「兼有某形态特征」 |
| 把形态当高低档位 | 说「Agent 最先进，对话式要被淘汰」 | 回扣金句「形态没有高下，匹配才对」；举反例：问天气用 Agent 是浪费，企业制度问答用知识库更稳 |
| 商业模式只会写「订阅制」 | 六形态全写订阅 | 用「成本结构 → 收费依据」倒推四类模式，要求必须写「凭什么」 |
| 技术依赖写成名词堆砌 | 「依赖 NLP、深度学习、大模型」 | 要求写成「这个形态成立的最低技术条件」，如知识库必须写出 RAG 四步 |
| 拆解报告写成产品评测 | 只写「好不好用、界面漂不漂亮」 | 强调报告回答三个问题：解决什么问题、靠什么成立、怎么收到钱 |
| **【术语混淆】把「形态」与「功能」混用** | 「这个产品的形态是改文案和翻译」 | 回对应板块对照卡：形态是交互范式（怎么交任务），功能是能力点（能干什么），先定形态再列功能 |
| **【术语混淆】分不清 Agent / 工作流 / Copilot** | 「能自动跑几步的就是 Agent」「Copilot 也是一种 Agent」 | 用两张辨析表锁死：步骤由谁拆（Agent 自己拆 / 工作流人画死）、默认动作（Copilot 建议 / Agent 执行）；配「副驾 / 代驾 / 流水线」三个生活类比反复过 |
| **【术语混淆】缩写当成懂了** | 会说「RAG」「Copilot」但说不出全称与中文 | 首次出现一律给全称 + 中文；术语自测表设「写全称」列，写不出不算过关 |
| **【面试失分】只报产品名、报不出形态** | 「我平时用豆包、Kimi、ChatGPT」然后卡住 | 套 60 秒三件套：产品形态 + 人在回路中的位置 + 价值维度，先给结论再给依据 |
| **【面试失分】「为什么不用视频 / 数字人」只答「太贵」** | 一句话带过，不算账、不给替代 | 强制三条算账：成本结构倒推、体验账（等待 / 抽卡 / 口型 / 不能检索复制）、信息可检索性，再给折中方案 |
| **【面试失分】被追问 2 层就改口或跑题** | 面试官一质疑就把主形态从「对话式」改成「Agent」 | 两两模拟按《面试模拟记录表》记追问层与自评分；教「先确认主交互不动摇，再补副形态」的应答句式 |
| **【面试失分】编造经历或甩锅** | 「是老板非要上数字人，不怪我」 | 行为题要求给「当时判断 + 损失 + 复盘判据 + 改进」四段，用设计背景案例示范，不出现真实学员姓名与未公开数据 |
