# 教案 · W1 周四《AI 产品形态拆解》

> AI 产品经理就业训练营 · 第一周第四天 · 90 分钟（2 课时）· 讲师版

## 一、基本信息

| 项目 | 内容 |
|---|---|
| 所属阶段 | 阶段一 · 认知筑基（Week 1） |
| 本课主题 | AI 产品形态拆解：六大形态的「用户价值 × 技术依赖 × 商业模式」 |
| 课时 | 90 分钟（2 课时） |
| 授课对象 | 转行 / 进阶层学员（已完成 W1D1 岗位全景、W1D2 大模型原理、W1D3 提示词与上下文工程） |

## 二、教学目标（可测量）

1. 能对任意一款 AI 产品按六大形态给出归类，并说出一条判断依据（对应环节三拆解练习 + 习题第一层归类题）。
2. 能用「用户价值 × 技术依赖 × 商业模式」三维完成 2 份产品拆解报告，每个维度至少写 2 条要点（对应周五前提交的作业）。
3. 能完成「业务场景 → 产品形态 → 商业模式」的匹配推理，并给出 2 条理由（对应环节四快答 + 习题第二层）。

## 三、教学重难点

- **重点**：六大形态的边界与判别特征。核心判据只有一句话——看人在回路中的位置：人问一句、人画流程、人只验收，对应三种完全不同的产品。
- **难点一**：形态归类的灰度地带。同一产品常跨形态（对话助手内置知识库、Agent 里嵌工作流），学员容易追求唯一答案。教「主形态 + 副形态」的表述法。
- **难点二**：商业模式与形态的匹配推理。学员容易只背「订阅制」三个字，说不清为什么这个形态适合订阅。用「成本结构 → 收费依据」倒推，四类模式：免费导流、订阅、按量、按席位。

## 五、六大形态三维拆解表（本课核心）

| 形态 | 一句话定义 | 用户价值 | 技术依赖 | 商业模式 | 判别特征 |
|---|---|---|---|---|---|
| 对话式助手 | 用自然语言随问随答的通用入口 | 降低信息获取与内容创作门槛，随问随答 | 基础大模型的对话、长上下文与推理能力 | 免费获客 + 会员订阅 + 生态导流 | 人问一句，AI 答一句；交互以对话为主 |
| 工作流编排 | 把多步任务串成可视化流水线 | 重复流程自动化，省人力、少出错 | 工作流引擎 + 工具与插件调用 + 多模型路由 | 平台订阅 / 按量计费 + 开发者生态 | 人先画流程，AI 按节点跑；节点与分支可见 |
| 知识库问答 | 让模型基于指定资料作答并给出处 | 散落文档变成可问答的组织资产，新人上手快 | RAG 技术栈：解析、分块、Embedding、检索、重排 | 订阅 / 席位收费 + 企业按量 | 答案必须带出处；资料边界清晰 |
| 多模态生成 | 生成图片、视频、语音等富媒体内容 | 内容生产成本数量级下降 | 文生图 / 文生视频 / 语音合成模型，算力成本高 | 积分 / 按生成量计费 + 订阅 | 人给创意，AI 出成品；一次生成一次付费 |
| Copilot 副驾 | 嵌入既有工作流的实时助手 | 不离开主场景，效率增强而不夺权 | 上下文工程 + 与宿主系统集成（文档、日历、代码库） | 按席位订阅，随宿主软件分发 | 人始终在主导位，AI 只做建议 |
| 自主 Agent | 接收目标后自主规划并执行多步任务 | 端到端交办，人只做验收 | 规划 + 工具调用 + 多步执行 + 错误恢复 | 订阅 + 按任务 / 积分计费 | 人给目标，AI 自己拆步骤；结果导向 |

## 六、教学步骤与时间拆分

| 时间 | 环节 | 教学内容 | 教学方法 | 对应产出 |
|---|---|---|---|---|
| 0–10 min | 导入：一个产品，六种问法 | 用同一助手回答六类需求（问知识、改文案、查资料、出图、跑流程、交办任务），引出「形态不同，产品长相完全不同」；点 1 名学员说感受 | 演示冲击 + 提问 | — |
| 10–20 min | 环节一：建立拆解框架 | 讲「用户价值 × 技术依赖 × 商业模式」三维；用 AI 产品全链路图定位「形态选择发生在应用开发环节」；抛金句「形态没有高下，匹配才对」 | 讲授 + 图示 | 学员在导学案补全三维定义 |
| 20–55 min | 环节二：六大形态逐一拆解 | 每形态约 5–6 分钟：一句话定义 → 一个标杆产品故事 → 三维点评 → 一句判别口诀 | 讲授 + 故事 + 演示穿插 | 六形态速记表填写 |
| 55–72 min | 环节三：真实产品演示与拆解练习 | 现场演示豆包、Kimi、扣子；学员用导学案模板当场拆解其中 1 款；相邻两人互评 | 演示 + 动手 + 互评 | 产品拆解报告初稿 1 份 |
| 72–82 min | 环节四：商业模式匹配快答 | 5 个场景快问快答：给定业务选什么形态、配什么商业模式；讲师点评并给「成本结构 → 收费依据」倒推法 | 快答 + 讲授 | 匹配练习表填写 |
| 82–90 min | 总结与作业 | 三句话收束 + 布置 2 份拆解报告（周五前交）+ 预告周五行业选择工作坊 | 讲授 | — |

## 七、课堂提问设计（6 问）

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 「同一句『帮我把这份会议记录整理成待办』，对话助手和 Agent 的反应差别在哪？」 | 导入 | 助手给整理好的文字；Agent 直接查数据、写文档、发通知——差别在交办深度，即人在回路中的位置 |
| 2 | 「判断一个产品是什么形态，最快的办法看什么？」 | 环节一 | 看人在回路中的位置：人问一句、人画流程、人只验收，分别对应对话 / 工作流 / Agent |
| 3 | 「豆包和 Kimi 都是对话助手，凭什么一个主打大众、一个主打长文档？」 | 环节二 · 对话式 | 同形态不同定位：技术特长（长上下文）决定差异化场景；形态相同不等于产品相同 |
| 4 | 「知识库问答凭什么敢收企业的钱？」 | 环节二 · 知识库 | 它把散落文档变成可问答资产，省下的是新人培训与查资料时间——价值可计量，所以敢按席位收 |
| 5 | 「多模态生成为什么普遍按积分收费，对话助手却敢免费？」 | 环节四 | 成本结构不同：一次生成的算力成本远高于一次对话；免费模式要靠流量与生态把钱补回来 |
| 6 | 「老板说『给我做一个像 Manus 那样的产品』，你第一句话问什么？」 | 环节四 | 先问任务边界与容错度：哪些任务能交办、错了代价多大——不是先问用什么模型 |

## 八、板书要点

```
拆解三维：用户价值（解决什么问题）× 技术依赖（靠什么成立）× 商业模式（凭什么收钱）

六大形态一句话：
对话式助手——人问一句，AI 答一句
工作流编排——人画流程，AI 按节点跑
知识库问答——答案必须带出处
多模态生成——一次生成，一次付费
Copilot 副驾——人主导，AI 建议
自主 Agent——人给目标，AI 走完全程

判别口诀：看人在回路中的位置
金句：形态没有高下，匹配才对
```

## 九、课堂练习参考答案

### （一）形态归类（环节三抽点）

| 产品 | 主形态 | 判断依据 |
|---|---|---|
| 豆包 | 对话式助手 | 以多轮对话为主要交互，随问随答 |
| Kimi | 对话式助手（长上下文特化） | 交互是对话，技术特长是超长上下文读长文档 |
| 扣子（Coze） | 工作流编排 | 用户先搭建工作流与插件，AI 按设定流程执行 |
| 讯飞星火 | 对话式助手（行业场景特化） | 对话交互为主，叠加教育等行业方案 |

### （二）商业模式匹配（环节四快答）

| 场景 | 匹配形态 | 匹配商业模式 | 关键理由 |
|---|---|---|---|
| 面向大众的免费问答入口 | 对话式助手 | 免费 + 会员订阅 + 生态导流 | 对话边际成本趋低，先占入口再变现 |
| 电商自动处理退换货全流程 | 工作流编排（复杂时用 Agent） | 平台订阅 / 按量计费 | 省下的人力可计量，按量或按订阅都说得通 |
| 金融机构内部制度问答 | 知识库问答 | 席位订阅 + 企业按量 | 替代培训与检索成本，按使用人数收费最直观 |
| 短视频团队批量出图 | 多模态生成 | 积分 / 按生成量计费 | 单次生成算力成本高，按量最公平 |
| 销售团队邮件写作帮手 | Copilot 副驾 | 按席位订阅 | 嵌在现有工作流里，按人头收费最直观 |

## 十、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 追求唯一正确答案 | 纠结某产品到底算助手还是 Agent | 教「主形态 + 副形态」表述法：先定主交互，再补一句「兼有某形态特征」 |
| 把形态当高低档位 | 说「Agent 最先进，对话式要被淘汰」 | 回扣金句「形态没有高下，匹配才对」；举反例：问天气用 Agent 是浪费，企业制度问答用知识库更稳 |
| 商业模式只会写「订阅制」 | 六形态全写订阅 | 用「成本结构 → 收费依据」倒推四类模式，要求必须写「凭什么」 |
| 技术依赖写成名词堆砌 | 「依赖 NLP、深度学习、大模型」 | 要求写成「这个形态成立的最低技术条件」，如知识库必须写出 RAG 四步 |
| 拆解报告写成产品评测 | 只写「好不好用、界面漂不漂亮」 | 强调报告回答三个问题：解决什么问题、靠什么成立、怎么收到钱 |
