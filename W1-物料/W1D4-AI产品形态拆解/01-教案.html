二、教学目标（可测量）

  1. 能对任意一款 AI 产品按六大形态给出归类，并说出一条判断依据（验证：习题第一层归类题 + 第 4 节当堂拆解报告，归类正确率 ≥80%）。
  2. 能用「用户价值 × 技术依赖 × 商业模式」三维完成 2 份产品拆解报告，每个维度至少写 2 条要点（验证：周五前提交的作业，每维要点数逐条可数）。
  3. 能完成「业务场景 → 产品形态 → 商业模式」的匹配推理，并给出 2 条理由（验证：第 3 节快答 + 习题第二层，理由数逐条可数）。
  4. 【术语目标】 能准确释义当日 12 个术语，并对「Agent vs 工作流」「Copilot vs Agent」两组易混概念各说出 1 条分界判据（验证：第 1 节《术语自测表》12 行自评 + 习题第 0 层术语辨析题，正确 ≥10 题）。
  5. 【面试目标】 能在 60 秒内用「产品形态 + 人在回路中的位置 + 价值维度」答完「你平时用什么 AI 产品、它是什么形态」，并承受 2 层追问不跑题（验证：第 5 节两两模拟 +《面试模拟记录表》自评分 ≥3/5）。
  6. 能说清「形态没有高下，匹配才对」，并从成本结构倒推解释「为什么这个场景不用视频 / 数字人」（验证：第 3 节反面案例讨论 + 第 5 节面试题 4 的踩分点达成数 ≥3）。
  7. 能把当日 3 类产出（拆解报告、术语自测表、面试模拟记录表）按《本日作品集积木》归档到指定位置（验证：第 6 节当堂验收，3 项归档齐全）。

三、教学重难点

  • 重点：六大形态的边界与判别特征。核心判据只有一句话——看人在回路中的位置：人问一句、人画流程、人只验收，对应三种完全不同的产品。
  • 难点一：形态归类的灰度地带。同一产品常跨形态（对话助手内置知识库、Agent 里嵌工作流），学员容易追求唯一答案。教「主形态 + 副形态」的表述法。
  • 难点二：商业模式与形态的匹配推理。学员容易只背「订阅制」三个字，说不清为什么这个形态适合订阅。用「成本结构 → 收费依据」倒推，四类模式：免费导流、订阅、按量、按席位。
  • 难点三【术语混淆】：零基础学员把「产品形态 / 产品功能」「AI 原生 / 加了 AI 按钮」「Chatbot / 知识库问答」混为一谈，尤其分不清「Agent vs 工作流」（步骤由谁拆）与「Copilot vs Agent」（默认动作是建议还是执行）。应对：第 1 节每个术语给「生活类比 + 易混辨析 + 面试说法」三件套，两组重点辨析用对照表反复过。
  • 难点四【面试失分】：学员被问「你平时用什么 AI 产品」时只报产品名、说不出形态；被问「为什么不做视频 / 数字人」时只答「太贵了」不算账；被追问 2 层就跑题或改口。应对：第 5 节给「踩分点 + 追问链 + 60 秒标准答法 + 失败答法」逐题拆解，两两模拟时按评分表互评。

七、课堂提问设计（20 问）

#提问提问时机类型预设答案 / 引导方向
1「产品形态」和「产品功能」差在哪？第 1 节术语辨析形态是整体交互范式（用户怎么把任务交给 AI），功能是单个能力点；如「对话」是形态，「改文案」是功能
2「AI 原生」和「旧系统加个 AI 按钮」是不是一回事？第 1 节术语辨析不是。AI 原生从零围绕模型能力重做流程；加按钮是「+AI 贴皮」，底层流程没变
3Chatbot 和知识库问答，都回答问题，分界在哪？第 1 节术语辨析Chatbot 靠模型通用记忆随口答；知识库问答答案必须带指定资料出处、资料边界清晰
4Agent 和工作流，到底谁在拆步骤？第 1 节术语辨析（重点）Agent 自己把目标拆成步骤（AI 临时规划）；工作流是人预先把步骤画成节点、AI 只按节点跑；前者灵活难控，后者死板可观测
5Copilot 和 Agent，看哪个动作一眼分清？第 1 节术语辨析（重点）看默认动作：Copilot 默认「建议」、等你采纳；Agent 默认「执行」、等你叫停；副驾与代驾之别
6「多模态」和「文生图」是同一个概念吗？第 1 节术语辨析不是。多模态是能力范畴（含理解与生成、含多种媒体）；文生图只是其中一种生成任务
7RAG 和「微调」差在哪？为什么知识库问答非它不可？第 1 节术语辨析RAG 检索外部资料再作答、不改模型参数、换资料即换答案；微调改模型本身；RAG 是知识库问答「答案带出处」的最低成立条件
8「价值维度」写成功能清单为什么不合格？第 1 节术语辨析要写成「没有它，用户多花多少时间或多花多少钱」的可计量句式，不是罗列功能
9同一句「帮我把会议记录整理成待办」，对话助手和 Agent 反应差在哪？第 2 节原理理解助手给整理好的文字；Agent 直接查数据、写文档、发通知——差别在交办深度，即人在回路中的位置
10判断一个产品是什么形态，最快的办法看什么？第 2 节原理理解看人在回路中的位置：人问一句、人画流程、人只验收，分别对应对话 / 工作流 / Agent
11豆包和 Kimi 都是对话助手，凭什么一个主打大众、一个主打长文档？第 2 节原理理解同形态不同定位：技术特长（长上下文）决定差异化场景；形态相同不等于产品相同
12知识库问答凭什么敢收企业的钱？第 2 节原理理解把散落文档变成可问答资产，省下新人培训与查资料时间——价值可计量，所以敢按席位收
13多模态生成为什么普遍按积分收费，对话助手却敢免费？第 3 节原理理解成本结构不同：一次生成的算力成本远高于一次对话；免费模式要靠流量与生态把钱补回来
14老板说「给我做一个像 Manus 那样的产品」，你第一句话问什么？第 3 节原理理解先问任务边界与容错度：哪些任务能交办、错了代价多大——不是先问用什么模型
15硬上数字人做制度播报，成本和体验各会翻在哪？第 3 节案例复盘成本：逐条生成 + 改字重渲 + 形象合规；体验：口型 / 念错、不能搜索复制、等待抽卡。需求本质是「查得到、带出处」，文本形态就够
16你平时用什么 AI 产品？它是什么形态？第 5 节面试追问先报产品 + 用「人在回路中的位置」给归类依据，再补一句定位或副形态；只报名字是失败答法
17我说它是 Chatbot，你凭什么说不是？再追一层：它跨形态吗？第 5 节面试追问用「主形态 + 副形态」表述，主交互为准；能举出内置知识库 / 插件等副形态特征
18这个场景你怎么选形态？为什么不上 Agent 全自动？第 5 节面试追问先问重复劳动与出错代价，稳定重复用工作流、需追责用知识库；Agent 有错误累积与责任边界问题

十、学员易错点预判与应对

易错点表现应对
追求唯一正确答案纠结某产品到底算助手还是 Agent教「主形态 + 副形态」表述法：先定主交互，再补一句「兼有某形态特征」
把形态当高低档位说「Agent 最先进，对话式要被淘汰」回扣金句「形态没有高下，匹配才对」；举反例：问天气用 Agent 是浪费，企业制度问答用知识库更稳
商业模式只会写「订阅制」六形态全写订阅用「成本结构 → 收费依据」倒推四类模式，要求必须写「凭什么」
技术依赖写成名词堆砌「依赖 NLP、深度学习、大模型」要求写成「这个形态成立的最低技术条件」，如知识库必须写出 RAG 四步
拆解报告写成产品评测只写「好不好用、界面漂不漂亮」强调报告回答三个问题：解决什么问题、靠什么成立、怎么收到钱
【术语混淆】把「形态」与「功能」混用「这个产品的形态是改文案和翻译」回第 1 节对照卡：形态是交互范式（怎么交任务），功能是能力点（能干什么），先定形态再列功能
【术语混淆】分不清 Agent / 工作流 / Copilot「能自动跑几步的就是 Agent」「Copilot 也是一种 Agent」用两张辨析表锁死：步骤由谁拆（Agent 自己拆 / 工作流人画死）、默认动作（Copilot 建议 / Agent 执行）；配「副驾 / 代驾 / 流水线」三个生活类比反复过
【术语混淆】缩写当成懂了会说「RAG」「Copilot」但说不出全称与中文首次出现一律给全称 + 中文；术语自测表设「写全称」列，写不出不算过关
【面试失分】只报产品名、报不出形态「我平时用豆包、Kimi、ChatGPT」然后卡住套 60 秒三件套：产品形态 + 人在回路中的位置 + 价值维度，先给结论再给依据
【面试失分】「为什么不用视频 / 数字人」只答「太贵」一句话带过，不算账、不给替代强制三条算账：成本结构倒推、体验账（等待 / 抽卡 / 口型 / 不能检索复制）、信息可检索性，再给折中方案
【面试失分】被追问 2 层就改口或跑题面试官一质疑就把主形态从「对话式」改成「Agent」两两模拟按《面试模拟记录表》记追问层与自评分；教「先确认主交互不动摇，再补副形态」的应答句式
【面试失分】编造经历或甩锅「是老板非要上数字人，不怪我」行为题要求给「当时判断 + 损失 + 复盘判据 + 改进」四段，用设计背景案例示范，不出现真实学员姓名与未公开数据
