课堂交互使用说明 · 《提示词调试台》（W1 周三专用）

AI 产品经理就业训练营 · 300 分钟（6 课时 × 50 分钟）
用途：本课核心教具，贯穿 300 分钟教学日的第 2 节（原理讲授与讲师示范）与第 4 节（32 分钟学员实操、自评验收），并支持第 6 节当堂验收复跑。工具位置：02-交互工具/提示词调试台.html
工具性质：单文件 HTML，零外部依赖，断网可用；回答为预置教学示例（不调用真实模型），评分基于关键词规则检测。使用前请完成「课前检查」，故障处理见第五节。
300 分钟版新增：《6 节使用时机表》见第七节，《设备要求表》（手机 / 平板 / 电脑三档）见第八节。

一、工具功能速览（讲师必读）

区域功能教学用途
顶栏「A/B 对比模式」开关一键切换单条调试 / 双条对比两种课堂模式
工作台System Prompt + User Prompt 两个输入框现场改写的主战场；改动即时反映到评分卡
场景模板4 个按钮：会议纪要总结 / 客户意图分类 / 合同信息抽取 / 文案改写一键填入五要素完整的标杆提示词
参数区模型（标准 / 长文本 / 轻量）、temperature 滑块（0–1）、max tokens口头演示：温度与稳定性的关系（细讲在 W6D1）
运行 / 重置「运行」出流式回答；「重置」一键还原当前模板原文「重置」是课堂救命键：改乱了 3 秒还原
模拟输出流式打字展示回答，附「复制回答」让学员「看见」同一提示词的输出形态
五要素评分卡总分 x/5、五段进度条、总评语、五行明细（已覆盖 / 缺失 + 改进建议）本课的第二主讲师：学员自评、互评都靠它
对比结果A/B 两栏回答 + 两侧评分 chip + 底部「差异解读」现场改写环节的收尾证据
快捷键Ctrl / Cmd + Enter 快速运行讲师连点时省鼠标路程

二、课前检查（开课前 10 分钟）

检查项操作
投屏分辨率浏览器窗口 ≥1280 px 宽，确保左右两栏不重叠、评分卡五行完整可见
模板就位打开后默认停在「会议纪要总结」模板，确认 System / User Prompt 两框有完整内容
评分卡验证点一次「运行」，确认评分卡显示 5/5、五段进度条全亮
差版预置提前把 User Prompt 改成「总结一下」备用（或上课时现场删），确认评分卡掉到 1/5
A/B 开关拨一次「A/B 对比模式」开关，确认左右工作台切换正常、出现「对比运行」按钮
学员端群里发布工具文件或链接，提醒学员用电脑浏览器打开（手机 ≤720 px 为单栏，替代动作见第八节）
备用方案另开一个标签页打开《提示词五要素检查卡》图片，工具卡住时切换照讲
字体大小投屏后站到教室最后一排确认能看清评分卡上的小字，必要时 Ctrl / Cmd +「+」放大至 125%

三、五步演示脚本（与讲课稿、教案节次对应）

工具内置了简版 5 步脚本（页面底部「课堂演示脚本」折叠区），此处为完整课堂版，含时间轴与提问。建议讲师课前照此走一遍。时间已按 300 分钟（6 课时 × 50 分钟）口径对齐：第 2 节 50–100 min 负责导入、逐要素与讲师示范，第 4 节 150–200 min 负责学员 32 分钟实操与自评验收。

第一步 · 制造冲突（第 2 节 · 50–60 min）

项目内容
操作确认停在单条工作台 → 全选删除 User Prompt，只输入「总结一下」→ 点「运行」
说「同一条需求，两种命运。现在左边四个字，看评分卡——1 分，五项缺四项。」
问「就这四个字，模型会怎么回答？」
讲输入缺信息，模型全靠猜；猜十次十种结果。
操作点「重置」→ 点「运行」
说「完整版回来——5 分。再看回答：四个部分、待办是表格、三百字以内。」
停让学员自己对比 10 秒，不讲解
问「差在哪？三个字以内回答。」（预期：结构 / 要素）

第二步 · 逐要素指认（第 2 节 · 60–82 min）

项目内容
操作保持完整提示词在屏，评分卡可见
说每讲一个要素，用手指评分卡对应行 + 提示词对应句
问「删掉 System Prompt 里那句角色设定，回答会变吗？」（角色）
问「『总结一下』和『整理成结构化纪要』，差在哪？」（任务，预期：可验收）
问「『不要添加原文没有的信息』这句话防的是什么？」（约束，预期：编造）
问「格式为什么不定到字段级？」（输出格式，预期：下游要解析）
问「示例是加分项还是必需品？」（示例，预期：看场景）
操作每问之间可点一次「运行」刷新输出，强化「提示词—输出」的因果
备用动作时间充裕时，逐个点 4 个模板按钮，让学员看到四类任务的提示词都长一个样——五要素结构通用

第三步 · 现场改写（第 2 节示范 82–92 min + 第 4 节学员实操 150–190 min，本课核心动作）

项目内容
操作拨开「A/B 对比模式」开关
说「现在左右两边提示词一样。我们在 B 侧现场改，改一项报一次分。」
A 侧保留学员的差版原文（如「帮我写个周报」），不动
B 侧按五要素逐项写入，每写一项停 5 秒报分：角色 → 任务 → 约束 → 格式 → 示例
操作点「对比运行」，等两侧回答流式输出完
说「先读回答，再看评分 chip——1 分对 5 分。底部差异解读那句，请一位同学念出来。」
停请 1 名学员朗读差异解读，强化「提示词越完整输出越可控」
收尾「现在轮到你们。打开导学案改写练习区，改你自己的那条——按第 4 节四步走，32 分钟。」（四步见讲课稿第 4 节与第七节使用时机表）
巡视记录三个高频问题：只加角色不加约束 / 约束写「请好好写」/ 格式写「格式清晰」，点评环节集中讲

第四步 · 参数一句话（第 4 节机动，2 min）

项目内容
操作单条模式下，把 temperature 从 0.3 拖到 0.9，点「运行」
说「温度是创造力和稳定性的权衡。0.3 适合生产，0.9 适合头脑风暴。今天记住结论就行，W6D1 专门讲参数。」
操作拖回 0.3，点「重置」

第五步 · 自评验收（第 4 节 · 190–200 min；第 6 节复跑同此操作）

项目内容
操作学员在自己设备上打开工具，把改写后的提示词贴进工作台
说「目标 4 分。到了的举手；没到的，看评分卡第五行的改进建议，缺哪项补哪项。」
讲「4 分是及格线的理由：四个骨架要素必须到位，示例看场景——格式简单的任务硬凑示例是噪音。」
巡记录未达标学员的共性缺失项，作为周末作业的重点提醒

四、A/B 对比模式课堂用法专述

场景配置方法课堂效果
差版 vs 好版（主用法）A 贴差版原文，B 贴改写版；两侧温度保持相同（都 0.3）隔离变量：差异全部来自提示词本身，底部解读会明说「两侧提示词不同，其中 B 的五要素评分更高」
同提示词 · 不同温度两侧提示词完全一致，B 侧温度拖到 0.9隔离变量：差异全部来自温度，解读会明说「适合单独观察温度的影响」
学员作品 vs 标杆模板A 贴学员改写稿，B 点模板按钮后手动贴入（模板按钮只填充当前侧，注意同步）让学员的稿子和标杆同屏对比，差距一眼可见

注意事项：

  1. A/B 模式下评分卡（单条模式的右栏）会被隐藏，两侧分数显示在回答框上方的「评分 x/5」chip——指分数时指 chip，别指空的评分卡区。
  2. 每次只改一个变量。同时改提示词又改温度，学生无法归因，课堂结论会糊。
  3. 模板按钮在 A/B 模式下点击会同时覆盖 A、B 两侧作为对比基准，需要「A 差 B 好」时，先点模板再手动把 A 侧改差，不要反过来操作。

五、常见故障处理

故障处理
点击「运行」无反应检查焦点是否在输入框；直接按 Ctrl / Cmd + Enter；仍无效则刷新页面
流式回答输出到一半停住属正常节奏（约 24 毫秒 2 字符）；若超过 10 秒不动，刷新后重跑；讲解不中断，用「工具也有卡住的时候，产品要有兜底」带过
评分卡分数和预期不符先查评分依据：评分检测的是关键词是否出现，比如「你是」「资深」「不要」「JSON」「示例」等。分低不一定是提示词差，可能是同义换词没被规则命中——顺势讲「规则有边界，工具是辅助不是裁判」
学员端打不开 / 打不开文件无需等待——本工具讲师演示型优先，学员课后可自学；确保课前已在群里发过文件；手机 / 平板走第八节替代动作
A/B 开关拨了没反应刷新页面；或检查是否点到了开关文字而非轨道（点击整行均可触发）
投屏字太小浏览器 Ctrl / Cmd +「+」放大至 125%–150%
断网 / 内网环境工具零外部依赖，断网可用；直接双击本地 html 文件即可
想恢复初始状态点「重置」：还原当前模板原文、参数复位（temperature 0.3、max tokens 500、标准模型）

六、课后学员自学指引（发群文案）

同学们，今天课的提示词调试台已发群（单文件，断网可用，建议用电脑浏览器打开）。课后请大家完成三件事：
① 把你们预习写的那条提示词，按课堂学的五要素改写到评分 4/5 以上，把改写前后的评分截图存好；
② 点开其余 3 个模板（客户意图分类、合同信息抽取、文案改写），对照评分卡看看它们五要素是怎么写的，重点看「约束」和「输出格式」两行；
③ 打开右上角「A/B 对比模式」，同一段提示词，一侧温度 0.3、一侧 0.9，各跑一次，把两个回答的差异写在导学案上。
提醒：周末的 30 条练习集，每条都要过这个评分，4 分是及格线。周五课前我会抽查 5 位同学的练习集。手机 / 平板同学按《设备要求表》走替代动作，产出一样算数。
