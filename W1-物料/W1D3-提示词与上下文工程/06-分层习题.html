分层习题 · W1 周三《提示词与上下文工程》

同步说明：本件已按 2026-11-13 版《02-讲课稿》结构化同步（去课时化 · 知识库课件补充 · 术语统一）。原有框架与题目保留；文末「讲稿同步补充」为按新讲稿追加的内容。

AI 产品经理就业训练营 · 去课时化版（按课堂节奏弹性安排）· 5 层难度 层级：第 0 层术语辨析 → 第 1 层基础巩固 → 第 2 层进阶实操 → 第 3 层求职挑战 → 第 4 层面试实战。 建议用法：第 0 层配对应板块当堂小测（10 分钟）；第 1 层当堂测 10 分钟；第 2 层当作业；第 3 层自测、第八周面试课复用；第 4 层配对应板块两两模拟与对应板块当堂验收。 原三层（基础巩固 / 进阶实操 / 求职挑战）全部保留并各补 ≥2 题；全部题目附参考答案与评分标准。

第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错 / 辨析四种题型）

配对应板块《术语自测表》与 12 题当堂小测；闭卷，每题 1 分，≥10/12 达标。

一、选择题（T1–T4，单选）

T1. 关于「提示词」与「上下文工程」的关系，下列说法正确的是（　） A. 上下文工程就是把提示词写得更长 B. 提示词是这一次对话的指令，上下文工程是组织喂给模型一切的系统设计 C. 两者是同一件事的两种叫法 D. 上下文工程只管历史对话，不管资料与工具

T2. 「不要添加原文没有的信息」与「输出 JSON，含 intent、confidence、reason 三个字段」分别属于（　） A. 约束 / 输出格式　B. 输出格式 / 约束　C. 任务 / 示例　D. 角色 / 约束

T3. 关于「Token 成本」，下列说法正确的是（　） A. 等于提示词的字数，少写字就能降成本 B. 只统计模型输出的字数，输入不计 C. 按词元计量，输入、输出、带进来的历史对话一起计入 D. 与上下文长度无关，只与模型版本有关

T4. 下列任务描述中，最「可验收」的是（　） A. 请好好总结一下　B. 写清楚你的分析，注意质量 C. 请将以下会议记录整理成四部分纪要，待办用表格含负责人和截止时间 D. 认真专业地处理一下这份材料

二、连线题（T5–T6）

T5. 将左列「五要素」与右列「缺失症状」连线（每项只连一次）：

左列 · 要素 右列 · 缺失症状
① 角色 A. 产出是散文，下游没法用
② 任务 B. 编造信息、跑题、超长
③ 约束 C. 格式和风格每次飘
④ 输出格式 D. 回答是「客服腔」，没有专业视角
⑤ 示例 E. 每次输出都不一样，无法验收

T6. 将左列「四组件」与右列「解决的病 / 不做后果」连线（每项只连一次）：

左列 · 组件 右列 · 解决的病 / 不做后果
① 资料注入 A. 模型不会用 → 该调不调、乱调错调
② 工具描述 B. 模型总失忆 → 用户重复自我介绍
③ 记忆设计 C. 多轮接不上 → 用户改三次日期它忘两次
④ 历史对话 D. 模型不知道 → 一本正经编造公司政策

三、改错题（T7–T9，指出错处并改写）

T7.「帮我写一篇公众号文章，要求文笔好一些，不要太长，别写差的内容。」——指出其中不可验收的约束并改写。

T8.「上下文工程就是把提示词写长一点，多塞点背景资料就行。」——指出概念错误并改写。

T9.「示例越多越好，我把 20 个输入输出例子全塞进提示词，评分肯定 5 分。」——指出两处误解并改写。

四、辨析题（T10–T12，每组用一句话说清区别）

T10. 资料注入 vs 记忆设计：都在「塞信息」，塞的一样吗？

T11. 工具描述 vs 历史对话：分别解决「不会用」还是「接不上」？

T12. 从以下两组中任选一组辨析：①「示例 / 少样本」vs「堆字数」；②「角色」vs「让模型变聪明」。

第 1 层 · 基础巩固题（概念层，原 1–10 题保留 + 新增 16、17 题）

一、提示词找茬题（每题 10 分，共 40 分）

1. 下面这条提示词缺了哪些五要素？（找出至少 3 项，写出缺失项名称与补法）

你是一名资深HR。

2. 下面这条提示词缺了哪些五要素？（找出至少 3 项，写出缺失项名称与补法）

请分析这份用户反馈，写清楚你的分析，注意质量。

3. 下面这条提示词有一处「写了等于没写」的约束，请指出并改写。

帮我写一篇公众号文章，要求文笔好一些，不要太长，别写差的内容。

4. 下面这条提示词的输出格式为什么不可用？请改到字段级。

把会议内容整理成表格。

二、五要素识别题（每题 10 分，共 40 分）

5. 「你是一名拥有 8 年经验的跨境电商运营专家，熟悉亚马逊平台规则与广告投放」——这句话属于哪个要素？删掉它，输出最可能发生什么变化？

6. 「只根据以下材料回答，材料中没有的信息一律回答『未提及』；回答不超过 200 字」——这句话属于哪个要素？它主要防住哪两类输出事故？

7. 「参考示例：输入：本周完成知识库文档整理 30 篇。输出：交付类——完成客服知识库 30 篇文档整理。」——这句话属于哪个要素？它在什么场景下可以省略？

8. 将下列五句话按五要素归类（每句只归一类）：

A. 「请将以下客户消息分类到指定意图类别，并给出置信度和判断理由」 B. 「你是一名电商平台客服中心的意图分类专家，判断准确、口径一致」 C. 「只能从上述类别中选择，不得自造类别；置信度低于 0.6 时归入『其他』」 D. 「输出 JSON，包含 intent、confidence、reason 三个字段，不要输出多余文字」 E. 「输入：『订单 123456 到哪了？三天了还没有物流更新。』输出：{\"intent\": \"物流查询\", \"confidence\": 0.98}」

三、上下文工程速答（每题 10 分，共 20 分）

9. 写出上下文工程四组件的名称，并各用一句话说明它解决什么产品问题。

10. 判断：以下场景分别最需要哪个组件？（每题选一个）

A. 用户问「你们公司年假几天」，模型回答「一般公司年假 5 到 15 天不等」 B. 用户上周说过「我住在浦东」，这周助手推荐会议地点时又问了一遍「您住哪」 C. 用户说「帮我订明天去北京的票」，模型回复「我无法订票」 D. 用户连问五个跟进问题，模型在第三个问题后开始答非所问

四、新增补题（16、17 题，每题 10 分）

16. 「可验收」与「写清楚」是不是一回事？请各举一条提示词，并说明判断依据。

17. 一条提示词把整份 2000 字文档和「请认真、专业、高质量地总结」全塞进去，调试台仍评 1/5。请用「堆长度 ≠ 补要素」解释原因，并指出该补哪两类要素。

第 2 层 · 进阶实操题（方案设计层，原 11、12 题保留 + 新增 18、19 题）

11. 低分提示词改造（50 分）

你接手一个同事写的提示词，调试台评分 1/5：

帮我看看这个数据。

已知业务背景：运营同事每周要把一份销售明细（Excel 粘贴的纯文本，含日期、渠道、订单数、成交额四列）变成一份给部门总监的摘要，总监关心三件事——哪个渠道在涨、哪个在跌、有没有异常波动。

请按五要素重写这条提示词，要求： 1. 五要素齐全，全文可直接复制使用； 2. 至少两条可验收的约束； 3. 输出格式定到字段级； 4. 附一个输入输出示例； 5. 说明你每一项的设计理由（每条理由一句话）。

12. 上下文工程方案设计（50 分）

你负责一款面向中小电商卖家的「经营参谋」AI 助手，已上线三个月，出现四个投诉：

  • 投诉 1：「我问它上周店铺退货率，它给了一个行业平均数字，根本不是我的」；
  • 投诉 2：「让它算一下投产比，它心算，还算错了」；
  • 投诉 3：「我每次都要重新说一遍我卖的是童装」；
  • 投诉 4：「聊到第五轮，它把我前面定的活动预算忘了」。

请为每个投诉匹配对应的上下文工程组件，并给出你的设计动作（每个组件：配什么、怎么配、注意什么边界）。

18. 场景选组件与成本收益（新增，50 分）

三个场景，分别判断「四组件里哪几个必须做、哪个可不做、哪个是陷阱」，并写一句成本收益理由： ① 客服机器人回答公司售后政策；② 差旅助手帮用户订机票酒店；③ 一次性文案润色（无用户系统）。

19. 记忆设计表（新增，50 分）

为一款「AI 学习助手」画一张记忆设计表，至少 4 个记忆项，逐项写清「存多久 / 失效条件 / 用户能否删除」，并回答：用户说「别再记我的偏好了」，产品上必须提供什么？

第 3 层 · 求职挑战题（面试层，原 13、14、15 题保留 + 新增 20、21 题）

13. 面试真题：提示词调了三天还不稳定，怎么办？（30 分）

面试官：「我们做一个合同抽取功能，提示词团队改了三天，抽取准确率还是波动很大，你会怎么处理？先提示词还是先微调？」

要求：先给结论，再按优先级给排查步骤，最后补一个「显专业」的补充观点。

14. 面试真题：说说你对上下文工程的理解（30 分）

面试官：「现在都在说上下文工程，和提示词工程什么关系？你做过哪些上下文层面的设计？」

要求：一句话说清两者关系；四组件至少展开两个，各配一个你做过的设计细节；收在一个金句上。

15. 案例题：同样的提示词，两个同事跑出两个结果（40 分）

团队里两位同事用同一条提示词处理同一批客户反馈，A 的产出被运营直接采用，B 的产出被打回重做。排查发现：两人的提示词原文确实一致，但 A 额外做了三件事。请列出你认为最可能的三件事，并说明每件事为什么影响产出。

20. 新增真题：怎么让输出可验收（30 分）

面试官：「你说提示词要可验收，具体怎么做？如果用户问的材料里根本没有答案，你怎么处理？」

要求：给「可验收」判据；列出任务、约束、格式、兜底四层动作；不编造效果数字。

21. 新增真题：上下文成本怎么控（30 分）

面试官：「我们想给产品加知识库、记忆、十几个工具，老板问成本会不会失控，你怎么答？」

要求：先给结论（越准越好不是越多越好）；给组件优先级与至少两条具体手段；用 Token 成本术语点明计费口径。

第 4 层 · 面试实战（7 题，每题含踩分点 / 追问链 / 失败答法 / 60 秒标准答法 / 评分表）

配对应板块两两模拟与对应板块当堂验收。四类必考：五要素是什么 / 提示词与上下文工程区别 / 怎么让输出可验收 / 怎么控制成本。

M1 · 请说说提示词五要素是什么（技术理解）

  • 踩分点：① 五要素报全且顺序正确；② 点出「前四项是骨架，示例是稳定器」；③ 用「可验收」解释任务要素；④ 至少给一个写法句式。
  • 追问链：L1 哪一项最易漏 → 约束与输出格式（爱写「请好好写」「格式清晰」）；L2 怎么判断约束合不合格 → 能判对错、两人同结论，如「不要添加原文没有的信息」；L3 示例是不是每条都要 → 看场景，格式简单可省，故及格线定 4 分。
  • 失败答法：「就是角色、任务、约束、输出格式、示例，写全就行。」——只报菜名，追问 L1 即卡住。
  • 60 秒标准答法：「五要素是角色、任务、约束、输出格式、示例，前四项是骨架、示例是稳定器。角色不是让模型变聪明，是换一副专业视角；任务的第一纪律是写到可验收；约束划边界防编造也管成本；输出格式定到字段级，因为格式定义就是接口文档；示例给个照着画的样板，看场景取舍。我写完用评分卡逐项自检，四个骨架到位即达标——这也是及格线定 4 分不定 5 分的原因。」

M2 · 提示词工程和上下文工程什么关系（技术理解）

  • 踩分点：① 一句话关系（前者是后者一个组件 / 指令层 vs 系统层）；② 四组件报全；③ 展开 ≥2 个组件带设计细节；④ 收在系统视角或金句。
  • 追问链：L1 举个做过的上下文设计 → 资料注入带引用标号 + 工具描述重写三句话；L2 为什么叫工程不叫技巧 → 数据源、刷新、历史、描述全是有依赖的系统设计；L3 PM 主战场在哪 → 模型是黑盒，上下文组织层才是主战场。
  • 失败答法：「上下文工程就是把提示词写得更长一点。」——把系统设计降级成「写长」，未提四组件。
  • 60 秒标准答法：「一句话：提示词是需求文档，上下文工程是系统设计，前者只是后者的一个组件。提示词管这一次的指令，管不到模型『不知道、不会用、总失忆』；上下文工程用四组件补——资料注入治『不知道』，检索后带引用标号拼入；工具描述治『不会用』，写成『什么时候用、传什么、返回什么』；记忆设计存跨会话偏好并留删除入口；历史对话用近轮原文加远轮摘要。面试官问这个，想听的是系统视角，不是背四个词。」

M3 · 你怎么让模型输出可验收（场景设计）

  • 踩分点：① 判据——两人看得出同一结论；② 任务动词具体、输入输出都交代；③ 约束可判（防编造 / 限长度 / 缺信息答「未提及」）；④ 格式到字段级 + 校验或评测集兜底。
  • 追问链：L1 材料里没答案怎么办 → 约束写死「一律答未提及」，宁可拒答不编；L2 下游要解析格式怎么定 → 字段名即契约，必要时加校验层；L3 怎么证明改完变好了 → 建 20–50 条评测集跑 badcase，用数据不用感觉。
  • 失败答法：「我会把要求写清楚一点，让模型认真答、别出错。」——全是感觉级，无判据无字段无兜底。
  • 60 秒标准答法：「我理解可验收是『完成没完成，两人能得出同一结论』。落到抽取任务我做四件事：任务写成『请将以下客户消息分类到指定意图类别』；约束写死『只从给定类别中选、不得自造，材料未提及一律答未提及』；输出格式定到字段级，输出 JSON 含 intent、confidence、reason，字段名即接口契约；最后加输出校验或建 20–50 条评测集跑 badcase。这样交付给研发和评测，大家看的是同一把尺子。」

M4 · 上下文越堆越多，成本怎么控（场景设计）

  • 踩分点：① 结论——不是抠字数，是控上下文，越准越好；② 组件优先级（先资料注入 / 工具，记忆后置）；③ ≥2 条具体手段（检索裁剪 / 近轮原文远轮摘要 / 单轮不做记忆）；④ 用 Token 成本点明「输入 + 输出 + 历史一起计费」。
  • 追问链：L1 Token 成本是什么 → 词元计量单位，输入、输出、带进来的历史一起上秤；L2 多轮历史怎么处理最省 → 近轮原文、远轮摘要、关键参数单独存档；L3 怎么论证砍组件 → 拿成本收益比说话，一次性咨询做记忆成本上去、感知为零。
  • 失败答法：「少写点字、把提示词缩短，或者换个便宜模型。」——把成本当字数问题，没答到上下文组织层。
  • 60 秒标准答法：「结论是控成本不是抠字数，是控上下文——Token 成本按词元计，输入、输出、带进来的历史一起上秤。做法三层：按成本收益排组件优先级，资料注入和工具描述先行、记忆后置；注入前先检索裁剪，只捞本次要用的那段；历史对话用近轮原文加远轮摘要，单轮任务不做记忆。尺子始终是上下文不是越多越好，是越准越好，每个组件都要过成本收益关。」

M5 · 提示词调了三天还不稳定，先提示词还是先微调（项目深挖）

  • 踩分点：① 结论——先穷尽提示词与输入，再考虑微调；② 排查成体系（五要素 → 统一输入 → 校验层 → 评测集）；③ 点出「一半提示词问题、一半数据问题」；④ 补显专业观点（badcase 归因 / 校验层兜底）。
  • 追问链：L1 第一步查什么 → 回五要素，查约束可验收、示例缺不缺，统一输入分隔符与字段；L2 怎么定位理解问题还是格式问题 → 建 20–50 条评测集跑 badcase；L3 什么时候真该微调 → 要改变模型行为且提示词与数据都穷尽后仍不稳，且微调前先上结构化输出与校验。
  • 失败答法：「调不好就微调呗，换个大模型一般就好了。」——跳过全部排查，暴露没有工程闭环。
  • 60 秒标准答法：「结论先给：先穷尽提示词，再考虑微调，微调前先上结构化输出与校验。排查四步：回五要素查约束是否可验收、示例缺不缺；统一输入格式与字段定义，输入质量决定输出上限；加输出校验层，用 JSON schema 或正则兜底格式；建 20–50 条评测集跑 badcase，分清是理解错还是格式不合规。补一个观点：多数准确率问题，一半是提示词问题、一半是数据问题——先看评测集再动模型。」

M6 · 你做过哪些上下文层面的设计，说一个细节（项目深挖）

  • 踩分点：① 明确选两个组件；② 每个带「配什么、怎么配」动作层细节；③ 带可核对的结果或边界（删除入口 / 成本 / 误调）；④ 落到系统视角收束。
  • 追问链：L1 资料从哪来、多久刷新 → 指定知识库、按版本刷新、拼入带引用标号；L2 记忆设计最大的坑 → 不是存不下，是没给用户查看与删除入口；L3 四组件全上是不是最好 → 不是，按成本收益比排优先级。
  • 失败答法：「我做过知识库，也做过记忆，还接了几个工具，效果还不错。」——三个名词各一句，无动作无边界，追问即空。
  • 60 秒标准答法：「我重点做过两个组件。资料注入上，把公司政策文档在回答前检索出来、按版本刷新，拼进提示词时带引用标号，模型不用编、答错也能溯源；工具描述上，把工程师复制的接口注释重写成『什么时候用、传什么参数、用完给用户看什么』三句话，模型乱调明显减少。两个设计都留了边界：记忆项必须可查看可删除，工具不是越多越好。我的体会是，四组件不是清单打勾，是上下文工程这套系统里按成本收益排先后。」

M7 · 用户说「别再记我的偏好了」，产品上要做什么（行为 / 合规）

  • 踩分点：① 秒答「提供记忆的查看与删除入口」；② 说清是底线功能不是加分项；③ 展开记忆设计四要素（存什么 / 存多久 / 谁可见 / 怎么删）；④ 关联 PRD 与隐私合规，且不编数字。
  • 追问链：L1 只删这一条够吗 → 要能查看全部、逐条删、一键清空，并确认删除后不再注入；L2 这张表写在哪 → PRD 单列一节；L3 记忆设计还容易和什么混 → 和资料注入混，一个存跨会话用户信息、一个塞本次外部资料。
  • 失败答法：「跟用户说好的，然后提示词里加一句『不要记偏好』就行。」——把合规底线当一句提示词，用户数据仍在系统里。
  • 60 秒标准答法：「产品上必须提供记忆的查看与删除入口，这不是加分项，是个人信息保护的底线功能。我会做三件事：让用户能看到系统记了哪些偏好、能逐条删也能一键清空，并确认删除后不再被拼进上下文；设计上先画表写清哪些信息进记忆设计、存多久、谁可见、怎么失效，这一节直接进 PRD；最后区分记忆和资料注入——前者是跨会话用户信息，后者只是本次要用的外部资料。用户说别记了，考验的不是提示词，是产品有没有把删除权交回去。」
