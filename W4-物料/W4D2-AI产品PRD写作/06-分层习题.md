## 第 3 层 · 求职挑战（4 题：原有 2 题 + 新增 2 题）

**3.1（原第 9 题）面试真题：怎么写 AI 产品的 PRD？（30 分）**

面试官：「我们准备做一个智能客服产品，你作为产品经理，PRD 里会写哪些 AI 产品特有的内容？和传统 PRD 差在哪？」
要求：先给总述，再逐条展开五处差异，每条配一个具体示例。

**3.2（原第 10 题）案例分析：评审会上被研发连环追问（30 分）**

评审会上，研发对你的 PRD 连发三问：「答错了算谁的？」「每回答一次多少钱？」「上线三个月后评测集还够用吗？」你当场如何回应？这暴露了你 PRD 的哪些章节缺失？请说明补写方案。
要求：三问逐一回应，每问指出对应章节与应补内容。

**3.3（新增）面试真题：提示词算不算需求？（30 分）**

面试官：「提示词算不算 PRD 的一部分？线上有人改了一行提示词，效果突然变差，你怎么追？」
要求：给出明确判断、至少两条理由、以及留痕与验证机制。

**3.4（新增）面试真题：评测标准的数字怎么定、会过时吗？（30 分）**

面试官：「你写引用正确率 ≥90%，这个数怎么来的？上线三个月后还准吗？」
要求：说清数字的两个来源、评测集的时效性问题、以及保持评测集有效的机制。

## 第 4 层 · 面试实战（6 题，每题含踩分点 / 追问链 / 评分表）

> 对应对应板块（200–250 min），与 02-讲课稿对应板块 7 道面试题同源，此处精选 6 题用于两两模拟与判分。每题均给：题目 + 题型、踩分点、2–3 层追问链（含应答要点）、典型失败答法 + 失分原因、60 秒标准答法精要、三档评分表。

### M1｜AI 产品的 PRD 和传统 PRD 差在哪？（技术理解）

- 踩分点：① 总述「骨架相同、五处不同」；② 五处齐全（评测标准 / 容错兜底 / 幻觉控制 / 成本预算 / 数据回流）；③ 至少 1 处给出「指标名 + 数字门槛 + 数据来源」示例；④ 补「提示词是需求的一部分」或「数据回流闭环」。
- 追问链：L1「挑一处说你项目里怎么写、怎么验收」→ 落到具体指标与评测集来源；L2「五处落在哪几章」→ 第 5–9 章，前三章与第十章通用；L3「只写 AI 能力需求一章算不算 AI PRD」→ 不算，只答「做什么」。
- 典型失败答法：「多了 AI 能力、多了提示词、要写模型。」失分原因：只报概念、举不出可验收例子，五处说不全，L1 即卡住。
- 60 秒标准答法精要：总述一句 → 五处各配「指标 + 数字 + 来源」示例 → 收「提示词改动走评审」。全文见 02-讲课稿对应板块题 1。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 说出至少 3 处差异，有基本解释 |
| 良好（75–89 分） | 五处齐全，每处带 1 个可验收示例，出现「三要素」「降级链」等框架词 |
| 优秀（90–100 分） | 额外答出「提示词是需求的一部分」或「数据回流闭环」，且 60 秒内结构清晰 |
| 典型失分 | 只背五个名称无例子；或把「幻觉控制」并入「容错兜底」——各扣 10 分 |

### M2｜你怎么把一条需求写成可验收的？（项目深挖）

- 踩分点：① 先对齐「口径」再写验收标准；② 功能写全输入 / 处理 / 输出；③ 评测标准三要素齐全；④ 说清「研发读完不用来问」这条判别线。
- 追问链：L1「『引用正确』怎么定义、谁定」→ 口径由产品与研发共同约定并写进 PRD；L2「数字门槛怎么来」→ 同行基准 + 小样本试跑；L3「研发说这条测不了」→ 拆口径、换代理指标、写进变更记录。
- 典型失败答法：「写清楚一点、加个验收标准就行。」失分原因：无三要素、无口径意识，L1 暴露没写过验收条款。
- 60 秒标准答法精要：三步——对齐口径 → 输入 / 处理 / 输出三件套 → 三要素；判别线「研发还需不需要来问第二个问题」。全文见 02 题 2。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 提到「写清输入输出」或「三要素」之一 |
| 良好（75–89 分） | 三步齐全，且明确「先对齐口径」 |
| 优秀（90–100 分） | 额外给出「研发读完不用来问」判别线，并落到自己项目的具体指标 |
| 典型失分 | 缺口径意识、验收标准只有形容词——各扣 10 分 |

### M3｜幻觉怎么约束？写进 PRD 哪几章？（技术理解 / 场景设计）

- 踩分点：① 点明「幻觉是概率续写引擎的本能，不是 bug」；② 三道防线齐全（引用 / 阈值拒答 / 红线 + 回滚）；③ 说清落在第 5、6、7、9 章；④ 点明责任人是产品经理。
- 追问链：L1「只写『标注引用来源』够不够」→ 不够，缺事中拦截与事后监控；L2「阈值设多少、谁定」→ 试跑定阈值，属边界条件与口径；L3「生成类产品没有知识库怎么办」→ 写「输出须可溯源或标注不确定性」+ 低置信重试与校验规则。
- 典型失败答法：「让算法把模型调准一点，幻觉就少了。」失分原因：把产品需求甩给技术，没答 PRD 里写什么，也没提三道防线。
- 60 秒标准答法精要：本能 → 三道防线 → 四章落点 → 「幻觉控制不是技术攻关，是产品需求」。全文见 02 题 3。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 答出「引用来源」+ 至少一道其他防线 |
| 良好（75–89 分） | 三道防线齐全，点明责任人是产品经理 |
| 优秀（90–100 分） | 额外说清章节落点，并回答「无知识库」的生成类变体 |
| 典型失分 | 把幻觉当技术 bug、只答一道防线——各扣 10 分 |

### M4｜研发说「这个指标 / 相似度阈值做不到」，你怎么办？（行为题）

- 踩分点：① 不争辩、不甩锅，先承认约束；② 拆「做不到」的是口径还是数值；③ 给降级方案或可测的代理指标；④ 写进变更记录并回归评测。
- 追问链：L1「是不是就把标准删了」→ 不删，先问清「算不出」还是「达不到」；L2「换代理指标谁拍板、怎么留痕」→ 共同确认口径，走变更流程；L3「是不是降低质量」→ 用护栏指标与红线守底线，降级不等于放水。
- 典型失败答法：「这是研发的事，让他们想办法」「应该能做到啊，我再催催」。失分原因：甩锅或空辩，无拆口径、无降级、无留痕。
- 60 秒标准答法精要：四步「承认约束 → 拆口径 → 给降级 → 留变更记录」+ 回归评测 + 评审同步。全文见 02 题 4。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 不甩锅，且提出「先问清做不到的是什么」 |
| 良好（75–89 分） | 四步齐全，给出代理指标或降级方案 |
| 优秀（90–100 分） | 额外体现「降级不等于放水」「PRD 是共识合同，改哪条都留痕」 |
| 典型失分 | 空辩 / 删标准 / 甩锅研发——出现任一扣 15 分 |

### M5｜评测标准的数字门槛怎么定？上线三个月后还准吗？（技术理解 / 场景设计）

- 踩分点：① 数字两个来源（同行基准 + 评测集试跑）；② 「跳一跳够得着」，不拍脑袋；③ 点出评测集会过时；④ 用数据回流每周把 badcase 筛进评测集。
- 追问链：L1「90% 拍脑袋行不行」→ 不行，要么形同虚设要么压垮团队；L2「评测集不更新会怎样」→ 分数虚高、产品在退步却看不出；L3「回流 badcase 谁标注、多久一次」→ 待标注队列、每周筛选、周报跟踪。
- 典型失败答法：「参考行业惯例定个 90% 就行。」失分原因：没说数据来源、没意识到评测集时效性，L2 直接失分。
- 60 秒标准答法精要：两来源 → 带数据来源 → 评测集会过时 → 第 9 章回流机制（标签 / 待标注队列 / 周报三指标）。全文见 02 题 5。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 说出数字的至少一个来源 |
| 良好（75–89 分） | 两来源齐全，且点出「评测集会过时」 |
| 优秀（90–100 分） | 完整给出回流闭环（标签 / 队列 / 周期 / 周报三指标） |
| 典型失分 | 只答「参考行业惯例」、答不出评测集时效性——各扣 10 分 |

### M6｜评审会上研发连问「答错了算谁的」「每回答一次多少钱」「三个月后评测集还够用吗」，你怎么回应？（行为题）

- 踩分点：① 三问逐一对应缺失章节（容错兜底 / 成本预算 / 数据回流）；② 每问给具体补写内容；③ 体现「承认缺口 + 方案 + 时间点」的沟通策略；④ 补出评测标准章。
- 追问链：L1「三问说明缺了什么」→ 五处差异里的三处落点；L2「当场答不上来怎么办」→ 承认缺口、给方案、给时间点，不硬撑；L3「补齐后怎么防再漏」→ 十章自查十问 + 评审清单。
- 典型失败答法：「这些是技术细节，评审不用管」「我回去补一下」。失分原因：把产品约束当技术细节，且无方案与时间点。
- 60 秒标准答法精要：三问各点一章 → 补写内容 → 「承认 + 方案 + 时间点」话术 → 补评测标准章。全文见 02 题 7。

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 三问都能对应到章节缺失 |
| 良好（75–89 分） | 每问给出具体补写内容（四级链路 / 成本公式 / 回流周期） |
| 优秀（90–100 分） | 额外体现「承认 + 方案 + 时间点」沟通策略，或指出还缺评测标准章 |
| 典型失分 | 把三问当技术细节、只答「回去补」——出现任一扣 15 分 |

### 第 2 层 · 片段改错与补写（2.1–2.3）

**2.1 参考答案（5 处问题与改写示范，均为教学示例）**：

| # | 问题 | 改写示范 |
|---|---|---|
| 1 | 无输入输出定义：「支持智能问答」不可开工 | 「用户以自然语言输入课程政策问题，系统在 3 秒内输出基于知识库、带引用来源的回答」 |
| 2 | 无评测标准：「效果要好，后续评估」 | 「引用正确率 ≥90%，评测集 50 条，来源为近三个月用户真实提问」 |
| 3 | 兜底方向错误：「应尽量给出参考答案，避免让用户失望」——鼓励编造 | 「知识库无依据时不得生成，改为拒答话术并推荐帮助中心入口」 |
| 4 | 无成本约束 | 「单次问答成本 ≤0.05 元，单用户单日上限 50 次」 |
| 5 | 无数据回流机制 | 「点踩必选归因标签，badcase 每周回流评测集，幻觉率周报跟踪」 |
| 加分项 | 「提升用户体验」为不可测表述；「研发自行选择方案」= 无验收口径 | 各加 10 分 |

| 档位 | 标准 |
|---|---|
| 合格（60–74 分） | 找出至少 3 处问题，改写方向正确但不必完整 |
| 良好（75–89 分） | 找出全部 5 处，改写符合「指标名 + 数字门槛 + 数据来源」等规范 |
| 优秀（90–100 分） | 全部 5 处 + 指出「尽量给出参考答案」与幻觉控制原则的根本冲突，或补出加分局（如可测性、验收口径） |

**2.2 参考答案**：先写口径（如「『引用正确』指引用片段与知识库原文一致」），再落三要素——「引用正确率 ≥90%，评测集 50 条，来源为近三个月用户真实提问；拒答恰当率 ≥85%；幻觉率 >5% 触发回滚」（教学示例）。评分：口径 30 分、指标名 + 数字门槛 40 分、数据来源 30 分；只写形容词不得分。

**2.3 参考答案**：低置信 → 澄清追问；无结果 → 明确拒答并推荐帮助中心；连续失败 → 引导转人工；服务不可用 → 降级为关键词搜索 FAQ；单次成本 ≤0.05 元（教学示例，按输入 2000 token + 输出 500 token 估算）；点踩归因标签 ≤4 个（答错 / 答非所问 / 引用错误 / 其他），badcase 每周回流评测集（条数自定并写明）。评分：四级链每级 10 分共 40 分，顺序颠倒扣 10 分；成本 20 分；回流标签与周期各 20 分。

### 第 3 层 · 求职挑战（3.1–3.4）

**3.1（原第 9 题）参考答案**：总述——AI 产品 PRD 在传统结构上加五处：评测标准（效果验收，三要素）、容错兜底（四级降级链）、幻觉控制（引用 + 拒答 + 红线）、成本预算（单次成本 + 上限 + 月预算）、数据回流（badcase 闭环）。每条配一个示例，如「引用正确率 ≥90%，评测集 50 条」（教学示例）。专业补充：提示词初稿放入 PRD 附录，改动走评审。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 说出至少 3 处差异，有基本解释 |
| 良好（24–27 分） | 五处齐全，每条有示例，出现「三要素」「降级链」等框架词 |
| 优秀（28–30 分） | 额外答出「提示词是需求的一部分」或「数据回流闭环」等深层观点 |

**3.2（原第 10 题）参考答案**：三问对应三处缺失。问一「答错了算谁的」——缺失「容错兜底」章，补四级降级链与幻觉率红线；问二「每次多少钱」——缺失「成本预算」章，补单次成本公式与月预算；问三「评测集还够用吗」——缺失「数据回流」章，补 badcase 回流机制与每周指标报告。回应话术要点：承认缺口 + 给出补写方案 + 给出补齐时间。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 三问都能对应到章节缺失 |
| 良好（24–27 分） | 每问给出具体补写内容（如四级链路、成本公式、回流周期） |
| 优秀（28–30 分） | 额外体现「承认缺口 + 方案 + 时间点」的评审沟通策略，或指出该 PRD 还缺评测标准章 |

**3.3 参考答案**：判断——算，提示词是需求的一部分。理由：① 线上改一行提示词可能让引用正确率从 90% 掉到 70%，直接决定输出行为与成本；② 提示词是产品决策，须版本管理与评审流程。留痕与验证：初稿作为附录进 PRD，改动走 PRD 变更流程、留变更记录、回归评测集验证；靠变更记录与版本对照定位是谁改的，没有留痕就查不到。评分：判断 5 分、两条理由各 7 分、留痕与回归机制 11 分。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 明确「算需求」，给出至少一条理由 |
| 良好（24–27 分） | 两条理由齐全，提到版本管理或评审流程 |
| 优秀（28–30 分） | 完整给出「变更记录 + 回归评测 + 靠留痕定位」的闭环 |

**3.4 参考答案**：数字两个来源——同行基准 + 自己评测集的小样本试跑，把「跳一跳够得着」的数写成门槛，且必须带数据来源；拍脑袋的数要么形同虚设要么压垮团队。时效性——会过时，评测集停在上线那天，用户问题变了仍拿老题测，分数虚高、产品其实在退步。机制：点踩必填归因标签、样本进待标注队列、每周筛选入评测集、采纳率 / 解决率 / 幻觉率每周出报告。评分：两来源 8 分、数据来源 4 分、时效性 8 分、回流机制 10 分。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 说出数字至少一个来源，并承认评测集会过时 |
| 良好（24–27 分） | 两来源齐全，点出「分数虚高」的后果 |
| 优秀（28–30 分） | 完整给出回流闭环（标签 / 队列 / 周期 / 周报三指标） |
