教案 · W4 周一《用户研究与需求分析》

AI 产品经理就业训练营 · 第四周第一天 · 90 分钟（2 课时）· 讲师版

一、基本信息

项目 内容
所属阶段 阶段三 · 产品硬功（Week 4）
本课主题 用户研究与需求分析
课时 90 分钟（2 课时，中间休息 5 分钟）
授课对象 转行 / 进阶层学员（主项目已立项锁定，原型已通过 W3D5 评审）
前置知识 主项目选题与目标用户假设、原型 V1.5、W1–W3 的 AI 产品形态与技术常识
本课产出 主项目调研启动包：访谈提纲 V1 + 验证型问卷初稿（课堂完成）
本周目标 产出支撑 PRD 的真实调研：≥5 个访谈 + ≥30 份有效问卷；D2 写 PRD、D5 PRD 评审大会
教学场地 教室或线上直播，需投屏 + 每位学员手机可扫码（腾讯问卷实操）

二、教学目标（可测量）

  1. 能用「需求真伪四问」框架（痛点真不真 / 场景有没有 / 现有方案是什么 / 替换成本高不高）对给定的 4 条需求描述做出真伪判断，每条至少给出 2 个论据（对应习题第二层第 8 题）。
  2. 能按「暖场 / 背景 / 场景还原 / 痛点挖掘 / 收尾」五段结构，为自己主项目写出访谈提纲 V1，其中含至少 2 个开放题、1 个「最近一次」场景还原问题（对应导学案课堂模板）。
  3. 能在腾讯问卷（或问卷星）中独立完成一份 ≥8 题的验证型问卷初稿，选项满足 MECE 且无倾向性（对应课堂实操 + 07-交互使用说明）。
  4. 能用 RICE 模型对 3 个需求打分排序并说明砍留理由（对应习题第二层第 9 题）。

三、教学重难点

  • 重点一：需求真伪四问框架——这是本课的主线工具，也是面试高频考点。
  • 重点二：AI 场景用户访谈的提问技巧（开放题 / 追问 / 沉默），学员第一次真人访谈前必须有现场示范。
  • 难点一：学员把访谈做成推销、把调研当成「确认自己想法」。需要讲师现场做「推销式 vs 访谈式」正反对比示范。
  • 难点二：问卷选项设计带倾向、题目混入「发现型」问题。用互填找茬机制让学员互相纠错。

五、教学步骤与时间拆分

时间 环节 教学内容 教学方法 对应产出
0–8 min 导入：一个被砍掉的功能 讲「AI 菜谱推荐」伪需求故事（教学示例）：访谈 5 人后发现真痛点是「买了的菜怎么消耗」而非「不知道做什么菜」；提问「用户说的需求为什么会变」 故事冲击 + 提问 —
8–13 min 本周地图：调研如何支撑 PRD 本周主线：D1 学方法 → D2–D4 执行调研（≥5 访谈 + ≥30 问卷）→ D2 写 PRD、D5 评审；明确「调研数据是 PRD 的弹药」 讲授 学员明确本周里程碑
13–31 min 环节一：AI 场景用户访谈方法 访谈不是聊天更不是推销；五段结构（暖场 / 背景 / 场景还原 / 痛点挖掘 / 收尾）；三类提问技巧示范：开放题（是非题改写经历题）、追问（「当时发生了什么」）、沉默（停 3 秒不填空）；学员现场 3 分钟两两演练 讲授 + 讲师示范 + 学员演练 导学案访谈提纲 V1（至少完成场景还原段）
31–36 min 休息 — — —
36–56 min 环节二：需求真伪四问框架（核心） 用流程图逐环讲四问：痛点真不真（用户做过什么努力）、场景有没有（最近一次 + 频率）、现有方案是什么（含「忍着」）、替换成本高不高（数据 / 习惯 / 协作链 / 价格）；课堂演练：用四问评估「AI 帮爸妈挂号」与主项目核心需求 图示 + 讲授 + 小组评估 导学案四问评估表填写
56–74 min 环节三：问卷设计与腾讯问卷实操 访谈发现假设、问卷验证假设；问卷设计三原则（一页原则、每题验证一个假设、选项 MECE 无倾向）；现场建卷 7 步演示 + 学员分组建卷互填找茬（组织方案见 07-交互使用说明） 投屏演示 + 学员实操 + 互填找茬 验证型问卷初稿（≥8 题）

86–90 min 总结与本周里程碑布置 三句话收束 + 布置本周调研任务 + 预告 D2 PRD 写作 讲授 —

时间拆分校验：8+5+18+5+20+18+12+4 = 90 分钟。

六、课堂提问设计（8 问）

# 提问 提问时机 预设答案 / 引导方向
1 「用户跟你说『我想要更快的马』，他真正要的是什么？」 导入 更快的位移——需求表述不等于需求本身，引出「听用户说什么不如看用户做什么」
2 「访谈和推销的区别是什么？」 环节一 推销想让用户认同你，访谈想让用户暴露真实行为；访谈里不得介绍自己的方案
3 「为什么『你以后会用吗』是个无效问题？」 环节一 预测行为不可靠、且受访者倾向给面子答案；应问过去的具体行为：「你上次遇到是什么时候，当时怎么处理的」
4 「用户停下来不说话了，你怎么办？」 环节一 等 3 秒，别急着填空——沉默会给对方压力，逼出更真实的补充；急着接话等于替用户作答
5 「四问里哪一问最容易漏？」 环节二 现有方案——大家默认用户是白纸，其实人人都有替代方案，包括用 Excel、用微信群、甚至「忍着」
6 「一个需求四问全过了，就能直接开发吗？」 环节二 / 四衔接 不能，还要看优先级与资源——进入 KANO 定类别、RICE 排顺序
7 「问卷只有 30 份，能下结论吗？」 环节三 训练营阶段用于验证方向足够：看选项分布和异常值，不看精确比例；正式产品决策需要更大样本与显著性检验
8 「KANO 里哪类功能，做了用户觉得理所当然、不做用户直接骂？」 环节四 基本型——做了不加分，不做扣分；对应 AI 产品里的「答得准、不幻觉、能兜底」

七、板书要点

需求真伪四问（不过四问，不进开发）
① 痛点真不真 —— 用户为这个问题做过什么努力？
② 场景有没有 —— 最近一次发生在什么时候？频率多高？
③ 现有方案是什么 —— Excel / 微信群 / 人肉 / 忍着，都算方案
④ 替换成本高不高 —— 数据迁移 / 习惯 / 协作链 / 价格

访谈五段：暖场 → 背景 → 场景还原 → 痛点挖掘 → 收尾
提问三技：开放题（问经历不问观点）· 追问（当时发生了什么）· 沉默（停 3 秒）

KANO：基本型 / 期望型 / 兴奋型 —— 定「做不做」
RICE：Reach × Impact × Confidence ÷ Effort —— 定「先做谁」

本周里程碑：≥5 个真实访谈 + ≥30 份有效问卷 → D2 PRD 用数据说话

八、课堂练习参考答案（四问评估演练）

练习题：用四问评估「AI 帮爸妈挂号」这个需求（学员分组 3 分钟）。

四问 评估要点 参考结论
痛点真不真 痛点存在（挂号难、子女异地着急），但要注意痛点主体可能是子女而非父母 痛点真实，但主体需重定义
场景有没有 低频场景（人均每月不到 1 次），且多发生在工作日早间抢号时段 场景真实但低频
现有方案是什么 医院官方 App、114 电话、找黄牛、让老家亲戚跑窗口 已有可用方案，官方 App 是强对手
替换成本高不高 老年人学习成本高、信任门槛高（敢不敢让 AI 挂号） 替换成本偏高

结论示范：原始表述「帮爸妈挂号」偏伪，问题重定义后变成「帮异地子女盯号源、约时间、提醒父母」——从「替父母操作」变成「给子女当助手」，替换成本大幅下降。此题无唯一答案，论证过程比结论重要（教学示例，用于演示四问用法）。

九、学员易错点预判与应对（6 条）

易错点 表现 应对
把访谈做成推销 访谈变成介绍自己的产品功能，追问用户「你会喜欢吧」 现场做「推销式 vs 访谈式」正反对比示范；立规矩：访谈中提到自己的方案时只能问「你现在怎么解决」，不得介绍功能
引导式提问 「你是不是觉得现在特别麻烦？」「大家都这么说对吧？」 给改写公式：是非题 → 经历题（「上次遇到是什么情况」）；课堂即兴纠错 2 轮
问卷选项带倾向 自家方案的选项描述更丰满、竞品选项写得含糊；选项不 MECE、有交叉 互填找茬环节专门查选项；发放问卷自查清单（见 07-交互使用说明）
问错人 只访谈身边同学、室友，样本全是「自己人」 强调目标用户画像三条线（谁有这个问题 / 谁在 actively 找方案 / 谁付得起成本）；预习任务已要求找 1 位目标用户，课上点名核对
把「用户说想要」直接当需求 调研报告里写「10 个用户里有 8 个说想要」 金句纠正：用户说的都是对的，用户做的才是真的；必须过四问，看行为不看口头承诺
访谈记录只记观点不记场景 记录里全是「他觉得」「他认为」，没有具体事件 提纲模板「场景还原」段强制要求记录「最近一次」的时间、经过、卡点；讲师抽查记录
