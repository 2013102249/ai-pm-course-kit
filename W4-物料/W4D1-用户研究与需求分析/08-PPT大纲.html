7第 2 节本周地图：调研如何支撑 PRD① D1 学方法 → D2–D4 执行调研 → D2 写 PRD、D5 评审大会；② 「禁止编造」；③ 调研在链路最前端强调周五评审第一问就是「有调研支撑吗」AI 产品全链路图
8第 2 节导入：一个被砍掉的功能① AI 菜谱推荐 → 访谈 5 人（教学示例）→ 真痛点是「买了的菜怎么消耗」；② 产品从「推荐菜谱」变「AI 管冰箱」；③ 问题重定义教学示例口径；先讲故事再揭转折—
9第 2 节用户说的都是对的，用户做的才是真的① 需求表述 ≠ 需求本身；② 看行为，不看表态；③ 回扣术语「伪需求」金句页：紫底白字全屏，放慢语速重复一遍—
10第 2 节访谈不是聊天，更不是推销① 推销求认同，访谈求真实行为；② 铁律：只问「你现在怎么解决」；③ 绝不介绍自己的方案现场做推销式 / 访谈式正反示范—
11第 2 节访谈五段结构① 暖场 / 背景 / 场景还原 / 痛点挖掘 / 收尾；② 场景还原 = 黄金段；③ AI 背景题「你用过哪些 AI 工具」让学员同步在导学案填写提纲导学案访谈提纲模板
12第 2 节正反面案例：推销式 vs 访谈式① 正面：问「你上次打开冰箱，最后那顿饭怎么定的」拿到完整事件；② 反面：演示原型 + 问「你会用吧」收了一堆礼貌；③ 用「验证 vs 确认自己想法」判哪份报告能用新增案例页；让学员指认反面案例三处错案例对照图（新增）
13第 3 节需求真伪四问框架（总览）① 需求 → ①痛点 → ②场景 → ③现有方案 → ④替换成本 → 通过 / 淘汰；② 每问有淘汰出口；③ 挂哪问记入伪需求档案本课主线工具；沿图走一遍需求真伪判断流程图
14第 3 节第一问：痛点真不真① 判据：用户做过什么努力；② 行为痕迹比口头承诺硬；③ 追问「你之前试过什么办法」提问：哪一问最容易漏（下一页揭晓）需求真伪判断流程图
15第 3 节第二问：场景有没有 + 第三问：现有方案是什么① 最近一次 + 频率；② Excel / 微信群 / 人肉 / 忍着都算方案；③ 「忍着是最大竞品」金句「忍着是最大竞品」金句页需求真伪判断流程图
16第 3 节第四问：替换成本高不高① 数据迁移 / 使用习惯 / 协作链 / 价格；② 优势定想不想，成本定换不换；③ 课堂演练：四问评估「AI 帮爸妈挂号」演练背景标「教学示例」，3 分钟分组填表需求真伪判断流程图 + 导学案四问评估表
17第 3 节正反面案例：四问的重定义与踩坑① 正面：挂号需求挂第三、四问后重定义为「帮子女盯号提醒」；② 反面：1 人抱怨就判「AI 口语陪练」为真，踩样本 + 验证两个坑；③ 四问价值在「结论影响产品动作」新增案例页；强调「四问全过 ≠ 可开发」案例对照图（新增）
18第 3 节KANO 与 RICE：给真需求排优先级① KANO 定「做不做」（基本 / 期望 / 兴奋）；② RICE 定「先做谁」（R×I×C÷E）；③ C = 调研底气现场演算 1 个 RICE 例子（教学示例数据）—
19第 4 节提问技巧一：开放题① 「你会不会」→「你上次是怎么」；② 要经历，不要预测；③ 改写公式现场纠错 1 条学员题目—
20第 4 节提问技巧二与三：追问与沉默① 追问万能句「当时发生了什么」；② 沉默停 3 秒，不替用户填空；③ 为什么事件比观点可信演示：学员答完故意停 3 秒—
21第 4 节两两演练：3 分钟微访谈① 规则：全程禁用「你是不是 / 你会不会」；② 主题「你上次决定今晚吃什么」；③ A 访 B 再互换计时 6 分钟；巡视挑 1 组点评导学案
22第 4 节问卷：验证假设的工具① 访谈发现假设，问卷验证假设；② 三原则：一页 / 每题验一假设 / 选项 MECE 无倾向；③ 必须给「不痛」留出口顺序反了两个都白做—
