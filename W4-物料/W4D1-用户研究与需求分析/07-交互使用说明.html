交互使用说明 · 腾讯问卷实操环节组织方案（W4 周一专用）

用途：本课无专用交互页（按生产卡设定）。本文件对应教案环节三（56–74 分钟）「问卷设计与腾讯问卷实操」的现场组织方案，兼作学员课后建卷的操作参考。
外部工具：腾讯问卷（主） / 问卷星（备）。工具为第三方在线服务，使用前必须完成「课前检查」并准备故障预案。

一、为什么本课不配专用交互页

问卷设计的教学目标不是「操作某个软件」，而是「每题验证一个假设、选项 MECE 无倾向」这套方法论。用真实问卷工具做实操，比做模拟交互页更接近工作现场；且学员本周要真投放、真回收，直接在腾讯问卷里建卷即是一步到位的产出。因此本日八件套以本「组织方案」代替专用交互页。

二、工具选择说明：腾讯问卷 vs 问卷星

维度 腾讯问卷（本课主用） 问卷星（备用）
登录 微信扫码即可，课堂零门槛 需注册账号，课堂多一步
投放生态 与微信 / 企业微信天然打通，学员发目标用户社群顺畅 站内样本库更成熟（付费），微信外渠道适配广
题型 单选 / 多选 / 量表 / 开放 / 跳转逻辑，本课全够用 题型更多（矩阵、排序等），本课用不到
免费额度 满足 ≥30 份回收 满足，但免费版展示广告，影响填写体验
企业普及率 腾讯系公司与大量 C 端团队常用 老牌工具，传统企业与高校普及率高

结论与讲法：课堂统一用腾讯问卷（登录快、投放顺）。讲师用一句话交代：「两家方法论完全一致，界面差异半小时就能上手；工作中遇到哪家就学哪家，重点永远是题目质量，不是工具。」

三、课前检查（开课前 30 分钟）

检查项 操作
讲师账号 提前登录腾讯问卷，建好一个半成品问卷（含标题 + 2 个示例题），演示时从半成品开始，节省现场点击时间
投屏 浏览器窗口 ≥1280px；提前打开半成品问卷的「编辑」页
学员端 班群提前发操作指引：确保手机微信可扫码、可访问 wj.qq.com
网络 现场实测一次扫码填写全流程
备用方案 另开标签页备好问卷星账号；纸质兜底见第六节

四、现场流程（与教案环节三 18 分钟对齐）

时间 动作 要点
56–62 min 讲师投屏演示建卷 7 步 从半成品开始，只现场新增 2 题（1 个单选 + 1 个量表），把节奏留给讲解
62–70 min 学员分组建卷（3–4 人一组，共用一位组员的微信建卷） 要求 ≥8 题，每题在备注里标注「验证哪条假设」
70–74 min 组间互填 + 找茬 + 修订 1 轮 找茬清单见下节

现场建卷 7 步（通用化描述，讲师照读）

  1. 登录：打开腾讯问卷，微信扫码登录。
  2. 创建：新建空白问卷，不用模板——模板会带偏你的题目结构。
  3. 设置标题与说明：标题写「关于 XX 的一分钟小调研」；说明栏写清「匿名、约 1 分钟、感谢」。
  4. 逐题添加：单选 / 多选 / 量表（五级）/ 开放题交替使用；每添加一题，自问一句「这题验证哪条假设」。
  5. 设置必答与跳转：核心题设必答；跳转逻辑用在「是否遇到该问题」的分流上。
  6. 预览：必须用手机预览一遍——你的用户在手机上答题。
  7. 发布：生成链接和二维码，发小组群。

互填找茬清单（学员互查用）

  • [ ] 有没有题目验证不了任何假设（凑数题）？
  • [ ] 有没有「经常 / 偶尔」这类没定义频率的词？
  • [ ] 有没有选项给自家方案堆形容词、给竞品缩水？
  • [ ] 选项是否 MECE，有没有交叉或遗漏？
  • [ ] 有没有给「我不遇到这个问题」留出口？
  • [ ] 手机端有没有显示异常（选项换行、题目截断）？

五、课后正式投放指引（发群文案）

同学们，今天课上建好的问卷请在正式投放前做三件事：① 按找茬清单自查一遍，重点看倾向词；② 组内互填一轮，修完再发；③ 投放到真实目标用户的社群（同学不算数），目标本周回收 ≥30 份。回收后导出数据截图，周四晚汇总进调研报告。周五 PRD 评审会上，「需求有调研支撑吗」就是第一问。

六、故障预案

故障 处理
腾讯问卷网页打不开 / 卡住 切换备用标签页的问卷星账号继续演示；话术：「正好，选型永远要有 Plan B——这也是今天讲现有方案那一问的现场版。」
现场网络差，学员扫码失败 立即降级为纸质：导学案「问卷题目设计区」本来就是建卷的底稿，先在纸上写题，课后各自建卷；互填找茬改为组内传阅纸质稿
学员微信登录异常 该组先用其他组员账号建卷；课后自行重建不影响产出
投屏字太小 浏览器 Ctrl / Cmd + 「+」放大至 125%
时间被前面环节挤压 优先保证「学员动手建卷」，7 步演示压缩为看半成品讲 3 个要点（每题验假设 / 手机预览 / 必答设置）；互填找茬改为课后组内完成
