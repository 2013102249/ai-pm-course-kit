讲课稿 · W4 周四《数据指标体系与 SQL 实战》（完整逐字稿）

AI 产品经理就业训练营 · 90 分钟 · 讲师授课时可直接照读，也可按个人风格改写
标记说明：【问】课堂提问 【停】停顿等待 【操作】投影操作指令 【故事】案例故事 【金句】面试金句（放慢语速重复一遍）
案例口径说明：本稿中公司案例均为教学示例，已在正文中标注「教学示例」，讲师授课时请保持口径一致，不得对外引用为真实公司。

开场与导入（0–8 分钟）

大家好，今天是第四周的周四。这周你的 PRD 已经写到 V1.0 了，兜底设计也做完了。我发现很多同学这两天的状态是——产品定义得很清楚，但你问他「你这个产品上线以后，怎么判断它做得好不好」，他答不上来，或者只会说一句「看用户量」。

今天这 90 分钟，我们就专门补这块短板：数据指标体系，加上从零开始学 SQL。下课的时候你要带走两样东西：第一，你自己主项目的指标看板设计——北极星、一级指标、护栏指标三层，直接能放进你周五要评审的 PRD 里；第二，你能自己写 SQL 跑出一份「按渠道算采纳率」的数据。这两件事，一件管方向，一件管手艺。

【停】

【故事】先讲个场景。教学示例：两个 AI 产品团队，产品几乎一样。A 团队每天开早会看三个数字：DAU、账单、老板心情。上个月 DAU 涨了，大家很高兴；这个月账单涨了，大家很紧张。有人提议砍模型换便宜的，有人提议加推送拉活，吵了一个月，谁也说服不了谁，因为每个数字都只反映「发生了什么」，不反映「该干什么」。B 团队的早会只盯一个数字：每周生成并被采纳至少三次的用户数。上个月这个数字跌了，他们顺着指标拆下去，发现是新用户的采纳率低——用户第一次生成的结果不好，用两次就走了。团队当周就改了新用户的默认模板。两周后数字回来了。

【停】

A 团队不是不努力，是没有仪表盘，在黑盒里开飞机——不知道高度、不知道油量、不知道方向。B 团队有一块仪表盘，跌了知道去哪查，涨了知道为什么。

【问】我问一下大家：你怎么知道你的 AI 产品是好是坏？看 DAU 够吗？【停，点 1–2 名学员】

对，不够。DAU 只告诉你「来了多少人」，不告诉你「用得值不值」。AI 产品的用户行为和传统产品不一样——用户来了，把你的生成结果扔掉一半，这个产品在用户心里其实已经死了。所以今天第一个任务，就是给大家装一块 AI 产品专属的仪表盘。

【过渡】我们进入环节一，五大核心指标。

环节一：AI 产品五大核心指标（8–31 分钟）

【操作：打开 PPT 第 5 页，展示《AI 产品指标体系图》】

看这张指标体系图，先记结构：最上面一层是北极星指标，全公司只看一个数；中间一层是一级指标，把北极星拆成几块，出问题能定位；最下面一层是护栏指标，防止北极星被「歪」着做上去。中间这一层的五个格子，就是今天要讲透的五大核心指标：采纳率、解决率、幻觉率、留存、单次成本。大家先把导学案上的「五大指标笔记表」翻出来，我一个一个讲，你们跟着填。

第一个，采纳率。 定义：AI 生成结果被用户接受的比例。公式：采纳率 = 被采纳的生成次数除以总生成次数。

听起来很简单，但这里有个面试官最爱挖的坑。

【问】采纳率的分母是什么？用户改了三个字才采纳，算不算「采纳」？【停】

分母是总生成次数，这个大家都能答对。第二个问题才是关键——修改后采纳算不算，没有标准答案，但必须有答案。你的产品把「原样发布」定为采纳，还是「采纳或修改后发布」都算，两种口径算出来的数字可能差一倍。所以采纳率这个指标，永远要带着口径说话：分母怎么算、采纳动作怎么定义、统计周期多长。口径不统一，指标就没法跨版本比较，这是新人写数据报告最常犯的错。

健康线怎么定？我教大家一个通用方法：基线对比法。不要背「行业采纳率是多少」，AI 产品的形态差异太大，没有放之四海的数字。正确做法是：上线第一周的全量数据就是你的基线，之后每个版本和基线比、和上一版比。写作辅助类产品常见区间大概在百分之三十到六十——这是示例值，需按业务校准，只能当量级参考。

常见误读有两条。第一，以为采纳率越高越好。如果一个用户重试十次才采纳一次，他的采纳率是百分之十——这个数字低是对的，因为它如实反映了「单次生成质量差」。第二，把「未采纳」一律归因为质量差。有可能用户只是进来试试看，根本没有真实任务。所以采纳率下降时，先查样本构成，再下结论。

第二个，解决率。 这是客服类、问答类产品的核心指标。定义：用户带着问题来，最终不需要人工介入、自然结束的比例。公式：解决率 = 无人工介入且自然结束的问题会话数，除以总问题会话数。

健康线怎么定？这里基线很好找——你公司人工坐席的解决率。AI 至少要追平人工，才谈得上替代，这是一条很硬的参照。客服场景公开参考值大概百分之六十到八十，示例值，需按业务校准。

【问】这里有个隐蔽的坑：用户没再说话，等于问题解决了吗？【停】

不一定。他可能是骂骂咧咧走了，可能是觉得「问这个破机器人不如自己查」。所以解决率必须交叉验证：看满意度评分、看转人工率、看重复进线率——同一个用户三天内为同一件事又来了，前一次的「自然结束」就是假解决。单一指标都会说谎，交叉验证才接近真相。

第三个，幻觉率。 这是 AI 产品区别于传统产品的特有指标。定义：生成内容中与事实或给定资料不符的比例。公式：幻觉率 = 被判定为幻觉的回答数，除以抽检回答总数。

注意，这个公式背后是「抽样 + 人工判定」或者「评测集回归」——为什么不能全自动统计？因为幻觉判定本身没有金标准，自动检测工具会漏也会误报，人工标注又贵又有主观性。

【问】那我顺着问一句：幻觉率没有金标准，我们是不是就不用管了？【停，听学员反应】

我听到有同学犹豫了。答案是：不量化，不等于不管理。没有金标准，我们做三件事：第一，分层抽检——按场景风险分配抽检比例，金额、政策、医疗这类高风险内容从严甚至全查，闲聊内容抽查即可；第二，评测集回归——每次改模型、改提示词，跑一遍固定评测集，防止「改好了 A 坏了 B」；第三，拒答单独统计——用户问超出范围的问题，模型说「我不知道」，这不是幻觉，这是好行为，混在一起算会惩罚诚实。

健康线按场景风险定门槛：对外知识问答类常见要求抽检幻觉率低于百分之二——示例值，需按业务校准；内部工具可以放宽，金融、医疗、法律对外场景要严格得多。

第四个，留存。 定义：一段时间后仍回来使用的用户比例。常用次日留存、七日留存，工具类产品还要看周活跃频次。公式：N 日留存 = 第 N 天仍活跃的新增用户数，除以当日新增用户数。

AI 产品的留存有个特殊现象：尝鲜用户特别多。热点一来，注册一波，用一次就走的比例天然偏高。所以除了传统的留存率，AI 产品更要盯一个数：习惯用户占比——每周使用三次以上的用户占活跃用户的比例。三次是个经验阈值，示例值，需按你的产品校准。留存要按核心行为算，也就是「生成过」的用户，而不是「打开过 App」的用户。

【问】那我问大家：DAU 涨了百分之三十，能说明产品变好了吗？【停】

不能。三个理由：打开不等于得到价值，可能只是推送把你叫回来的；DAU 可以被廉价手段拉高，签到、积分、每日弹窗都行；而且 DAU 跌了你查不出原因，因为它不和任何价值环节挂钩。这个问题我们环节二展开，它是今天最重要的一题。

第五个，单次成本。 定义：每一次有效请求的平均推理成本。公式：单次成本 = 当期 token 用量乘以单价之和，除以有效请求次数；简单版就是当月 API 账单除以当月有效请求次数。

这是 AI 产品独有的「边际成本」视角——传统互联网产品边际成本趋近于零，AI 产品每回答一次都在花钱。健康线怎么定？不跟别人比，跟自己的「单次价值」比：单次成本必须显著小于单次收益，这个收益可以是营收贡献，也可以是替代的人力成本，用毛利倒推出成本上限。

常见误读三条：只看总账单不看单次——总量随增长上涨是正常的，会失控的是单次；为了省成本砍上下文、换小模型，结果采纳率掉了，省下的钱远不够赔的；忽略重试的隐性账——用户不满意多生成三次，成本翻了四倍，这四次都要算进来。

【金句】五大指标讲完了，收一句金句，这句可以写进面试自我介绍：传统指标回答「来了多少人」，AI 指标回答「用得值不值」——采纳率、解决率、幻觉率、留存、单次成本，缺一个都是在黑盒里飞。

【过渡】一级指标有了，接下来是今天最重要的一件事：在五个格子和你的产品之间，选出那个唯一要抬头看的数字——北极星指标。

环节二：北极星指标与护栏指标（31–46 分钟）

什么叫北极星指标？全公司所有团队，在所有争论拿不定主意的时候，抬头看的那一个数。它不是 KPI——KPI 是用来考核的，北极星是用来对齐方向的。

选北极星有三条标准，大家记下来，这本身就是一个面试题的标准框架：

第一，绑价值。用户获得核心价值的那一刻，就在贡献这个数字。自检问句：这个数字涨的时候，用户是真的多得到了价值吗？

第二，可影响。团队能通过本周的工作推动它，而不是只能等市场行情。自检问句：下个迭代我们做什么，能让它动？

第三，可拆解。它能拆成一级指标，出问题时能定位到环节。自检问句：它跌了，我能查到是哪个环节跌的吗？

现在用这三条标准，拆一个反面教材——DAU。

【问】用三条标准逐条过一遍：DAU 绑价值吗？【停】

不绑。打开 App 不等于得到价值，尤其是 AI 产品，打开之后甩手走人的比例不低。可影响吗？太可影响了——推送、签到、每日抽奖，都能把它推高，恰恰因为它太容易被廉价手段影响，反而失真。可拆解吗？DAU 跌了，你能查到是「采纳率跌了」还是「留存跌了」吗？查不到，因为它跟价值环节不挂钩。三条全灭，所以 DAU 不能当 AI 产品的北极星。

那正例长什么样？给大家一个教学示例：某 AI 写作工具，原来的北极星是 DAU，团队天天在做拉新和推送；后来把北极星改成了「每周生成并被采纳三次及以上的用户数」。注意这个定义的三个零件：有核心行为——生成；有质量门槛——被采纳；有习惯阈值——每周三次。改完之后，团队动作立刻从拉新转向了留存——因为新用户的采纳率上不去，这个数字就不动，而拉新拉来一堆不采纳的用户，数字反而被稀释。这是教学示例，不是真实公司数据，但结构是真实的：北极星一换，全团队的动作跟着换。这就是「北极星」这三个字的含义——它决定船往哪开。

【操作：PPT 第 13 页，护栏指标页】

光有北极星还不够，还要配护栏指标。什么是护栏？防止北极星被「歪」着做上去的约束指标。我给大家三个典型组合，可以直接抄进看板：北极星盯采纳，护栏就要盯重试率——采纳率涨了五个点，重试次数翻倍，说明用户是试了三次才成功一次，单次质量其实在降；北极星盯增长，护栏就要盯幻觉率和单次成本——新用户涌入如果让幻觉率和成本失控，增长就是在烧钱买口碑恶化；北极星盯留存，护栏要盯推送退订率——留存如果是靠弹窗弹回来的，退订率会先告诉你真相。

【金句】第二句金句：北极星决定船往哪开，护栏指标防止你为了追星把船开翻。

现在宣布主项目要求：今天课堂环节四，你要在导学案的「指标看板设计表」里，为自己的主项目填出完整三层——北极星一个，写明为什么过三标准；一级指标三到五个，从五大核心指标里选；护栏指标至少两个。周五 PRD 评审，「指标」是评委必问章节，今天这张表就是你的底稿。

【过渡】指标体系讲完了，下半场我们练手艺。休息五分钟，助教现在逐个确认大家的 SQL 环境都装好了——预习任务没做完的同学，现在找助教拿在线平台的备用链接。

环节三启动：SQL 是 AI 产品经理的硬技能（46–56 分钟，含休息 5 分钟）

欢迎回来。先回答一个灵魂问题：产品经理为什么要学 SQL？让数据分析师跑不行吗？

三个理由。第一，不排队：分析师的排期永远比你急，一个「采纳率跌没跌」的小问题，等一天不如自己三十秒。第二，不被糊弄：别人甩给你一个结论「数据不好看是正常波动」，你自己跑一遍，就没人能糊弄你。第三，会讲故事：面试的时候，能现场说出「我跑了一条 SQL，发现某渠道采纳率特别低，于是砍掉了那个渠道的投放」的候选人，比背了十个指标的候选人值钱得多。

【操作：PPT 第 14 页，教学数据集结构】

今天用的数据集叫「小笔」，一个 AI 写作助手的模拟数据，两张表，特别简单：users 表，用户表，三个字段——user_id、channel 获客渠道、register_date 注册日期，一共八个用户；gen_records 表，生成记录表，六个字段——gen_id、user_id、gen_date、is_accepted 是否采纳、tokens 消耗量、cost_yuan 成本，一共十三条生成记录。两张表靠 user_id 关联。就这两个表，今天所有练习都从里面出，课后十题也是它，所以环境里有了它，等于零成本复习。

大家在自己电脑上确认一下这两张表都能查出来，输入 select star from users，回车，能看到八行，就绪。没就绪的同学举手，助教一对一处理，我们不等，先往下走——你有问题随时截屏找助教。

环节三：SQL 四关闯关 + 现场跑数（56–81 分钟）

SQL 就四个关键字：SELECT、WHERE、GROUP BY、JOIN。我们把它做成四关，一关一个字，闯过一关你就能干一类的活。

第一关，SELECT——选列。 【操作：投屏 SQL 环境，输入查询 1】

SELECT 管的是「要哪些列」。看屏幕：

SELECT gen_id, is_accepted, cost_yuan FROM gen_records;

FROM 后面是表名，SELECT 后面是你要的列，逗号隔开。星号表示全要。跑一下——十三条记录，三列。这就是一条完整的 SQL。产品经理日常百分之四十的取数需求，一个 SELECT 就够了。

第二关，WHERE——筛行。

SELECT 管列，WHERE 管行。我只看没被采纳的：

SELECT * FROM gen_records
WHERE is_accepted = 0;

注意三个细节：等号是一个等号，不是两个；字符串要加引号；多个条件用 AND、OR 连接。我加一个日期条件，只看九月三号之后的未采纳记录——WHERE is_accepted = 0 AND gen_date 大于等于单引号 2026-09-03 单引号。跑一下，四条。现在你已经在做「切片」了：从全量数据里切出你关心的那一块。

学员现在做导学案练习 1：查 2026 年 9 月 3 号当天的生成记录，输出 gen_id、user_id、is_accepted 三列。开始。【停，约 3 分钟，巡视】

大部分同学写出来了。标准写法：SELECT gen_id, user_id, is_accepted FROM gen_records WHERE gen_date 等于单引号 2026-09-03。有人把列名和条件里的日期搞混了——记住，SELECT 后面是列，WHERE 后面是条件，日期是条件，不是列。

第三关，GROUP BY——分组。

前两关你只能「看」，第三关开始你就能「算」了。问题：每个用户一共生成了几次、被采纳了几次？

SELECT user_id,
       COUNT(*) AS gen_cnt,
       SUM(is_accepted) AS acc_cnt
FROM gen_records
GROUP BY user_id;

GROUP BY user_id 的意思是：按用户分组，每组算一遍。COUNT 星号数行数，SUM 求和——这里有个巧思，is_accepted 是 0 和 1，求和正好等于采纳次数。AS 是起别名，看板上列名直接用别名，养成习惯。

【问】SELECT 和 WHERE 各管什么？快速抢答。【停】

对，SELECT 管列，WHERE 管行，GROUP BY 管组。三关口诀：先筛行，再分组，后选列。学员做练习 2：统计每个用户的生成次数和采纳次数，只留生成三次以上的。提示：加上 HAVING COUNT 星号大于等于三。HAVING 是分组后的过滤，WHERE 是分组前的过滤，这个区分面试也考。开始。【停，约 3 分钟】

好，跑出来的同学会看到：只有 user_id 3 满足，生成三次、采纳两次。顺便看一眼全员分布，八个用户里有六个生成次数不超过两次——注意，这本身就是一个留存预警信号，数据会自己说话。

第四关，JOIN——连表。

最后的大招。前面所有分析都只有 gen_records 一张表，但我现在问：哪个渠道的用户质量最高？ 渠道在 users 表，采纳在 gen_records 表，两张表必须连起来。

SELECT u.channel,
       COUNT(*) AS gen_cnt,
       SUM(g.is_accepted) AS acc_cnt,
       ROUND(SUM(g.is_accepted) * 1.0 / COUNT(*), 2) AS acc_rate
FROM gen_records g
JOIN users u ON g.user_id = u.user_id
GROUP BY u.channel
ORDER BY acc_rate DESC;

逐个拆：FROM gen_records g，给表起短名字 g；JOIN users u，把用户表连进来；ON g.user_id = u.user_id，连接条件——两边靠 user_id 对上号；最后 GROUP BY 渠道，ORDER BY 按采纳率降序。

跑之前，我故意先跑一个错误版本给大家抓 bug：【操作：跑 SUM 除以 COUNT 不乘 1.0 的版本】

看，采纳率全是 0。为什么？【停】

有同学看出来了——整数除法。SUM 和 COUNT 返回的都是整数，整数除以整数，小数部分直接扔掉，任何小于一的比率都变成零。修正：乘一个 1.0，把它变成浮点除法。这个坑以后你一定会踩，今天踩过一次，以后三秒解决。

【金句】第三句金句，送给大家贴在工位上：比率必乘 1.0，口径必写注释——数据报告的两大保命符。

好，重跑，出结果了。现在进入今天下半场的高潮：现场跑数。我不随机讲，我按「用数据讲故事」的标准三步来，这三步你面试讲数据分析题时照用。

第一条查询，看整体：产品健康吗？【操作：跑附录 B 查询 1】

一条查询出三个数：总共十三条生成，整体采纳率 0.54，平均单次成本 0.039 元。30 秒结论：「小笔 13 次生成里 7 次被采纳，采纳率 0.54，每次成本不到 4 分钱。」这是讲故事的第一步——用一句话给整体下判断。

第二条查询，做切片：整体看着还行，但有没有哪天掉过链子？【操作：跑查询 2，按日期分组】

按天看，9 月 5 号那天采纳率是 0.00——两次生成，零采纳。这就是切片的价值：整体健康不代表天天健康，趋势里的异常日就是你要追的问题。注意这里又一次出现了乘 1.0，以及 gen_cnt 只有 2——样本很小，先标记「待观察」，不要立刻定性。

第三条查询，做归因：9 月 5 号的问题到底是什么问题？我们换个维度，按渠道切开看。【操作：跑查询 3，JOIN 版】

结果：referral 渠道三次全采纳，search 0.43，social 只有 0.33。social 渠道的用户生成少、采纳少——假设你的投放预算正在往 social 砸，这条数据就是一句商业判断：「social 渠道来的用户质量偏低，先停投放，做一次落地页和新手引导的排查再说。」注意我刚才全程没有用一个形容词，全是数字加动作。

【金句】第四句金句，这是今天的主线：整体看健康，切片找异常，归因给动作——数据讲故事就这三步。

【停】

再强调一遍刚才那条纪律：referral 是 1.00 的采纳率，但只有三次样本。样本量小的时候，先看次数，再看比率——面试官如果追问「你这结论可靠吗」，这一句就是你的加分答案。

环节四：主项目指标看板设计（81–87 分钟）
