分层习题 · W4 周四《数据指标体系与 SQL 实战》

三层难度：基础巩固（概念）→ 进阶实操（方案设计 + SQL 上机）→ 求职挑战（面试真题）。
建议用法：基础层当堂测 10 分钟；进阶层为课后作业（SQL 十题验收标准：全对或讲清错因）；求职挑战层自测，第八周面试课复用。
所有题目附参考答案与评分标准；SQL 题附完整可运行的数据表与参考查询。

第一层 · 基础巩固题（概念层）

一、选择题（每题 10 分，共 30 分）

1. 关于采纳率的口径，说法正确的是：
A. 采纳率 = 采纳用户数 / 注册用户数
B. 修改后是否算「采纳」属于口径定义，必须先定义清楚再统计
C. 采纳率越高，说明单次生成质量一定越好
D. 行业有统一的采纳率健康线，直接照搬即可

2. 关于幻觉率，理解正确的是：
A. 模型拒答用户问题属于幻觉行为，应计入幻觉率
B. 幻觉率没有金标准，所以无法管理，也不用统计
C. 幻觉率 = 被判定为幻觉的回答数 / 抽检回答总数，可通过分层抽检 + 评测集回归管理
D. 幻觉率只与技术有关，产品经理不需要关注

3. 下列 SQL 的作用是：

SELECT channel FROM users GROUP BY channel;

A. 查出所有渠道名称，并去重分组
B. 查出每个渠道的用户明细
C. 语法错误，GROUP BY 后必须接聚合函数
D. 等价于 SELECT DISTINCT 的反操作，会列出重复渠道

二、简答题（每题 20 分，共 40 分）

4. 面试官问：「幻觉率的判定没有金标准，你们为什么还要统计它？」请给出两条理由。

5. 为什么说 DAU 不适合作为大多数 AI 产品的北极星指标？请用北极星三标准逐条说明。

第二层 · 进阶实操题（SQL 上机 + 方案设计层）

6. SQL 上机：整体健康查询（30 分）
使用上方数据集，写出一条查询，同时输出三个数：总生成次数（gen_cnt）、整体采纳率（acc_rate，保留两位小数）、平均单次成本（avg_cost，保留四位小数）。

7. SQL 上机：定位异常日（30 分）
写出查询：按生成日期分组，输出每天的生成次数、采纳次数与采纳率（保留两位小数），按日期升序排列。并回答：哪一天的采纳率最低？该结论需要注意什么样本量问题？

8. 指标设计题：为你的主项目设计指标看板（60 分）
为自己的主项目（你 PRD 中的 AI 产品）设计完整指标看板，要求：
① 北极星指标 1 个，写出定义，并用三标准（绑价值 / 可影响 / 可拆解）逐条自检；
② 一级指标 3–5 个，从五大核心指标（采纳率 / 解决率 / 幻觉率 / 留存 / 单次成本）中选取，每个附公式与口径（分母定义、统计周期）；
③ 护栏指标至少 2 个，每个写清「防什么动作」。

第三层 · 求职挑战题（面试层）

9. 面试真题：数据归因分析（40 分）
面试官：「我们 AI 写作产品 DAU 涨了 30%，但收入没涨，老板让你分析原因。你怎么做？」
要求：按「整体 → 切片 → 归因」三步给出分析框架，每步至少指出 1 个要看的具体指标，最后给出 1 条可能的产品动作。

10. 面试真题 + SQL 验证假设（40 分）
面试官：「假如采纳率这个月从 54% 掉到了 45%，你的第一个假设是什么？怎么用数据验证？」
要求：① 写出你的第一个假设与验证思路；② 基于上方数据集写出一条验证用 SQL（提示：可按渠道或按日期切片），说明你预期看到什么结果才支持这个假设。

第一层 · 基础巩固

题 答案 给分点
1 B 选 B 得满分；选 C 得 5 分（忽略重试膨胀与样本构成问题）；选 D 得 0 分并回看「示例值需按业务校准」
2 C 选 C 得满分；选 A 得 0 分（拒答是好行为，单独统计）；选 B 得 0 分（不量化不等于不管理）
3 A 选 A 得满分；GROUP BY 单独使用即可实现分组去重，不强制要求聚合函数
4 要点两条：① 没有金标准不等于不能管理——分层抽检 + 评测集回归 + 高风险场景从严，可以得到足够可靠的估计；② 不统计的后果是幻觉风险不可见、版本改好改坏无从判断。每条 10 分：理由成立 6 分 + 有具体做法/后果 4 分
5 逐条对照三标准：① 不绑价值——打开不等于得到价值（7 分）；② 表面可影响实则失真——推送、签到等廉价手段即可推高（7 分）；③ 不可拆解——DAU 跌了无法定位到采纳、留存等价值环节（6 分）。只答「DAU 不好」不给分，必须落到标准上

第二层 · 进阶实操（三档 Rubric）

第 6 题参考查询：

SELECT COUNT(*)                                          AS gen_cnt,
       ROUND(SUM(is_accepted) * 1.0 / COUNT(*), 2)       AS acc_rate,
       ROUND(AVG(cost_yuan), 4)                          AS avg_cost
FROM gen_records;

参考结果：gen_cnt = 13，acc_rate = 0.54，avg_cost ≈ 0.0392。

档位 标准
合格（18–23 分） 三个聚合函数使用正确，能输出三列
良好（24–27 分） 比率正确乘 1.0 避开整数除法，ROUND 位数符合要求
优秀（28–30 分） 列名全部使用 AS 别名（看板规范），并能口头指出「不乘 1.0 会恒为 0」的坑

第 7 题参考查询：

SELECT gen_date,
       COUNT(*)                                    AS gen_cnt,
       SUM(is_accepted)                            AS acc_cnt,
       ROUND(SUM(is_accepted) * 1.0 / COUNT(*), 2) AS acc_rate
FROM gen_records
GROUP BY gen_date
ORDER BY gen_date;

参考结果：最低为 2026-09-05 与 2026-09-08，采纳率均为 0.00；其中 09-05 样本 2 次、09-08 样本仅 1 次。

档位 标准
合格（18–23 分） 分组聚合正确，能指出最低日期
良好（24–27 分） 查询含别名与排序；主动指出样本量小、结论是「待观察」而非定论
优秀（28–30 分） 额外提出下一步动作：按渠道或按用户切片做归因，体现「整体→切片→归因」链路

第 8 题参考框架（以教学示例「AI 简历助手」为例，非唯一答案）：北极星 = 每周用 AI 修改简历并被查看 ≥2 次的求职者数；一级指标 = 采纳率（分母=AI 生成的修改建议条数，口径=用户点击「采用」或下载修改后版本）、7 日留存（分母=当日新增，按「完成过一次简历诊断」的核心行为算）、单次成本（口径=月账单 / 月有效诊断次数）；护栏 = 重试率（防采纳率靠多次重试刷上去）、幻觉率抽检（防工作经历被改写失实——简历场景高风险）、推送退订率（防留存靠弹窗拉回）。

档位 标准
合格（36–47 分） 三层齐备，北极星过了三标准，一级指标来自五大指标且公式正确
良好（48–55 分） 每个指标带完整口径；护栏与北极星的「歪路」一一对应，逻辑成对
优秀（56–60 分） 北极星定义含核心行为 + 质量门槛 + 频次阈值三零件；结合自己产品的场景风险对幻觉率/解决率做了分层设计（如高风险字段从严）

第三层 · 求职挑战（三档 Rubric）

第 9 题参考答案：第一步整体——确认收入口径与成本口径，看采纳率、单次成本是否随 DAU 同步变化；第二步切片——按新/老用户、渠道、平台切开，定位增长来自哪里（典型假设：推送拉来的低质量新用户，用了不采纳）；第三步归因——看新用户采纳率、7 日留存、习惯用户占比是否被稀释，给出动作：若为低质拉新，收窄投放渠道、改新手引导。注意每步给出指标名而非笼统「看数据」。

档位 标准
合格（24–31 分） 三步框架完整，每步有至少 1 个具体指标
良好（32–37 分） 指标选取体现 AI 特性（采纳率、留存按核心行为算），假设有因果逻辑链
优秀（38–40 分） 主动指出「DAU 涨可能是廉价手段推高」并给出验证方法（如退订率、推送打开率），动作具体到功能层面

第 10 题参考答案：第一假设——某渠道/某时段混入了低质量流量，或某次版本发布降低了单次生成质量。验证思路：先把大盘子切片，找出「掉的那部分」来自哪。参考查询（按渠道切片）：

SELECT u.channel,
       COUNT(*)                                    AS gen_cnt,
       ROUND(SUM(g.is_accepted) * 1.0 / COUNT(*), 2) AS acc_rate
FROM gen_records g
JOIN users u ON g.user_id = u.user_id
GROUP BY u.channel
ORDER BY acc_rate ASC;

预期判读：若某渠道采纳率显著低于其他渠道且样本量足够，则支持「流量质量」假设；若各渠道同步下降，则转向「版本质量」假设，按日期继续切片并关联发版时间。

档位 标准
合格（24–31 分） 假设明确，SQL 能跑通且切片维度合理
良好（32–37 分） 假设—查询—判读三者闭环：说明「看到什么结果支持/推翻假设」
优秀（38–40 分) 给出双假设分支（流量质量 vs 版本质量）及各自的验证查询，主动提及样本量与置信度
