第 0 层 · 术语辨析题（12 题，含选择 / 连线 / 改错三种题型）

对应对应板块当堂小测；重点辨析「率类指标的分子分母」。每题 10 分，共 120 分，答对 ≥10 题（≥100 分）为达标。

一、选择题（0-1 ~ 0-4，每题 10 分）

0-1. 关于「率类指标的分母」，说法正确的是： A. 幻觉率 = 被判定为幻觉的回答数 / 全部回答数 B. 幻觉率 = 被判定为幻觉的回答数 / 抽检回答总数 C. 7 日留存 = 第 7 天仍活跃用户数 / 全部活跃用户数 D. 采纳率 = 被采纳生成次数 / 活跃用户数

0-2. 关于「分组」与「聚合」，说法正确的是： A. GROUP BY 负责算值，COUNT / SUM 负责分组 B. 先聚合后分组，顺序不影响结果 C. GROUP BY 分组定维度，COUNT / SUM / AVG 聚合算每组值，先分组后聚合 D. 只分组不聚合是语法错误

0-3. 关于 DAU 与留存，说法正确的是： A. DAU 是一个率，分母是当日新增用户数 B. DAU 是当日活跃用户的计数、没有分母；留存是率，分母是当日新增用户数 C. 二者只是叫法不同，可以互相代替 D. 留存的分母是全部活跃用户数

0-4. 关于「指标口径」与「幻觉率口径」，说法正确的是： A. 二者是同一个东西 B. 指标口径是通用定义（分母 / 周期 / 来源），幻觉率口径是幻觉率这一指标的抽检与判定规则 C. 口径只影响显示格式，不影响数值 D. 口径换了，数字不变，跨版本照常比较

二、连线题（0-5 ~ 0-8，每题 10 分；把左列与右列正确配对）

0-5. 率类指标 ↔ 正确分母（3 组）

左：① 采纳率   ② 幻觉率        ③ 留存
右：A 当日新增用户数   B 总生成次数   C 抽检回答总数

0-6. 术语 ↔ 最容易混淆的相邻概念（3 组）

左：① 北极星指标   ② 基线        ③ 看板
右：A 一条 SQL 查询结果   B KPI   C 行业健康线 / 目标值

0-7. SQL 关键字 ↔ 业务上回答的问题（4 组）

左：① SELECT   ② WHERE   ③ GROUP BY   ④ JOIN
右：A 按什么维度切、每组算几个   B 要看哪几列   C 跨表两个事实怎么对上   D 只看哪部分数据（分母从这里变）

0-8. 英文缩写 ↔ 全称与中文（2 组）

左：① DAU   ② SQL
右：A Structured Query Language，结构化查询语言   B Daily Active Users，日活跃用户数

三、改错题（0-9 ~ 0-12，每题 10 分；先判断错在哪，再写出正确说法）

0-9. 「幻觉率 = 被判定为幻觉的回答数 / 全部回答数，全量自动统计即可，不用抽检。」

0-10. 「7 日留存 = 第 7 天仍活跃的用户数 / 全部活跃用户数，打开过 App 就算活跃。」

0-11. 「采纳率越高，说明单次生成质量一定越好，所以这个指标不用配护栏。」

0-12. 「GROUP BY 就是聚合，先聚合后分组；聚合列不用起别名，看板手写列名就行。」

第 1 层 · 基础巩固题（概念层，原第一层保留 + 补 2 题）

一、选择题（每题 10 分，共 30 分）

1. 关于采纳率的口径，说法正确的是： A. 采纳率 = 采纳用户数 / 注册用户数 B. 修改后是否算「采纳」属于口径定义，必须先定义清楚再统计 C. 采纳率越高，说明单次生成质量一定越好 D. 行业有统一的采纳率健康线，直接照搬即可

2. 关于幻觉率，理解正确的是： A. 模型拒答用户问题属于幻觉行为，应计入幻觉率 B. 幻觉率没有金标准，所以无法管理，也不用统计 C. 幻觉率 = 被判定为幻觉的回答数 / 抽检回答总数，可通过分层抽检 + 评测集回归管理 D. 幻觉率只与技术有关，产品经理不需要关注

3. 下列 SQL 的作用是：

SELECT channel FROM users GROUP BY channel;

A. 查出所有渠道名称，并去重分组 B. 查出每个渠道的用户明细 C. 语法错误，GROUP BY 后必须接聚合函数 D. 等价于 SELECT DISTINCT 的反操作，会列出重复渠道

二、简答题（每题 20 分，共 40 分）

4. 面试官问：「幻觉率的判定没有金标准，你们为什么还要统计它？」请给出两条理由。

5. 为什么说 DAU 不适合作为大多数 AI 产品的北极星指标？请用北极星三标准逐条说明。

三、补充题（补 1 · 选择 10 分；补 2 · 简答 20 分）

补 1. 关于「基线」，说法正确的是： A. 基线就是行业公开的健康线数字，直接照搬 B. 基线是上线首周全量数据当参照起点，之后逐版看环比 C. 基线是要够到的目标值 D. 基线只在幻觉率上用，其他指标不用

补 2. 请写出「指标口径」必须包含的三项内容，并说明为什么「口径不统一，指标跨版本不可比」。

第 2 层 · 进阶实操题（SQL 上机 + 方案设计层，原第二层保留 + 补 2 题）

6. SQL 上机：整体健康查询（30 分） 使用上方数据集，写出一条查询，同时输出三个数：总生成次数（gen_cnt）、整体采纳率（acc_rate，保留两位小数）、平均单次成本（avg_cost，保留四位小数）。

7. SQL 上机：定位异常日（30 分） 写出查询：按生成日期分组，输出每天的生成次数、采纳次数与采纳率（保留两位小数），按日期升序排列。并回答：哪一天的采纳率最低？该结论需要注意什么样本量问题？

8. 指标设计题：为你的主项目设计指标看板（60 分） 为自己的主项目（你 PRD 中的 AI 产品）设计完整指标看板，要求： ① 北极星指标 1 个，写出定义，并用三标准（绑价值 / 可影响 / 可拆解）逐条自检； ② 一级指标 3–5 个，从五大核心指标（采纳率 / 解决率 / 幻觉率 / 留存 / 单次成本）中选取，每个附公式与口径（分母定义、统计周期）； ③ 护栏指标至少 2 个，每个写清「防什么动作」。

补 1. SQL 上机：按用户统计次数（补充，30 分） 写出查询：统计每个用户的生成次数（gen_cnt）与采纳次数（acc_cnt），按生成次数降序排列；并回答「八个用户里有几个生成次数不超过 2 次，这提示什么？」。零编程 / 手机同学可改为「读懂下方参考查询、写出分组维度与两个聚合函数」。

补 2. 口径核对题（补充，20 分） 下面这条查询想算「9 月 3 日当天的采纳率」，但它算出来的分母和「整体采纳率」不一致。请指出问题，并写出修正后、口径与整体一致的一条查询（提示：整体采纳率分母是「全部生成次数」，切片也要声明清楚分母范围）：

SELECT SUM(is_accepted) / COUNT(*) AS acc_rate
FROM gen_records
WHERE gen_date = '2026-09-03';

第 3 层 · 求职挑战题（面试层，原第三层保留 + 补 2 题）

9. 面试真题：数据归因分析（40 分） 面试官：「我们 AI 写作产品 DAU 涨了 30%，但收入没涨，老板让你分析原因。你怎么做？」 要求：按「整体 → 切片 → 归因」三步给出分析框架，每步至少指出 1 个要看的具体指标，最后给出 1 条可能的产品动作。

10. 面试真题 + SQL 验证假设（40 分） 面试官：「假如采纳率这个月从 54% 掉到了 45%，你的第一个假设是什么？怎么用数据验证？」 要求：① 写出你的第一个假设与验证思路；② 基于上方数据集写出一条验证用 SQL（提示：可按渠道或按日期切片），说明你预期看到什么结果才支持这个假设。

补 1. 面试真题：整体涨了分组跌了（补充，40 分） 面试官：「整体采纳率这个月涨了，但拆开看某渠道跌了，怎么解释？到底算好还是不好？」 要求：指出至少 1 种可能的结构原因，写出验证所需的切片维度，说明小样本如何处理。

补 2. 面试真题：指标体系设计（补充，40 分） 面试官：「你要给一个 AI 客服产品设计看板，五个核心指标里你选哪几个当一级指标、为什么？护栏配什么？」 要求：从北极星倒推选一级指标（不堆数字），每个写口径，护栏写清防什么动作。

第 4 层 · 面试实战题（6 题，每题含踩分点 / 追问链 / 评分表）

对应对应板块；每题给「题目 + 题型 / 踩分点 3–4 条 / 2–3 层追问链 / 典型失败答法 + 失分原因 / 三档评分表」。60 秒标准答法全文见《02-讲课稿.md》对应板块同题，模拟时对照使用。每题 100 分制评分表折算到档位。

4-1. 「你怎么衡量一个 AI 产品做得好不好？看什么指标？」（题型：技术理解 / 场景设计） - 踩分点：① 先给价值视角「来了多少人 vs 用得值不值」；② 给三层结构北极星 / 一级 / 护栏；③ 报出五大核心指标中 ≥4 个；④ 主动点名 DAU 不能当北极星并给一条理由。 - 追问链：① 五个指标哪个最重要 → 从北极星倒推、按产品形态定命门；② 健康线怎么定 → 基线对比法、示例值需按业务校准；③ 指标涨了就一定好吗 → 配护栏、举采纳率涨重试翻倍。 - 典型失败答法 + 失分原因：「看 DAU、留存、转化率、增长率。」——全是流量视角、没结构；失分在把传统产品那套直接搬过来。 - 评分表：

档位 标准 分值
合格 报出 ≥4 个指标，但不给结构、不提价值视角 60–74
良好 给三层结构 + 价值视角，主动点名 DAU 不宜当北极星 75–89
优秀 再补「从北极星倒推选一级指标、每项带口径、配护栏」，并接住 2 层追问 90–100

4-2. 「采纳率怎么定义？用户改了三个字才发布，算不算采纳？」（题型：技术理解 / 项目深挖） - 踩分点：① 给公式并说清分子分母；② 指出「修改后算不算」是口径问题、无唯一答案但必须有答案；③ 说清口径三要素（分母按次 / 会话、采纳动作、周期与来源）；④ 补「口径不统一则跨版本不可比」。 - 追问链：① 你们当初怎么定的 → 给一个明确口径并说明全版本一致；② 重试 10 次才采纳 1 次说明什么 → 10% 是诚实的、配重试率护栏；③ 口径后来改过怎么办 → 重算历史基线、标注断点。 - 典型失败答法 + 失分原因：「就是用户用了的比例，改了肯定也算。」——没公式没分母、把口径当常识；被追问「按次还是按会话」即卡。 - 评分表：

档位 标准 分值
合格 说出公式「被采纳 / 总生成」，但没提口径 60–74
良好 主动补口径三要素 + 跨版本不可比 75–89
优秀 再补「口径变了要重算基线、标断点」+ 重试率护栏，接住 2 层追问 90–100

4-3. 「整体采纳率涨了，但某个渠道跌了，怎么解释？」（题型：场景设计 / 项目深挖） - 踩分点：① 不复述「涨了就好」，按「整体 → 切片 → 归因」拆；② 指出可能是分母结构变化（低质渠道停投 / 样本构成变化）；③ 先确认切片前后口径一致、看样本量；④ 给一个具体动作。 - 追问链：① 到底算好还是不好 → 拆结构、主力渠道跌就不是真好；② 怎么验证渠道质量 vs 版本质量 → 按渠道 + 按日期双切片、关联发版时间；③ 某渠道 1.00 能否加预算 → 先看次数再看比率、标待观察。 - 典型失败答法 + 失分原因：「整体涨了说明策略有效，个别渠道波动正常。」——只看大盘、没切片、没查样本量；把结构变化误读成整体变好。 - 评分表：

档位 标准 分值
合格 知道要切片看分组，但没说结构原因 60–74
良好 指出分母结构变化 + 口径一致性检查 + 给动作 75–89
优秀 再补双切片验证（渠道 + 日期关联发版）、小样本先看次数、不把相关当因果 90–100

4-4. 「你不会写 SQL，能做数据方向的产品经理吗？」（题型：行为题） - 踩分点：① 不把「不会写」说成硬伤，先划清产品与开发边界；② 说清产品必懂三件事（读懂查询 / 核对分母与口径 / 判断结论）；③ 举一个能抓的错（整数除法恒为 0、口径漂移、小样本）；④ 给协作方式。 - 追问链：① 怎么不被分析师糊弄 → 核分母 / WHERE 有没有改口径 / 比率乘没乘 1.0；② 举一个真读懂过的例子 → 按渠道 GROUP BY 算采纳率、说清分子分母；③ 只招一个会写 SQL 的产品为什么不招你 → 产品稀缺能力是把数变成动作。 - 典型失败答法 + 失分原因：「我确实不会写，但我会努力学。」——把不会当缺陷道歉、无边界无实证；既没说清产品该懂什么也没证明自己懂。 - 评分表：

档位 标准 分值
合格 表态能学、态度积极，但没划边界 60–74
良好 划清边界 + 说出「读懂 / 核口径 / 判结论」三件事 75–89
优秀 再举出具体能抓的错（整数除法 / 口径漂移 / 小样本）+ 协作方式，接住 2 层追问 90–100

4-5. 「DAU 能不能当 AI 产品的北极星指标？」（题型：技术理解 / 场景设计） - 踩分点：① 明确说不能；② 用三标准逐条拆；③ 给替代公式「每周完成核心行为 N 次的用户数」并说出三零件；④ 补护栏。 - 追问链：① DAU 也有好处吧 → 当规模监控 / 护栏可以、不能当方向；② 换北极星团队动作会变吗 → 教学示例从拉新转留存；③ 怎么防新北极星被刷 → 配重试率 / 幻觉率 / 退订率。 - 典型失败答法 + 失分原因：「能啊，DAU 涨说明用的人多。」——方向性错误、没用三标准；把规模当价值。 - 评分表：

档位 标准 分值
合格 说不能，但只给一两句理由 60–74
良好 三标准逐条拆完 + 给替代公式 75–89
优秀 再说出三零件（核心行为 / 质量门槛 / 频次阈值）+ 护栏 + 团队动作变化 90–100

4-6. 「采纳率涨了 5 个点，但重试次数翻倍，说明什么？」（题型：项目深挖） - 踩分点：① 判定为护栏报警、不是纯利好；② 解释机理「多试几次才命中、单次质量在降」；③ 关联基线 / 样本构成排查；④ 给动作（查单次质量、看版本变更、别发捷报）。 - 追问链：① 这个数还能用吗 → 能用但必须和重试率一起看；② 怎么定位 → 按日期切片关联发版、按新老用户切片看构成；③ 成本怎么变 → 重试翻倍单次成本涨、交叉验证。 - 典型失败答法 + 失分原因：「说明用户更爱用了，重试多代表活跃，是好事。」——把护栏报警读成利好；只看北极星不看护栏。 - 评分表：

档位 标准 分值
合格 觉得「有点问题」但说不清机理 60–74
良好 判定护栏报警 + 说清机理 + 给排查方向 75–89
优秀 再补按日期 / 新老用户双切片、单次成本交叉验证、明确「不发捷报」 90–100

第 2 层 · 进阶实操（三档 Rubric）

第 6 题参考查询：

SELECT COUNT(*)                                          AS gen_cnt,
       ROUND(SUM(is_accepted) * 1.0 / COUNT(*), 2)       AS acc_rate,
       ROUND(AVG(cost_yuan), 4)                          AS avg_cost
FROM gen_records;

参考结果：gen_cnt = 13，acc_rate = 0.54，avg_cost ≈ 0.0392。

档位 标准
合格（18–23 分） 三个聚合函数使用正确，能输出三列
良好（24–27 分） 比率正确乘 1.0 避开整数除法，ROUND 位数符合要求
优秀（28–30 分） 列名全部使用 AS 别名（看板规范），并能口头指出「不乘 1.0 会恒为 0」的坑

第 7 题参考查询：

SELECT gen_date,
       COUNT(*)                                    AS gen_cnt,
       SUM(is_accepted)                            AS acc_cnt,
       ROUND(SUM(is_accepted) * 1.0 / COUNT(*), 2) AS acc_rate
FROM gen_records
GROUP BY gen_date
ORDER BY gen_date;

参考结果：最低为 2026-09-05 与 2026-09-08，采纳率均为 0.00；其中 09-05 样本 2 次、09-08 样本仅 1 次。

档位 标准
合格（18–23 分） 分组聚合正确，能指出最低日期
良好（24–27 分） 查询含别名与排序；主动指出样本量小、结论是「待观察」而非定论
优秀（28–30 分） 额外提出下一步动作：按渠道或按用户切片做归因，体现「整体→切片→归因」链路

第 8 题参考框架（以教学示例「AI 简历助手」为例，非唯一答案）：北极星 = 每周用 AI 修改简历并被查看 ≥2 次的求职者数；一级指标 = 采纳率（分母=AI 生成的修改建议条数，口径=用户点击「采用」或下载修改后版本）、7 日留存（分母=当日新增，按「完成过一次简历诊断」的核心行为算）、单次成本（口径=月账单 / 月有效诊断次数）；护栏 = 重试率（防采纳率靠多次重试刷上去）、幻觉率抽检（防工作经历被改写失实——简历场景高风险）、推送退订率（防留存靠弹窗拉回）。

档位 标准
合格（36–47 分） 三层齐备，北极星过了三标准，一级指标来自五大指标且公式正确
良好（48–55 分） 每个指标带完整口径；护栏与北极星的「歪路」一一对应，逻辑成对
优秀（56–60 分） 北极星定义含核心行为 + 质量门槛 + 频次阈值三零件；结合自己产品的场景风险对幻觉率 / 解决率做了分层设计（如高风险字段从严）

第 2 层补 1 参考查询：

SELECT user_id,
       COUNT(*)          AS gen_cnt,
       SUM(is_accepted)  AS acc_cnt
FROM gen_records
GROUP BY user_id
ORDER BY gen_cnt DESC;

参考结果：user_id 3 生成 3 次；user_id 1 / 4 / 6 各 2 次；其余各 1 次。八个用户里 7 个生成次数 ≤2 次（仅 user_id 3 为 3 次），这是留存预警信号——多数用户没形成使用习惯。评分：分组维度写对 10 分、两个聚合函数与别名 10 分、结论「多数用户 ≤2 次 + 留存预警」10 分；手机 / 只读同学答出「分组维度 = user_id、聚合 = COUNT 与 SUM」即得 20 分，口头结论 10 分。

第 2 层补 2 参考答案：问题有三处——① SUM / COUNT 未乘 1.0，整数除法恒为 0；② 加了 WHERE gen_date 后分母变成「9 月 3 日当天生成次数」，与整体分母「全部生成次数」不同，这正是「口径漂移」，两个比率不能直接比；③ 没有 AS 别名与口径注释。修正版（保留当天切片、但明确声明分母范围，并乘 1.0）：

SELECT '2026-09-03'                                  AS stat_scope,
       COUNT(*)                                      AS gen_cnt,
       SUM(is_accepted)                              AS acc_cnt,
       ROUND(SUM(is_accepted) * 1.0 / COUNT(*), 2)  AS acc_rate   -- 分母=当天生成次数，口径注释
FROM gen_records
WHERE gen_date = '2026-09-03';

评分：指出整数除法 7 分、指出分母口径漂移并说明「切片分母 ≠ 整体分母、比较前须对齐口径」8 分、修正查询可运行且带别名 / 注释 5 分。只改乘 1.0 而没提口径，最多 10 分。

第 3 层 · 求职挑战（三档 Rubric）

第 9 题参考答案：第一步整体——确认收入口径与成本口径，看采纳率、单次成本是否随 DAU 同步变化；第二步切片——按新 / 老用户、渠道、平台切开，定位增长来自哪里（典型假设：推送拉来的低质量新用户，用了不采纳）；第三步归因——看新用户采纳率、7 日留存、习惯用户占比是否被稀释，给出动作：若为低质拉新，收窄投放渠道、改新手引导。注意每步给出指标名而非笼统「看数据」。

档位 标准
合格（24–31 分） 三步框架完整，每步有至少 1 个具体指标
良好（32–37 分） 指标选取体现 AI 特性（采纳率、留存按核心行为算），假设有因果逻辑链
优秀（38–40 分） 主动指出「DAU 涨可能是廉价手段推高」并给出验证方法（如退订率、推送打开率），动作具体到功能层面

第 10 题参考答案：第一假设——某渠道 / 某时段混入了低质量流量，或某次版本发布降低了单次生成质量。验证思路：先把大盘子切片，找出「掉的那部分」来自哪。参考查询（按渠道切片）：

SELECT u.channel,
       COUNT(*)                                    AS gen_cnt,
       ROUND(SUM(g.is_accepted) * 1.0 / COUNT(*), 2) AS acc_rate
FROM gen_records g
JOIN users u ON g.user_id = u.user_id
GROUP BY u.channel
ORDER BY acc_rate ASC;

预期判读：若某渠道采纳率显著低于其他渠道且样本量足够，则支持「流量质量」假设；若各渠道同步下降，则转向「版本质量」假设，按日期继续切片并关联发版时间。

档位 标准
合格（24–31 分） 假设明确，SQL 能跑通且切片维度合理
良好（32–37 分） 假设—查询—判读三者闭环：说明「看到什么结果支持 / 推翻假设」
优秀（38–40 分） 给出双假设分支（流量质量 vs 版本质量）及各自的验证查询，主动提及样本量与置信度

第 3 层补 1 参考答案：结构原因——很可能是分母结构变化，例如低质量渠道停投、样本构成变化，把大盘比率抬上去了，而主力渠道其实在跌（辛普森式结构效应）；也可能只是切片前后口径不一致。验证：按渠道切片（看各分组涨跌是否一致）+ 按日期切片（关联发版时间，区分流量质量 vs 版本质量）；先确认切片查询的分母与整体那条口径一致、没漂移。小样本处理：先看次数再看比率，样本量小的分组标「待观察」，不直接定性或加预算。评分：结构原因 15 分、双切片维度 15 分、口径一致性 + 小样本处理 10 分。

第 3 层补 2 参考答案（教学示例「AI 客服产品」）：北极星 = 无人工介入且被满意度评为解决的会话数；从北极星倒推，一级指标只选两个——解决率（分母 = 总问题会话数，口径 = 无人工介入且自然结束，周期 = 周）与幻觉率（分母 = 抽检回答总数，口径 = 分层抽检 + 拒答单独统计，周期 = 每次发版回归）；不把采纳率 / 留存 / 单次成本全堆上去，因为客服场景命门是「问题闭环」与「敢不敢信」。护栏 = 转人工率（防解决率靠把难题推给人刷高）、重复进线率（防「自然结束」是假解决）、单次成本（防为追解决率无限重试）。评分：北极星与倒推逻辑 15 分、一级指标少而准且各带口径 15 分、护栏写明防什么动作 10 分；堆满五个指标不倒扣但不得「优秀」档。
