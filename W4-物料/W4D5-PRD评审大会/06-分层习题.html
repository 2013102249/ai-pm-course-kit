分层习题 · W4 周五《PRD 评审大会（里程碑 ③）》

300 分钟（6 课时 × 50 分钟）· 六节主线：术语 → 评审标准 → 反面案例 → 多轮答辩实操 → 面试讲解 → 验收
节次对齐：第 1 节 0–50 min / 第 2 节 50–100 min / 第 3 节 100–150 min / 第 4 节 150–200 min / 第 5 节 200–250 min / 第 6 节 250–300 min（第 0 层对应第 1 节，第 1–3 层对应第 2–4、6 节，第 4 层对应第 5 节）。
本课原为评审日「不设常规书面习题」页（答辩与质询即当堂练习，见 03-导学案评审记录表；V2.0 过审验收清单见本文件附录）。300 分钟版因新增「术语精讲」与「面试讲解」两节，补入可测的第 0 层术语辨析与第 4 层面试实战，并把原验收清单完整保留为附录；全卷扩为 5 层，全部题目均给参考答案与评分标准。

第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错三种题型）

A. 单项选择题（Q1–Q5）

Q1 「评审」最准确的一句话定义是：
A. 给 PRD 打分、决定谁过关的考试
B. 对需求文档集中质疑并达成是否放行的共识会
C. 讲师单方面宣布裁定的通知会
D. 研发内部的技术评审

Q2 下列哪一组是「验收标准」而不是「目标值」？
A. 采纳率 ≥40%
B. 解决率 ≥60%
C. 提交前「十章齐全、P0 兜底全覆盖、单次成本可复算」逐条打勾
D. 用户满意度提升到 4.5 分

Q3 「阻塞点」与「风险」的区别，正确的是：
A. 两者完全一样，只是叫法不同
B. 风险是已经卡住的，阻塞点是可能发生的
C. 阻塞点是已经 / 确定卡住、不解决别的做不了；风险是可能发生
D. 阻塞点只出现在开发阶段，风险只出现在评审阶段

Q4 质询人收尾做研发评估，正确的估时口径是：
A. 「一个月吧，差不多」
B. 「一个迭代」
C. 按任务包拆到人日（链路 3–5 / 界面 3–5 / 评测 3 / 埋点 2，合计 13–18 人日）
D. 让研发自己随便报，PM 不介入

Q5 关于「决策记录」，下列说法正确的是：
A. 记下全场每个人的发言，越详细越好
B. 只记结论 + 依据 + 责任人 + 时间四要素
C. 等同于「修订要求」，写清要改什么即可
D. 会后由记录人凭记忆补写，不必当场定

B. 连线题（Q6–Q7）

Q6 把「四区拆解」的四块连到对应的「四维评分」维度：

左（区块）右（维度）
A. 目标区① 方案完整性
B. 方案区② 数据支撑
C. 数据区③ 风险识别
D. 风险区④ 目标清晰度

Q7 把术语连到它「最易混」的相邻概念：

左（术语）右（最易混）
A. 变更① 会议纪要
B. 决策记录② 目标值
C. 验收标准③ 修订要求
D. 质疑④ 挑刺 / 下结论
E. 答辩⑤ 念 PRD / 演讲

C. 改错题（Q8–Q12，先判错，再改正）

Q8 「这方案不行，目标用户都没想清楚。」——这是合格的质疑。
Q9 「修订要求：优化目标章、完善评测，下周尽快交。」
Q10 「评审没共识，那就投票，少数服从多数。」
Q11 「访谈补到 5 人、附 5 条原声，属于一次变更，要走变更记录。」
Q12 「会前材料就是会后整理的那份会议纪要，现场投屏的 PPT 也算。」

第 0 层 · 参考答案与评分标准

题参考答案评分标准（每题 2 分，共 24 分；≥20 分达标）
Q1B选 B 得 2；选 A / C / D 得 0（A 把评审当考试、C 当通知会、D 混为技术评审，均属术语混淆）
Q2C选 C 得 2；其余 0 分（A / B / D 都是上线后效果指标＝目标值）
Q3C选 C 得 2；B 得 0（说反了）；A / D 得 0
Q4C选 C 得 2；A / B 得 0（魔法数字 / 不可换算口径）；D 得 0
Q5B选 B 得 2；A 得 0（那是会议纪要）；C 得 0（混淆决策记录与修订要求）；D 得 0（须当场定四要素）
Q6A-④ B-① C-② D-③每连对 1 条 0.5 分，共 2 分；连错不得分
Q7A-③ B-① C-② D-④ E-⑤每连对 1 条 0.4 分，共 2 分
Q8错。这是结论不是质疑；应改成「目标用户和高频场景，能不能一句话说清？」判「错」1 分；改写成可回答的问句 1 分；只判错不改 0.5 分
Q9错。三要素缺失；改为「目标章补成功指标与目标值，改成『采纳率 ≥40%』，周一 12:00 前；评测章按评测集来源 / 条数 / 门槛三件套重写，周日 24:00 前」判错 1 分；每条补齐三要素（改哪章 / 改成什么 / 截止时间）各 0.5 分，共 1 分；写出具体日期才给满
Q10错。共识会不等于表决会；应把两派主张 / 依据 / 担心写进决策记录，标为阻塞点，拉决策人限时定，给临时口径让其余环节继续判错 1 分；写出「决策记录 + 阻塞点 + 限时 / 临时口径」任 2 项得 1 分
Q11错。补访谈属于「修订要求」（改文档内容），不是「变更」；只有改动已确认范围 / 排期才走变更记录判错 1 分；说清「修订 vs 变更」边界 1 分
Q12错。会前材料是会前发出、带页码目录供预读的文档；会议纪要是会后产出，投屏 PPT 是讲述辅助判错 1 分；点出「会前 / 会后」与「独立预读」两点各 0.5 分

Q1 写出评审四段流程，并各写一句该段的产出。

Q5 质询两条铁律是什么？把「你这个调研肯定有偏差」改写成合格问题。

第 1 层 · 参考答案与评分标准

题参考答案评分标准（每题 5 分，共 30 分；≥24 分达标）
Q1陈述 → 质询 → 修订 → 终审；产出：质询记录表 / 修订要求清单 / 带日期修订清单 / 裁定档位四段各 0.75 分（3 分），四段产出各 0.5 分（2 分）；顺序错扣 1 分
Q2背景 1′（谁在什么场景遇到什么问题 + 调研数据）、方案 2′（做什么 / 链路 / 为什么这么设计 / 取舍）、数据与风险 2′（评测标准与目标值 / 最大风险与兜底）时长 1 分、三段各 1 分（3 分）、「主动讲风险」1 分
Q3复述问题 → 给答案 → 给依据。复述用于确认没听歪 + 争取 2 秒组织答案，避免答偏方向三步各 1 分（3 分）；答出「确认理解 / 防答偏」2 分
Q4目标清晰度最高 3 分；数据支撑最高 3 分（样本低于 ≥5 访谈 / ≥30 问卷底线）每空 2.5 分；答「2 分」或「4 分」均不得分
Q5对方案不对人；只提问、不下结论。改写：「你的问卷选项是怎么设计的，怎么防止引导性偏差？」两条铁律各 1 分（2 分）；改写成可回答的问句 3 分（仍是结论得 0）
Q6对话链路 3–5 / 知识库 2–3 / 界面 3–5 / 评测 3 / 埋点看板 2；合计 13–18 人日五个任务包各 0.6 分（3 分）、合计区间 2 分；报「一个月」0 分

第 2 层 · 参考答案与评分标准

题参考答案评分标准（每题 5 分，共 30 分；≥24 分达标）
Q1目标区：无指标无目标值，不可验收；方案区：链路 / 十章 / 取舍是否齐全；数据区：结论能否回溯到原声 / 原表、样本量；风险区：风险分级、P0 兜底、成本章四区各 1 分（4 分）；用「四区拆解」术语并体现「先拆解后打分」1 分

Q1 ·「你的 PRD 在评审会上被当场说成伪需求，你怎么接？」（场景设计题 · 被挑战怎么接）

项内容
踩分点① 第一句复述质疑、不辩解；② 给可回溯数据依据；③ 用 ≥2 个当日术语；④ 答不出的记进修订要求并给截止时间
追问链层 1「反例数据正好相反呢？」→ 复述反例、承认样本边界、约定补样本后复盘；层 2「这轮还继续吗？」→ 标为阻塞点，其余三区先过，争议限时定；层 3「事后真是伪需求呢？」→ 走变更记录、复盘回补会前材料
典型失败答法「我觉得这需求没问题，我们调研过的，可能他没理解。」失分：第一句辩解、依据无出处、把质疑答成对抗

Q2 ·「评审会上研发和业务吵到没共识，你作为 PM 怎么办？」（场景设计题 · 没共识怎么办）

项内容
踩分点① 不硬拍、不站队、先结构化分歧；② 用决策记录写四要素；③ 标为阻塞点并给升级路径与限时；④ 给临时口径保证会不空转
追问链层 1「决策人也不在？」→ 临时口径 + 书面升级路径 + 明确截止时间，会后补确认；层 2「说你和稀泥？」→ 给判据（有判据 / 责任人 / 截止 vs 无判据地拖）；层 3「时限到了谁背锅？」→ 按决策记录责任人与升级路径走，对事不对人
典型失败答法「先让大家冷静，然后投票，少数服从多数。」失分：共识会答成表决会、无决策记录与阻塞点意识
评分表不站队不投票 1 / 决策记录四要素 1 / 阻塞点 + 限时 1 / 临时口径 1 / 抗 2 层追问 1

Q3 ·「研发说这功能『做不了 / 要一个月』，你怎么回应？」（技术理解题 · 研发质疑）

项内容

Q4 ·「研发质疑你的评测门槛太高、上线达不到，怎么谈？」（项目深挖题 · 研发质疑）

项内容

追问链层 1「门槛该研发定，PM 别插手？」→ 门槛是产品对用户的承诺，依据来自评测集与 badcase；层 2「上线前达不到？」→ 无 P0 badcase 为硬门槛，补修复轮次写进修订要求；层 3「算阻塞点吗？」→ 卡住放行即阻塞点，拉决策人限时
典型失败答法「那门槛调低一点，灵活些。」失分：无依据退让、混淆验收标准与目标值、评测章不可执行

用法：周日 24:00 提交前逐项自查；助教按「核验方式」列逐项复核。五条硬标准全部通过 = 过审；任何一条不通过，V2.0 不算提交。

1. 调研数据支撑（≥5 访谈 + ≥30 问卷引用）

验收要求核验方式
PRD 用户与场景章引用 ≥5 次访谈（含至少 5 条原声引用，标注访谈编号）与 ≥30 份有效问卷（标注回收数与有效率）助教随机抽 3 条结论回溯到访谈记录 / 问卷后台原始表；引不出原始记录 = 不通过；原始数据与引用数字对不上 = 不通过
调研为真实样本，禁止编造抽 1 名被访谈者信息做一致性核对（学员须能复述访谈场景与对方原话语境）；复述矛盾 = 不通过

2. 十章结构完整

验收要求核验方式
十章齐全：① 背景与机会 ② 目标与成功指标 ③ 用户与场景 ④ 需求优先级 ⑤ 功能方案 ⑥ 核心流程与状态机 ⑦ 评测标准 ⑧ 异常与兜底 ⑨ 成本预算 ⑩ 数据指标与回流助教对照目录逐章打勾；缺任一章 = 不通过（章名允许微调，内容必须在位；第 ⑥⑧ 章可直接并入 W4D3 兜底设计文档并在 PRD 中引用）

3. 评测标准可执行

验收要求核验方式
评测三件套齐全：评测集来源与条数（复用 W2 评测集需注明）、核心指标定义、上线门槛数值（如准确率 ≥90% 且无 P0 badcase）按「交给工程师能不能直接照此执行」判断：指标无目标值、评测集无来源、门槛无数值，三者缺一 = 不通过

4. 兜底方案覆盖全部 P0 异常

验收要求核验方式
异常清单已分级（P0 / P1），P0 每条有兜底动作与触发条件，与 W4D3 兜底设计文档一致（降级 / 澄清 / 拒答 / 转人工至少覆盖三类）助教对照兜底设计文档逐条核 P0；缺 1 条兜底或 PRD 与兜底文档冲突 = 不通过；兜底写「人工介入」而无触发条件 = 不通过

5. 成本预算有依据

验收要求核验方式
单次对话成本可复算：token 用量估算 × 模型单价，公式与过程写明；月度预算含用户量假设助教按文中公式独立复算一遍，偏差 >20% = 不通过；月度预算无用户量假设 = 不通过
