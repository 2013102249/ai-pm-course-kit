讲课稿 · W4 周五《PRD 评审大会（里程碑 ③）》

术语精讲与零层入口

同学们，今天是周五，第四周的收口日，主线项目里程碑 ③——PRD 评审大会。这周你们交了五样东西：调研报告、PRD V1.0、兜底设计文档、指标看板、SQL 练习。今天我们不学新技术，今天做一件事：把 PRD V1.0 摆上台面，交叉评审，讲师终审，然后每人带走一份带截止时间的修订要求清单。周末据此出 PRD V2.0 过审版——V2.0 过不过审，决定你能不能上第五周的中期答辩。

但今天和以往不一样。以往这种评审日，一上来就开打；今天前面，我们先把「话」说齐。我带过太多期，评审会上吵得面红耳赤，一半不是方案有分歧，是两个人嘴里的「评审」「验收」「变更」根本不是一个意思。术语不齐，攻防就是鸡同鸭讲。所以，12 个词，一个一个过。

先给零基础的同学一个零层入口。 你只需要记住一句：PRD，全称 Product Requirement Document，产品需求文档，就是写给研发看的「施工说明书」——不是作文，是让工程师照着就能干活的图纸。今天所有词，都围着「这张图纸怎么被审」转。听懂这句，就够了。

好，进入 12 个词。每个词我给五样东西：一句话定义、一个生活类比、一处最易混的辨析、一句能直接说出口的面试说法、还有术语卡在哪张。请同步填《术语自测表》。

术语 1 · 评审

  • 一句话定义（≤30 字）：对需求文档集中质疑并达成是否放行的共识会。
  • 生活类比：装修前全家围着图纸拍板，哪面墙能不能拆当场定；不是贴完瓷砖再砸墙。
  • 易混辨析：最易混「考试 / 终审」。考试是打分淘汰，评审是把分歧摆桌面；终审只是评审四段里的最后一段（讲师裁定），不等于整场评审。
  • 面试说法：「我把评审定位为共识会，目标是在写第一行代码前把分歧摆上桌，而不是给方案打分。」
  • 术语卡：03-配图素材/术语卡/评审.svg（待制，见 05-配图清单 图 3 登记）。

术语 2 · 答辩

  • 一句话定义：被评人限时陈述方案并现场应答质疑的过程。
  • 生活类比：论文答辩或求职面试——先自我介绍，再答台下连珠炮式的问题。
  • 易混辨析：最易混「演讲 / 念 PRD」。演讲是单向输出，答辩必须有攻防；照着 PRD 一字一句念不叫答辩，答辩要讲取舍和风险。
  • 面试说法：「答辩我按三段走——背景、方案、数据与风险，主动讲风险反而更可信。」
  • 术语卡：03-配图素材/术语卡/答辩.svg（待制）。

术语 3 · 共识会

  • 一句话定义：以「分歧摆上桌、每条有去处」为目标的决策会议。
  • 生活类比：一家人为去哪旅游开会，最后没去成自己想去的那个人也认，因为他的意见被听到、被记录了、有了安排。
  • 易混辨析：最易混「表决会 / 通知会」。共识不是少数服从多数投票，也不是领导单向宣布；共识是每条反对意见都有记录、修订或升级的去处。
  • 面试说法：「评审是共识会不是考试——通过是共识，驳回也是共识。」
  • 术语卡：03-配图素材/术语卡/共识会.svg（待制）。

术语 4 · 质疑

  • 一句话定义：对方案假设与依据提出可回答的疑问。
  • 生活类比：医生问诊「哪儿疼、多久了、什么情况下加重」，是提问，不是当场下诊断。
  • 易混辨析：最易混「挑刺 / 下结论 / 质询」。「这方案不行」是结论不是质疑，要换成一个问题再问；「质询」是本课评审中的固定环节与角色，「质疑」是贯穿其中的具体动作，一个是场地一个是动作。
  • 面试说法：「被质疑时我先复述问题确认没听歪，再给答案和依据，绝不第一句就辩解。」
  • 术语卡：03-配图素材/术语卡/质疑.svg（待制）。

术语 5 · 四区拆解

  • 一句话定义：把 PRD 拆成目标 / 方案 / 数据 / 风险四块逐块评。
  • 生活类比：验房按水电、墙体、门窗、防水四项逐一验，不笼统丢一句「房子还行」。
  • 易混辨析：最易混「四维打分」。拆解是把评审对象切块（对象），打分是给分（动作）；顺序一定是先四区拆解、再四维打分，别凭整体印象直接给 4 分。
  • 面试说法：「我评审先做四区拆解——目标、方案、数据、风险逐块过，避免凭整体印象打分。」
  • 术语卡：03-配图素材/术语卡/四区拆解.svg（待制）。

术语 6 · 验收标准

  • 一句话定义：事先写定、可逐条打勾判定放行的条件。
  • 生活类比：菜谱写「盐 3 克、烤箱 200 度 20 分钟」，而不是「盐适量、烤到差不多」。
  • 易混辨析：最易混「目标值 / 评分档位」。目标值是上线后的效果指标（如采纳率 ≥40%），验收标准是提交 / 放行前逐条打勾的门槛；评分档位是相对打分，验收是二元通过 / 不通过。
  • 面试说法：「V2.0 过审有五条硬标准，逐条可核验，没有『优化完善』这种模糊项。」
  • 术语卡：03-配图素材/术语卡/验收标准.svg（待制）。

术语 7 · 变更

  • 一句话定义：评审后对已确认范围、排期或方案的正式改动。
  • 生活类比：装修中途要挪插座，得重开一张增项单，写清差价和工期，不能口头一句「顺便加一下」。
  • 易混辨析：最易混「修订要求」。修订要求是评审产出的待办清单（改文档内容）；变更是对已确认的范围 / 排期基线的正式改动，必须留痕可追溯。补两句访谈原声是修订，把上线时间推后两周是变更。
  • 面试说法：「评审后的改动我分两类：文档修订走清单，范围或排期变动走变更记录，留痕可追溯。」
  • 术语卡：03-配图素材/术语卡/变更.svg（待制）。

术语 8 · 阻塞点

  • 一句话定义：卡住后续环节、不解决就无法推进的关键依赖。
  • 生活类比：高速前方事故封路，后面整条车龙全停，绕不开、缓不了。
  • 易混辨析：最易混「风险 / 普通待办」。风险是「可能发生」，阻塞点是「已经 / 确定卡住」；普通待办可以并行先放着，阻塞点不解决别的全做不了。
  • 面试说法：「我会把没共识的验收口径标成阻塞点，先拉决策人对齐，再放行开发。」
  • 术语卡：03-配图素材/术语卡/阻塞点.svg（待制）。

术语 9 · 里程碑

  • 一句话定义：项目阶段性的、绑定可验收成果的节点。
  • 生活类比：高铁的「铺轨完成 / 联调联试 / 正式通车」三个节点，到点必须交出东西、验完才走。
  • 易混辨析：最易混「截止日期 / 日常任务」。日期只是时间点，里程碑必须绑定一个可交付成果和验收动作；写「周五评审」是任务，写「周五评审双过关、出 V2.0 过审版」才是里程碑。
  • 面试说法：「PRD 评审是主线项目里程碑 ③，双过关出 V2.0 过审版，才有中期答辩入场券。」
  • 术语卡：03-配图素材/术语卡/里程碑.svg（待制）。

术语 10 · 会前材料

  • 一句话定义：评审前按约定时间发出、供参会人预读的文档集合。
  • 生活类比：开演前先把剧本发给演员，现场才对戏，不是上台才第一次读稿。
  • 易混辨析：最易混「会议纪要 / 现场投屏」。纪要是会后产出，会前材料是会前输入；投屏 PPT 是讲述辅助，会前材料必须能独立预读、带页码目录，质询时现场翻得到。
  • 面试说法：「我要求会前材料提前一天发，附页码目录——评审现场不读文档，只处理分歧。」
  • 术语卡：03-配图素材/术语卡/会前材料.svg（待制）。

术语 11 · 决策记录

  • 一句话定义：把评审拍定的结论、依据与责任人落成的可追溯条目。
  • 生活类比：装修每项增项都签字留底，写清「改成什么、为什么、谁认、哪天定」，日后不扯皮。
  • 易混辨析：最易混「会议纪要 / 修订要求」。纪要记过程发言，决策记录只记四要素：结论 + 依据 + 责任人 + 时间；修订要求是「要改什么」，决策记录是「定了什么、凭什么」。
  • 面试说法：「评审没共识我不硬拍，把可选方案与依据写进决策记录，拉决策人限时定。」
  • 术语卡：03-配图素材/术语卡/决策记录.svg（待制）。

术语 12 · 复盘

  • 一句话定义：事后回看目标与结果差距、提炼可复用经验的过程。
  • 生活类比：球赛后看录像，不纠结比分，专看哪个配合下次能复制、哪个失误下次能躲。
  • 易混辨析：最易混「总结 / 追责」。总结容易变成罗列成绩表功，复盘必须找差距与根因；复盘对事不对人，不是找谁背锅。
  • 面试说法：「每次评审后我做复盘：哪类质疑最常问住我，就补进下一版会前材料。」
  • 术语卡：03-配图素材/术语卡/复盘.svg（待制）。

再压一遍最容易翻车的六组：评审 ≠ 考试、质疑 ≠ 下结论、验收标准 ≠ 目标值、变更 ≠ 修订要求、阻塞点 ≠ 风险、决策记录 ≠ 会议纪要。这六组，第 0 层习题会用选择、连线、改错三种题型反复考，面试里也最爱从这里绕你。

现在做三道热身。「这方案不行」算不算质疑？（不算，是结论，要换成问题）「采纳率 ≥40%」是验收标准还是目标值？（目标值）先四区拆解还是先四维打分？（先拆解）。

答对 10 题以上过关；错 2 题以上的，验收前找我补测，不卡你，但术语不能带着糊涂进面试。

核心原理讲授 A：评审标准

同学们，回到今天这件事：把 PRD V1.0 摆上台面，交叉评审，讲师终审，每人带走一份带截止时间的修订要求清单。我先说清楚：V2.0 过不过审，决定你能不能上第五周的中期答辩，这是本周硬验收。

先讲一个我的观察。每一期学员的 PRD，评审时被问住的地方惊人地相似，丑话说在前面——这段我留到对应内容那一段用整节的反面案例铺开，这里先给你们尺子。

第一把尺子：四段流程。 整个流程四段：陈述、质询、修订、终审。看这张图，四个泳道：陈述人、质询人、记录人、我。陈述段 5 分钟，质询段 5 分钟，这两段在组内轮着来；修订段你们拿着修订要求回去改；终审段我来裁定，三档：过审、有条件通过、退回。今天课上完成前三段的主场，终审当场出裁定口径，V2.0 周末交。

第二把尺子：四区拆解（术语落地）。 别一上来就凭印象给「这份 PRD 挺好」。先切四块：目标区（用户 / 场景 / 指标 / 目标值）、方案区（链路 / 十章 / 取舍）、数据区（调研引用 / 样本量 / 可回溯）、风险区（风险分级 / P0 兜底 / 成本）。四块逐块过完，再打分——这就是「先拆解、后打分」。

第三把尺子：四维评分标准。 记录表按四维打分：目标清晰度、方案完整性、数据支撑、风险识别，各 0 到 5 分，档位表卡背有，打分前对一眼。

维度2 分及以下3 分4–5 分
目标清晰度说不清目标用户 / 场景，或「所有人都能用」用户与场景明确，但指标无目标值用户、场景、指标、目标值齐全且能说明取舍
方案完整性核心链路讲不清，或缺评测 / 兜底 / 指标任一章十章齐全但评测 / 兜底不可执行链路清楚，评测可执行、兜底覆盖 P0、估时有依据
数据支撑关键结论无数据，或引不出原始记录有引用但样本低于底线（访谈 <5 或问卷 <30）≥5 访谈 + ≥30 问卷，关键结论可回溯到原声 / 原表
风险识别无风险章或只写「有风险」列了风险但无应对风险分级（P0 / P1），P0 全部有兜底与触发条件

提醒一句：只有指标没有数值，目标清晰度最高 3 分——这就是档位的意义，把「感觉」卡成「分数」。

再说今天的答辩怎么打。5 分钟陈述，三段结构，这是今天要练进肌肉里的东西：

第一段，背景，1 分钟。 谁在什么场景下遇到什么问题？用调研数据说话——不要说「很多用户都有这个痛点」，要说「5 次访谈里 4 次被提到，问卷里 68% 的人选了它」。

第二段，方案，2 分钟。 你做什么？核心链路怎么走？为什么这么设计？这里是 STAR 的 S 和 A——背景、任务、动作，讲清取舍，不堆功能。

第三段，数据与风险，2 分钟。 你的方案凭什么行——评测标准、目标值；以及最大的风险是什么、兜底在哪。敢主动讲风险的 PRD，评审通过率反而高，因为你把别人要问的话先说了。

然后是被质询时的应答公式，三个动作，一个都不能少：先复述问题，再给答案，最后给依据。 复述问题有两个作用：一是确认你没听歪，二是给你争取两秒钟想答案。我示范一遍。

质询人问：「你这个核心功能研发要多久？」

错误示范：「呃……应该……一个月吧，差不多。」——这叫拍脑袋，研发负责人听到这句，你们的项目就已经进延期名单了。

正确示范：「您问的是核心功能的人日估算。答案是：按任务拆解，对话链路 4 人日、界面 4 人日、评测 3 人日，合计 13 人日左右，核心链路两周内可以跑通。依据是：我们调现成模型 API，不训模型，评测集 W2 就建好了，直接复用。」——复述、答案、依据，三步。这个公式在面试答辩里一模一样地用。

今天只有一句金句，但我希望你们带进任何一家公司：评审是共识会不是考试——通过是共识，驳回也是共识。 它不是来给你打分的，是来把分歧摆到桌面上，让产品在写第一行代码之前变得更便宜。所以今天台下所有的问题，都是在帮你省钱。

最后说规则。4 到 5 人一组，组内轮流答辩，每人 10 分钟：5 分钟陈述、5 分钟质询。每轮三个角色：陈述人、质询人、记录人，按轮值表轮换，每人今天至少当一次质询人。质询三类问题——目标类、方案类、数据类——每类至少 1 问，收尾 1 分钟做研发评估：几个人日、怎么排期、最大风险。质询两条铁律：对方案不对人；只提问，不下结论。 想说「这方案不行」的时候，把它换成一个问题。每人必须写出至少 1 条质询记录和 1 条修订要求，修订要求三要素：改哪章、改成什么、截止时间。下课后记录表回收，每人 4 份，一份不能空。全员满分，等于评审失败。

上一期有位设计背景学员，答辩第三段主动说：「我这版最没把握的是成本章，单次对话成本我按 token 用量估了，但月度用户量假设还没人帮我核。」质询人顺势只问了一句「假设按多少量算」，当场把这条写进修订要求、定了周日截止。结果四维 4/5/4/4 过审。主动暴露风险，等于把最凶的一问提前拆了——这就是应答公式里「给依据」的延伸用法。

同一期另一位零基础学员，5 分钟里有 3 分半在念 PRD 的功能列表，念到「方案章」计时器就硬切了。质询人问「成功指标目标值多少」，他第一句回「我们觉得应该会不错」——既没复述、没答案、也没依据。目标清晰度 2 分、方案完整性 2 分，退回。问题不在他不懂产品，在他把答辩当成了朗读。

为什么非要「先复述问题」？不是礼貌，是风控：评审里大量质疑其实问的是 A，被评人听成 B 就答偏了，复述一遍让对方有机会纠正，答错方向的成本比多花两秒高得多。

应答公式的边界：它用来接「信息性质疑」，不用来接「已拍板的结论」。如果一条已经被写进决策记录，别再复述重开，直接指回记录。

常见误解是「三段式 = 把 PRD 十章压缩成 5 分钟」。不是。三段式是重排：背景讲证据、方案讲取舍、数据风险讲底气，十章是给你翻的，不是给你念的。

「你的目标用户是谁？一句话。」（答「所有人都能用」即追问「V2.0 先服务谁」）「这个功能上线后怎么判断成没成？目标值是多少？」

这段在面试里怎么答：面试官问「你怎么做需求评审」，别背流程四段，用这把尺子收口——「我先用四区拆解把 PRD 切目标 / 方案 / 数据 / 风险四块，再按四维打分，被质疑时用复述—答案—依据三步接；评审在我这里是共识会，不是打分会。」一句话里三个当日术语，面试官自然会往「那没共识怎么办」追，正好接。

核心原理讲授 B + 反面案例

上节末我说了丑话，这节把它摊开。每一期学员的 PRD，评审时被问住的地方惊人地相似，我把它拆成五条，你们边听边给自己的 V1.0 打勾。

反面案例一 · 目标章：写「提升用户效率」，没有指标、没有目标值。被问「怎么判断成没成」当场卡住。为什么这是硬伤？因为「效率」不可验收——前面说过，验收标准要能逐条打勾，「提升效率」勾不了。改法：补指标 + 数值 + 取舍，例如「采纳率 ≥40%，只完成一半时先砍 P2 功能」。

反面案例二 · 数据章：功能章引用调研结论，但访谈只有 3 个人、问卷 12 份。被一句「样本呢」问穿。边界提醒：样本底线是访谈 ≥5、问卷 ≥30，这不是玄学，是「结论能不能回溯到原声 / 原表」的最低要求；低于底线不等于结论错，等于证据链不完整，数据支撑维度最高 3 分。

反面案例三 · 评测章：只写「效果要好」，没有评测集来源、没有上线门槛。常见误解是「评测是上线之后的事」——恰恰相反，评测三件套（评测集来源与条数 / 核心指标定义 / 门槛数值）必须写进 PRD，否则工程师不知道照什么执行。

反面案例四 · 成本章：整章空着，被问「一次对话多少钱」答不上。补法：token 用量估算 × 模型单价，公式与过程写明，月度预算附用户量假设。

反面案例五 · 修订要求：写「优化」「完善」——这四个字等于什么都没写。这是最普遍也最不该犯的一条：修订要求三要素（改哪章 / 改成什么 / 截止时间）缺一不可，「下周」「尽快」不算日期。

五条里中三条以上别慌，今天就是来治这个的。现在做个改写练习：把「优化目标章」「完善评测」「下周尽快补数据」三句，改成合格修订要求。参考：「目标章补成功指标与目标值，改成『采纳率 ≥40%』，周一 12:00 前」「评测章按评测集来源 / 条数 / 门槛三件套重写，周日 24:00 前」「用户与场景章补访谈至 5 人并附 5 条原声编号，周一 12:00 前」。看出来了吗——改完的每一条都能直接当工单派下去。

（原清算段保留）十章齐全、每个 P0 异常有兜底与触发条件、单次对话成本可复算、评测集来源与门槛齐全——四维 4 / 5 / 4 / 4，过审。修订要求两条，周日 24:00 前并入 V2.0：补两条访谈原声；成本章补月度预算的用户量假设。

注意看，正例也有修订要求——过审不等于零意见，通过是共识，驳回也是共识，有条件通过同样是共识。 共识的意思是：分歧摆上了桌面，而且每一条都有了去处。

（原清算段保留）目标章无指标无数值、访谈只有 3 人、评测章不可执行、成本章空缺——四维 2、2、2、1，退回。修订要求四条，全部周一 12:00 前：目标章补指标加目标值；访谈补到 5 人并附原声引用；评测章按「评测集来源、条数、门槛」三件套重写；成本章按 token 单价补单次对话成本。

质询收尾固定动作：「最后一分钟，研发评估：这个核心功能几个人日、怎么排期、最大风险是什么？」谁来对上面这位「退回」同学的 PRD 报一次估时？对照人日基准表：对话链路 4、界面 4、评测 3、埋点 2，合计 13 人日左右。答「一个月」「一个迭代」而无任务拆解的，打回重估。风险三高发任答其一即可：幻觉率达不到评测门槛、单次对话成本超预算、用户反馈数据无回流通道。

为什么「敢主动讲风险反而通过率高」？因为评审的本质是共识会，被评人主动把风险摆上桌，等于替质询人完成了最费力的一步；剩下的时间用来定兜底，而不是用来互相试探。

「对方案不对人」的边界：它管的是措辞，不是回避尖锐问题。可以问「这条结论的样本量为什么只有 3 人」，这不叫挑刺；只许提问不许下结论，是为了让对方答得上，不是为了把问题磨钝。

常见误解是「终审退回 = 失败」。不是。退回的同学比周一写 V1.0 时多了一份研发视角的问题清单，这就是评审给的东西；我们会把它原样归档进作品集。

这段在面试里怎么答：面试官问「你见过最差的 PRD 什么样 / 你会怎么改」，别只说「写得不细」。用五条翻车案收口——「最典型的是目标无指标、样本不可回溯、评测章不可执行、成本章空缺、修订要求写『优化』；我的改法是把每条都翻译成带三要素的修订要求，让它能直接派工。我自己在评审里也用四区拆解逐块查这五条。」把反面案例讲成你的检查表，比讲成吐槽值钱得多。

多轮答辩实操与巡场

好，各组按轮值表开始。但今年多一句话：这不是一轮走过场，是多轮攻防。 我把组织方式拆成四件事，写在白板上，全程不调。

第一件 · 角色分配（轮值表）。 每轮四角色：陈述人（被评人）、质询人、记录人、补充质询（5 人组第 5 人，至少追加 1 问，不重复主质询已问类别）。4 人组轮 4 轮，每人恰任陈述人 1 次；质询人与记录人由轮值表指定，保证每人至少任质询人 1 次、记录人 1 次。轮值表开课写在组内白板，全程不调——「不调」是为了不让有人专挑好答的角色。

第二件 · 质疑清单（三类 × 追问链）。 质询人不是临场憋问题，按清单走，每类至少 1 问，答上才追下一环：

类别开场问题追问链
目标类「这个功能的目标用户和使用场景，一句话说清。」场景 → 成功指标与目标值 → 取舍：如果指标只完成一半，先砍哪个功能
方案类「核心链路怎么走？为什么这么设计而不是别的方案？」链路 → 研发评估：几个人日、怎么排期 → 最大技术风险是什么、兜底在哪

收尾 1 分钟固定做研发评估：几个人日、怎么排期、最大风险。质疑两条铁律再念一遍：对方案不对人；只提问，不下结论。

第三件 · 时间控制。 每人 10 分钟：5 分钟陈述 + 5 分钟质询，计时器投屏大字号，助教操作，到点硬切不商量。开轮话术：「第 N 轮，陈述人 ____，5 分钟，背景 1 分钟、方案 2 分钟、数据与风险 2 分钟。质询人准备三类问题。开始。」超时话术：「时间到，硬切。没讲完的留给质询——台下的问题会替你把它讲出来。质询人，第一问。」换轮过渡：「谢谢。记录人当场把分数和修订要求念一遍给陈述人确认，然后下一轮。」

第四件 · 评分表。 记录人用四维评分表（目标清晰度 / 方案完整性 / 数据支撑 / 风险识别，各 0–5 分，打分依据必填），加质询记录 ≥1 条、修订要求 ≥1 条（三要素齐全）、研发评估记录一条。当场念给被评人确认。全员满分，等于评审失败；记录表质询记录空白我不收。

  • 巡场发现挑刺苗头：「停一下。刚才那句『你这个调研肯定有偏差』是结论，不是问题。换成问题再问一遍——『你的问卷选项是怎么设计的，怎么防止引导性偏差？』这样问，他答得上，你也拿到了信息。」
  • 巡场发现只夸不质询：「这组已经两轮没人提问题了。提醒一下，三类问题每类至少 1 问，记录表质询记录空白我是不收的。我先示范一个数据类的：你的优先级排序，RICE 的分是怎么算的？」
  • 被评人被打懵：「别急着辩解，用应答公式：复述他的问题，答你知道的部分，答不了的记进修订要求——记下来不丢人。」
  • 质询冷场无人提问：「我先来一个数据类的：这条结论的数据来自哪次调研？样本多大？」
  • 估时拍脑袋：「『一个月』没法排期。拆任务：链路几个人日、界面几个人日、评测几个人日？」
  • 修订要求写「完善」：「『完善』不进清单。改成什么、几点前交？现在补。」

面试讲解与追问防御

先立个框架：这四类题，面试官判的不是「你态度好不好」，是「你有没有动作、有没有依据、会不会用术语、被追两层会不会崩」。每道题我都按五样东西拆：题目与题型、踩分点、追问链、失败答法、60 秒标准答法。标准答法里必须带当日至少一个术语——不带术语，等于白学。

题 1 ·「你的 PRD 在评审会上被当场说成伪需求，你怎么接？」（场景设计题 · PRD 被挑战怎么接）

  • 踩分点（4 条）：① 第一句复述对方质疑、不辩解；② 给可回溯的数据依据（访谈 / 问卷编号）；③ 用到 ≥2 个当日术语；④ 答不出的部分当场记进修订要求并给截止时间。
  • 追问链：层 1「如果对方拿出的反例数据正好和你相反呢？」→ 要点：不硬杠，复述反例 → 承认样本边界 → 约定补样本后复盘；层 2「那这轮评审还继不继续？」→ 要点：把该争议标为阻塞点，先过其余三区，争议项限时由决策人定；层 3「事后发现真是伪需求呢？」→ 要点：走变更记录，写清范围调整与依据，复盘回补会前材料。
  • 典型失败答法：「我觉得这个需求没问题，我们调研过的，可能他没理解。」失分原因：第一句就辩解（踩分点 ① 直接丢）、「调研过」无出处（② 丢）、把质疑答成对抗，面试官会判定「听不进反馈」。
  • 60 秒标准答法：「我先复述一下您的质疑：您担心的是这个场景并非高频刚需，对吗？（复述）我的依据是 5 次访谈里 4 次被主动提到、问卷 68% 选择了它，原始记录编号我可以现场翻给您（依据）。如果这条结论的样本边界确实不够，我不在现场硬争，会把它记进修订要求——补到 8 次访谈、附原声，周一 12:00 前给您复核（动作 + 术语）。评审是共识会不是考试，被质疑不是被否定，是把分歧摆上桌；真要调整范围，我走变更记录留痕，不口头改。答不了的部分记下来不丢人，比当场编一个数字可信。」

题 2 ·「讲一次你的 PRD 被挑战的经历，当时怎么应对、结果如何？」（行为题 · STAR · PRD 被挑战怎么接）

  • 踩分点：① STAR 四段齐全且 A（动作）占一半以上；② 出现「应答公式 / 修订要求 / 复盘」中 ≥2 个术语；③ 结果可量化（四维分数、几条修订、是否过审）；④ 有复盘与可复用经验。
  • 追问链：层 1「当时最尖锐的一问是什么？」→ 要点：报原问 + 你用复述—答案—依据怎么接；层 2「如果重来一次你会改哪一步？」→ 要点：会前材料提前发、把该问补进预判清单；层 3「这个经验后来复用过吗？」→ 要点：下一版会前材料里加了「样本量」自检项。
  • 典型失败答法：「有一次评审大家提了些意见，我都虚心接受了，后来改了改就过了。」失分原因：无具体动作、无数据、无术语、无复盘，四段全空，典型的「态度替代动作」。
  • 60 秒标准答法：「情境是 W4 的 PRD 评审大会，任务是 5 分钟答辩加 5 分钟质询（S/T）。动作上，我被问『成功指标目标值是多少』时没有辩解，先复述问题，再给依据——采纳率 ≥40%，出处是问卷第 6 题；答不出的成本章用户量假设，我当场记进修订要求，定了周日 24:00 截止（A）。结果是四维 4/5/4/4 过审，带两条修订要求（R）。复盘我提炼了一条可复用的：把最常被问住的一类质疑，提前补进下一版会前材料。所以后来我再上评审，被问懵的次数明显少了。」

题 3 ·「评审会上研发和业务吵起来，两派没共识，会开不下去了，你作为 PM 怎么办？」（场景设计题 · 评审没共识怎么办）

  • 踩分点：① 不硬拍、不站队，先把分歧结构化；② 用「决策记录」写清可选方案 + 依据 + 责任人 + 时间；③ 把卡住的点标为「阻塞点」并给升级路径与限时；④ 明确临时口径保证其余环节继续。
  • 追问链：层 1「决策人也不在，限时不下来呢？」→ 要点：定临时口径 + 书面升级路径 + 明确截止时间，写进决策记录，会后补确认；层 2「对方说你这是在和稀泥，怎么回？」→ 要点：给判据——和稀泥是无判据地拖，我是有判据、有责任人、有截止地推进；层 3「如果时限到了还没定，谁背锅？」→ 要点：按决策记录里的责任人与升级路径走，对事不对人，复盘时回看判据是否要改。
  • 典型失败答法：「我会先让大家冷静一下，然后投票，少数服从多数。」失分原因：把共识会答成表决会（术语混淆），且投票会留下「输的一方不认」的隐患，也没有决策记录与阻塞点意识。
  • 60 秒标准答法：「我先不站队，也不投票——评审是共识会，不是表决会。第一步把分歧结构化：两派各自的主张、依据、担心写进决策记录，四要素齐全：结论、依据、责任人、时间。第二步判断它是不是阻塞点：如果卡住开发启动，就标为阻塞点，拉决策人限时定，同时给一个临时口径让其余三区先过、会不空转。第三步，如果决策人不在，我定临时口径加书面升级路径，写明『周几几点前必须定』，会后补确认。对方要说我和稀泥，我的判据是：和稀泥是没有判据地拖，我是每条分歧都有去处、有责任人、有截止时间。」

题 4 ·「终审给了『有条件通过』，但你的导师不同意这个裁定，你怎么办？」（行为题 · 评审没共识怎么办）

  • 踩分点：① 先复述裁定与异议各自的依据，不情绪化；② 区分「修订要求」与「变更」——补样本是修订，改范围 / 排期才走变更；③ 异议走书面复核而非当堂辩论；④ 有截止时间与复盘。
  • 追问链：层 1「导师坚持要你当场改口呢？」→ 要点：裁定留痕、异议写进决策记录备注，按复核时限走；层 2「复核结果维持原裁定呢？」→ 要点：执行裁定，把导师意见作为修订要求的补充项纳入；层 3「这事你怎么记进作品集？」→ 要点：意见闭环表记「被挑战哪条、依据、怎么闭环」。
  • 典型失败答法：「那肯定听导师的，他是前辈。」失分原因：无判据、无流程、把共识会答成论资排辈，暴露「不会用决策记录 / 变更」的术语与流程短板。
  • 60 秒标准答法：「我先复述两边依据：裁定的依据是有条件通过只卡样本量缺口，导师的异议可能在评测门槛（复述）。然后我分类处理：补到 5 次访谈 + 30 份问卷是修订要求，不动范围；如果导师要改上线范围或排期，那是变更，得走变更记录留痕。异议我不当堂辩论，把依据写进决策记录备注，按复核时限（周一 12:00 前）提交，由裁定人复核。评审里通过是共识、驳回也是共识，有条件通过同样是共识——分歧摆上桌、每条有去处就行。最后我会把『被挑战哪一条、怎么闭环的』记进作品集的意见闭环表，这正是面试高频题的现成答案。」

题 5 ·「研发说你这个功能『做不了 / 要一个月』，你怎么回应？」（技术理解题 · 怎么回应研发质疑）

  • 踩分点：① 不直接接受「一个月」，请对方拆任务到人日；② 对照人日基准表复算（13–18 人日口径）；③ 把不可换算口径换成可排期口径 + 最大风险；④ 用「先拆任务再估时」这一动作收口。
  • 追问链：层 1「研发就是不拆，坚持一个月呢？」→ 要点：给基准表请他指认哪块超了，把争议落到具体任务包；层 2「拆完发现确实要 20 人日，超你预期呢？」→ 要点：谈取舍——砍 P2 保 P0，或走变更调排期，写进决策记录；层 3「这算不算变更？」→ 要点：改排期是变更，改文档内容是修订要求，别混。
  • 典型失败答法：「那我们就按一个月排吧，研发说的应该准。」失分原因：接受魔法数字、无拆解、无基准、无取舍，暴露「不懂估时口径」，正是本课难点一的典型表现。
  • 60 秒标准答法：「我不接『一个月』这种没法排期的口径，先复述：您指的是核心功能的总工期对吗？能不能按任务包拆一下（复述 + 动作）。我们有人日基准表：对话链路 3–5、知识库 2–3、界面 3–5、评测 3、埋点 2，合计 13–18 人日，约 1–2 名工程师 × 2 周。请您指认是哪一块超了基准、卡在幻觉率还是回流通道（依据 + 最大风险）。拆完真超预期，我谈取舍：砍 P2 保 P0；要动上线时间就走变更记录。估时先拆任务再给人日——拍脑袋的数字，研发会用一个延期还回来。」

题 6 ·「研发质疑你的评测门槛定得太高，上线根本达不到，怎么谈？」（项目深挖题 · 怎么回应研发质疑）

  • 踩分点：① 复述质疑并确认门槛数值出处；② 区分「验收标准」（放行前门槛）与「目标值」（上线后效果），指出对方混的是哪一个；③ 给评测三件套（评测集来源 / 条数 / 门槛数值）与 badcase 修复一轮的依据；④ 谈不拢写进决策记录、限时定。
  • 追问链：层 1「对方说门槛就该由研发定，PM 别插手？」→ 要点：门槛是产品对用户的承诺，依据来自评测集与 badcase，不是谁拍；层 2「那上线前达不到怎么办？」→ 要点：明确「无 P0 badcase」为硬门槛，达不到不放行，按修订要求补修复轮次；层 3「这算阻塞点吗？」→ 要点：卡住放行就是阻塞点，拉决策人限时。
  • 典型失败答法：「那门槛就调低一点吧，灵活些。」失分原因：无依据退让、混淆验收标准与目标值、不懂评测三件套，面试官会判定「评测章不可执行」——正是反面案例三。
  • 60 秒标准答法：「先复述：您担心的是准确率 ≥90% 且无 P0 badcase 这个上线门槛达不到，对吗？这里要分清两个词：验收标准是放行前逐条打勾的门槛，目标值是上线后的效果指标，您说的『达不到』指的是哪一个？（术语辨析）我的门槛有出处：复用 W2 评测集、标注条数、跑一轮 badcase 修复，三件套写进 PRD，工程师照着就能执行。达不到就不放行，补修复轮次写进修订要求、带截止时间。真谈不拢，把双方依据写进决策记录，标成阻塞点，拉决策人限时定——不现场拍脑袋调低。」

题 7 ·「评审完拿到一堆修订要求，会后你怎么改？先改哪条？」（项目深挖题 · 会后怎么改）

  • 踩分点：① 按「阻塞点 / 验收硬标准」排序而非按条目顺序；② 每条修订要求带三要素（改哪章 / 改成什么 / 截止时间）；③ 区分修订与变更，范围 / 排期变动单独留痕；④ 改完对照 V2.0 五条硬标准逐条自查。
  • 追问链：层 1「两条都标了周一截止，先做哪条？」→ 要点：先看哪条卡住开发启动（阻塞点），再看哪条属于五条硬标准；层 2「改到一半发现要动范围呢？」→ 要点：走变更记录，不塞进修订清单；层 3「怎么证明改完了？」→ 要点：五条硬标准自查表 + 助教核验，双口径签字。
  • 典型失败答法：「我从第一条开始一条条改，改完再检查。」失分原因：无优先级判据、无三要素意识、无验收闭环，答成「勤恳但没方法」。
  • 60 秒标准答法：「我不按条目顺序改，先排序：第一优先是阻塞点——不解决就卡住开发启动的；第二是 V2.0 五条验收硬标准里被点名的那条（数据支撑 / 十章完整 / 评测可执行 / P0 兜底 / 成本可复算）。每条修订要求我核三要素：改哪章、改成什么、截止时间，缺日期的当场补，『下周』『尽快』不算日期。改到一半发现要动上线范围或排期，那不是修订，走变更记录留痕。改完我不自己说了算，对照五条硬标准逐条打勾，再交助教按核验方式复核——PRD V2.0 = V1.0 + 每条带截止时间的修订要求，闭环了才算过审。」

题 8 ·「评审记录表里被打了低分，你怎么处理这些意见？」（行为题 · 会后怎么改）

  • 踩分点：① 先复述低分对应的维度与打分依据，不辩解；② 把每条意见归类到四区（目标 / 方案 / 数据 / 风险）；③ 转化为带三要素的修订要求；④ 复盘：高频质疑回补下一版会前材料。
  • 追问链：层 1「有条低分你觉得是误判呢？」→ 要点：把依据写进决策记录备注走复核，不当场争；层 2「打分的人没写依据呢？」→ 要点：请对方补一句依据，否则这条不进修订清单（打分依据必填是本课硬规则）；层 3「下次怎么少挨低分？」→ 要点：复盘最高频质疑，前置进会前材料自检项。
  • 典型失败答法：「低分说明我做得不好，我会全部重做一遍。」失分原因：全盘接受无辨析、无归类、无闭环，还把「修订要求」做成「重做」，暴露不懂三要素与四区拆解。
  • 60 秒标准答法：「我先复述低分落在哪个维度、打分依据是什么——不辩解，也别急着全盘重做（复述）。第二步用四区拆解归类：目标区的归目标章、数据区的归数据章、风险区的归兜底章，一条意见落一个区。第三步把每条翻成修订要求，三要素齐全：改哪章、改成什么、截止时间；打分没写依据的，请对方补一句，否则不进清单，这是我们记录表的硬规则。觉得是误判的，把依据写进决策记录备注走复核，不当堂争。最后做复盘：这轮最常被问住的是哪类质疑，补进下一版会前材料的自检项。低分不是分数，是一份带日期的工单。」

学习目标

结论前置：评审不是「看文档写得漂不漂亮」，而是用同一把尺子判定这份 PRD 能不能开工。

  1. 说出评审角色分工与 5 步流程，写出评审 Checklist。
  2. 用 100 分评分表打分，逐项写出扣分理由。
  3. 把 10 条驳回意见转成修改动作，给出评审后版本管理规则。

结论：里程碑 ③ 的交付物是「一份冻结的 PRD + 一套可回算的验收证据」，不是一份 PPT。
