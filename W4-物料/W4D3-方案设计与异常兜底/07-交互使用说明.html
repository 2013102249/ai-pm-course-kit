课堂交互使用说明 · 翻车案例分析环节组织方案（W4 周三专用）

AI 产品经理就业训练营 · 第四周第三天 · 300 分钟（6 课时 × 50 分钟）· 课堂交互使用说明
本课无专用交互网页。原因：异常兜底是学员第一次把设计落进自己项目的 PRD 章节，本课的「动手」发生在导学案表格与小组讨论里，不在屏幕上。本文件即第 4 节（150–200 min）实操演练与巡场中「翻车案例分组讨论」段的组织方案（原版环节五组织方案，时间已对齐 300 分钟版 6 节结构），讲师开课前通读。
300 分钟版新增《6 节使用时机表》与《设备要求表》，见文末第七、八节；全课交互按 6 节拆分，工具与产出逐节对齐。
无需课前设备检查；仅需投屏展示案例卡（见附录）与计时器；设备不足学员走「纸笔 + 拍照」替代路径。

一、环节定位与时间结构（共 13 分钟，落在第 4 节 177–190 min）

300 分钟口径说明：本段是第 4 节（150–200 min）实操演练与巡场的一部分，前面 150–177 min 已完成「画状态机草图 / 填兜底设计表五行 / 决策树四连问自查」三步；本段做第四步「案例卡讨论与汇报」，其后的 190–200 min 为讲师讲评，与本段汇报讲评自然衔接，讲师可据现场进度合并。

时间（300 分钟口径）动作说明
177–178 min规则宣布 + 分组按座位就近 3–4 人一组；每组自动分工（见下表）
178–183 min分组讨论（5 分钟，计时）每组一张案例卡；讲师巡场，只提问不打断
183–189 min逐组汇报（每组 2 分钟 ×3）计时员卡时间，超时由讲师用指定话术切走
189–190 min讲师总点评 + 收束按「四查」框架点评，落金句

二、分组规则

项目规则
组规模3–4 人；不足 3 人的组合并到相邻组
角色分工① 记录员：在导学案兜底设计表背面记讨论要点；② 汇报员：负责 2 分钟汇报；③ 计时员：提醒「还剩 1 分钟」；4 人组增设「抬杠员」，专职质疑方案漏洞
组间差异三组发不同案例卡（卡 A / B / C），避免汇报重复；巡场时留意各组进度，弱组提示「先把翻车点写下来」
底线要求汇报必须含至少一个数字（触发条件），说不出数字的方案视为未完成

三、汇报格式（四句话，写在投屏上全程可见）

  1. 翻车点：用户看到了什么现象（一句话，讲现象不讲技术）
  2. 根因：产品设计的哪一块缺失（指向状态机出口 / 触发条件 / 文案 / 升级路径之一）
  3. 方案：用四件套的哪几件，产品动作是什么
  4. 数字：关键触发条件的量化值是多少

汇报话术模板（投屏展示）：「我们组的案例是____，用户看到的现象是____，根因是____，我们用____（件套）解决，触发条件是____（含数字）。」

四、讲师点评框架（每组汇报后约 30 秒，按「四查」执行）

查查什么点评话术示例
一查：触发条件是否量化有没有数字；数字是否合理（如「超时 10 秒」对周报生成是否过短）「方案对，但『用户不满时』不是触发条件——多少轮算不满？填个数字。」
二查：文案是否说人话有无错误码式表述；是否符合三原则（说人话 / 给出路 / 兜住情绪）「这句文案在『给出路』上缺一步——用户听完知道下一步做什么吗？」
三查：升级路径是否闭环兜底动作之后有没有下一步；badcase 有没有回流「降级之后呢？补答谁做？这个 badcase 流向哪里？」
四查：是否装得进 PRD方案能否直接写成 PRD 兜底章节的一行「很好——这四句话直接抄进你们 PRD 的『容错兜底』章，周五评审就能用。」

总点评收束（189–190 min，可顺延至 190–200 min 讲评段）：指出三组共性——没有一个事故是「模型不够强」造成的，全是「没设计会发生什么」造成的；随后落本课金句收束。

五、常见问题处理

问题处理
某组讨论冷场计时员提醒后仍无进展，讲师入场抛锚点：「用户此刻屏幕上是什么？他下一个动作会是什么？」
汇报超时「方案已经很好了，触发条件的数字留着填进导学案，下一组接上。」
方案明显不可行（如「让模型自己判断要不要转人工」）不当场否定，转为提问：「这个判断的置信度谁来保证？——留给大家课后查一查置信度阈值怎么做。」
组数不足 3 组缺的案例卡改为讲师引导全班口头快答，只走「翻车点 + 数字」两步
线上直播场景用会议软件分组讨论室，每组指定一人在共享文档里记录；汇报回到主会场进行
学员只有手机 / 平板，无法用画图工具走「纸笔手画 + 拍照归档」：状态机、兜底设计表、决策树自查一律用导学案纸质版填写拍照，讨论与口述汇报照常参与，见第八节设备要求表

六、附录：三张案例卡内容（打印或投屏用；均为教学化虚构案例）

案例卡场景描述
卡 A · 白屏的周报助手某内容生成工具：用户口述两千字工作要点，AI 生成的周报命中敏感词被系统拦截，页面直接白屏，草稿未保存，用户重新输入三遍后弃用产品。
卡 B · 坚持己见的模拟面试官某面试模拟助手：用户问「针对产品岗应该准备什么」，助手开始讲运营岗的准备清单；用户指出答错，助手回复「抱歉给您带来困扰」，然后继续讲运营岗；连续三轮如此。
卡 C · 失忆的学习助手某答疑助手：用户连续六轮追问同一道数学题的解法细节，第七轮问「那这道题的第二问呢」，助手回复「您好，请问有什么可以帮您？」，全部上下文丢失，用户从头复述问题。

三张卡分别对应第 3 节讲过的三种典型缺失：卡 A 缺错态 / 空态 / 可恢复（拦截后一片空白）、卡 B 缺澄清 / 拒答的低置信出口、卡 C 缺降级与上下文接续。第 3 节「9:12–9:23 只做正常态、异常态一片空白」的反面案例可作为卡 A 的加长版，讲师视时间选用。

八、《设备要求表》（新增，手机 / 平板 / 电脑三档）

本期学员画像中设备不足 3/6，故全课所有产出均须有非电脑路径。下表逐档写明「可完成任务 / 受限任务 / 替代动作」，讲师按此巡场，不因设备判不合格。

档位可完成任务受限任务替代动作
电脑全部：用画图工具画状态机 / 决策树、填电子兜底设计表、打开术语卡与配图源文件、编辑宽表格、录音与文件归档无—
平板看投屏、用手写笔在白板 App 绘图、填电子或纸质导学案、参与讨论、口述汇报、手机式录音复杂画图工具排版不便；宽表格（兜底设计表、积木表）编辑不便；多窗口切换慢状态机 / 决策树用系统备忘录或白板 App 手绘后拍照归档；宽表格改用导学案纸质版 + 笔填写再拍照；术语卡看投屏即可
手机看投屏、读术语卡、参与分组讨论、口述四句话汇报、口述 60 秒面试答法并录音、给纸质产出拍照归档、纸质勾选术语自测无法用画图工具画状态机 / 决策树；不便编辑宽表格；不便多窗口对照；无法打开本地 SVG 源文件状态机、兜底设计表、决策树自查、积木表全部用导学案纸质版 + 笔手画手填后拍照上传；术语自测用纸质勾选；案例讨论照常口述；面试答法用手机录音自评；配图统一看教室投屏

通用替代原则（三档都适用）：

  1. 任何「画图 / 填表」任务都允许「纸笔手画 + 拍照」，拍照件与电子件同等计入第 6 节作品集归档与当堂验收。
  2. 投屏素材由讲师统一展示，学员端不需打开任何本地素材文件；术语卡、时间轴图、追问链图均以投屏为准。
  3. 两两模拟的「面试官 / 答题者 / 记分员」三角色，手机学员可担任任意角色；记分用纸质评分表，录音用手机自带录音机。
  4. 线上直播场景叠加使用：分组讨论室 + 共享文档记录（无电脑者口述、由记录员代填），汇报回主会场进行。
  5. 设备差异不进入评分：《6 节使用时机表》的「预期产出」只认内容是否达标（触发条件是否量化、状态机是否有超时值与出口、答法是否含术语），不认载体是电子还是纸质拍照。

本课不编造故障率、就业率、薪资数字；涉及业务数据写「待教务补充」。全部案例为教学化虚构，不出现真实学员姓名。
