## 第 0 层 · 术语辨析题（12 题，共 100 分）

> 题型覆盖选择 / 连线 / 改错三种；专治第 1 节点名的「术语混淆」难点。建议第 1 节末 10 分钟当堂测。

### 一、选择题（每题 5 分，共 20 分）

**1.** 「状态机」回答的核心问题是：
A. 系统有哪些功能模块
B. 用户从 A 到 B 走哪条路径
C. 此刻停在哪、卡住了往哪退
D. 产品定价多少

**2.** 下列哪一项是「兜底」的视角，而不是「容错」的视角：
A. 保证服务不宕机
B. 出错时用户看到什么、下一步能做什么
C. 增加接口重试次数
D. 提升模型准确率

**3.** 「空态」与「白屏」的根本区别是：
A. 底色深浅不同
B. 空态是设计过的（有引导、有下一步），白屏是没设计（什么都没有）
C. 空态只出现在首次使用，白屏只出现在出错时
D. 白屏是加载太慢，空态是加载太快

**4.** 四件套按升级成本从低到高，正确顺序是：
A. 转人工 → 降级 → 澄清 → 拒答
B. 澄清 → 降级 / 拒答 → 转人工
C. 降级 → 转人工 → 澄清 → 拒答
D. 四件平级并行，没有顺序

### 二、连线题（每题 10 分，共 20 分；每条连线 2.5 分）

**5.** 把状态机状态与对应的界面态连线：

| 左栏（状态） | 右栏（界面态） |
|---|---|
| ① 空闲 | A. 加载态 |
| ② 理解中 / 生成中 | B. 空态 |
| ③ 异常 / 恢复 | C. 正常内容态 |
| ④ 完成 | D. 错态 |

**6.** 把术语与它最容易混的邻居连线：

| 左栏（术语） | 右栏（易混邻居） |
|---|---|
| ① 降级 | A. 加载时间 |
| ② 超时 | B. 报错 / 无限重试 |
| ③ 可恢复 | C. 报错日志 |
| ④ 提示文案 | D. 重试 |

### 三、改错题（每题 10 分，共 60 分；指出错处 5 分 + 改正 5 分）

**7.** 「降级就是弹一句『系统异常，请稍后再试』。」

**8.** 「加载态就是画个转圈动画，等的时候有东西看就行。」

**9.** 「异常分支和异常状态是一回事，都是指系统出错了。」

**8.** 兜底方案设计题（60 分）——本课核心考点

你负责一款「周报助手」：用户口述本周工作要点，AI 生成结构化周报（支持导出）。上线前你要完成异常兜底设计。已知该产品的三个风险点：生成偶发超时；生成内容可能命中公司敏感词库被拦截；部分用户口述信息太少导致周报空泛。

请设计完整兜底方案，要求：

② 针对上述三个风险点及你认为必要的其他场景，设计至少 4 条兜底策略，每条覆盖四要素：量化触发条件 / 产品动作 / 兜底文案 / 升级路径；
③ 说明你的转人工触发条件及理由。

**9.** 决策树应用题（40 分）

**10.（新增）** 三态落点设计题（40 分）

仍以「周报助手」为例：请画出「状态机状态 → 界面态 → 提示文案」三列对照表，覆盖空闲、理解中 / 生成中、被拦截后的异常、恢复四个环节；并为「空闲」「生成超时」「敏感词拦截」「恢复」各写一条符合三原则的提示文案。

**11.（新增）** 反面案例补写题（40 分）

下面是「AI 会议纪要助手」只做正常态、异常态一片空白的教学化时间线：9:12 上传 40 分钟录音后停在「正在生成」转圈、无进度；9:18 刷新后纯白白屏；9:19 重弹「Error: timeout」；9:20 历史列表为空、草稿与原文都没了。

请逐节点写出：① 缺的是哪个术语 / 界面态；② 本该用四件套里的哪一件、提示文案怎么写；③ 如果只允许补一件事，你先补哪件、为什么（用升级成本逻辑说明）。

**10.** 面试真题（30 分）
面试官：「你们做的是 AI 产品，模型输出不可控，你们在产品设计上怎么保证体验不下线？」

**11.** 案例分析（30 分）
某公司上线一款 AI 面试模拟助手。上线后用户流失高于预期（具体数据待教务补充），用户调研还原了两类典型经历：其一，用户答完题，助手评价「回答不错」，但用户追问「哪里不错」，助手重复同一段话；其二，用户连续三轮表达不满，界面始终没有出现人工辅导入口，第四轮用户卸载了应用。
请分析：两个经历分别暴露了什么兜底缺失？给出对应的产品改进动作（含量化触发条件）。

**12.（新增）** PRD 改错题（30 分）
以下摘自某「AI 会议纪要助手」PRD V1.0 的功能描述：「用户上传录音，系统生成结构化纪要，用户可导出为文档。」全文除这一句外，无任何异常相关描述。
请指出该描述至少 3 处兜底缺失，并把其中一处补写成「容错兜底」章的一行（四要素齐全、触发条件量化）。

**13.（新增）** 协作对齐题（30 分）
你给「转人工」定的触发条件含「用户情绪负面」，研发反馈：「情绪检测不好埋点，超时值也不好定，先写『必要时转人工』上线再说。」
请写一段和研发的对齐方案，须包含：① 可观测的等价量化信号；② 阈值如何可配置、谁来定；③ 怎么验收兜底生效；④ 上线后的回流闭环。

## 第 4 层 · 面试实战题（8 题，每题含踩分点 / 追问链 / 评分表）

> 配合第 5 节「面试讲解与追问防御」，题源与 02-讲课稿第 5 节 8 题一致。每题给：题目 + 题型 / 踩分点 / 追问链（含应答要点）/ 失败答法 + 失分原因 / 参考答案（60 秒答法要点）/ 评分表。两两模拟时按每题评分表打分并记入《面试模拟记录表》。

### 题 30 · 翻车设计四件套是哪四件？为什么是这个顺序？〔技术理解〕

- **踩分点**：① 报出降级 / 澄清 / 拒答 / 转人工并各给一句定义；② 说出每件四要素；③ 点破「顺序即升级成本递增」；④ 至少给 1 个量化触发条件。
- **追问链**：
  - L1「为什么不把转人工放第一位？」→ 人工最可靠但最贵，人力成本随调用量上升，顺序本质是升级成本最小化。
  - L2「四件套之间会打架吗？同时超时又低置信」→ 按决策树四连问定优先级，先判「能理解吗」走澄清，再判「答得出吗」走降级；每个叶子触发条件各写各的量化值。
  - L3「上线后怎么知道够不够用？」→ badcase 回流 + 转人工工单归因，看未解决集中在哪层，反补触发条件或词表。
- **失败答法 + 失分原因**：「就是四个功能，出错挑一个用。」——只背名字、无四要素、无顺序理由、无数字，还把四件套说成平级功能；丢②③。
- **参考答案（60 秒要点）**：四件套 = 降级（退回次优方案）/ 澄清（没听懂问一次）/ 拒答（超边界明确说不能）/ 转人工（兜不住人上场）；每件按四要素写进 PRD，触发条件量化（超时 >10 秒、连续 2 轮未解决）；顺序按升级成本递增，能用便宜的绝不启动贵的；本质是升级成本最小化。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 只背四个名字，无四要素、无顺序理由 | 1–2 |
| 合格 | 四件齐全 + 每件四要素 + ≥1 个量化触发条件 | 3 |
| 良好 | 加说「顺序即成本递增」并扛住 1 层追问 | 4 |
| 优秀 | 再补「状态机 / 提示文案 / 和研发对齐」任一深度点，60 秒完整含术语 | 5 |

### 题 31 · 用户让 AI 生成内容，命中合规被拦，页面一片空白，你怎么改？〔场景设计〕

- **踩分点**：① 定性「异常分支没画」而非技术问题；② 降级兜住：保留草稿 + 标疑似位置 + 提示文案；③ 落到三态（空 / 错 / 加载态）；④ 补升级路径（补生成推送、badcase 回流）与可恢复。
- **追问链**：
  - L1「只加一句『内容含敏感词』够不够？」→ 不够，只说原因没给出路；按三原则还要认账、给预期、给下一步，且保留草稿做到可恢复。
  - L2「草稿保留会不会有合规风险？」→ 用户侧保留、屏蔽命中片段再展示，服务端按合规策略处理，给出路但不绕过审核。
  - L3「怎么验收？」→ 把「不白屏、草稿可恢复、文案无错误码」写成可勾选界面验收项，进容错兜底章。
- **失败答法 + 失分原因**：「让研发做个报错弹窗，告诉用户被拦了就行。」——把错态做成错误码提示，没提三态、没保草稿、没升级路径，用户资产仍丢；丢②③。
- **参考答案（60 秒要点）**：先定性异常分支整条没画；再分三层——降级（拦截不白屏、提示文案认账给预期给出路、保留草稿做到可恢复）、三态补齐（加载态给进度、错态说人话、空态给引导）、升级路径（后台补生成推送 + badcase 回流）；落一句「拦截不是错，拦截之后什么都不做才是事故」。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 只答「加个报错提示」，无三态、无草稿保留 | 1–2 |
| 合格 | 说出降级 + 保留草稿 + 定性为异常分支缺失 | 3 |
| 良好 | 三态齐全、文案过三原则、给出升级路径 | 4 |
| 优秀 | 补合规边界（屏蔽片段 / 不绕审核）或可验收界面项 | 5 |

### 题 32 · 异常态你一般怎么写进 PRD？写在哪一章、写到什么颗粒度？〔项目深挖〕

- **踩分点**：① 写进「容错兜底」章而非散落备注；② 按状态机逐状态列四要素表；③ 触发条件量化到能当测试用例；④ 三态写成可勾选界面项 + 和研发对齐方式。
- **追问链**：
  - L1「写那么细 PRD 会不会太长？」→ 正常路径可简，异常路径必须细；用表格不增篇幅、反减少来回沟通。
  - L2「谁来验收？」→ 产品给阈值与出口、测试按每行触发条件写用例、研发保证可观测，三方盯同一张表。
  - L3「需求变了怎么维护？」→ 和 Prompt 一样纳入版本管理，改动走评审 + 回归，badcase 回流驱动迭代。
- **失败答法 + 失分原因**：「PRD 里有专门一章讲异常处理，强调要重视稳定性。」——只有章节名和态度，无表、无数字、无界面项，研发无法写判断、测试无法写用例；丢②③。
- **参考答案（60 秒要点）**：写进「容错兜底」章；按状态机逐状态（空闲 / 理解中 / 生成中 / 完成 / 异常 / 恢复）列表，每行四列——量化触发条件、产品动作、提示文案、升级路径；触发条件必须是数，不写「必要时」；把空 / 错 / 加载态写成界面验收项；这张表就是产品、研发、测试的同一份契约，改动走版本、评审、回归。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 只说「有一章讲异常 / 要重视」，无表无数字 | 1–2 |
| 合格 | 说出章节 + 逐状态四要素表 | 3 |
| 良好 | 触发条件量化 + 三态写成可验收界面项 | 4 |
| 优秀 | 补三方对齐契约 / 版本评审回归 / badcase 回流 | 5 |

### 题 33 · 状态机怎么画？以一个对话产品为例说说你会标哪些东西。〔技术理解〕

- **踩分点**：① 主干五状态 + 异常分流 + 恢复；② 每状态标三样（超时值 / 用户感知 / 异常出口）；③ 三条画图纪律；④ 「完成 → 理解中」回路 + 三态落点。
- **追问链**：
  - L1「超时值拍脑袋吗？」→ 按用户容忍度与真实分布定，先给教学基准值再按自己数据调；关键是阈值一到必须有出口。
  - L2「异常是终点吗？」→ 不是，是分流站，四条出口落四件套；终点式异常即死胡同，不可恢复。
  - L3「所有功能都要画吗？」→ 不，有等待、可被打断、结果不确定的对话 / 生成类才必须；纯表单提交画流程图即可。
- **失败答法 + 失分原因**：「画五个框用箭头连起来。」——只有骨架，无超时值、无出口、无回路、无纪律，把状态机画成直线流程图；丢②③。
- **参考答案（60 秒要点）**：主干空闲 → 理解中 → 生成中 → 完成 / 异常 → 恢复；每状态标超时值（理解中 3 秒、生成中 10 秒）、用户感知、异常出口；三条纪律（标超时值 / 异常有出口 / 恢复指回具体状态），「没有超时值的状态机是摆设」；画「完成 → 理解中」回路（对话是环）；异常是分流站、不是终点；界面上空闲对空态、等待对加载态、异常对错态。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 只报五个状态名，无标注无纪律 | 1–2 |
| 合格 | 五状态 + 每状态三样标注 | 3 |
| 良好 | 三条纪律 + 回路 + 异常分流站 | 4 |
| 优秀 | 补三态落点或「不是所有功能都需状态机」的边界判断 | 5 |

### 题 34 · 空态、错态、加载态怎么区分？各给一个设计要点。〔场景设计〕

- **踩分点**：① 三者定义不混（没有 / 出错 / 等待）；② 各对应到状态机具体状态；③ 各给一个可落地要点（建议问题 / 说人话给出路可恢复 / 进度预期 + 超时出口）；④ 点破白屏、错误码、无限转圈是三者对应反面。
- **追问链**：
  - L1「空态和白屏看着都没内容，差在哪？」→ 空态设计过（有引导有下一步），白屏没设计（用户不知发生了什么）。
  - L2「加载态转个圈就行？」→ 转圈只是表现，核心给进度预期且必须配超时值与出口，不能无限转。
  - L3「错态最关键一件事？」→ 可恢复：说清发生了什么 + 给一个能点的动作 + 不丢草稿 / 上下文。
- **失败答法 + 失分原因**：「空态就是没数据，错态就是报错，加载态就是转圈，差不多。」——定义糊、无对应状态、无要点，漏可恢复与超时出口；丢②③。
- **参考答案（60 秒要点）**：空态 = 没有内容，对应空闲 / 无结果，要点是设计过（建议问题引导第一步），杜绝白屏；错态 = 出错，对应异常 / 恢复，要点说人话 + 说清发生了什么 + 给恢复动作（可恢复、不丢草稿），杜绝错误码；加载态 = 等待，对应理解中 / 生成中，要点给进度预期并配超时值，杜绝无限转圈。三者分别对应状态机不同状态，也是四件套在界面上的三个落点。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 三者定义混淆或只说「差不多」 | 1–2 |
| 合格 | 三定义分清 + 各对应状态机状态 | 3 |
| 良好 | 各给 1 个可落地要点 + 点出对应反面 | 4 |
| 优秀 | 补可恢复 / 超时出口 / 三态与四件套落点关系 | 5 |

### 题 35 · 兜底方案你怎么和研发对齐？触发条件、超时值谁定、怎么验收？〔项目深挖 / 协作〕

- **踩分点**：① 职责分清（产品定阈值与出口 / 研发定可观测与实现 / 测试写用例）；② 用兜底设计表当唯一对齐物，逐行量化；③ 阈值可观测、可配置、可回归；④ 变更机制（版本 / 评审 / 回归）+ badcase 回流闭环。
- **追问链**：
  - L1「研发说阈值做不到 / 不好埋点」→ 不退回到形容词，一起找可观测等价信号（如用「连续 N 次失败」替代难测的「情绪」），阈值做成可配置，先上线再按数据调。
  - L2「怎么证明兜底真生效？」→ 测试按每行触发条件造异常用例，验收界面项；线上看 badcase 与转人工工单归因。
  - L3「阈值定错了谁背锅？」→ 不追责个人，走回流机制，改动走评审和回归，是协作问题不是甩锅问题。
- **失败答法 + 失分原因**：「需求写清楚丢给研发就行，触发条件他们定，我不管实现。」——放弃产品对阈值与出口的定义权，无验收无回流，研发拿不到可测标准；丢①③。
- **参考答案（60 秒要点）**：用一张兜底设计表当唯一契约；产品定量化触发条件与出口（超时 10 秒、连续 2 轮）、研发定可观测与可配置实现、测试按每行写异常用例；「形容词不是需求，触发条件必须是数」；验收造超时 / 拦截 / 连续否定用例，逐条对空 / 错 / 加载态界面项；上线靠 badcase 与工单归因调阈值，改动走版本、评审、回归。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 「丢给研发 / 我不管实现」，无职责无验收 | 1–2 |
| 合格 | 职责分清 + 用一张表对齐 + 触发条件量化 | 3 |
| 良好 | 阈值可观测可配置 + 测试按用例验收 | 4 |
| 优秀 | 补可观测等价信号的协商思路 / 回流闭环 / 不甩锅的协作观 | 5 |

### 题 36 · 讲一次你发现方案只做了正常路径、异常一片空白，你是怎么补的？〔行为题〕

- **踩分点**：① STAR 结构、场景具体；② 说清「怎么发现」（走查 / 工单 / 故意刁难）；③ 动作落到状态机 + 四件套 + 三态 + 量化条件；④ 有结果与沉淀（进 PRD 章、成模板、可复用）。
- **追问链**：
  - L1「怎么发现的？」→ 不等投诉，拿「故意刁难」清单逐状态走查，或翻工单 / badcase 看正常路径之外的空白。
  - L2「先补哪块、为什么？」→ 先补加载态超时值与出口、再补拦截降级的草稿保留，成本最低、覆盖最早，符合成本递增。
  - L3「怎么保证不复发？」→ 沉淀成 PRD 兜底章模板 + 评审检查项，之后每个功能强制走决策树四连问。
- **失败答法 + 失分原因**：「我们挺重视体验，出问题就赶紧修，后来反馈好多了。」——无情境、无具体动作、无量化、无沉淀，全是态度词；丢①③。
- **参考答案（60 秒要点）**：情境 V1.0 只写正常路径；任务补齐容错兜底章；发现靠逐状态走查模拟超时 / 拦截 / 连续否定，结果生成中卡住、拦截白屏、历史空白；动作三步——补超时值与出口、四件套四要素表且触发条件量化、三态写成界面验收项并保留草稿做到可恢复；结果过评审且沉淀为模板与评审检查项，不再等投诉才补。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 全是「重视 / 赶紧修」等态度词，无情境无动作 | 1–2 |
| 合格 | STAR 齐全 + 说出怎么发现 | 3 |
| 良好 | 动作落到状态机 / 四件套 / 量化条件 | 4 |
| 优秀 | 有结果沉淀（模板 / 评审检查项）+ 三态与可恢复 | 5 |

### 题 37 · 转人工的触发条件怎么定？定松了、定紧了分别会怎样？〔场景设计〕

- **踩分点**：① 量化条件组合（连续 N 轮 / 情绪词命中 / 主动要求 / 超时次数）；② 两种失衡后果（成本爆炸 vs 用户流失）；③ 强调「带上下文摘要」；④ 回流闭环（工单归因 → 调阈值 / 补能力）。
- **追问链**：
  - L1「用户直接说『转人工』要不要无条件转？」→ 要，主动要求是强信号，无条件满足且带上下文；其余按量化阈值。
  - L2「转人工最不能漏的一件事？」→ 携带完整上下文摘要，不让用户重说一遍，是可恢复最值钱的落地。
  - L3「转人工量突然涨了怎么看？」→ 不先怪模型，做工单归因——能力缺口、触发失灵还是词表过严，再决定补能力还是调阈值。
- **失败答法 + 失分原因**：「检测到用户不满意就转人工，尽量让人工多接，体验最好。」——形容词触发、无量化、无成本意识、漏上下文与回流；丢①③。
- **参考答案（60 秒要点）**：转人工是唯一要花钱的，触发条件最要量化：连续 2 轮未解决、强负面情绪词命中、用户明确要求、单会话超时 ≥3 次，任一满足立刻转，主动要求无条件转；定松成本爆炸、AI 白建，定紧用户流失，只能靠数字走钢丝；动作关键是携带完整上下文摘要（可恢复最值钱落地）；工单 24 小时内回访、归因回流调阈值或补能力，形成闭环。

| 档位 | 标准 | 分值（5 分制） |
|---|---|---|
| 不合格 | 「不满意就转 / 人工多接」，形容词触发无数字 | 1–2 |
| 合格 | 给出量化条件组合 + 两种失衡后果 | 3 |
| 良好 | 强调带上下文摘要 + 主动要求无条件转 | 4 |
| 优秀 | 补工单归因回流闭环 / 不先怪模型的判断 | 5 |

### 第 2 层 · 进阶实操（4 题，共 180 分）

| 良好（24–31 分） | 四条文案齐全且过三原则，含认账 / 给预期 / 给出路 |
| 优秀（32–40 分） | 额外标出「超时 → 转降级」的出口动作，或给出拦截场景的草稿保留 / 疑似位置标注 |

**第 11 题（40 分）参考答案要点**：9:12–9:15 转圈无进度 → 缺**加载态**与**超时**值 / 出口 → 该用**降级**前置提示；9:18 白屏 → 缺**空态**（设计过的引导）→ 该用**降级** + **提示文案**；9:19 错误码 → 缺**错态**（说人话 / 恢复动作）→ 该用**降级** + 提示文案三原则；9:20 历史空白草稿丢失 → 缺**可恢复**（不丢成果、恢复指回具体状态）→ 该用**降级**保留草稿 + **转人工**兜底。「只允许补一件」标准答案：先补「生成中的**超时**值 + 出口」，因为成本最低、覆盖最早，符合四件套升级成本递增顺序，用户不必走到白屏那一步。结论：四条都不是「模型不够强」，是**异常分支**整条没画。

| 档位 | 标准 |
|---|---|
| 合格（16–23 分） | 四个节点各写出缺的界面态 / 术语，基本对应正确 |
| 良好（24–31 分） | 每节点写出该用哪件套 + 一条合格提示文案 |
| 优秀（32–40 分） | 「先补超时值 + 出口」且用升级成本逻辑论证；点出「无一条是模型不够强」 |

### 第 3 层 · 求职挑战（4 题，共 120 分）

**第 10 题（30 分）参考答案**：框架先行——「我们把异常路径当正常路径一样设计：状态机管住每个状态的超时与出口，四件套管住异常分流」。举例：澄清（置信度 <0.6 追问一次带选项）、降级（超时 >10 秒切规则话术）、拒答（命中高风险域用审核过的固定文案）、转人工（连续 2 轮未解决，携带上下文摘要）。显专业补句：「拒答是产品设计出来的动作，不是模型临场发挥的礼貌；另外 Prompt 我们按需求管理，改动走版本、评审和回归。」

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 说出四件套框架与状态机，至少一个例子 |
| 良好（24–27 分） | 每件套配量化触发条件；表达有「框架先行」结构 |
| 优秀（28–30 分） | 补出 Prompt 即需求 / 兜底文案三原则 / 升级成本最小化任一深度观点 |

**第 11 题（30 分）参考答案**：经历一暴露两处缺失——评价生成空洞（低置信时强行作答）+ 追问无出口（缺澄清机制）。改进：评价置信度 <0.6 时先澄清「想听结构建议还是内容建议？」；评价产出改为「总体分 + 至少 2 条具体改进点」的结构化输出。经历二暴露转人工触发缺失——连续三轮不满无人工入口。改进：量化触发条件（连续 2 轮负面反馈 / 情绪词命中 / 用户明确要求）任一满足即在界面置顶展示人工辅导入口；同时 24 小时内回访并把未解决原因归因回流。说明：题干「用户流失高于预期」为定性描述，具体数据待教务补充，不作数字论证。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 正确指认两处兜底缺失（澄清缺失 / 转人工触发缺失），改进方向对 |
| 良好（24–27 分） | 改进动作含量化触发条件，且与缺失一一对应 |
| 优秀（28–30 分） | 额外指出「结构化评价输出」「badcase 归因回流」或「流失与兜底缺失的关联论证」，体现系统性 |

**第 12 题（30 分）参考答案**：三处缺失——① 只写正常路径，**异常分支**整条没画；② 无状态机，生成中无**超时**值与出口、异常态是死胡同；③ 无三态（空 / 错 / 加载态）与**提示文案**，拦截 / 超时 / 失败全部一片空白；④ 无**可恢复**设计，草稿与上下文不保（写出任意 3 处即可）。补写示例（容错兜底章一行）：「生成中｜触发条件：生成请求超过 10 秒未返回首字｜产品动作：转降级，切换规则话术并保留用户已上传录音｜提示文案：『生成比平时慢，已为您保留录音，可先做别的，好了通知您』｜升级路径：后台补生成后推送，本次记入 badcase 回流」。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 指出 ≥3 处缺失，方向正确 |
| 良好（24–27 分） | 补写的一行四要素齐全、触发条件量化 |
| 优秀（28–30 分） | 补写含三态 / 可恢复 / 升级闭环，或指出「形容词不是需求」 |

**第 13 题（30 分）参考答案**：① 等价量化信号——把难埋点的「情绪负面」换成可观测的「连续 2 轮否定 / 用户主动输入『转人工』/ 单会话超时 ≥3 次」，并保留「情绪词命中」作为可选增强项；② 阈值由产品给基准值、研发做成可配置项，先按教学基准上线，再按真实数据调，产品不退回「必要时」这类形容词；③ 验收——测试按每行触发条件造异常用例（超时、拦截、连续否定），逐条核对空 / 错 / 加载态界面项与转人工是否带上下文摘要；④ 回流——转人工工单 24 小时内回访并归因，看是能力缺口还是触发失灵，反过来调阈值或补能力，改动走版本、评审、回归。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 给出等价量化信号 + 职责分工，方向正确 |
| 良好（24–27 分） | 含可配置阈值、测试用例验收、三方对齐物 |
| 优秀（28–30 分） | 含回流闭环 / 不追责个人的协作观 / 「形容词不是需求」坚持 |
