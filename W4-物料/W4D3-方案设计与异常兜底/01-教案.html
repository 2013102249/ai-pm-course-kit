教案 · W4 周三《方案设计与异常兜底》

AI 产品经理就业训练营 · 第四周第三天 · 90 分钟（2 课时）· 讲师版

一、基本信息

项目 内容
所属阶段 阶段三 · 产品硬功（Week 4：用户研究 · 需求分析 · AI 产品 PRD · 指标体系）
本课主题 方案设计与异常兜底
课时 90 分钟（2 课时，中间不设休息，第 45 分钟附近插入 1 分钟起立调整）
授课对象 转行 / 进阶层学员（正在撰写主项目 PRD V1.0，周五进入 PRD 评审大会）
前置知识 W4D1 需求真伪判断；W4D2 AI 产品 PRD 五处差异（其中「容错兜底」为本课展开项）
本课产出 兜底设计表（五行）+ 对话产品状态机草图，并入主项目 PRD「容错兜底」章节
教学场地 教室或线上直播，需投屏 + 白板 / 白板笔（本课无专用交互页，靠板书与画图）

二、教学目标（可测量）

  1. 能为一个对话产品独立绘制状态机草图，覆盖「空闲 → 理解中 → 生成中 → 完成 / 异常 → 恢复」全部状态，且每个异常状态都有明确出口（对应课后产出：状态机图）。
  2. 能针对任意一个 AI 功能，逐项写出翻车四件套（降级 / 澄清 / 拒答 / 转人工）的触发条件、产品动作、文案示例与升级路径，触发条件必须量化（对应课堂产出：兜底设计表）。
  3. 能画出一张兜底决策树，并用它解释自己主项目里至少 2 个异常场景的处理路径（对应习题：兜底方案设计题）。
  4. 能说明为什么 Prompt 是需求的一部分，并说出 Prompt 管理的三项机制（版本 / 评审 / 回归）。

三、教学重难点

  • 重点：AI 产品翻车设计四件套——降级、澄清、拒答、转人工。每件按「触发条件 / 产品动作 / 文案示例 / 升级路径」四要素教学，落进学员自己的兜底设计表。
  • 难点一：状态机思维。学员习惯只画「用户说 → 系统答」的直线流程，画不出循环、等待与异常出口。对策：用对话产品逐状态拆解，强制标注每个状态的「超时值」和「异常出口」。
  • 难点二：触发条件的量化。学员写得出「检测到用户不满就转人工」，写不出「不满怎么检测、阈值是多少」。对策：给出量化模板（连续 N 次 / 超时 T 秒 / 情绪词表命中 M 个），现场逼学员填数。
  • 难点三：把 Prompt 当需求管理。学员默认 Prompt 是「开发的实现细节」。对策：用「改一句 Prompt = 改一次产品行为 = 需要评审与回归」的逻辑链打通。

六、状态机教学设计（环节二详解，以一个对话产品为例）

教学动作：讲师在白板画出如下状态流转，学员在导学案「状态机草图区」同步照画并补注超时值。

          用户输入              意图识别
  [空闲] ────────→ [理解中] ────────→ [生成中] ────────→ [完成]
     ↑                │                  │                  │
     │                │ 识别失败/低置信   │ 超时/敏感词/      │ 用户追问/
     │                │ → [异常·澄清/拒答]│ 生成失败          │ 再次输入
     │                │                  │ → [异常·降级]     │ (回到理解中)
     │                │                  │                  │
     └──── [恢复] ←───┴──────────┬───────┴──────────────────┘
             用户主动要求 /       连续 2 次未解决 /
             连续 2 次未解决      情绪负面
             → [异常·转人工]

逐状态教学要点：

状态 进入条件 超时设置（教学基准值） 用户感知设计 异常出口
空闲 会话开始 / 上一轮完成 无 展示建议问题引导输入 —
理解中 收到用户输入 3 秒：超时提示「还在理解」 轻量动效 + 消息气泡「已读」 置信度低于阈值 → 异常·澄清；命中违规 → 异常·拒答
生成中 意图识别通过 10 秒：超时转降级 流式输出首字延迟 ≤2 秒 超时 / 生成失败 / 敏感词拦截 → 异常·降级
完成 回答流式输出完毕 无 引导追问「还需要帮您做什么吗」 用户再次输入 → 回到理解中
异常 任一超时 / 失败 / 拦截触发 各异常态停留 ≤30 秒 按四件套给对应文案 分流至澄清 / 拒答 / 降级 / 转人工
恢复 兜底动作执行完毕 无 告知用户当前状态与下一步 转人工成功 → 挂起；降级成功 → 回到空闲

三条画图纪律（板书强调，学员画图自查）：
1. 每个状态必须标「超时值」——没有超时值的状态机是摆设。
2. 每个异常状态必须有出口——异常态不能是死胡同。
3. 恢复必须指回具体状态——用户从哪里重来，要画清楚。

七、翻车四件套逐个教学（环节三详解）

统一教学句式：「什么情况触发 → 产品做什么 → 屏幕上显示什么话 → 还不行怎么办」。

件 定义 触发条件（量化基准） 产品动作 文案示例 升级路径
① 降级 AI 暂时干不了，退回次优方案，保住可用性 生成超时 >10 秒；接口连续失败 ≥2 次；输出命中敏感词被拦截 切换规则话术 / 返回缓存答案 / 提示稍后重试；禁用「重新生成」无限重试（限 1 次） 「这个问题我需要再想一想，已经为您记录，X 分钟内会给出答案。着急的话，您可以先看看这份指南。」 降级应答 → 后台补答并推送 → 记入 badcase 回流
② 澄清 没听懂就问，不装懂 意图识别置信度 <0.6；一次查询命中 ≥2 个候选意图且分差 <0.1 追问 1 次，且必须给选项（降低用户打字成本） 「您是想问 A 还是 B？点一下就行。」 澄清 1 次后仍模糊 → 给「猜你最想问」列表 + 人工入口，不追问第二次
③ 拒答 超出能力边界或合规红线，明确说不能 命中违规词表；问题超出产品知识范围且检索无据；涉及医疗 / 法律 / 投资建议等高风险域 礼貌拒答 + 说明边界 + 给替代出路；禁止模型自己生成拒答话术（文案固定、走审核） 「这个我帮不了您，原因是……。您可以试试：① …… ② 联系人工。」 用户申诉误判 → 人工复核队列 → 词表迭代（周级）
④ 转人工 AI 兜完了还解决不了，人上场 连续 2 轮未解决；用户消息命中情绪词表 ≥1 个强负面词；用户明确说「转人工」；单会话超时 ≥3 次 排队转人工，携带完整上下文摘要（用户已说过的话不让用户重说一遍） 「已为您转接人工，之前的对话我都带过去了，您不用重复。」 人工工单 → 24 小时内回访 → 工单归因回流到训练与词表

教学补充两点：
- 四件套的顺序即优先级：能用降级解决的不转人工，能澄清一次解决的不追问两次——每一次升级都有成本。
- 兜底文案三原则：说人话（不用「系统异常错误码 5002」）；给出路（永远附下一步动作）；兜住情绪（先认账再解释）。

八、兜底决策树画法（环节四详解）

教学动作：配合配图《兜底决策树》，讲师在白板重画一遍，强调「先问能不能理解，再问能不能答，最后才谈满不满意」。

用户输入
 ├─ 能理解吗？
 │   ├─ 否（低置信 / 有歧义）→ 【澄清】追问 1 次 → 仍模糊 → 提供候选 + 人工入口
 │   └─ 是 ↓
 ├─ 能答吗？
 │   ├─ 否（违规 / 超边界 / 检索无据）→ 【拒答】固定文案 + 替代出路 → 申诉走人工复核
 │   └─ 是 ↓
 ├─ 答得出吗？
 │   ├─ 否（超时 / 失败 / 拦截）→ 【降级】规则话术 / 缓存答案 → 补答推送
 │   └─ 是 → 正常回答 ↓
 └─ 用户满意吗？
     └─ 否（连续 2 轮未解决 / 情绪负面 / 主动要求）→ 【转人工】带上下文摘要

画图纪律：决策树每个叶子节点必须落在四件套之一或「正常回答」上；两个叶子落在同一件套但触发条件不同是允许的，触发条件必须各写各的量化值。

九、Prompt 即需求（环节四下半，10 分钟内）

论点 讲解要点
为什么 Prompt 是需求 一句 Prompt 决定产品行为：语气、格式、边界、拒答策略全写在里面。改 Prompt = 改产品行为 = 改需求，凭什么不用走需求流程？
机制一：版本管理 Prompt 纳入版本库，与代码同粒度管理；每次修改记录「改了哪句、为什么改、谁批准」
机制二：评审上线 Prompt 变更走评审，像 PRD 变更一样；重要 Prompt（如拒答策略）变更需产品经理签字
机制三：回归测试 Prompt 改动后必须跑一遍评测集（回扣 W2），确认老能力没退化——没有回归的 Prompt 调优等于裸奔

十、课堂提问设计（7 问）

# 提问 提问时机 预设答案 / 引导方向
1 「这三个翻车场景里，哪个最伤产品口碑？为什么？」 导入 意见开放，引导出共识：答非所问还坚持己见最伤——用户发现「它不仅错了，还骗我」，信任归零
2 「功能结构图、流程图、状态机，三张图各回答什么问题？」 环节一 有什么（静态模块）/ 怎么走（动态路径）/ 此刻在哪、卡住怎么办（任意时刻状态）。AI 产品异步与概率特性让第三张图从可选变必选
3 「『理解中』如果卡了 30 秒没有任何提示，用户会做什么？」 环节二 疯狂重复点击、直接退出、给差评。所以每个状态必须有超时值与超时后的出口
4 「澄清为什么最多只问一次、还必须给选项？」 环节三·澄清 追问第二次用户就烦了；开放式追问把成本甩回给用户，选项化让用户「点一下」就行
5 「拒答和说『我不知道』是一回事吗？」 环节三·拒答 不是。拒答 = 明确边界 + 给替代出路 + 文案固定可审核；「我不知道」是模型生成的不确定表述，不可控且不可审
6 「转人工转多了会怎样？转少了会怎样？触发条件怎么定？」 环节三·转人工 转多了成本爆炸、AI 白建；转少了用户被耗到流失。触发条件必须量化：连续 N 轮未解决 / 情绪词命中 / 用户主动要求 / 高价值客户标记
7 「改一句 Prompt，算不算改需求？要走过哪些流程？」 环节四 算。版本记录 → 评审 → 回归测试。引导出结论：Prompt 是需求的一部分，不是开发的实现细节

十一、板书要点

AI 产品的体验，一半在兜底——正常路径大家都会写，翻车路径才见功力

三层表达：功能结构图（有什么）→ 流程图（怎么走）→ 状态机（在哪 / 卡住怎么办）

状态机：空闲 → 理解中 → 生成中 → 完成 / 异常 → 恢复（每个状态标超时值 + 异常出口）

四件套 = 降级（干不了就退一档）/ 澄清（没听懂就问一次）/ 拒答（不该答就直说）/ 转人工（兜不住就找人）
   每件四要素：触发条件（量化）/ 产品动作 / 文案示例 / 升级路径

决策树四连问：能理解吗 → 能答吗 → 答得出吗 → 用户满意吗

兜底文案三原则：说人话 / 给出路 / 兜住情绪
Prompt 三机制：版本 / 评审 / 回归

十三、学员易错点预判与应对

易错点 表现 应对
只设计正常路径 PRD 里只写「用户提问 → 系统回答」，异常一字不提 用导入翻车合集冲击：三个场景全是「正常路径没问题、异常路径全裸奔」；布置硬指标——兜底设计表不满五行不许进周五评审
兜底文案写得像机器人 文案是「系统异常，错误码 5002，请稍后再试」 现场对比改写：同一场景两条文案投票；给出三原则（说人话 / 给出路 / 兜住情绪），让学员逐条自查
转人工没有触发条件 写「必要时转人工」「检测到用户不满时转人工」 追问「不满怎么检测？多少算不满？」；给出量化模板（连续 N 轮 / 情绪词命中 M 个 / 超时 T 秒），现场逼每个人填具体数字
状态机只有单向流转，异常态是死胡同 画了异常状态但没画出口，异常之后不知道去哪 三条画图纪律上墙：每个状态标超时值、每个异常有出口、恢复指回具体状态；巡场逐个检查
把 Prompt 当实现细节 认为「Prompt 是开发的事，PRD 不用写」 讲透逻辑链：一句 Prompt 定产品行为 → 改 Prompt = 改行为 = 改需求 → 需求就要版本 / 评审 / 回归
兜底方案无法量化验收 方案只有形容词没有数字 规定兜底设计表每行「触发条件」列必须含至少一个数字，否则退回重写

十四、课后作业（进 PRD）

  1. 将课堂兜底设计表五行情景扩写为完整版（至少 6 行），并入主项目 PRD「容错兜底」章节，周五评审前提交。
  2. 依据状态机草图，用画图工具补全主项目核心业务流程的状态机图，每个状态标注超时值与异常出口。
  3. 对照兜底决策树自查 PRD：四个判断问题各找出至少 1 个自己项目的对应设计，找不到的即为缺口，列入 PRD 待补清单。
