二、教学目标（可测量）

  1. 能为一个对话产品独立绘制状态机草图，覆盖「空闲 → 理解中 → 生成中 → 完成 / 异常 → 恢复」全部状态，且每个异常状态都有明确出口（验证：状态机草图，按「三条画图纪律」逐条打勾，缺 1 条即退回补画）。
  2. 能针对任意一个 AI 功能，逐项写出翻车设计四件套（降级 / 澄清 / 拒答 / 转人工）的触发条件、产品动作、文案示例与升级路径，触发条件必须量化（验证：兜底设计表，每行「触发条件」列至少含 1 个数字，否则退回重写）。
  3. 能画出一张兜底决策树，并用它解释自己主项目里至少 2 个异常场景的处理路径（验证：习题「兜底方案设计题」，决策树四层判断齐全、叶子节点落在四件套或正常回答）。
  4. 能说明为什么 Prompt 是需求的一部分，并说出 Prompt 管理的三项机制（版本 / 评审 / 回归）（验证：课堂口头问答，需完整说出因果链与三机制，缺一补问）。
  5. 术语目标：能准确复述并辨析本日 12 个核心术语（状态机、兜底、翻车设计四件套、降级、超时、空态、错态、加载态、异常分支、用户预期、可恢复、提示文案），每个术语写出「一句话定义 + 一个易混辨析」；且能把空态、错态、加载态分别对应到状态机的具体状态（验证：《术语自测表》12 行自评 ≥10 行为「会」，第 1 节当堂术语小测 10 题答对 ≥8 题）。
  6. 面试目标：能就「翻车设计四件套 / 异常态怎么写进 PRD / 状态机怎么画 / 和研发怎么对齐兜底」四类高频题，给出含至少 1 个本日术语、带量化触发条件的 60 秒标准答法，并扛住 2 层追问（验证：《面试模拟记录表》两两模拟，每题自评分 ≥3/5，且追问链无「答不上来」记录）。
  7. 能完成本日作品集积木归档：状态机草图、兜底设计表、决策树自查表、面试题标准答法各 1 份，标注归档位置（验证：《本日作品集积木》表 4 行填满，第 6 节当堂验收）。

三、教学重难点

  • 重点：AI 产品翻车设计四件套——降级、澄清、拒答、转人工。每件按「触发条件 / 产品动作 / 文案示例 / 升级路径」四要素教学，落进学员自己的兜底设计表；并把空态、错态、加载态作为四件套在界面上的三种落点讲透。
  • 难点一：状态机思维。学员习惯只画「用户说 → 系统答」的直线流程，画不出循环、等待与异常出口。对策：用对话产品逐状态拆解，强制标注每个状态的「超时值」和「异常出口」。
  • 难点二：触发条件的量化。学员写得出「检测到用户不满就转人工」，写不出「不满怎么检测、阈值是多少」。对策：给出量化模板（连续 N 次 / 超时 T 秒 / 情绪词表命中 M 个），现场逼学员填数。
  • 难点三：把 Prompt 当需求管理。学员默认 Prompt 是「开发的实现细节」。对策：用「改一句 Prompt = 改一次产品行为 = 需要评审与回归」的逻辑链打通。
  • 难点四 · 术语混淆：零基础学员易把「兜底」当「容错」、把「空态」当「白屏」、把「错态」当「错误码提示」、把「降级」当「报错」、把「加载态」当「超时」、把「异常分支」与「异常状态」混为一谈。对策：第 1 节每术语强制做「易混辨析」，用非技术生活类比建立区分；术语小测设「改错题」专门暴露混淆，当堂订正。
  • 难点五 · 面试失分：学员能背出四件套名字，但说不出「顺序即成本递增」、说不出量化触发条件、说不清「异常态写进 PRD 的哪一章、什么颗粒度」、也不会讲「和研发怎么对齐」。对策：第 5 节逐题给「踩分点 + 追问链 + 失败答法 + 60 秒标准答法」，两两模拟后按评分表互评，把「背概念」纠成「给结构 + 给数字 + 给协作动作」。

六、状态机教学设计（第 2 节详解，以一个对话产品为例）

教学动作：讲师在白板画出如下状态流转，学员在导学案「状态机草图区」同步照画并补注超时值。本节与第 1 节术语「状态机 / 超时 / 异常分支 / 加载态 / 可恢复」直接对应，讲到每个状态回扣一次术语卡。

          用户输入              意图识别
  [空闲] ────────→ [理解中] ────────→ [生成中] ────────→ [完成]
     ↑                │                  │                  │
     │                │ 识别失败/低置信   │ 超时/敏感词/      │ 用户追问/
     │                │ → [异常·澄清/拒答]│ 生成失败          │ 再次输入
     │                │                  │ → [异常·降级]     │ (回到理解中)
     │                │                  │                  │
     └──── [恢复] ←───┴──────────┬───────┴──────────────────┘
             用户主动要求 /       连续 2 次未解决 /
             连续 2 次未解决      情绪负面
             → [异常·转人工]

逐状态教学要点：

状态进入条件超时设置（教学基准值）用户感知设计异常出口对应界面态
空闲会话开始 / 上一轮完成无展示建议问题引导输入（设计过的空态）—空态
理解中收到用户输入3 秒：超时提示「还在理解」轻量动效 + 消息气泡「已读」（加载态）置信度低于阈值 → 异常·澄清；命中违规 → 异常·拒答加载态
生成中意图识别通过10 秒：超时转降级流式输出首字延迟 ≤2 秒（加载态）超时 / 生成失败 / 敏感词拦截 → 异常·降级加载态
完成回答流式输出完毕无引导追问「还需要帮您做什么吗」用户再次输入 → 回到理解中正常内容态
异常任一超时 / 失败 / 拦截触发各异常态停留 ≤30 秒按四件套给对应文案分流至澄清 / 拒答 / 降级 / 转人工错态
恢复兜底动作执行完毕无告知用户当前状态与下一步（可恢复）转人工成功 → 挂起；降级成功 → 回到空闲提示文案

三条画图纪律（板书强调，学员画图自查）：

  1. 每个状态必须标「超时值」——没有超时值的状态机是摆设。
  2. 每个异常状态必须有出口——异常态不能是死胡同。
  3. 恢复必须指回具体状态——用户从哪里重来，要画清楚。

「为什么 / 边界 / 常见误解」深化点：状态机不是把流程图画得更细，而是换了一个视角——流程图问「下一步去哪」，状态机问「此刻停得住吗、停久了往哪退」。边界：状态机适用于「有等待、可被打断、结果不确定」的对话与生成类功能，纯表单提交类功能画流程图即可，不必强行上状态机。常见误解：把「异常」画成一个终点框，讲完就停——异常是分流站，不是终点。

七、翻车四件套逐个教学（第 3 节详解）

统一教学句式：「什么情况触发 → 产品做什么 → 屏幕上显示什么话 → 还不行怎么办」。

件定义触发条件（量化基准）产品动作文案示例升级路径主要界面态
① 降级AI 暂时干不了，退回次优方案，保住可用性生成超时 >10 秒；接口连续失败 ≥2 次；输出命中敏感词被拦截切换规则话术 / 返回缓存答案 / 提示稍后重试；禁用「重新生成」无限重试（限 1 次）「这个问题我需要再想一想，已经为您记录，X 分钟内会给出答案。着急的话，您可以先看看这份指南。」降级应答 → 后台补答并推送 → 记入 badcase 回流错态 / 提示文案
② 澄清没听懂就问，不装懂意图识别置信度 <0.6；一次查询命中 ≥2 个候选意图且分差 <0.1追问 1 次，且必须给选项（降低用户打字成本）「您是想问 A 还是 B？点一下就行。」澄清 1 次后仍模糊 → 给「猜你最想问」列表 + 人工入口，不追问第二次错态 / 提示文案
③ 拒答超出能力边界或合规红线，明确说不能命中违规词表；问题超出产品知识范围且检索无据；涉及医疗 / 法律 / 投资建议等高风险域礼貌拒答 + 说明边界 + 给替代出路；禁止模型自己生成拒答话术（文案固定、走审核）「这个我帮不了您，原因是……。您可以试试：① …… ② 联系人工。」用户申诉误判 → 人工复核队列 → 词表迭代（周级）错态 / 提示文案
④ 转人工AI 兜完了还解决不了，人上场连续 2 轮未解决；用户消息命中情绪词表 ≥1 个强负面词；用户明确说「转人工」；单会话超时 ≥3 次排队转人工，携带完整上下文摘要（用户已说过的话不让用户重说一遍）「已为您转接人工，之前的对话我都带过去了，您不用重复。」人工工单 → 24 小时内回访 → 工单归因回流到训练与词表错态 / 提示文案

教学补充两点：

  • 四件套的顺序即优先级：能用降级解决的不转人工，能澄清一次解决的不追问两次——每一次升级都有成本。
  • 兜底文案三原则：说人话（不用「系统异常错误码 5002」）；给出路（永远附下一步动作）；兜住情绪（先认账再解释）。这三原则即第 1 节「提示文案」术语的展开。

空态 / 错态 / 加载态与四件套的对应关系（第 1 节术语在第 3 节落地）：加载态覆盖「理解中 / 生成中」两个等待状态，靠首字延迟与阶段提示稳住用户预期；错态覆盖「异常 / 恢复」状态，靠提示文案做到可恢复；空态覆盖「空闲」状态与新会话、筛选无结果等场景，靠建议问题与引导给第一步。三者共同回答「异常态一片空白」这个反面案例扣的分。

八、兜底决策树画法（第 3 节详解）

教学动作：配合配图《兜底决策树》，讲师在白板重画一遍，强调「先问能不能理解，再问能不能答，最后才谈满不满意」。

用户输入
 ├─ 能理解吗？
 │   ├─ 否（低置信 / 有歧义）→ 【澄清】追问 1 次 → 仍模糊 → 提供候选 + 人工入口
 │   └─ 是 ↓
 ├─ 能答吗？
 │   ├─ 否（违规 / 超边界 / 检索无据）→ 【拒答】固定文案 + 替代出路 → 申诉走人工复核
 │   └─ 是 ↓
 ├─ 答得出吗？
 │   ├─ 否（超时 / 失败 / 拦截）→ 【降级】规则话术 / 缓存答案 → 补答推送
 │   └─ 是 → 正常回答 ↓
 └─ 用户满意吗？
     └─ 否（连续 2 轮未解决 / 情绪负面 / 主动要求）→ 【转人工】带上下文摘要

画图纪律：决策树每个叶子节点必须落在四件套之一或「正常回答」上；两个叶子落在同一件套但触发条件不同是允许的，触发条件必须各写各的量化值。四层判断顺序即成本递增顺序：澄清零成本 → 降级 / 拒答低成本 → 转人工人力成本。

九、Prompt 即需求（第 3 节下半）

论点讲解要点
为什么 Prompt 是需求一句 Prompt 决定产品行为：语气、格式、边界、拒答策略全写在里面。改 Prompt = 改产品行为 = 改需求，凭什么不用走需求流程？
机制一：版本管理Prompt 纳入版本库，与代码同粒度管理；每次修改记录「改了哪句、为什么改、谁批准」
机制二：评审上线Prompt 变更走评审，像 PRD 变更一样；重要 Prompt（如拒答策略）变更需产品经理签字
机制三：回归测试Prompt 改动后必须跑一遍评测集（回扣 W2），确认老能力没退化——没有回归的 Prompt 调优等于裸奔

十、课堂提问设计（21 问）

分类：〔术〕术语辨析 7 问、〔面〕面试追问 7 问、〔理〕原理与实操 7 问；术语辨析 ≥6、面试追问 ≥6，满足本课提问规范。

#类别提问提问时机预设答案 / 引导方向
1〔理〕「这三个翻车场景里，哪个最伤产品口碑？为什么？」第 2 节导入意见开放，引导出共识：答非所问还坚持己见最伤——用户发现「它不仅错了，还骗我」，信任归零
2〔理〕「功能结构图、流程图、状态机，三张图各回答什么问题？」第 2 节有什么（静态模块）/ 怎么走（动态路径）/ 此刻在哪、卡住怎么办（任意时刻状态）。AI 产品异步与概率特性让第三张图从可选变必选
3〔术〕「『状态机』和『业务流程图』到底差在哪？为什么说对话是环、流程图画不了？」第 1 / 2 节流程图讲路径，状态机讲任意时刻的状态快照 + 卡住往哪退；对话可随时插话改口重来，是环不是线
4〔术〕「『兜底』和『容错』是一回事吗？分别站谁的视角？」第 1 节容错偏技术（系统不崩），兜底偏产品体验（用户看到什么、下一步做什么）；兜底是「发生之后」，不是「不让发生」
5〔理〕「『理解中』如果卡了 30 秒没有任何提示，用户会做什么？」第 2 节疯狂重复点击、直接退出、给差评。所以每个状态必须有超时值与超时后的出口
6〔术〕「『空态』和『白屏』看着都是没内容，区别在哪？」第 1 / 3 节空态是设计过的（有引导、有下一步），白屏是没设计（什么都没有）；空态还分首次使用、筛选无结果等场景
7〔术〕「『错态』和甩一句『错误码 5002』差在哪？」第 1 / 3 节错态要说人话 + 说清发生了什么 + 给恢复动作（草稿已保留、点此重试）；错误码只是把技术日志甩给用户
8〔术〕「『加载态』和『超时』是同一件事吗？」第 1 节加载态是「还在等」的进度反馈，超时是「等太久了」的产品阈值 + 到点必须有出口动作
9〔术〕「『降级』和『报错 / 无限重试』差在哪？」第 1 节降级是还给得出东西（规则话术 / 缓存答案）并限重试 1 次，报错是什么都不给，无限重试把失控甩给用户
10〔术〕「『异常分支』和『异常状态』，一个是路径一个是节点，怎么分？」第 1 节异常状态是「停在哪」（状态机节点），异常分支是「从这往哪走」（处理路径）；PRD 最常缺的就是这一支
11〔术〕「『可恢复』和『重试』差在哪？为什么说异常态是死胡同就不可恢复？」第 1 节重试是再点一次同一操作，可恢复是清楚回到哪个状态且不丢成果（保留草稿、携带上下文）；死胡同让用户从头来
12〔面〕「翻车设计四件套是哪四件？为什么是这个顺序、不能调换？」第 5 节降级 / 澄清 / 拒答 / 转人工；顺序即成本递增，能用便宜的解决绝不启动贵的
13〔面〕「异常态你一般怎么写进 PRD？写在哪一章、写到什么颗粒度？」第 5 节写进「容错兜底」章，按状态机逐状态列触发条件（量化）/ 产品动作 / 文案 / 升级路径，附空态 / 错态 / 加载态验收项
14〔面〕「状态机怎么画？以一个对话产品为例说说你会标哪些东西。」第 5 节五个主干状态 + 异常分流 + 恢复；每状态标超时值、用户感知、异常出口；三条画图纪律收口
15〔面〕「兜底方案你怎么和研发对齐？触发条件、超时值谁定、怎么验收？」第 5 节产品定阈值与出口、研发定可观测与实现；用兜底设计表当对齐物，逐行量化、可测、可回归
16〔面〕「转人工触发条件定松了、定紧了分别会怎样？」第 5 节松了人力成本爆炸、AI 白建；紧了用户被耗到流失；必须量化：连续 N 轮 / 情绪词命中 / 主动要求
17〔面〕「拒答文案为什么不能让模型现场生成？」第 5 节模型生成不可控不可审；拒答是产品设计动作，文案写死走审核，边界与合规才可控
18〔面〕「空态、错态、加载态，面试里怎么一句话说清三者？」第 5 节没内容时的引导是空态、出错时的认账与出路是错态、等待中的进度反馈是加载态，分别对应空闲 / 异常 / 生成中
19〔理〕「澄清为什么最多只问一次、还必须给选项？」第 3 节追问第二次用户就烦了；开放式追问把成本甩回给用户，选项化让用户「点一下」就行
20〔理〕「拒答和说『我不知道』是一回事吗？」第 3 节不是。拒答 = 明确边界 + 给替代出路 + 文案固定可审核；「我不知道」是模型生成的不确定表述，不可控且不可审
21〔理〕「改一句 Prompt，算不算改需求？要走过哪些流程？」第 3 节算。版本记录 → 评审 → 回归测试。引导出结论：Prompt 是需求的一部分，不是开发的实现细节

第 3 节 · 核心原理讲授 B + 案例

  Prompt 三机制：版本 / 评审 / 回归

十三、学员易错点预判与应对

易错点表现应对
只设计正常路径PRD 里只写「用户提问 → 系统回答」，异常一字不提用导入翻车合集冲击：三个场景全是「正常路径没问题、异常路径全裸奔」；布置硬指标——兜底设计表不满五行不许进周五评审
兜底文案写得像机器人文案是「系统异常，错误码 5002，请稍后再试」现场对比改写：同一场景两条文案投票；给出三原则（说人话 / 给出路 / 兜住情绪），让学员逐条自查
转人工没有触发条件写「必要时转人工」「检测到用户不满时转人工」追问「不满怎么检测？多少算不满？」；给出量化模板（连续 N 轮 / 情绪词命中 M 个 / 超时 T 秒），现场逼每个人填具体数字
状态机只有单向流转，异常态是死胡同画了异常状态但没画出口，异常之后不知道去哪三条画图纪律上墙：每个状态标超时值、每个异常有出口、恢复指回具体状态；巡场逐个检查
把 Prompt 当实现细节认为「Prompt 是开发的事，PRD 不用写」讲透逻辑链：一句 Prompt 定产品行为 → 改 Prompt = 改行为 = 改需求 → 需求就要版本 / 评审 / 回归
兜底方案无法量化验收方案只有形容词没有数字规定兜底设计表每行「触发条件」列必须含至少一个数字，否则退回重写
术语混淆（新增）把「空态」当「白屏」、把「错态」写成错误码、把「兜底」当「容错」、把「降级」当「报错」、把「加载态」和「超时」画等号第 1 节每术语强制做易混辨析 + 非技术生活类比；术语小测设「改错题」专门暴露混淆，当堂订正；《术语自测表》把混淆项列成对照栏
面试失分（新增）四件套只背名字不说顺序成本；说不出量化触发条件；问「异常态写进 PRD 哪一章」答不上；不会讲「和研发怎么对齐兜底」第 5 节逐题给踩分点 + 追问链 + 失败答法 + 60 秒标准答法；两两模拟按评分表互评；把「背概念」纠成「给结构 + 给数字 + 给协作动作」
