# 教案 · W5 周五《主项目中期评审（里程碑 ④）》

> AI 产品经理就业训练营 · 第五周第五天 · 300 分钟（6 课时 × 50 分钟）· 讲师版
> 本课为里程碑评审日深化版：在原 90 分钟轻量评审基础上，把「术语 → 答辩标准 → 反面案例 → 多轮评审实操 → 面试讲解 → 验收」铺成六节完整链路，从「走一遍流程」升级为「可迁移的决策能力与答辩能力」。
> 六节固定结构：第 1 节 0–50 术语精讲与零层入口｜第 2 节 50–100 核心原理讲授 A｜第 3 节 100–150 核心原理讲授 B + 案例｜第 4 节 150–200 实操演练与巡场｜第 5 节 200–250 面试讲解与追问防御｜第 6 节 250–300 复盘 · 作品集归档 · 当堂验收。

## 二、教学目标（可测量）

1. **术语目标**：能在《术语自测表》上，不看书写出本日 11 个术语的一句话定义与相邻概念辨析，11 题对 ≥9 题为达标；能把其中 ≥3 个术语自然用于一次 60 秒口述（对应第 1 节当堂小测与第 5 节面试答法）。
2. **答辩表达目标**：每人能在 8 分钟内完成「问题与方案 2′ / 数据验证 2′ / 成本与计划 2′ / 风险·里程碑·取舍 2′」四段式中期陈述，且每段至少引用 1 个注明出处或样本量的真实数据（对应评审评分卡「数据支撑」维度 ≥3 分）。
3. **质询应对目标**：每人能接住「投资人五问」中至少 4 问，并给出可复算的数据型回答；被问住时能主动说「记下来，进 Scope 清算」，不沉默、不编数（对应质询记录表 ≥3 条有效记录）。
4. **Scope 决策目标**：每人能产出 V3 Scope 决策表：每条功能标注 P0/P1/P2（Priority 0/1/2，优先级 0/1/2）等级、判定依据（答辩数据 + 工时测算）与本周工时，P0 总工时 ≤ 上限 60%，并通过 V3 Scope 验收清单（对应 06-分层习题验收清单四项全过）。
5. **反面案例辨析目标**：能针对 1 个「失败中期答辩」与 1 个「失败 Scope 决策」反面案例，各指出 ≥3 处违规点并给出改法（对应第 3 节双案例研讨记录）。
6. **面试目标**：能在《面试模拟记录表》上完成 ≥4 道本日面试题的两两模拟，每题踩分点自评 ≥3/4 条命中，且能应对 2 层追问不跑题（对应第 5 节面试评分示例）。
7. **复盘与归档目标**：能把 ≥3 条质询意见逐条转成「改了什么 / 不改的理由」写入 PRD 变更记录，并完成 P5 迭代页积木归档动作（对应第 6 节当堂验收与周日 22:00 提交物）。

## 三、教学重难点

- **重点一**：术语系统。评审日的 11 个高频词（中期评审、里程碑、V3 Scope、砍需求、投资人视角、数据备齐、答辩、风险预判、复盘、决策记录、验收标准）是听懂规则、写好记录、答好面试的共同前提，必须先建立语言系统再进入实训。
- **重点二**：中期答辩的结构化表达——结论先行、每个论断配数字；「投资人五问」作为质询与自检的双重骨架。
- **难点一**：「砍需求」决策。学员普遍舍不得砍、或凭感觉砍。必须让判定依据落到两条硬约束上：中期答辩数据 + 两周工时上限。
- **难点二**：评审意见落纸面（决策记录）。口头意见如不誊写进记录表，Scope 清算时无据可依，W6 又会复发。
- **难点三（术语混淆）**：学员易把「中期评审」与「结业路演」混为一谈，把「需求池」当成「V3 Scope」，把「用户视角」当成「投资人视角」，把「评分」当成「验收标准」，把「风险预判」当成「事后复盘」。第 1 节须用易混辨析逐对拆开，第 9 节课堂提问设 ≥6 道辨析题反复校准。
- **难点四（面试失分）**：学员答项目题时习惯只讲功能、不讲取舍；数据不好看时容易含糊或编数；被质疑时要么硬顶要么沉默；不会把当日术语自然嵌进 60 秒答法。第 5 节须用「踩分点 + 追问链 + 失败答法 + 标准答法」四件套逐题矫正。

## 六、「投资人视角」五问设计

五问是本课质询骨架，也是学员未来融资路演与面试项目深挖的通用追问链。质询人每轮至少选 1 问发起，并沿追问链追第二层；第 5 节将把五问整体转成面试追问防御训练。

| # | 五问 | 追问链（第二层） | 好答案标准 |
|---|---|---|---|
| 1 | 这事解决谁的问题？ | 这个人群现在怎么解决？你的方案好多少，好到值得换吗？ | 人群有边界、现状有数字、差异有量级 |
| 2 | 凭什么你能做成？ | 已有人在做，差异在哪？你的独特积累（数据 / 场景 / 分发）是什么？ | 指向别人拿不走的积累，而非「模型更强」 |
| 3 | 数据在哪？ | 样本多少、怎么收集的？被质疑「样本有偏」怎么回？ | 每个论断有出处：问卷 / 访谈 / 评测集 / 竞品数据 |
| 4 | 成本怎么算？ | 单次对话 token（词元）成本多少？1000 活跃用户月成本多少？毛利正吗？ | 数字当场可复算，回扣 W5D3 单位经济模型 |
| 5 | 下周就能上线吗？ | P0 工时合计多少？做不完先砍哪个？ | 能报出工时总数与砍的顺序，引出 Scope |

## 七、V3 Scope 决策规则

**判定依据只有两条：中期答辩数据 + 两周工时上限（W6 冲刺周至路演收尾，单人可投入约 80 小时）。两条依据逐条核对，不允许「凭感觉」。**

| 等级 | 判定标准 | 表决口径 | W6 处理 |
|---|---|---|---|
| P0 保留 | 有数据支撑（问卷 / 访谈 / 评测 / 试用数据至少其一），且工时在上限内 | 无条件保留，P0 总工时 ≤ 上限 60% | W6D1–D3 必做，路演必演示 |
| P1 有条件 | 数据部分支撑，或依赖外部条件；全量做会爆工时 | 必须写明三件事：简化到什么程度、触发条件与检查点（建议 W6D2 中午核心链路跑通）、不过怎么办 | 检查点达标才做，否则自动降 P2 |
| P2 砍 | 无数据支撑、无差异化、或两周工时装不下 | 写入「暂存池」并附书面理由（一句话即可，不许空着） | W6 不做；路演可作未来规划讲述 |

## 八、砍需求决策演示参考答案（教学示例：留学文书助手）及课堂练习参考答案

教学示例与学员项目区隔，避免对号入座。背景：两周工时上限约 80 小时，三个候选功能全做需 64 小时，工时看似装得下，仍按理由链逐条裁决。

| 功能 | 答辩数据 | 工时测算 | 裁决 | 理由链 |
|---|---|---|---|---|
| F1 文书智能改写 | 问卷 82% 排第一；访谈 5/5 提及；原型已有 | 打磨 12h | P0 保留 | 数据强 + 有基础 + 工时小 |
| F2 智能选校推荐 | 访谈 4/5 提及选校焦虑，但 0 人愿单独付费；需接外部选校数据 | 全量 28h；简化版（按背景推荐三档）8h | P1 有条件 | 数据不弱但全量爆工时；降为简化版，触发条件 = W6D2 中午核心链路跑通，不过自动降 P2 |
| F3 简历一键生成 | 问卷仅 9% 提及 | 开发 + 模板维护 24h | P2 砍 | 数据弱 + 竞品免费遍地无差异化 + 工时挤占 P0 打磨 |

演示结论：三进二。每个决定背后必须站着「数据、竞争、工时」中至少两条，缺一条依据即退回重判。

**术语小测参考答案（第 1 节当堂小测用，11 题，每题 1 分）**

| # | 题目（简写） | 参考答案要点 |
|---|---|---|
| 1 | 中期评审考什么？ | 考方向对不对、盘子切得准不准；产出是 V3 Scope 决策；与结业路演（考结果）不同 |
| 2 | 里程碑与待办的区别？ | 里程碑有可验收产出 + 过关口径；待办做完即划掉 |
| 3 | V3 Scope 是不是需求池？ | 不是。Scope 是资源约束下的排序结果，锁定后不加需求；需求池只进不出 |
| 4 | 砍需求 = 功能没价值吗？ | 不是。多为数据弱或工时装不下，砍掉进暂存池，是有取舍的证据 |
| 5 | 投资人视角问的是什么？ | 谁的问题 / 凭什么 / 数据 / 成本 / 能否上线；与用户视角（好不好用）不同 |
| 6 | 「数据备齐」查的是什么？ | 有出处、注明样本量、可复算；不是数值好看。数据不好看也要如实带 |
| 7 | 答辩的核心产出是什么？ | 质询记录（决策记录），不是掌声或演示效果 |
| 8 | 风险预判怎么写才满分？ | 有优先级 + 有应对动作；只提风险无应对只给 3–4 分 |
| 9 | 复盘与感想的区别？ | 复盘落到「哪条意见 → 改了什么 → 不改的理由」，进 PRD 变更记录 |
| 10 | 决策记录记什么？ | 定了什么、凭哪条数据、凭多少工时；不是「谁说了什么」的会议纪要 |
| 11 | 验收标准与评分的区别？ | 评分是「多好」（0–5 分），验收是「放不放行」（过 / 不过二值） |

**面试评分示例（第 5 节用，以「你砍过什么需求」一题示范，满分 4 条踩分点）**

| 踩分点 | 命中标准 | 示范判定 |
|---|---|---|
| ① 说出具体功能与背景 | 报出功能名、当时阶段（中期评审） | 命中 1 分；只说「砍了一些」0 分 |
| ② 两条硬依据 | 明确「答辩数据 + 两周工时上限」，且给出至少 1 个数字 | 命中 1 分；说「凭感觉砍」0 分 |
| ③ 决策记录与暂处理由 | 提到判定依据写进决策表、砍掉项写书面理由进暂存池 | 命中 1 分 |
| ④ 收尾落到结果与复盘 | 说清 W6 按 Scope 执行、未占用冲刺工时，或补一句复盘所得 | 命中 1 分 |
| 追问防御加分 | 被追「砍完后悔吗 / 数据后来变好怎么办」仍能回到「检查点 + 暂存池 + 下一版再评」 | 不跑题即达标；硬顶或编数判失分 |

## 九、课堂提问设计（20 问）

> 标注：【术语】术语辨析题（8 问）｜【面试】面试追问题（7 问）｜【原理】原理与决策题（5 问）。

| # | 类型 | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|---|
| 1 | 【术语】 | 中期评审和 W6D5 结业路演，考察的东西有什么不同？ | 第 1 节 | 中期看「方向对不对、盘子切得准不准」，考决策；路演看「做没做出来、讲不讲得清」，考结果。今天错，下周还来得及改 |
| 2 | 【术语】 | 「里程碑」和甘特图里的一条待办，差在哪？ | 第 1 节 | 里程碑绑可验收产出 + 过关口径；待办做完划掉即可。里程碑 ④ 的产出是 V3 Scope 决策表 |
| 3 | 【术语】 | 把 V3 Scope 说成「功能愿望清单」错在哪？ | 第 1 节 | Scope 是资源约束下的排序结果，核心动作是砍、锁定后不加；愿望清单只进不出 |
| 4 | 【术语】 | 「用户视角」和「投资人视角」分别问什么？ | 第 1 节 | 用户问好不好用；投资人问谁的问题、凭什么、数据、成本、能否上线，是「值不值得投」 |
| 5 | 【术语】 | 「数据备齐」是要求数据好看吗？数据不好看怎么办？ | 第 1 / 2 节 | 查的是出处、样本量、可复算；不好看也如实带，标注「实验进行中 + 出数日期」，不许编数 |
| 6 | 【术语】 | 「评分」和「验收标准」是同一件事吗？ | 第 1 / 6 节 | 评分 0–5 分看「多好」；验收过 / 不过看「放不放行」。V3 Scope 验收四项全过才进 W6 |
| 7 | 【术语】 | 「风险预判」和「复盘」哪个在评审前、哪个在评审后？ | 第 1 / 6 节 | 风险预判是还没发生、提前给应对；复盘是已发生、逐条归因转动作 |
| 8 | 【术语】 | 「决策记录」和会议纪要的区别是什么？ | 第 1 / 4 节 | 纪要记「谁说了什么」；决策记录记「定了什么、凭哪条数据、凭多少工时」，意见不落纸面等于没评 |
| 9 | 【原理】 | 投资人五问里，哪一问答不上最致命？为什么？ | 第 2 节 | 开放讨论，引导到第 1 问或第 3 问：人群不成立则一切归零；数据缺失则所有论断等于没说 |
| 10 | 【原理】 | 「我的功能个个都重要，一个都不能砍」，这句话怎么反驳？ | 第 3 节 | 反问两句：两周工时装得下吗？每个功能的答辩数据分别是什么？重要是价值判断，Scope 是资源约束下的排序 |
| 11 | 【原理】 | P1 的「有条件」要写成什么样才合格？ | 第 3 节 | 三件套：简化到什么程度 + 检查点时间 + 不过怎么办。「尽量做」不算条件 |
| 12 | 【原理】 | 砍掉的功能是不是白做了？ | 第 3 节 | 不是。砍掉的功能进暂存池，是路演「未来规划」的素材，也是面试「你砍过什么需求」的答案 |
| 13 | 【原理】 | 数据还没跑出来（实验没到周期），答辩时怎么办？ | 第 2 / 4 节 | 诚实标注「实验进行中，X 月 X 日出数」，给出已有前置数据与预期区间；编造数字按 0 分处理并重审 |
| 14 | 【原理】 | 为什么 P0 总工时要压在上限的 60% 以内？ | 第 3 / 4 节 | 冲刺周必然有联调、修 bug、试用反馈返工；按 100% 排期等于第一天就注定延期 |
| 15 | 【面试】 | 面试官问「讲一下你项目中期怎么汇报的」，你先说哪三句？ | 第 5 节 | 先说阶段与里程碑、再说四段式结构、再说结论配数字；忌上来就演示功能清单 |
| 16 | 【面试】 | 「你砍过什么需求，为什么砍」——追问「砍完后悔吗」，怎么接？ | 第 5 节 | 回到检查点与暂存池：P1 设检查点、P2 进暂存池下一版再评；取舍有依据就不叫后悔，叫按数据迭代 |
| 17 | 【面试】 | 「中期数据不好看，你怎么汇报？」追问「会不会是你实验设计错了」？ | 第 5 节 | 先如实报基准值 → 结果值并附归因，再谈迭代计划；不藏不编，把「数据不好看」讲成「发现了真问题」 |
| 18 | 【面试】 | 「投资人当场质疑你样本有偏」，追问「那这数据还能用吗」？ | 第 5 节 | 承认边界、说明样本构成与适用范围、给补样或交叉验证计划；不硬顶、不沉默、不编数 |
| 19 | 【面试】 | 答项目题时，怎样把「V3 Scope」「决策记录」这类术语自然说出口？ | 第 5 节 | 不要背定义，把它嵌进动作：「我用两条硬依据定 V3 Scope，每个去留都留决策记录」 |
| 20 | 【面试】 | 被连追三层后答不上来，最后一句怎么收才不失分？ | 第 5 节 | 「这个点我当场记下来，进复盘和下一版验证」——把答不上转成有复盘意识，不沉默、不放任跑题 |

## 十、板书要点（按 6 节重排）

```
【第 1 节 · 术语精讲】
11 术语：中期评审 / 里程碑 / V3 Scope / 砍需求 / 投资人视角 / 数据备齐 / 答辩 / 风险预判 / 复盘 / 决策记录 / 验收标准
四组易混：中期评审≠结业路演｜Scope≠需求池｜投资人视角≠用户视角｜评分≠验收标准
金句：先把词说准，才把事做对、把话说得分

【第 2 节 · 答辩标准】
中期评审 = 数据答辩 + Scope 清算
陈述四段 × 2 分钟：问题与方案 / 数据验证 / 成本与计划 / 风险·里程碑·取舍
投资人五问：谁的问题 / 凭什么 / 数据 / 成本 / 能上线吗
评分五维：问题真实度 · 方案完整度 · 数据支撑 · 成本可信度 · 风险预判
及格线：每维 ≥3 且总分 ≥18/25
金句：每一句结论都要配一个数字

【第 3 节 · 原理 B + 反面案例】
Scope 决策：P0 保留 · P1 有条件 · P2 砍
判定依据 = 中期答辩数据 + 两周工时上限（约 80h）
P1 三件套：简化程度 / 检查点 / 不过怎么办
P0 ≤ 上限 60%，P2 进暂存池
理由链：数据 · 竞争 · 工时，每个决定至少两条
反面案例：全是 P0 的表 / 无数据答辩 / P1 写「尽量做」

【第 4 节 · 多轮实操】
单轮 = 讲 8′ + 质询 5′ + 评分 2′ + 迭代复述
第 1 轮打分 → 记质询 → 第 2 轮按意见改 → 再打分（看涨幅，不看绝对值）
巡场三连问：工时上限摆了吗？依据对应哪条数据？P1 检查点写了吗？

【第 5 节 · 面试讲解】
四主题：中期怎么汇报 / Scope 怎么砍 / 数据不好看怎么讲 / 被质疑怎么接
每题四件套：踩分点 · 追问链 · 失败答法 · 60 秒标准答法
金句：答项目题，讲的是取舍，不是功能

【第 6 节 · 复盘 · 归档 · 验收】
三句收束：意见落纸面 / Scope 今晚定稿 / W6 锁定不加需求
V3 Scope 验收四项：五维过线 · 保留有依据 · 砍掉有理由 · 甘特图按 Scope 更新
P5 迭代页：1 组假设→实验→结论 + ≥1 组带来源的基准值→结果值
金句：评审桌上多流汗，冲刺周里少流血
```

## 十一、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 答辩只讲功能不讲数据 | 8 分钟全在演示功能清单，没有一个数字 | 巡场随时打断示范：「停一下，这个判断的数据是什么？」宣讲时明确：无数据论断在数据支撑维度按 0–1 分计 |
| Scope 该砍不砍 | 决策表「全是 P0」；或用「以后会用上」当保留理由 | 用教学示例反推：80 小时盘子摆出来，超了谁让路？「以后会用上」请换算成本周工时和数据依据再谈 |
| 评审意见不落纸面 | 质询意见口头说完即散，Scope 表看不到对应修改 | 硬性要求：每条质询意见当场誊入导学案质询记录栏；Scope 决策表的判定依据须能对应到某条记录或某组数据 |
| 陈述超时、前松后紧 | 问题背景讲 4 分钟，成本与计划 30 秒带过 | 计时员黄牌制度 + 宣讲时给出四段各 2 分钟的硬拆分；超时部分由质询人用五问逼着补回 |
| 把评审当批斗，心态失衡 | 被追问后沉默、放弃答辩 | 讲师定性开场：「评审不是考试，是拿别人的脑子帮自己的项目排雷」；质询规则加一条：每轮质询结束质询人须先说一条本组认可的优点 |
| 术语混淆：把 Scope 当需求池 | 说「我 Scope 里先攒着 20 个功能，以后慢慢做」 | 第 1 节用「旅行行李清单」类比反复校准：Scope 的核心动作是砍、锁定后不加；攒功能的是需求池 / 暂存池 |
| 术语混淆：把评分当验收 | 说「我总分 20，肯定能进 W6」 | 板书并排写清：评分 0–5 分看「多好」，验收过 / 不过看「放不放行」；V3 Scope 验收四项全过才放行，与总分无关 |
| 面试失分：只讲功能不讲取舍 | 答「讲一个你做过的项目」时全程介绍功能，不提砍过什么 | 第 5 节强制用「四段式 + 两条硬依据」重构答法；评分示例里「说出具体功能与背景」「两条硬依据」为必踩分点 |
| 面试失分：数据不好看时编数或含糊 | 被问「数据不好看怎么讲」时说「应该还不错」或临时编一个百分比 | 明确红线：编造数字按 0 分处理并重审；标准答法用「如实报基准值→结果值 + 归因 + 迭代计划」 |
| 面试失分：被质疑时硬顶或沉默 | 被问「样本有偏」时回「不可能」或直接冷场 | 追问防御三步：承认边界 → 说明样本构成与适用范围 → 给补样 / 交叉验证计划；答不上就「记下来进复盘」 |
