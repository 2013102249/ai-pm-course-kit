## 二、教学目标（可测量）

1. 每人能在 6 分钟内完成「问题与方案 2 分钟 / 数据验证 2 分钟 / 成本与计划 2 分钟」三段式中期陈述，且每段至少引用 1 个真实数据（对应课堂评审评分：数据支撑维度）。
2. 每人能接住「投资人五问」中至少 4 问，并给出可复算的数据型回答（对应质询记录表）。
3. 每人能产出 V3 Scope 决策表：每条功能标注 P0/P1/P2 等级、判定依据（答辩数据 + 工时测算）与本周工时，并通过 V3 Scope 验收清单（对应 06-分层习题验收清单）。

## 三、教学重难点

- **重点**：中期答辩的结构化表达——结论先行、每个论断配数字；「投资人五问」作为质询与自检的双重骨架。
- **难点一**：「砍需求」决策。学员普遍舍不得砍、或凭感觉砍。必须让判定依据落到两条硬约束上：中期答辩数据 + 两周工时上限。
- **难点二**：评审意见落纸面。口头意见如不誊写进记录表，Scope 清算时无据可依，W6 又会复发。

## 六、「投资人视角」五问设计

五问是本课质询骨架，也是学员未来融资路演与面试项目深挖的通用追问链。质询人每轮至少选 1 问发起，并沿追问链追第二层。

| # | 五问 | 追问链（第二层） | 好答案标准 |
|---|---|---|---|
| 1 | 这事解决谁的问题？ | 这个人群现在怎么解决？你的方案好多少，好到值得换吗？ | 人群有边界、现状有数字、差异有量级 |
| 2 | 凭什么你能做成？ | 已有人在做，差异在哪？你的独特积累（数据 / 场景 / 分发）是什么？ | 指向别人拿不走的积累，而非「模型更强」 |
| 3 | 数据在哪？ | 样本多少、怎么收集的？被质疑「样本有偏」怎么回？ | 每个论断有出处：问卷 / 访谈 / 评测集 / 竞品数据 |
| 4 | 成本怎么算？ | 单次对话 token 成本多少？1000 活跃用户月成本多少？毛利正吗？ | 数字当场可复算，回扣 W5D3 单位经济模型 |
| 5 | 下周就能上线吗？ | P0 工时合计多少？做不完先砍哪个？ | 能报出工时总数与砍的顺序，引出 Scope |

## 七、V3 Scope 决策规则

**判定依据只有两条：中期答辩数据 + 两周工时上限（W6 冲刺周至路演收尾，单人可投入约 80 小时）。两条依据逐条核对，不允许「凭感觉」。**

| 等级 | 判定标准 | 表决口径 | W6 处理 |
|---|---|---|---|
| P0 保留 | 有数据支撑（问卷 / 访谈 / 评测 / 试用数据至少其一），且工时在上限内 | 无条件保留，P0 总工时 ≤ 上限 60% | W6D1–D3 必做，路演必演示 |
| P1 有条件 | 数据部分支撑，或依赖外部条件；全量做会爆工时 | 必须写明三件事：简化到什么程度、触发条件与检查点（建议 W6D2 中午核心链路跑通）、不过怎么办 | 检查点达标才做，否则自动降 P2 |
| P2 砍 | 无数据支撑、无差异化、或两周工时装不下 | 写入「暂存池」并附书面理由（一句话即可，不许空着） | W6 不做；路演可作未来规划讲述 |

## 八、砍需求决策演示参考答案（教学示例：留学文书助手）

教学示例与学员项目区隔，避免对号入座。背景：两周工时上限约 80 小时，三个候选功能全做需 64 小时，工时看似装得下，仍按理由链逐条裁决。

| 功能 | 答辩数据 | 工时测算 | 裁决 | 理由链 |
|---|---|---|---|---|
| F1 文书智能改写 | 问卷 82% 排第一；访谈 5/5 提及；原型已有 | 打磨 12h | P0 保留 | 数据强 + 有基础 + 工时小 |
| F2 智能选校推荐 | 访谈 4/5 提及选校焦虑，但 0 人愿单独付费；需接外部选校数据 | 全量 28h；简化版（按背景推荐三档）8h | P1 有条件 | 数据不弱但全量爆工时；降为简化版，触发条件 = W6D2 中午核心链路跑通，不过自动降 P2 |
| F3 简历一键生成 | 问卷仅 9% 提及 | 开发 + 模板维护 24h | P2 砍 | 数据弱 + 竞品免费遍地无差异化 + 工时挤占 P0 打磨 |

演示结论：三进二。每个决定背后必须站着「数据、竞争、工时」中至少两条，缺一条依据即退回重判。

## 九、课堂提问设计（7 问）

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 中期评审和 W6D5 结业路演，考察的东西有什么不同？ | 规则宣讲 | 中期看「方向对不对、盘子切得准不准」，考决策；路演看「做没做出来、讲不讲得清」，考结果。今天错，下周还来得及改 |
| 2 | 投资人五问里，哪一问答不上最致命？为什么？ | 规则宣讲 | 开放讨论，引导到第 1 问或第 3 问：人群不成立则一切归零；数据缺失则所有论断等于没说 |
| 3 | 「我的功能个个都重要，一个都不能砍」，这句话怎么反驳？ | Scope 规则宣讲 | 反问两句：两周工时装得下吗？每个功能的答辩数据分别是什么？重要是价值判断，Scope 是资源约束下的排序 |
| 4 | P1 的「有条件」要写成什么样才合格？ | Scope 规则宣讲 | 三件套：简化到什么程度 + 检查点时间 + 不过怎么办。「尽量做」不算条件 |
| 5 | 砍掉的功能是不是白做了？ | 砍需求演示后 | 不是。砍掉的功能进了暂存池，是路演「未来规划」的素材，也是面试「你砍过什么需求」的答案 |
| 6 | 数据还没跑出来（实验没到周期），答辩时怎么办？ | 巡场常见问题 | 诚实标注「实验进行中，X 月 X 日出数」，给出已有前置数据与预期区间；编造数字按 0 分处理并重审 |
| 7 | 为什么 P0 总工时要压在上限的 60% 以内？ | Scope 清算 | 冲刺周必然有联调、修 bug、试用反馈返工；按 100% 排期等于第一天就注定延期 |

## 十、板书要点

```
中期评审 = 数据答辩 + Scope 清算
投资人五问：谁的问题 / 凭什么 / 数据 / 成本 / 能上线吗
Scope 决策：P0 保留 · P1 有条件 · P2 砍
判定依据 = 中期答辩数据 + 两周工时上限（约 80h）
P0 ≤ 上限 60%，P1 写明检查点，P2 进暂存池
金句：Scope 是砍出来的——什么都保留，等于什么都没有资源做好
```

## 十一、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 答辩只讲功能不讲数据 | 6 分钟全在演示功能清单，没有一个数字 | 巡场随时打断示范：「停一下，这个判断的数据是什么？」宣讲时明确：无数据论断在数据支撑维度按 0–1 分计 |
| Scope 该砍不砍 | 决策表「全是 P0」；或用「以后会用上」当保留理由 | 用教学示例反推：80 小时盘子摆出来，超了谁让路？「以后会用上」请换算成本周工时和数据依据再谈 |
| 评审意见不落纸面 | 质询意见口头说完即散，Scope 表看不到对应修改 | 硬性要求：每条质询意见当场誊入导学案质询记录栏；Scope 决策表的判定依据须能对应到某条记录或某组数据 |
| 陈述超时、前松后紧 | 问题背景讲 4 分钟，成本与计划 30 秒带过 | 计时员黄牌制度 + 宣讲时给出三段各 2 分钟的硬拆分；超时部分由质询人用五问逼着补回 |
| 把评审当批斗，心态失衡 | 被追问后沉默、放弃答辩 | 讲师定性开场：「评审不是考试，是拿别人的脑子帮自己的项目排雷」；质询规则加一条：每轮质询结束质询人须先说一条本组认可的优点 |
