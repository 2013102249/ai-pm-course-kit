7第 2 节好项目是怎么死在推进上的① 算法说做不到 / 工程排不上 / 消息没人回；② deadline 前还在开会；③ 大部分项目死于推进不动、非技术不行；④ 现场调研：你的项目卡在哪现场调研点 2–3 名学员；收口「你们自己验证了今天的课题」—；原第 3 页保留
8第 2 节AI 项目的三角协作① 三条泳道：产品定方向与验收 / 算法管模型与数据 / 工程管系统与稳定；② 数据回流闭环；③ 研发三角 = 三种职能角色；④ 上线即新一轮开始手指沿泳道与箭头走一遍；回扣第 1 节「研发三角」卡AI产品研发流程图；原第 4 页保留
9第 2 节谁在哪个环节交付什么① 八环节交付物接力（需求调研 → PRD → 数据准备 → 选型 → Prompt/工作流 → 工程开发 → 评测验收 → 上线监控）；② 产品交给算法的是带数据来源与标注标准的需求定义；③ 评测验收画在产品泳道；④ W2 合规清单在数据准备格是硬约束提问设计 2、3：产品交给算法什么 / 验收为何在产品泳道；点出「这是一条依赖」AI产品研发流程图；原第 5 页保留
10第 2 节产品经理的四个抓手① 需求翻译；② 验收标准（先于开发）；③ 里程碑（可验收交付物，不是 deadline）；④ 风险清单（活的文档）；⑤ 边界：都能对话、都能验收，不都动手、不越权让学员抄录；补正 / 反案例各 1（越权替算法定模型 → 责任模糊）—；原第 6 页保留并深化
11第 2 节案例：「算法说做不到」① 教学示例：主项目要个性化推荐，算法说做不到；② 退缩与告状都是错的选择；③ 拆出「冷启动没数据 + 排序没标注」两个可解子问题；④ 标注「教学示例」讲故事节奏，停在「她会怎么办」；点明这是「阻塞」不是「依赖」—；原第 7 页保留
12第 2 节翻译三问① 具体哪一步做不到（不是「为什么」）；② 有没有替代路径（先规则后模型）；③ 代价是什么（标注人力 / 转化损失）；④ 终点：写成新需求边界与共识；⑤ 边界：真做不成走变更、不硬磨现场小组拆解 3 分钟（多轮追问场景）；补「为什么用哪一步」的语言原理—；原第 8 页保留并深化

16第 3 节向上汇报：结论先行—数据支撑—需要的支持① 三段结构 30s / 90s / 60s；② 万能开头句；③ 给选择题不给问答题；④ 金句「汇报是隐形 KPI」放慢重复；⑤ 不能藏风险提问设计 7：结论是「我做了什么」还是「状态 + 请求」；补「看汇报对象调深度」汇报三段结构示意卡；原第 13 页保留并深化
