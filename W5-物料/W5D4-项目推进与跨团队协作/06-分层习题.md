## 第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错三种题型）

### 一、选择题（T1–T6，每题 5 分，共 30 分）

**T1. 关于「里程碑」，理解正确的是：**
A. 里程碑就是 deadline，核心是日期
B. 里程碑是带验收标准、能判断过没过的关键交付物节点
C. 里程碑只在项目结束时设一个
D. 里程碑越多越好，越多越可控

**T2.「评测验收依赖评测集就绪」与「算法说做不到把项目卡住了」，分别属于：**
A. 都是依赖
B. 都是阻塞
C. 前者是依赖（计划内该等），后者是阻塞（计划外被卡）
D. 前者是阻塞，后者是依赖

**T3. 关于「验收」与「测试」，正确的是：**
A. 验收和测试是一回事，都由测试岗完成
B. 测试找缺陷，验收是产品经理按评测集判「能不能上线」的产品决策
C. 验收由算法主导，因为只有算法懂指标
D. 验收就是跑一遍评测集出个分数

**T4.「隐形 KPI」中 KPI 的全称与中文是：**
A. Key Process Input（关键过程输入）
B. Key Performance Indicator（关键绩效指标）
C. Known Product Item（已知产品项）
D. Key Point Index（关键点指数）

**T5.「翻译三问」的第一问是：**
A. 为什么做不到
B. 具体是哪一步做不到
C. 这个需求能不能砍掉
D. 谁来背这个责任

**T6. 关于「研发三角」，理解正确的是：**
A. 三个必须独立设立的部门
B. 产品、算法、工程三种职能角色的分工结构，小团队一人兼两角也成立
C. 产品、设计、测试三方
D. 需求、开发、上线三个阶段

### 二、连线题（T7，共 12 分）

**T7. 把左侧术语与右侧「最容易混淆的相邻概念 + 关键差别」连线（每组 2 分）。**

| 左侧术语 | | 右侧辨析（打乱） |
|---|---|---|
| ① 里程碑 | | A. 通知：单方面告知；本词要双方书面确认、可追溯 |
| ② 依赖 | | B. 随口加需求：一句话带过；本词要评估影响并留痕 |
| ③ 验收 | | C. deadline：只有日期；本词有验收标准、能判过没过 |
| ④ 共识 | | D. 正式绩效指标：白纸黑字可量化；本词是「靠不靠谱」这类印象 |
| ⑤ 隐形 KPI | | E. 测试：找缺陷；本词是判能否上线的产品决策 |
| ⑥ 变更 | | F. 阻塞：计划外意外卡住；本词是计划内本就该等的约束 |

### 三、改错题（T8，共 12 分）

**T8. 下面 4 句话各有一处术语误用，圈出并改正，再各写一句理由（每句 3 分）。**

1. 「这个需求周五截止，这就是我们的里程碑，到点问一下做完了没就行。」
2. 「算法说做不到，这属于一条依赖，排进甘特图等着就好，不用上报。」
3. 「产品把验收标准写进 PRD，等开发完再让测试岗来主导验收。」
4. 「老板临时加个功能，反正不大，直接加进这周排期，算一次变更。」

### 四、简答题（T9–T12，共 46 分）

**T9.（10 分）**「共识」和「通知」差在哪？为什么跨部门协作里「我以为」不算共识？

**T10.（12 分）**「变更」和「随口加需求」差在哪？一次合格的变更要评估哪四项影响？

**T11.（12 分）**「风险清单」和「问题日志」差在哪？结合甘特图说明：为什么「留半天缓冲」本身也是风险管理？

**T12.（12 分）**从 12 个当日术语中任选 4 个，各写一句 ≤30 字的一句话定义；并写出 KPI、PRD（Product Requirements Document）、MVP（Minimum Viable Product）三个缩写的中文全称。

## 第 3 层 · 求职挑战题（面试层，4 题：原 2 题保留 + 新增 2 题）

**15.（原第三层第 10 题保留，30 分）汇报结构改写题**

面试官情境题（教学示例）：「给你一段某 PM 的周报，问题在哪？请改写成结论先行的版本。」

要求：先指出这段周报的 2 个问题，再改写成「结论先行—数据支撑—需要的支持」三段结构（数据可以合理虚构，但要标注为虚构示例）。

**16.（原第三层第 11 题保留，30 分）案例分析：跨部门推动**

情境（教学示例）：你的主项目需要数据团队 3 个工作日内提供一批脱敏对话数据。你在群里发了两次消息，没人回复；私聊对方负责人，对方说「最近忙，排期看看吧」。距离你需要的日期只剩 4 天。请给出你的下一步行动方案（至少 3 步，按顺序），并说明每步对应机制三件套中的哪一件。

① 三方分别站在哪个术语视角（里程碑 / 验收 / 成本）？冲突的根因是什么？

**18.（本课版新增，30 分）汇报对象与模板题**

情境（教学示例）：同一份项目素材，要分别向「直属上级」和「大老板」汇报。请写出：① 周报三栏与月报三段各是什么；② 对两类对象在「讲细节 / 讲结论」上的深度差异；③ 用一句话说明为什么「项目周报」是 W7 写简历时的数字来源库。

## 第 4 层 · 面试实战（6 题，每题含踩分点 / 追问链 / 评分表 / 参考答案）

> 用法：对应板块两两模拟抽题；每题 60 秒口播 + 追问 2–3 层；评分表满分 10 分，≥6 分为达标（换算自评 ≥3 分）。
> 四类覆盖：算法说做不到（M1）、怎么和研发对齐（M2）、项目延期怎么汇报（M3、M4）、跨团队冲突（M5、M6）。

### M1 · 算法说做不到怎么办（题型：场景设计）

| 项目 | 内容 |
|---|---|
| **踩分点** | ① 不情绪化（不告状、不直接砍需求）2 分；② 用翻译三问把整体拒绝拆成环节级子问题 2 分；③ 给 ≥2 条替代路径并说清代价 2 分；④ 写成需求边界 / 共识，含 ≥1 个当日术语 2 分 |
| **追问链** | 第 1 层「拆完发现是真做不成呢？」→ 走变更、砍范围，不硬磨（翻译三问的边界）；第 2 层「算法用术语驳回、你听不懂？」→ 请他用「哪一步、什么条件」重述，复述确认、落到书面，不装懂；第 3 层「他仍不配合？」→ 机制三件套 + 双方上级对齐优先级（机制升级非情绪升级） |
| **失败答法 + 失分原因** | 「我会找老板说明算法不配合」——情绪化、制造冲突、无翻译动作，踩分点①②全丢，落进「面试失分·情绪化」 |
| **评分表** | 见下方「M1 评分表」 |

**M1 评分表**

| 踩分点 | 分值 | 得分 | 判分说明 |
|---|---|---|---|
| ① 不情绪化 | 2 | | 出现「告状 / 直接砍」即 0 分 |
| ② 翻译三问拆子问题 | 2 | | 三问齐全满分，缺一问扣 1 |
| ③ 替代路径 + 代价 | 2 | | ≥2 条路径 1 分、说清代价 1 分 |
| ④ 需求边界 / 共识 + 术语 | 2 | | 含 ≥1 术语 1 分、写成书面边界 1 分 |
| 60 秒内答完、结构稳定 | 1 | | 开口先给结论 |
| 追问链防御（被追 2 层不崩） | 1 | | 用「我补充一层」回到踩分点 |
| **合计** | **10** | | ≥6 达标 |

档位：8–10 优秀（含边界与机制升级）｜6–7 合格（三问齐全、有替代路径）｜0–5 待改进（触发失败答法或 60 秒无结论）。

**参考答案（60 秒标准答法）**：「我不会把『做不到』当终局。第一步用翻译三问：先问具体是哪一步做不到，把整体判决拆成环节级子问题——比如个性化推荐其实是冷启动没数据、排序没标注两个问题；第二步问有没有替代路径，热门兜底、规则冷启动、先规则后模型都能让功能先跑起来；第三步问代价，把标注人力、注册转化损失摆到桌面。最后把『在什么成本、什么时间内能做到什么程度』写成新的需求边界，双方签字形成共识。大多数做不到，其实是按当前方案做不到；确实做不成，我就走变更砍范围，不硬磨。」

### M2 · 怎么和研发对齐排期（题型：项目深挖）

| 项目 | 内容 |
|---|---|
| **踩分点** | ① 先理清依赖（谁等谁）2 分；② 用甘特图按天排、留缓冲 2 分；③ 区分依赖与阻塞、阻塞单独上报 2 分；④ 含「甘特图 / 依赖 / 里程碑」术语 2 分 |
| **追问链** | 第 1 层「研发说排不上，怎么判断真假？」→ 问清哪条依赖被卡、能否并行，把口头「快了」换成书面交付日期；第 2 层「一处延误了？」→ 看缓冲、看能否并行补，触发风险清单应对；第 3 层「他给不出日期？」→ 机制升级 + 启动替代路径 |

|---|---|
| 合格（24–31 分） | 四项任务全覆盖且按天可执行 |
| 良好（32–37 分） | 给出明确的砍 / 压决策与理由，试用邀约前移 |
| 优秀（38–40 分） | 体现并行排期（邀约与开发并行）与缓冲意识（不把 5 天排满） |

**第 13 题参考答案**：① 不是「记不住」，而是「轮次多了以后早期关键信息被稀释」——整体拒绝拆成环节级子问题；② 替代路径 ≥2：每轮结束抽取摘要存起来 / 把关键信息做成结构化记忆注入（上下文工程）/ 限制有效轮次；③ 代价：摘要有信息损耗、结构化记忆要多做一层设计、限轮次牺牲长对话体验；④ 真做不成则走「变更」：把「全量多轮」改成「限定轮次 + 摘要」写进需求边界，双方签字形成共识，不硬磨（翻译三问的边界）。

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 三问齐全、拆出环节级子问题 |
| 良好（32–37 分） | ≥2 条替代路径且各带代价 |
| 优秀（38–40 分） | 含「真做不成走变更、不硬磨」的边界说明，并回扣共识 |

**第 14 题参考答案**：四项影响——依赖（积分页依赖用户数据接口，可能卡在接口未就绪）、排期（5 天已排满，加页会吃掉缓冲 / 挤压测试）、风险（冒出「接口延迟」「路演演示不完整」两条新风险，须补进风险清单）、验收（上线口径与里程碑要重签）。二选一诉求示例：「A，本周五先上不含积分页的核心链路，积分页挪到下周期；B，砍掉 1 个次要功能换积分页，本周五一并上。我建议 A，理由：路演底线是可演示核心链路，缓冲不能再吃。」理由：范围可以变，但须评估 + 留痕 + 重新书面共识，悄悄变等于把风险留到演示现场。

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 四项影响覆盖 ≥3 项，有二选一诉求 |
| 良好（32–37 分） | 四项影响齐全，二选一带建议与理由 |
| 优秀（38–40 分） | 点破「顺手加一下不算变更」的误区，说明留痕与重新共识 |

### 第 3 层 · 求职挑战（三档 Rubric）

**第 15 题参考答案**：问题一，无结论——读完不知道项目什么状态；问题二，无数字——每件事都没有结果度量（另，「下周想聊聊」无议题无选项也是问题，答出加分）。改写示例（数据为虚构示例，已标注）：「本周项目整体正常，有 1 个风险需要您决策。进展：竞品拆解完成 3 家（虚构示例），输出选型建议 2 条；与算法对齐数据口径，标注标准已书面确认。风险：调研文档比计划晚 2 天，因增加了 1 个竞品维度。需要您拍板：A，明早先过初稿方向；B，周一一并交终稿。建议 A。」

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 指出问题 ≥2 个，改写有结论先行意识 |
| 良好（24–27 分） | 三段结构完整，进展带数字，诉求明确 |
| 优秀（28–30 分） | 指出「无议题的约聊」问题，诉求给二选一并附建议与理由，或补充「与计划对比」表述 |

**第 16 题参考答案**：参考行动链——① 不再群发，改为带议题的日历邀请 + 一页纸需求说明（交付物明确：数据条数、脱敏标准、格式）；② 目标对齐开场：说明这批数据对数据团队的价值（如成为他们的案例数据 / 下季度指标），请对方给一个「能给的最早时间」，哪怕不是你要的时间；③ 时间写死并升级：若仍无承诺，请自己的上级与对方上级对齐优先级（机制升级而非情绪升级）；④ 同时启动替代路径：先用脱敏合成数据 / 自己标注的小样本顶住，把 4 天风险对冲掉。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 行动 ≥3 步且按顺序合理 |
| 良好（24–27 分） | 体现机制三件套中至少两件，行动具体可执行 |
| 优秀（28–30 分） | 额外含升级路径（上级对齐）或替代方案对冲（合成数据 / 小样本），体现「不把项目押在单一协调上」的系统性 |

**第 17 题参考答案**：① 三方视角——产品站「里程碑」（周五可演示的交付物节点）、测试工程师背景学员站「验收」（评测集与 badcase 口径）、算法站「成本 / 阻塞」（补标注 2 天人力）；根因是「依赖 / 阻塞 / 验收 / 共识」四个术语没对齐，不是谁对谁错。② 四步——共识：把「可演示 / 上线口径 / 谁判定」三方书面写清；变更：把全量范围改「核心链路 + 5 人小范围试用」，评估对依赖链与里程碑的影响并留痕；向上汇报：给二选一（A 砍 1 个次要功能换 1 天补标注保 10 人试用 / B 试用缩到 5 人），建议 A；风险清单：把「标注补不齐」写成概率高影响大、应对带动作 + 责任人 + 时间、触发信号设「周三晚不足 50 条」。③ 追问应答：验收是产品主导的产品决策（能不能上线取决于用户 / 场景 / 风险承受力），但必须基于评测集证据、口径来自三方共识；不是测试一票否决，也不是产品一人独断。

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 三方视角识别正确，四步写出 ≥3 步 |
| 良好（32–37 分） | 四步齐全且各步标注对应术语，二选一有建议 |
| 优秀（38–40 分） | 追问应答说清「产品决策 + 评测集证据 + 共识口径」三层，且点破根因是术语没对齐 |

**第 18 题参考答案**：① 周报三栏：本周进展（带数字、对比计划）、风险与求助（写清需要的支持）、下周计划（写到「可验收」粒度）；月报三段：月初目标回顾、关键结果（用数字交代差距）、下月计划与资源。② 深度差异：直属上级可讲过程细节（他替你扛细节风险），大老板只讲结论与决策、三分钟内让他听懂「要我拍什么板」；同一份素材两种剪法。③ 项目周报逐周留带数字的进展与对比，W7 写简历时所有「完成度 / 评测分 / 用户数 / 成本」都能回溯，是数字来源库。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 周报三栏 / 月报三段写全 |
| 良好（24–27 分） | 说清两类对象的深度差异 |
| 优秀（28–30 分） | 点出「周报 = 简历数字来源库」并可验收粒度 / 同一素材两种剪法 |

### 第 4 层 · 面试实战

M1–M6 每题的踩分点、追问链、失败答法、评分表（含分值、判分说明、三档 Rubric）与 60 秒标准答法已随题给出，见本层各题表格与「参考答案（60 秒标准答法）」。统一判分口径：满分 10 分，≥6 分达标（换算 5 分制自评 ≥3 分）；出现该题「失败答法」即①②④类踩分点按 0 分计；被追问 2 层仍能用「我补充一层」回到踩分点的，追问链防御项给满分。

**本日面试金句（3 条，供评分时对照「是否用上当日语言」）**
1. 「做不到」不是答案，是提问的开始——拆到子问题，才有解法。
2. 产品经理的价值不在画图，在翻译——把「不可能」翻译成「什么条件下可能」。
3. 向上汇报不是表功，是给上级确定性——汇报是隐形 KPI。
