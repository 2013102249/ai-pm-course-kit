3. 能用「翻译三问」拆解一个「算法说做不到」的拒绝，并给出至少 2 条可执行的替代路径（对应对应板块案例练习 + 习题第 2 层）。

6. **面试目标**：能用 60 秒标准答法应答「算法说做不到怎么办」「怎么和研发对齐」「项目延期怎么汇报」「跨团队冲突怎么处理」四类高频题，每题至少命中 3 条踩分点、答满 2 层追问、且不出现典型失败答法（对应对应板块两两模拟 + 面试模拟记录表自评分 ≥3 分 + 习题第 4 层评分表）。
7. 能把本日 5 类产出登记进《本日作品集积木》并写清归档位置，当堂验收 5 项齐备（对应对应板块作品集归档动作）。

## 三、教学重难点

- **重点一**：AI 项目研发流程的三角协作——产品 / 算法 / 工程谁在哪个环节交付什么；产品经理在流程中的四个抓手：需求翻译、验收标准、里程碑、风险清单。
- **重点二**：12 个当日术语的精确定义与相邻概念辨析（对应板块）；把当日知识转成面试得分点（对应板块）。
- **难点一**：把「算法说做不到」从「终局判决」翻译成「可拆解的子问题集合」。学员容易在第一句「做不到」面前放弃，或直接向上升级制造冲突。
- **难点二**：风险清单写「空话」——只写风险不写应对、应对没有责任人和时间。学员误以为风险清单是「写给讲师看的作业」。
- **难点三**：向上汇报流水账。学员默认汇报 = 罗列做过的事，不会把结构换成「上级视角」。
- **难点四 · 术语混淆（新增）**：学员容易把「里程碑 ↔ deadline」「依赖 ↔ 阻塞」「验收 ↔ 测试」「共识 ↔ 通知」「隐形 KPI ↔ 正式绩效指标」「变更 ↔ 随口加需求」六组相邻概念混为一谈；且对「研发三角」误以为是三个独立部门、对「翻译三问」第一问误记成「为什么做不到」。对应板块须用「易混辨析 + 当堂小测」逐组纠正，验收标准为术语自测表 ≥10/12 正确。
- **难点五 · 面试失分（新增）**：学员在「算法说做不到」「项目延期」类题里容易出现三种失分——① 情绪化答法（「找老板告状」「那就砍需求」）；② 无结构答法（想到哪说到哪，60 秒内不给结论）；③ 被追问即崩（追问「数据哪来的」「为什么现在才说」时改口或沉默）。对应板块须用「踩分点清单 + 追问链演练 + 失败答法对照」逐项打靶，验收标准为两两模拟自评分 ≥3 分且不触发失败答法。

## 六、核心环节教学设计详解

### 1. 术语精讲教学设计（对应对应板块）

讲法：每张术语卡按「一句话定义（≤30 字）→ 生活类比（非技术场景）→ 易混辨析（至少 1 个相邻概念）→ 面试说法（可直接说出口）→ 术语卡链接」五步过，12 张卡约 25 分钟；随后 15 分钟做六组易混概念辨析（里程碑↔deadline、依赖↔阻塞、验收↔测试、共识↔通知、隐形 KPI↔正式绩效指标、变更↔随口加需求），最后 10 分钟当堂小测（习题第 0 层选 10 题）。

- 首次出现的英文缩写须给全称与中文：KPI（Key Performance Indicator，关键绩效指标）、PRD（Product Requirements Document，产品需求文档）、MVP（Minimum Viable Product，最小可行产品）。
- 术语只从当日内容提取，不引入当天用不到的新概念；「依赖 / 阻塞 / 共识 / 变更」四个词虽在原 本课未作为词条出现，但均出自当日「交付物接力 / 卡点 / 双方签字确认 / 砍功能」等原内容，属提取而非新增技术概念。
- 零层入口：对「完全不了解技术」的 5/6 学员，先用 `00-技术零层.md` 补「数据、模型、标注、评测集」四个底层名词，再进术语卡，避免「用技术比喻技术」。

### 2. 三角协作教学设计（对应对应板块，配图：AI产品研发流程图.svg）

讲图顺序：先讲三条泳道各管什么，再沿箭头讲交付物接力，最后落「数据回流 · 持续迭代」闭环。核心表格（板书同步）：

| 环节 | 主导方 | 交付物 | 产品经理在其中的动作 |
|---|---|---|---|
| 需求调研 | 产品经理 | 调研报告 + 需求定义 | 定义「为谁解决什么问题、成功指标是什么」 |
| PRD | 产品经理 | PRD（含异常兜底） | 把需求翻译成可开发的功能与边界 |
| 数据准备 | 算法 | 数据集 + 数据说明 | 给数据来源、标注标准，确认合规（回扣 W2） |
| 选型评估 | 算法 | 选型评估报告 | 给场景约束与成本上限，参与评审 |
| Prompt / 工作流 | 产品经理 | 提示词 + Dify/Coze 工作流编排 | 主导设计，用 W1–W3 能力落地 |
| 工程开发 | 工程 | 可运行系统 | 排期确认、验收标准前置对齐 |
| 评测验收 | 产品经理 | 验收报告（用 W2 评测集） | 主导验收，判定能不能上线 |
| 上线监控 | 工程 | 监控看板 + 指标 | 定义监控指标阈值，接数据回流做迭代 |

归纳四个抓手（学员抄录）：**需求翻译**（把业务语言翻成技术语言、把「做不到」翻成「什么条件下可以」）、**验收标准**（先于开发写清楚，用评测集说话）、**里程碑**（每个里程碑必须是可验收的交付物，不是 deadline）、**风险清单**（活的文档，跟周报走）。

讲图定位话术：「这张流程图，今天之后不是知识，是工具——你们要把它变成自己主项目的甘特图。」

**深化点（本课版）**：补一处「边界」——产品经理「都能对话、都能验收，但不用都能动手」。正面案例：产品在数据准备环节只需说清标注标准与合规底线，不必自己跑清洗脚本；反面案例：产品越权替算法定模型选型，出问题后责任反而模糊。

### 3. 风险清单三栏法教学（对应对应板块）

| 栏 | 写什么 | 合格标准 | 反例 |
|---|---|---|---|
| 风险 | 具体事件，写「会发生什么」而不是「担心什么」 | 一句话说清影响对象与后果 | 「进度可能不太乐观」 |
| 概率影响 | 概率高 / 中 / 低 × 影响大 / 中 / 小 | 两维都要给，并说明判断依据 | 只写一个「高」字 |
| 应对 | 动作 + 责任人 + 时间；含触发信号 | 应对里出现人名和日期 | 「加强关注」「持续跟进」 |

讲师示范 2 条（基于主项目常见风险），学员当堂续写至 5 条。核心话术：「风险清单不是写给自己的日记，是写给团队的合同——没有责任人的风险，不算风险。」

**深化点（本课版）**：补「为什么两维都要」——风险管理的本质是注意力分配，概率高影响大的前移、概率低影响小的备查即可；补「常见误解」——风险清单不是「已发生问题日志」，它管的是还没发生、但要提前管的事。

### 4. 向上汇报结构教学（对应对应板块前半）

三段结构（学员抄录）：
1. **结论先行**（30 秒）：第一句话说清「项目现在是什么状态、今天要你做什么决策」。允许的句式：「关于 X 项目，我汇报三件事：进展、风险、需要的支持。」
2. **数据支撑**（90 秒）：2–3 条关键进展，每条带数字（完成度、评测分、用户数、成本），对比计划讲「提前 / 正常 / 延迟」。
3. **需要的支持**（60 秒）：风险 1–2 个，诉求要明确到「要人、要时间、还是要拍板」，并给出你建议的选项（给选择题不给问答题）。

反面教材（教学示例）：一段周报从「周一开了会」讲到「周五写了文档」，七件事没有一件有数字、有结论——上级读完不知道你到底想说什么。改写示范见 02-讲课稿对应板块。

**深化点（本课版）**：补「看汇报对象调深度」——直属上级可讲过程细节，大老板只讲结论与决策；补「常见误解」——汇报不是表功，是给上级确定性，风险也要报，上级要的是「风险被管理着的项目」。

### 5. 「产品与测试 / 算法视角冲突」案例教学设计（对应对应板块，本期新增）

- 背景（教学示例，不出现真实姓名）：主项目临近 W6D4 试用，产品经理按里程碑要求「本周五交付可演示版本」；测试工程师背景学员提出「追问类 badcase 未跑完、评测集仅 30 条，不建议按当前范围上线」；算法同学补充「补标注要 2 天人力」。三方视角冲突：产品盯里程碑、测试盯验收口径、算法盯成本。
- 拆解路径：① 用「共识」把三方口径写下来（上线 = 什么标准、谁判定）；② 用「变更」评估压缩范围对依赖与排期的影响；③ 用「向上汇报」给上级二选一（A 砍次要功能换 1 天补标注 / B 试用范围先缩到 5 人）；④ 把冲突写进「风险清单」并设触发信号。
- 讨论题（10 分钟）：「验收到底是产品的权力还是测试的权力？」「如果算法说补标注要 2 天，这个『做不到』用翻译三问怎么拆？」
- 讲师收口：视角冲突不是谁对谁错，是「依赖 / 阻塞 / 验收 / 共识」四个术语没对齐；这正是对应板块术语在对应板块的一次实战回收。

### 6. 汇报演练环节设计（对应对应板块后半，方案详见 07-交互使用说明）

- 组织形式：三人一组（汇报人 / 上级扮演者 / 观察员），时间盒 9 分钟，每人轮转：汇报 2 分钟 + 反馈 1 分钟。
- 互评三维：结论先行 / 数据支撑 / 诉求明确，各 1–5 分，写在导学案互评表。
- 学员在对应板块讲授阶段即按模板边听边填稿，演练不等「准备好」，用真实主项目素材。
- 讲师点评 1–2 组，只评结构与数字，不评口才。

### 7. 面试讲解教学设计（对应对应板块，全新）

- 8 道题覆盖四类高频场景：「算法说做不到怎么办」（2 题）、「怎么和研发对齐」（2 题）、「项目延期怎么汇报」（2 题）、「跨团队冲突怎么处理」（2 题）。
- 每题按 5 项过：题目 + 题型 / 踩分点 3–4 条 / 2–3 层追问链 / 典型失败答法 + 失分原因 / 60 秒标准答法（含当日至少 1 个术语）。
- 节奏：题型拆解 15′（讲 8 题的踩分点结构）→ 示范答 15′（讲师演 2 题 60 秒标准答法 + 失败答法对照）→ 两两模拟 20′（上级扮演者持面试追问卡连追 2–3 层，汇报人用标准答法应答，观察员填面试模拟记录表）。
- 收口：统一附「本日面试金句」3 条，要求学员抄录进导学案。

## 七、课堂提问设计（20 问：术语辨析 8 + 面试追问 7 + 原理 5）

| # | 类别 | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|---|
| 1 | 术语辨析 | 「里程碑和 deadline 差在哪？为什么『周五交 PRD』不算里程碑？」 | 对应板块 | 里程碑有验收标准能判过没过，deadline 只有日期；引导说出「含异常兜底的 PRD V2.0 过审」才是里程碑 |
| 2 | 术语辨析 | 「『评测验收依赖评测集就绪』和『算法说做不到把项目卡住了』，哪个是依赖、哪个是阻塞？」 | 对应板块 | 前者是计划内的先后约束（依赖），后者是计划外意外卡住（阻塞）；引导「依赖排进计划，阻塞要上报 + 绕行」 |
| 3 | 术语辨析 | 「验收和测试是不是一回事？为什么评测验收画在产品泳道？」 | 对应板块 | 测试找缺陷、验收判「能不能上线」是产品决策；产品用 W2 评测集主导 |
| 4 | 术语辨析 | 「群里发一句『这个需求改一下』算不算共识？跟通知差在哪？」 | 对应板块 | 不算；共识要双方确认、书面、可追溯，通知是我说你听、「我以为」不算 |
| 5 | 术语辨析 | 「隐形 KPI 里的 KPI 全称是什么？为什么汇报算隐形 KPI？」 | 对应板块 | Key Performance Indicator（关键绩效指标）；上级对项目的判断大多来自汇报，不写进考核表却左右评价 |
| 6 | 术语辨析 | 「随口加一个功能，算不算变更？变更要评估什么？」 | 对应板块 | 不算；变更要评估对依赖、排期、风险、验收的影响并留痕 |
| 7 | 术语辨析 | 「研发三角是不是三个独立部门？小团队一人兼两角还成立吗？」 | 对应板块 | 是三种职能角色不是三个部门；成立，三角讲的是职能分工不是组织架构 |
| 8 | 术语辨析 | 「翻译三问第一问为什么是『哪一步做不到』，不是『为什么做不到』？」 | 对应板块 | 「为什么」像质问会触发防御，「哪一步」直接把整体判决拆成环节级子问题 |
| 9 | 原理 | 「你的主项目现在卡在哪一步？卡你的是技术问题，还是人和协作问题？」 | 对应板块导入 | 预设多为「算法不知道行不行」「没人配合」「不知道排期对不对」——顺势引出：技术之外的能力才是今天的主菜 |
| 10 | 原理 | 「流程图上，需求调研到数据准备的箭头为什么是从产品指向算法？产品交给算法的到底是什么？」 | 对应板块 | 交付的是「带数据来源与标注标准的需求定义」；引导：PRD 之外还要给「数据语言」的需求 |
| 11 | 原理 | 「评测验收这一格为什么画在产品经理的泳道里？」 | 对应板块 | 上线与否是产品决策，不是技术决策；产品用 W2 评测集主导验收——回扣「验收标准」抓手 |
| 12 | 原理 | 「算法同事说『做不到』，你的第一句话应该问什么？」 | 对应板块案例 | 不是「为什么做不到」，而是「具体是哪一步做不到」——把整体拒绝拆成环节级问题；引出翻译三问 |
| 13 | 原理 | 「风险应对里写『持续跟进』，行不行？」 | 对应板块 | 不行——应对必须是「动作 + 责任人 + 时间」，并带触发信号；反问：跟进什么？谁跟进？到什么程度算跟进完？ |
| 14 | 面试追问 | 「面试被问『算法说做不到怎么办』，第一句答『我会找老板协调』会丢哪几分？」 | 对应板块 | 触发情绪化失败答法：显得制造冲突、无翻译动作；应先用翻译三问拆子问题 |
| 15 | 面试追问 | 「面试官追一句『数据哪来的』，你 60 秒答法里第二段要补什么？」 | 对应板块 | 补数据来源与对比计划的口径，回扣「数据支撑」段带数字、与计划比 |
| 16 | 面试追问 | 「『项目延期怎么汇报』，追问『为什么现在才说』，标准答法怎么接？」 | 对应板块 | 承认触发信号设晚了，给出「已把该风险写进风险清单、设了周日检查点」这类机制改进 |
| 17 | 面试追问 | 「『怎么和研发对齐』，追问『对方就是不配合呢』，怎么不落进人情模式？」 | 对应板块 | 走机制三件套 + 机制升级（双方上级对齐优先级），不靠「帮个忙」 |
| 18 | 面试追问 | 「『跨团队冲突怎么处理』，追问『如果测试坚持不放行』，你站哪边？」 | 对应板块 | 不站队，回到「共识」写清上线口径 + 「变更」评估 + 向上汇报给二选一 |
| 19 | 面试追问 | 「60 秒答法里，哪一个当日术语必须出现？为什么？」 | 对应板块 | 至少 1 个（如翻译三问 / 里程碑 / 风险清单 / 共识）；术语是「懂行」的可判定信号，踩分点里明确要求 |
| 20 | 面试追问 | 「被连追两层后发现自己答错了，改口还是补结构？」 | 对应板块 | 不大段改口；用「我补充一层」回到踩分点结构，避免「被追问即崩」失分点 |

### （一）汇报演练参考结构（原 本课保留）

以主项目「面试陪练 Agent」为示范（教学示例），3 分钟汇报稿结构：

|---|---|---|
| 结论先行 | 30 秒 | 「关于面试陪练 Agent，我汇报三件事：进展、风险、需要的支持。目前整体按计划，评测准确率 82%，距上线标准差 8 个点。」 |

## 十、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 风险清单写了没人跟 | 清单交了就归档，无责任人、无更新、中期评审时原样抄一遍 | 立规矩：每条应对必须出现人名和日期；风险清单固定为周报的一个栏目，中期评审逐条检查更新痕迹 |
| 汇报流水账 | 按「周一开会、周三写文档」时间线罗列，无结论无数字 | 现场改写示范：同一周素材，先给结论再挑 3 条带数字的进展；演练互评把「结论先行」单独设 5 分项 |
| 跨部门靠人情不靠机制 | 「找算法同学帮个忙」，口头请求、无书面交付物与时间 | 教机制三件套：目标对齐（对他有什么好处）、交付物明确（书面确认）、时间写死（日历邀请代替口头约定）；话术见讲课稿对应板块结尾 |
| 把「算法说做不到」当终局 | 学员复述案例时直接说「那换个功能」 | 用翻译三问现场重拆：先问「具体哪一步做不到」，再问替代路径与代价；强调大多数「做不到」是「按当前方案做不到」 |
| 甘特图只排开发不排测试与试用 | W6 计划全排开发，测试试用无预留 | 模板强制四段：开发 / 测试 / 试用 / 路演按天排；提醒 W6D4 有 ≥10 人真实用户试用的硬验收，倒推预留 |
| 汇报只报喜不报忧 | 只讲进展不讲风险，怕「显得能力差」 | 点破：风险也是确定性的一部分——上级要的不是「没有风险的项目」，是「风险被管理着的项目」 |
| **术语混淆 · 六组相邻概念（新增）** | 把里程碑说成 deadline、把阻塞说成依赖、把验收说成测试、把通知当共识、把隐形 KPI 当正式指标、把随口加需求当变更 | 对应板块逐组做「易混辨析卡」对照；当堂小测专设 6 道辨析题；术语自测表错哪组补哪组，验收线 ≥10/12 |
| **术语混淆 · 缩写与角色（新增）** | KPI / PRD / MVP 只记字母不知全称；把研发三角误当三个独立部门；翻译三问第一问记成「为什么做不到」 | 首次出现给全称与中文；用「三种职能角色」重述研发三角；三问第一问用板书红笔圈「哪一步」 |
| **面试失分 · 情绪化答法（新增）** | 「算法不配合就找老板」「那就砍需求」「跨团队冲突谁声大听谁的」 | 失败答法对照表逐条打靶；用 60 秒标准答法覆盖，先翻译 / 先共识 / 先给选择题 |
| **面试失分 · 无结构与被追问即崩（新增）** | 60 秒想到哪说到哪不给结论；被追「数据哪来的」「为什么现在才说」就改口或沉默 | 强制三段 / 踩分点清单开口；两两模拟用面试追问卡连追 2–3 层，练「我补充一层」而不是大段改口；面试模拟记录表登记追问与自评分 |
| **设备受限（新增）** | 手机 / 平板学员打不开多列甘特图与大表，实操环节空转 | 按「四、教学准备」设备三档给替代动作：纸笔手绘横道图拍照、三行文本代替三栏表、语音备忘录练 60 秒口播、同组电脑学员代填后截图回传 |
