随堂填写

① 今天的核心链路是什么（原有表格，保留）

项目 定义
核心链路 一次完整的「输入 → 处理 → 输出」：用户在页面提交一条真实输入，后端收到并调用模型 API，模型结果展示回前端
输入 用户在你的产品上完成的第一个有效动作：填一个表单、传一个文件、或点一个预设示例按钮
处理 后端收到输入后，组织提示词、调用模型 API、拿到返回结果（允许有一次重试）
输出 模型结果以产品形态展示在前端：文本、卡片、列表或结构化字段均可，必须来自真实调用
不属于今天 样式美化、注册登录、支付、历史记录、多模型切换——这些留给 W6D3 之后

② 完成标准（原有表格，保留，放学验收口径）

维度 标准 自检问题
可运行 服务常驻不崩：连续提交 3 次不报错、不白屏 「我能连续点 3 次都出结果吗？」
可演示 一条真实输入 → 真实输出，全程无手动搬数据；路演时可当场演示 「敢不敢现在投屏给全班看一遍？」
日志可见 每次调用的请求时间、模型名、token 消耗、耗时，能在控制台或调用记录里指出 「刚才那次请求，日志在哪？」

三条全过 = 跑通。缺任何一条 = 未跑通，按对应板块补救路径执行。

对应板块：1. 输入 → 处理 → 输出。中间手动搬数据或写死假数据，链路就不是「一次完整走通」，路演真人一点就穿；Mock 只能开发期用。2. 5 硬 = 输入真实 / 调用真实 / 输出可见 / 日志可见 / 连续稳定；2 软 = 降级策略 / 日志规范。软标准只决定「合格 vs 良好」，不卡通过。3. 不是取消，是排期：完美落在 W6D3（功能与体验、三态设计），今天先保跑通。

对应板块：1. 不是失败，是时间边界；不先划这条线，页面就转圈到死，也没有「到点再试一次」的触发点，所以超时在重试之前。2. 429（限流）可重试、降频或等 1 分钟；401 / 403 不重试，那是凭证问题，该查 Key 与请求头 Bearer 前缀。3. 缓存复用是拿上一次真实结果顶上并明示「当前为缓存结果」；静态兜底是给一段写好的说明加稍后重试入口、不假装结果。两者都要明示是降级结果，不能伪装成模型刚算出来的输出。
