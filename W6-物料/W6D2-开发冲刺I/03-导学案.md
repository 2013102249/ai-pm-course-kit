## 一、今天的核心链路是什么（先读再动手）

| 项目 | 定义 |
|---|---|
| 核心链路 | 一次完整的「输入 → 处理 → 输出」：用户在页面提交一条真实输入，后端收到并调用模型 API，模型结果展示回前端 |
| 输入 | 用户在你的产品上完成的第一个有效动作：填一个表单、传一个文件、或点一个预设示例按钮 |
| 处理 | 后端收到输入后，组织提示词、调用模型 API、拿到返回结果（允许有一次重试） |
| 输出 | 模型结果以产品形态展示在前端：文本、卡片、列表或结构化字段均可，**必须来自真实调用** |
| 不属于今天 | 样式美化、注册登录、支付、历史记录、多模型切换——这些留给 W6D3 之后 |

## 二、完成标准（放学验收口径，逐条自评）

| 维度 | 标准 | 自检问题 |
|---|---|---|
| 可运行 | 服务常驻不崩：连续提交 3 次不报错、不白屏 | 「我能连续点 3 次都出结果吗？」 |
| 可演示 | 一条真实输入 → 真实输出，全程无手动搬数据；路演时可当场演示 | 「敢不敢现在投屏给全班看一遍？」 |
| 日志可见 | 每次调用的请求时间、模型名、token 消耗、耗时，能在控制台或调用记录里指出 | 「刚才那次请求，日志在哪？」 |

> 三条全过 = 跑通。缺任何一条 = 未跑通，按第六节补救路径执行。

## 四、卡点求助规则（三级制，纪律同纪律）

| 级别 | 动作 | 时限 | 说明 |
|---|---|---|---|
| 第一级 | 自己排查：看报错首行 → 翻教案第六节预判表 → 按步骤走 | 最多 5 分钟 | 排查时把试过的步骤记在「我的进度记录」里，提问时直接用 |
| 第二级 | 举手叫助教，说清三件事：卡点、已排查步骤、报错截图 | 助教 3 分钟内到场 | 环境 / Key / 联调三类问题，助教按排查手册当场处理 |
| 第三级 | 升级讲师：仅当助教无法解决、或涉及方案级决策 | 讲师排期处理 | 升级时必须带着排查记录，讲师只收「已排查过」的问题 |

**三类高频卡点速查**（完整步骤见教案，此处为索引）：

| 卡点 | 首查动作 |
|---|---|
| 环境配置 | 报错首行是 not found 还是 module 缺失；版本 Node ≥18 / Python ≥3.10；端口占用换端口 |
| API 密钥 | 先用最小请求直连验证 Key，再查 401（配错）/ 429（限流）/ 余额 |
| 联调 CORS / 权限 | F12 看 Network 状态码；CORS 加响应头；404 对路由；401 查请求头 Bearer |
