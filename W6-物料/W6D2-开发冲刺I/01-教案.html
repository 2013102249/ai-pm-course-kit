教案 · W6 周二《开发冲刺 I：核心链路》

同步说明：本件已按 2026-11-13 版《02-讲课稿》结构化同步（去课时化 · 知识库课件补充 · 术语统一）。原有框架与题目保留；文末「讲稿同步补充」为按新讲稿追加的内容。

AI 产品经理就业训练营 · 第六周第二天 · 去课时化版（按课堂节奏弹性安排）· 讲师 + 助教协作版 课型定位：开发冲刺日。本日按 去课时化版（按课堂节奏弹性安排）把「讲术语 → 讲链路 → 讲降级 → 长时段实操 → 面试讲解 → 验收」铺满：讲授不再让位于「纯巡场」，而是先用术语与原理把语言系统、链路顺序、降级预案立稳，再进入对应板块的实操冲刺。讲师与助教的全部动作仍围绕一件事——让每位学员的核心链路在当天跑通。

二、教学目标（可测量，对应产出验收清单）

  1. 每位学员在对应板块终验前，完成核心链路一次完整跑通：前端提交一条真实输入 → 后端收到并调用模型 → 前端展示输出，且日志可见。（验证方式：06-分层习题.md 附录 A 的 5 条硬标准逐项打勾，5 条全过即达标。）
  2. 学员能说出自己项目里「哪个环节最容易挂、挂了怎么降级」，至少写出 1 条可执行的降级策略（超时重试 → 缓存复用 → 静态兜底文案）。（验证方式：对应板块随堂填写 + 对应板块步骤 C 演练记录，写清触发条件与兜底文案即达标。）
  3. 当天卡点当天清：下课时 blockers 清单上，每条都有「责任人 + 状态 + 明日动作」，不允许出现无人认领的问题。（验证方式：对应板块清算表逐条过，未清项 100% 有责任人与时限即达标。）
  4. 【术语目标】 能对本日 12 个术语（核心链路 / MVP / 联调 / API / 降级 / 超时 / 重试 / 状态码 / Mock / 日志 / 验收标准 / 阻塞点）各自说出「一句话定义 ≤30 字 + 一个非技术生活类比 + 一个最易混的相邻概念」，并能在面试口语里正确使用。（验证方式：对应板块末《术语自测表》当堂 12 题小测，对 ≥10 题即达标；错 ≥2 题进对应板块补练，对应板块验收一复测。）
  5. 【面试目标】 能就「你怎么跟进开发」「接口挂了产品怎么办」「怎么定义 MVP 验收」「冲刺日怎么排优先级」四道必考题，各说出 ≥3 条踩分点，并接住至少 2 层追问。（验证方式：对应板块两两模拟 + 《面试模拟记录表》自评分，四题平均 ≥「良好」档即达标。）
  6. 能按「先分后合」定位一处联调卡点：先看状态码区分「没发出 / 被拦 / 报错」，再单侧各自验证，最后合并。（验证方式：对应板块步骤 B 卡点记录表，能写出状态码与首查动作即达标。）
  7. 能区分 Mock（模拟替身 / 假数据）与真实调用，说清「写死假数据不算跑通」，并能在验收时把替身换回真实调用。（验证方式：习题第 0 层改错题 + 对应板块硬标准 2「调用真实」判定，两项均过即达标。）
  8. 能在对应板块当堂完成三件作品集积木归档，并复述本日三句收束。（验证方式：当堂验收表逐项打勾，三项全勾为通过。）

三、教学重难点

类型 内容 说明
重点 核心链路的拆解顺序与联调顺序 先通输入、再通调用、最后串输出；每步都有可打勾的验收动作，防止学员「一口吃成胖子」
重点（新增） 对应板块 12 个术语的「一句话定义 + 生活类比 + 易混辨析」三件套 先把语言系统立起来，对应板块讲降级、对应板块讲面试才不卡壳；生活类比一律非技术场景，不得用技术比喻技术
难点一 模型 API 接入与降级 Key 配置、超时、限流、失败兜底——冲刺日最高频的挂点，预判表见对应板块
难点二 进度差异管理 同班学员速度差可达 3 倍；讲师要用检查点制度让快的往体验走、慢的不掉队，而非统一讲解
难点三（新增 · 术语混淆） 本期 6/6 技术概念在「听过名词」及以下 最易把相邻词搅在一起：「降级 vs 报错 / 功能关闭」「超时 vs 失败」「重试 vs 无限重试」「状态码 vs 日志」「Mock vs 真调用 / 造假」「MVP vs 半成品」「联调 vs 各做各的」「阻塞点 vs 普通 Bug」。应对：每个术语强制配「最易混的相邻概念」，对应板块用连线题、改错题当堂暴露混淆，对应板块补练，对应板块验收一复测
难点四（新增 · 面试失分） 零基础学员面试常见三种失分 ① 讲「跟进开发」只说「开会催进度」，没有检查点与验收标准；② 答「接口挂了」只说「让研发修」，没有产品侧降级与兜底；③ 被追问两层就卡住或改口。应对：对应板块每题先亮「典型失败答法 + 失分原因」，再用 60 秒标准答法示范，两两模拟强制追问 2–3 层
纪律要求 「先跑通再完美」 反复强调：今天允许丑、允许慢、不允许没跑通；样式和异常处理留给 W6D3

六、三个最常卡住的点 · 预判表（巡场排查用，对应板块直接调用）

按往年数据，冲刺日约 80% 的卡点集中在这三类。助教巡场发现学员卡住超过 5 分钟，直接按本表步骤代查，不要等学员自己悟。本课版中，本表既是对应板块「讲降级 / 讲联调」的讲解索引，也是对应板块步骤 B「联调卡点演练」的排查底稿；原有三张表逐字保留。

卡点 1 · 环境配置（依赖装不上 / 起不来 / 端口占用）

排查步骤 操作 通过标准
步骤 1 确认运行环境版本：Node ≥18 或 Python ≥3.10（按 W6D1 定的技术栈） node -v / python -v 输出达标
步骤 2 看报错首行：是「command not found」还是「module not found」 前者重装环境，后者重装依赖
步骤 3 重装依赖：删 node_modules 或 venv 后重跑安装命令，国内网络加镜像源 安装无 error 结尾
步骤 4 端口占用（报 EADDRINUSE）：换端口或杀掉占用进程 服务成功启动，本地地址能打开
步骤 5 仍不行：直接用讲师参考工程目录替换重来，不要恋战 15 分钟内必须恢复可运行状态

卡点 2 · API 密钥（调不通 / 401 / 余额不足）

排查步骤 操作 通过标准
步骤 1 确认 Key 放在环境变量里，代码读的是环境变量不是明文 .env 有值且代码引用正确
步骤 2 用最小请求验证 Key：绕过业务代码，curl 或调试台直连一次 API 返回 200 且有内容
步骤 3 返回 401/403：Key 复制错误（首位末位空格）、未开通该模型、未实名或未充值 控制台看到调用成功记录
步骤 4 返回 429：触发限流，降频或等 1 分钟；确认账户余额与免费额度 限流解除，请求恢复
步骤 5 Key 泄露到代码库或截图外发：立即吊销重发，并宣讲安全纪律 新 Key 生效，旧 Key 作废

卡点 3 · 联调 CORS 与权限（前端能跑、接口不通）

排查步骤 操作 通过标准
步骤 1 浏览器 F12 看 Network：请求发出去了吗？状态码是多少？ 定位到是没发出、被拦、还是报错
步骤 2 报 CORS：后端加跨域响应头（开发期放开来源），前端确认请求地址与端口写对 Console 无 CORS 报错
步骤 3 报 404：路径拼错（少了 /api 前缀或多了一层），前后端对齐路由表 请求打到后端日志
步骤 4 报 401/403：请求头没带 Key 或带错位置（Bearer 前缀缺失） 后端返回业务数据
步骤 5 仍不通：后端先用接口调试工具单独验证，再让前端接——先分后合 单边各自验证通过

# 类别 提问 提问时机 预设答案 / 引导方向
1 巡场（原） 「你的核心链路是哪三步？给我指一下现在卡在哪一步？」 每位学员开场必问，对应板块 答不出三步的，带他回到检查清单配图逐段过；目标是把「大工程」拆成「三步走」
2 巡场（原） 「输入这一端，用户最少操作几步能提交？」 步骤 A，问进度快者 超过 3 步的提醒：先做默认示例一键提交，别让输入本身成为门槛
3 巡场（原） 「Key 配在环境变量里，还是直接写在代码里？」 步骤 A / B，全员扫一遍 写在代码里的当场改，并讲一句：Key 进代码库等于密码发群里
4 巡场（原） 「如果模型 30 秒没返回，你的页面会发生什么？」 步骤 C，问已完成调用者 答「转圈到死」的，要求补超时设置与兜底文案——这就是降级意识
5 巡场（原） 「这次跑通的记录，你从哪里能看到？」 步骤 A 收口 / 对应板块终验 指不出日志或控制台记录的，带他打开调用记录页——日志可见是硬标准之一
6 巡场（原） 「明天 W6D3 你要打磨的第一件事是什么？」 对应板块清算，问 2–3 人 答「样式」的纠偏：先三态（空态 / 错态 / 加载态）再美化；答不出的一起看检查清单
7 理解 「为什么冲刺日只要求一条核心链路，而不是把功能一次做齐？」 对应板块（约 62 min） 链路是任督二脉，链路不通加多少功能都是空中楼阁；先跑通再完美
8 理解 「联调卡住时，为什么必须先分后合、各自单侧验证？」 对应板块（约 138 min） 两个人对着一个黑盒互相怀疑最耗时；先让后端单独验证、前端再接，责任才分得清
9 〔术〕 「降级和直接报错、或者把功能关掉，是同一件事吗？」 对应板块术语精讲（约 22 min） 不是。降级是「换个方式把事办成」，报错 / 关闭是「什么都不给」；降级有兜底产出
10 〔术〕 「超时是『失败了』吗？它和重试有什么区别？」 对应板块（约 26 min） 超时是「我主动不等了」的时间边界，不是结果判定；重试是超时之后「再试一次」的动作，且有次数上限
11 〔术〕 「状态码和日志，哪个是给机器看的简短结论、哪个是给人查的流水账？」 对应板块辨析练习（约 36 min） 状态码是简短结论（如 200 / 401 / 429），日志是逐笔记录（时间 / 模型名 / token / 耗时）；别把两者混成一回事
12 〔术〕 「Mock 出来的假数据，算不算『核心链路跑通』？」 对应板块 + 对应板块复问（约 30 min / 285 min） 不算。Mock 是开发期替身，验收必须换回真实调用；写死假数据按硬标准 2 判「未跑通」
13 〔术〕 「MVP 是『做了一半的半成品』吗？它和『劣质品』差在哪？」 对应板块（约 14 min） 不是。MVP 是「最小但完整可跑通」，砍的是功能数量不是质量；半成品是没跑完，劣质品是跑通了但质量差
14 〔术〕 「阻塞点和普通 Bug 有什么区别？为什么它要当天清？」 对应板块（约 40 min） 阻塞点是「不解开后面全停」的那一个，普通 Bug 可以绕过；冲刺日按 blockers 清单当天认领，不允许跨夜
15 〔面〕 「你怎么跟进开发？别只说开会催进度，说清你盯什么。」 对应板块（约 205 min） 盯检查点（CP1/CP2/CP3）、盯验收标准、盯 blockers 责任人；不是「催」，是「按可打勾的标准验收」
16 〔面〕 「我追一层：接口挂了，研发在修，产品这一侧当下做什么？」 对应板块追问层 1（约 210 min） 产品侧不等研发：超时设置、重试 1 次、缓存复用、静态兜底文案、错误提示与日志留痕，先让用户「有得用」
17 〔面〕 「你怎么定义 MVP 的验收标准？谁说了算？」 对应板块（约 215 min） 用可打勾的硬标准定义（输入真实 / 调用真实 / 输出可见 / 日志可见 / 连续稳定），产品写、研发与讲师双确认，不靠「看着差不多」
18 〔面〕 「冲刺日任务堆在一起，你怎么排优先级？」 对应板块（约 222 min） 先解阻塞点，再保核心链路三步，最后才轮到样式与体验；判据是「不做会不会让后面全停」
19 〔面〕 「再追一层：如果老板要你今天就把样式也做漂亮，你怎么答？」 对应板块追问层 2（约 232 min） 不硬顶也不改口：先亮当日验收线（先跑通再完美），说明样式排在 W6D3，并给一个可看的最小演示替代
20 〔面〕 「被追到第三层：你说先跑通再完美，那『完美』什么时候做、谁负责？」 对应板块追问层 3（约 240 min） 时间上落在 W6D3（功能与体验、三态设计），责任上产品定验收标准、研发实现、讲师终验；顺序不是取消，是排期

8.2.1 术语小测参考答案（对应板块末 12 题，对应导学案《术语自测表》）

# 题目要点 参考答案 判分
1 核心链路 一次完整的「输入 → 处理 → 输出」，中间不靠手动搬数据 三环节齐全 1 分 +「无手动搬运」1 分
2 MVP 全称与中文 MVP = Minimum Viable Product，最小可行产品；最小但完整可跑通，不是半成品 全称 + 中文 1 分 +「非半成品」1 分
3 联调 把前端与后端接起来一起跑，确认两边对得上；不是各做各的 「两边接起来」1 分 +「≠单测」1 分
4 API 全称与中文 API = Application Programming Interface，应用程序编程接口；是调用的「窗口 / 约定」，不是 Key 全称 + 中文 1 分 +「≠Key」1 分
5 降级 主路走不通时换个方式把事办成（兜底文案 / 缓存 / 备用模型），不是报错或关功能 「换方式办成」1 分 +「有兜底产出」1 分
6 超时 主动设定的等待上限，到点就不再等；是时间边界，不是结果判定 「时间边界」1 分 +「≠失败」1 分
7 重试 失败后按有限次数、带间隔再试一次；不是无限重试，也不是刷新页面 「有限次数」1 分 +「有间隔」1 分
8 状态码 机器读的简短结论（如 200 / 401 / 404 / 429 / 5xx），一眼判断成没成、卡在哪 「简短结论」1 分 +「≠日志」1 分
9 Mock 开发期的模拟替身 / 假数据，用来先跑通流程；验收必须换回真实调用 「开发期替身」1 分 +「验收换真」1 分
10 日志 逐笔留痕的记录（时间 / 模型名 / token / 耗时 / 状态码），供排查者回查 「逐笔记录」1 分 +「供排查」1 分
11 验收标准 可打勾、可判「过 / 不过」的硬条件，不靠主观感觉 「可打勾」1 分 +「≠感觉」1 分
12 阻塞点 不解开后面全停的那一个问题，须当天认领责任人与时限 「后面全停」1 分 +「当天清」1 分

满分 24 分；对 ≥20 分（约合 12 题对 ≥10 题）为达标，低于 20 分登记进对应板块术语补练，对应板块验收一复测。
