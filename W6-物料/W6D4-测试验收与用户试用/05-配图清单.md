## 图 1 · 测试验收流程图（已制成，本课主图）

### 规格说明

| 项目 | 规格 |
|---|---|
| 画布 | 1600 × 900 px（16:9 投屏版）；另出 1080 × 1920 px 竖版供社群传播 |
| 布局 | 上方主流程横向四节点闭环；下方归因分支四卡片；底部纪律条；右上角三个数字徽章 |
| 主色 | 流程主线与关键节点用紫 #7C3AED；分支卡片与数据流用蓝 #2563EB |
| 字体 | 节点标题 28–32 px 加粗；卡内正文 20–22 px；纪律条 24 px |
| 风格 | 扁平、圆角矩形节点、箭头带方向；白底；禁用渐变与阴影堆叠 |

### 画面内容（自上而下）

| 区域 | 内容 |
|---|---|
| 主流程（四个紫色圆角节点 + 箭头） | ① badcase 收集 → ② 归因 → ③ 修复 → ④ 回归测试；④ 的箭头回指向「跑分」形成闭环，闭环箭头用蓝色虚线，标注「回归通过 → 回到评测集」 |
| 归因分支（节点 ② 下方挂四张卡片，蓝框白底） | 解析问题（引用原文错：乱码 / 表格错位）｜分块问题（答案被切断 / 主题稀释）｜检索问题（资料里有却没捞到）｜生成问题（好资料仍编造 / 格式错误）；每张卡右下角标注主要责任方：数据工程 / 算法工程 / 算法 / 算法产品 |
| 纪律条（底部紫色通栏，白字） | 「无归因不派单 · 先数据后模型 · 先便宜后贵」 |
| 数字徽章（右上角，三个蓝色小圆角块） | 评测集 ≥50 条 ｜ badcase 率 30% 警戒线 ｜ 通过率 ≥90% 且无 P0 |

### 讲法脚本

- **讲法**：分三段。先用手沿主流程走一遍四步，每步一句话——「收集是把 badcase 兜住，归因是给它定罪，修复是对症下药，回归是证明药有效」；再展开归因节点的四张分支卡，各念一个教学化标签（「答非所问」「编造政策」「格式错误」）；最后落在底部纪律条，放慢语速念一遍。
- **闭环强调**：手指沿蓝色虚线回到起点，问学员「哪一步最容易被跳过」——预期答案是「回归」，顺势讲「修复不回归 = 没修」。
- **提问点**：「四张分支卡里，哪一类修起来最贵？」（预期：生成问题，改提示词还算便宜，动模型按周计算——所以它排漏斗最后一层）
- **过渡话术**：「图是地图，手上得有真数据。下一页，我们把 3 条用例拖进工具里跑分。」

## 图 2 · 四层排查漏斗图（已制成）

### 规格说明

| 项目 | 规格 |
|---|---|
| 画布 | 900 × 1200 px（竖版漏斗，四层自上而下收窄） |
| 四层（自上而下） | 第 1 层 引用原文对吗？（最宽，蓝色）→ 第 2 层 chunk 完整吗？→ 第 3 层 正确资料召回了吗？→ 第 4 层 裸模型拿着好资料还错吗？（最窄，紫色） |
| 每层右侧 | 一个「对勾出口」箭头指向右侧文字：「排除，往下一层」；第 4 层右侧为终点徽章：「定位：生成问题」 |
| 左侧色带 | 从浅蓝到深紫的渐变色带，暗示「排查成本逐层升高」 |

### 讲法脚本

- **讲法**：破案示范时逐层揭开（可用白纸遮挡或分四次动画淡入）。每揭示一层，先念问题，再报本案例的证据，最后给结论「排除 / 定位」。
- **核心记忆点**：漏斗宽度暗示成本——越往下越贵，所以顺序不能反。念一遍「先数据后模型，先便宜后贵」。
- **提问点**：「前三层都排除了，说明什么？」（预期：资料侧无罪，问题在模型侧——这时候才轮到提示词和模型）

## 图 3 · AI 产品评估打分工具 · 统计面板（动态投屏）

- **讲法**：导入示例数据后，手指按「四个数字 + 一张图」的顺序走：badcase 率 33.3%（指红色警戒）→ 综合均分 3.6 → 通过率 33.3% → 雷达图形状（沿五个角逐一指过，在准确性、有帮助性、格式规范性三个凹点各停一秒）。最后念自动结论文案。
- **提问点**：「雷达图三个角一样凹，为什么结论只说准确性？」（预期：工具只会比大小，人要会归因——三个凹点归因后其实是两件事）
- **备注**：本图为工具实况投屏，无需截图；课件里如需静态页，可在导出报告后对 Markdown 报告节选制图。

## 图 4 · 用户反馈分级条（已制成）

### 规格说明

| 项目 | 规格 |
|---|---|
| 画布 | 1600 × 420 px（横向三段条） |
| 三段 | P0 编造 / 安全 / 数据错误——当天修 + 回归（红 #DC2626 细条在最左，占比视觉最小）；P1 体验 / 流程 / 功能缺口——排期修（蓝 #2563EB，中段最宽）；P2 吐槽 / 审美 / 边角——记录不排（灰 #7A7590，右段） |
| 每段下方 | 放一条教学化原声示例：P0「我问年假几天，它说有 20 天」；P1「每轮都忘了我刚才说的话」；P2「界面有点丑」 |
| 底部 | 一行小字：「原声照抄，勿润色——原声是证据，转述是观点」 |

### 讲法脚本

- **讲法**：从左到右逐段念，每段先念判据再念原声。念完问「三段哪段占比视觉最小但最致命」——P0。引出「修复资源按危害分配，不按声音大小分配」。
- **提问点**：「9 个说挺好，1 个说找不到入口，听谁的？」（预期：都听，重点听那 1 个——9 个「挺好」往往是任务设计太简单）
- **过渡话术**：「反馈分完级，改进自然浮出来。≥3 条有效改进，就是明天路演『数据与思考』那一页的正文。」
