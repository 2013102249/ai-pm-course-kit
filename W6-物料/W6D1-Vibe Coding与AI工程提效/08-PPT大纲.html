8第 2 节Vibe Coding：一句话定义① 说清楚 → AI 生成 → 人验收迭代；② 2025 年初 Andrej Karpathy 提出；③ 「不是不写代码，是不亲手写代码」；④ 「说清楚」是 PM 老本行（PRD 功底）强调「不亲手写」≠「不写」；回扣 P5 术语卡 Vibe Coding术语卡 VibeCoding
9第 2 节五步循环（主视觉）① 说清楚 / 生成 / 跑起来 / 挑毛病 / 再说清楚；② 闭环不是直线，通常 3–10 轮；③ 本质 = 快速迭代，不是一次生成对；④ 带实习生类比；⑤ 许愿机误区：上限是提示词，下限是品味手指沿循环箭头划回第一步；删角色/精简指令的失控留到 P18 演示Vibe Coding 流程图（图 1，已制成）

11第 2 节能力边界：不适合做什么① 生产级系统（SLA / 抗攻击）；② 核心链路（支付 / 登录 / 权限）；③ 长期维护的大型工程；④ 强合规场景（等保 / 备案 / 可审计）；⑤ 判断主线「可撤回性」金句「演示层快跑，核心层慢验」；MVP 是 Demo 加强版，策略两层分离流程图边界区（图 1）

15第 3 节现场演示：10 分钟搭一个页面① 任务 = 本周 MVP 冲刺看板；② 指令五段式：是什么/给谁用/包含什么/长什么样/不能怎样；③ 「单文件 HTML、零依赖、断网可开」写进红线；④ 边输入边念，念完再运行本机投屏，边输入边念指令；念完停一下再点运行讲师本机（投屏·交互）
16第 3 节演示复盘：挑毛病与一句话反馈① AI 做对三件：结构 / 样式 / 交互；② 做错三件：倒计时写死 / 按钮没反应 / 手机端溢出（可用性）；③ 合格反馈 = 指出现象 + 给出方向；④ 反例「不对，重做」；⑤ AI 出体力、我出判断让学员先试「怎么让 AI 改」再演示；点出「手机上溢出只有手机视角看得见」讲师本机（投屏·交互）
17第 3 节规则文件：给 AI 立规矩① AGENTS.md 是什么（项目宪法、跨工具通用）；② 四块：项目背景 / 技术约定 / 输出规范 / 红线；③ 能打勾的示例「改完必须本地运行确认无报错」；④ 空话「请注意代码质量」等于没写现场加一条「配色统一用 #7C3AED」并保存；对比五段式「只管一次」真实 AGENTS.md（讲师本机·交互）
18第 3 节提示词即代码 + 深化与面试连接① 五要素评分卡 = 编译检查器；② 五步：认识结构 / 缺一行 / 体验失控 / 对照改进 / A-B 理解参数；③ 缺一行就像缺一个 import；④ 深化：评分卡验指令不验业务、越靠前省事越靠后兜底；⑤ 这段在面试里怎么答回扣 W5D2「A/B 一次只改一个变量」；金句「提示词是新的源代码，评分卡是新的编译器」提示词调试台（图 3·交互） + 正反面案例对照图（图 7）
