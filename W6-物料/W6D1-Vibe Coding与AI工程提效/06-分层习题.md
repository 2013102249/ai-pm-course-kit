# 分层习题 · W6 周一《Vibe Coding 与 AI 工程提效》

> 三层难度：基础巩固（概念）→ 进阶实操（方案设计）→ 求职挑战（面试真题）。
> 本课核心考点：**工具场景匹配**——给定任务，能选出对的工具并论证。
> 建议用法：基础层当堂测 10 分钟；进阶层当作业（周二课前交）；求职挑战层自测，W8 面试课复用。
> 所有题目附参考答案与评分标准。

---

## 第一层 · 基础巩固题（概念层）

### 一、选择题（每题 10 分，共 50 分）

**1. 关于 Vibe Coding 的理解，正确的是：**
A. Vibe Coding 是不写代码，完全交给 AI 自由发挥
B. Vibe Coding 是用自然语言说清需求、AI 生成代码、人负责验收与迭代
C. Vibe Coding 只能做玩具 Demo，没有任何职业价值
D. Vibe Coding 要求产品经理先学会读全部生成代码

**2. 以下场景最适合用 Vibe Coding 的是：**
A. 银行核心交易系统的支付链路
B. 周五路演前夜，快速搭一个可点击的产品演示页
C. 需要扛百万并发的生产服务
D. 要过等保测评的正式系统

**3. 按课堂的派别划分，WorkBuddy 与豆包属于：**
A. 工程派，适合项目级持续迭代
B. 对话派，零门槛适合演示与原型
C. 编译派，负责代码检查
D. 评测派，负责跑分验收

**4. 关于规则文件（AGENTS.md），理解正确的是：**
A. 它是给编译器用的配置文件
B. 它是放在项目根目录、用自然语言给 AI 智能体立的项目规矩
C. 它只对某一款特定工具有效，换工具即失效
D. 它只用来记录 bug

**5. 「一主两辅」原则的含义是：**
A. 一个项目用三种编程语言
B. 一款主力工具吃透 + 两款备用工具补位，避免工具集邮
C. 一位主讲师 + 两位助教
D. 主力工具只用一天，备用工具用两天

### 二、简答题（每题 25 分，共 50 分）

**6. 用一句话向非技术同事解释「什么是 Vibe Coding」，并配一个生活类比。**

**7. 写出给 AI 工具下指令的「五段式」结构（五个要素各 2 分，共 10 分），并任选其中一段说明它防住什么失控（15 分）。**

你是主项目的负责人，团队只有你一个人，MVP 周五路演、周四要接至少 10 名真实用户试用。现有五个国产工具可选：WorkBuddy、豆包、Trae、通义灵码、CodeBuddy。请为下列四个任务分别选出最合适的工具，并给出**两条理由 + 一条风险与对策**。

| B. 周二到周四，持续迭代 MVP 核心页面 | | | | |
| C. 你有熟悉的编辑器使用习惯，想给存量代码提速 | | | | |

## 第三层 · 求职挑战题（面试层）

**10. 面试真题：你不会写代码，怎么做 Demo？（30 分）**

面试官：「我看你简历写主导了 AI 产品 MVP，但你是运营转岗的——你不会写代码，这个 Demo 到底是不是你自己做的？你平时用什么工具？」
要求：先给结论，再讲方法论（含工具与边界），最后补一个「显专业」的补充观点。

**11. 案例分析：路演前夜，Demo 翻车（30 分）**

周五路演当天，你提前 10 分钟到场，发现演示页在会场电脑上打不开——页面依赖了一个本地服务和一个只有你电脑有的字体文件；更糟的是，你昨晚刚让 AI「优化」过一轮，按钮交互变了。评委已经在座位上。
请给出：① 现场的应急动作（按优先级）；② 复盘——这类事故靠什么机制提前防住（至少两条，对应今天所学）。

## 参考答案与评分标准

### 第一层 · 基础巩固

| 题 | 答案 | 给分点 |
|---|---|---|
| 1 | **B** | 选 B 得满分；选 A 得 3 分（知道交给 AI 但漏掉「人负责验收」这个关键） |
| 2 | **B** | 选 B 得满分；能说明 A/C/D 属于「核心层 / 生产级 / 强合规」加 5 分 |
| 3 | **B** | 选 B 得满分；能顺带说出工程派三款加 5 分 |
| 4 | **B** | 选 B 得满分；选 C 得 5 分（方向对但结论反——AGENTS.md 通用性正是其价值） |
| 5 | **B** | 选 B 得满分 |
| 6 | 「用自然语言说清需求、AI 生成代码、人负责验收迭代」+ 类比合理（带实习生 / 甲方提需求） | 一句话准确 15 分 + 类比贴切 10 分 |
| 7 | 五段式：是什么 / 给谁用 / 包含什么 / 长什么样 / 不能怎样 | 五要素每个 2 分；「不能怎样」防自由发挥、「长什么样」防风格漂移，意思对即可得 15 分 |

### 第二层 · 进阶实操（三档 Rubric）

**第 8 题参考答案**：
- A：WorkBuddy 或豆包。理由：对话派零门槛、不装环境，一句话到页面；路演前夜时间最贵。风险与对策：生成质量不稳定——提前把五段式指令存成模板，出问题换备用工具重放。
- B：Trae。理由：AI 原生 IDE，项目级工程可连续迭代；工程派支持调试与工具扩展。风险与对策：上手有项目概念门槛——周三前把规则文件立好，减少返工。
- C：通义灵码或 CodeBuddy。理由：插件形态，装在熟悉的编辑器里，不迁移工作习惯；个人有免费额度。风险与对策：插件能力边界——补一款对话派工具做演示层。
- D：WorkBuddy。理由：智能体形态，可读写文件、执行命令，串得起多步任务流。风险与对策：自动化链路要设人工确认点，避免误操作。
- 补充问：一主两辅组合，忌五款全上——理由围绕「注意力是最稀缺资源」「每多一款工具多一套学习与故障成本」。

| 档位 | 标准 |
|---|---|
| 合格（30–39 分） | 四个任务都选了工具，理由基本成立；组合题有结论 |
| 良好（40–44 分） | 每个任务两条理由到位且区分了对话派 / 工程派；风险与对策具体可执行 |
| 优秀（45–50 分） | 补充问答出「一主两辅」的资源逻辑（如「注意力稀缺」「故障成本」），或提到「提前备好指令模板」等工程习惯 |

**第 9 题参考答案**：四块齐全、红线 ≥2 条、标注最重要的 3 条。最重要的 3 条通常应包含：一条红线（不许调用未经验证接口 / 不许改核心计算逻辑）、一条技术约定（单文件 / 无外部依赖 / 配色统一）、一条输出规范（改完必须运行验证）。理由指向：安全兜底、一致性、可验收。

| 档位 | 标准 |
|---|---|
| 合格（30–39 分） | 四块结构完整，10 条写完，红线不少于 2 条 |
| 良好（40–44 分） | 条目具体可执行（无「注意代码质量」式空话），标注的 3 条理由说清 |
| 优秀（45–50 分） | 规则体现本项目特有风险（如数据接口、配色规范、禁止事项与周四真实用户试用联动） |

### 第三层 · 求职挑战（三档 Rubric）

**第 10 题参考答案**：结论=「是我主导做的，我的代码是提示词和工作流」。方法论：五段式写指令、五步循环快速迭代、工具一主两辅按场景匹配、边界两层分离（演示层快跑，核心层慢验）。专业补充：「选工具看生态匹配——国内团队、国内合规，工具链也长在国内」或「AI 生成的代码必须过人工验收关，我不追一次生成对，我追迭代速度」。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 结论清晰，讲清 Vibe Coding 方法论，答出用什么工具 |
| 良好（24–27 分） | 理由带「提示词 + 工作流 = 我的代码」的框架表述，提到边界分层 |
| 优秀（28–30 分） | 补上「工具选型看生态 / 合规匹配」或「人工验收关」等显专业观点，表达有结构 |

**第 11 题参考答案**：应急动作优先级：① 改用手机 / 备用设备打开已缓存的静态版本，先保证「有东西可演」；② 会前 3 分钟向评委说明情况，用截图版流程讲；③ 不当场 debug。复盘机制：① 环境标准化——演示页必须是「零依赖单文件 + 系统字体 + 可离线打开」，写进规则文件红线；② 改动管控——路演前 24 小时冻结需求，AI 的每次「优化」必须跑通验收后才允许保存；③ 提前彩排——按会场设备完整走一遍。

| 档位 | 标准 |
|---|---|
| 合格（18–23 分） | 按优先级给出应急动作，含「不当场 debug」意识 |
| 良好（24–27 分） | 复盘机制两条以上，且对应到今天所学（规则文件 / 验收 / 边界） |
| 优秀（28–30 分） | 机制上升到流程（如改动冻结、彩排清单），体现「Demo 可移植性」的产品意识 |
