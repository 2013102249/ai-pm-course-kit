## 三、教学重难点

- **重点**：Vibe Coding 方法论的五步循环与能力边界；国产工具选型的「一主两辅」原则与选型四问；规则文件的四块结构；12 个当日术语的精准使用；四类面试题的踩分点。
- **难点一**：能力边界的判断——学员容易把「能跑起来」等同于「能交付」，需用「演示层快跑，核心层慢验」建立分层意识。【原难点保留】
- **难点二**：工具选型的论证——五款工具只做客观定位描述，学员易凭印象选工具，需用「四问决策」把选择变成可复用的判断框架。【原难点保留】
- **难点三（术语混淆）**：零编程学员易把「零依赖」与「单文件页面」画等号、把「幻觉」与「普通 bug」混为一谈、把「可用性」和「可验收」当成同一件事、把「降级」误解为「工具坏了」。需用生活类比 + 易混辨析表逐对拆开，并当堂做术语小测纠偏。
- **难点四（面试失分）**：学员答「不会写代码怎么做 Demo」时，容易滑向两个失分极端——要么心虚地强调「我不会写代码」，要么夸大「都是我做的」；答「怎么验收」时易只说「我会看一眼」，缺机制、缺术语。需用踩分点、追问链、失败答法、60 秒标准答法四件套做防御训练。

## 四、Vibe Coding 能力边界（本课核心表格）

| 维度 | 适合做什么 | 不适合做什么 |
|---|---|---|
| 交付物性质 | 原型与 Demo：把想法变成可点击、可演示的页面，用于验证与路演 | 生产级系统：要扛真实流量、有 SLA（Service Level Agreement，服务等级协议）要求、要抗攻击的线上服务 |
| 使用范围 | 内部小工具：团队自用的数据整理、报表、自动化脚本，用户量小、容错高 | 核心链路：支付、登录、权限判断等错一次就是事故的模块 |
| 生命周期 | 一次性交付：路演页、活动页、数据可视化页，用完即弃、不长期维护 | 长期维护的大型工程：半年后无人说得清每行代码的意图，包括 AI |
| 实验目的 | 学习与验证：两小时内验证一个技术想法的可行性 | 强合规场景：需过等保、算法备案评估的正式系统，代码可审计性是硬要求 |
| 质量保障 | 有人工验收关：每次生成后有人逐项对照需求检查 | 无人验收的全自动流水线：生成即上线、无人 review（复核）的「甩手」模式 |

**边界口诀：演示层快跑，核心层慢验。** 主项目 MVP 采用「两层分离」策略——演示层用 Vibe Coding 快速搭建，真实用户试用涉及的核心数据流转必须设置人工验收关（周四测试验收课细讲）。

> 深化提示（对应板块用）：本表五个维度可归纳为一条判断主线——「错了能不能撤回」。能撤回的（演示页、内部小工具、一次性交付）交给 AI 快跑；不能撤回的（钱、账号、合规、长期资产）必须人工慢验。这条「可撤回性」判断，是面试里解释「AI PM 技术边界」最凝练的说法。

## 七、课堂提问设计（≥18 问）

> 术语辨析 ≥6（标【术】）、面试追问 ≥6（标【面】），其余为原理与实操类。原 7 问全部保留并扩写。

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 「不会写代码，怎么做 Demo？传统办法有哪几条，各差在哪？」 | 对应板块导入 | 找程序员合伙（不可控）、外包（沟通成本高）、自学三个月（来不及）；引出第四条路：Vibe Coding【原问保留】 |
| 2 | 「我们的 MVP 属于能力边界表的哪一边——适合还是不适合？」 | 对应板块 | MVP 是「原型与 Demo」的加强版（要多接 ≥10 名真实用户）；结论：演示层快跑，核心层慢验【原问保留】 |
| 3 | 「五款工具能分成几派？规律是什么？」 | 对应板块 | 两派：对话派（WorkBuddy、豆包，零门槛做演示）与工程派（Trae、通义灵码、CodeBuddy，项目级迭代）【原问保留】 |
| 4 | 「AI 生成的页面哪里不合预期？用一句话怎么让它改？」 | 对应板块 | 合格反馈 = 指出现象 + 给出方向，如「倒计时请改为实时计算，不要写死日期」；不合格反馈 =「不对，重做」【原问保留】 |
| 5 | 「没有规则文件，连续迭代三天会发生什么？」 | 对应板块 | 每次生成的风格与结构不一致、AI 自行「优化」掉依赖功能、周三周四大规模返工【原问保留】 |
| 6 | 「删掉角色描述，评分卡哪一项变了？这说明什么？」 | 对应板块 | 角色设定从已覆盖变缺失；提示词「缺一行」就像代码「缺一个 import」——能跑但边界条件下崩【原问保留】 |
| 7 | 「你的主力工具是哪款？一句话理由。」 | 对应板块汇报 | 用选型四问之一论证即可，如「演示一次选对话派，迭代一周选工程派」【原问保留】 |
| 8 | 【术】「『零依赖』和『单文件页面』是不是一回事？各防住什么？」 | 对应板块 | 不是。单文件页面讲「东西装在一个文件里」，零依赖讲「不靠外部资源也能跑」；单文件可能仍引用在线字体（有外部依赖），零依赖也可能是多文件但全本地 |
| 9 | 【术】「『幻觉』和普通的 bug 差在哪？为什么 Demo 里也要防幻觉？」 | 对应板块 | bug 是代码写错、可复现可定位；幻觉是 AI 编造了不存在的接口 / 字段 / 事实，看着合理实则无中生有；Demo 里幻觉会伪装成「做对了」 |
| 10 | 【术】「『可用性』和『可验收』，哪个是用户视角、哪个是流程视角？」 | 对应板块 | 可用性是用户视角（能不能看懂、点得动、不溢出）；可验收是流程视角（有条条对照的验收标准、有人签字） |
| 11 | 【术】「『降级』是不是等于『工具坏了做不了』？」 | 对应板块 | 不是。降级是主动换一条更轻的路径达成目标（如手机组改用网页版工具、语音输入指令），是计划内的备选，不是被动放弃 |
| 12 | 【术】「『Demo』和『原型』、『生产级系统』怎么区分？」 | 对应板块 | Demo 用于演示与验证、可撤回；原型偏流程验证；生产级系统要扛真实流量与合规，错一次是事故 |
| 13 | 【术】「『规则文件』和『五段式指令』，哪个管一次、哪个管长期？」 | 对应板块 | 五段式指令管「这一次生成」；规则文件是项目宪法，管「每一轮生成」，跨工具、跨天数生效 |
| 14 | 【术】「『国产大模型』这个词，为什么限定『国产』而不只说『大模型』？」 | 对应板块 | 涉及数据出境、内容安全、供应链自主与合规对标，是选型约束，不只是能力描述 |
| 15 | 【面】「你说不会写代码却主导了 Demo——那到底是不是你做的？」（第 1 层） | 对应板块 | 先给结论：逻辑、验收、迭代方向是我的；代码是 AI 按我的规矩写的 |
| 16 | 【面】「追问：AI 生成的代码你怎么验收？怎么知道不是幻觉堆出来的？」（第 2 层） | 对应板块 | 逐项对照五段式需求做清单验收；重点查编造的接口 / 字段；跑起来亲眼验证；核心层设人工验收关 |
| 17 | 【面】「再追：如果周四真实用户试用时出了事故，责任怎么算？你怎么提前防？」（第 3 层） | 对应板块 | 责任在 PM 不在 AI；提前靠规则文件红线 + 改动冻结 + 人工验收关 + 彩排清单 |
| 18 | 【面】「规则文件具体写哪几块？写一句『注意代码质量』算不算？」 | 对应板块 | 四块：项目背景 / 技术约定 / 输出规范 / 红线；空话不算，要具体到「改完必须本地运行确认无报错」这种粒度 |
| 19 | 【面】「哪些事你绝不会交给 AI 做？边界怎么划？」 | 对应板块 | 用「可撤回性」判断：钱、账号、合规、长期维护资产不交；演示页、内部小工具、一次性交付可交 |
| 20 | 【面】「你只用了国产工具，是不是因为用不了国外的？」（压力追问） | 对应板块 | 不是能力限制，是生态与合规选择：客户在国内、团队在国内、合规对标国内，工具链长在国内是加分项 |
| 21 | 【面】「演示层快跑、核心层慢验，落到你项目里是哪两块、怎么切？」 | 对应板块 | 演示层（页面 / 样式 / 看板）交给 AI 快跑；核心层（真实用户数据流转、成本计算）设人工验收关 |
| 22 | 「手机 / 平板的同学，哪几步必须借电脑？替代动作是什么？」 | 对应板块 | 装工程派工具、存规则文件、断网验证、A/B 双栏必须借电脑；替代：网页版工具、语音输入指令、结对代跑、截图验收 |

带实习生类比｜许愿机误区：上限是提示词，下限是品味
边界口诀：演示层快跑，核心层慢验｜一句话判断：错了能不能撤回

【对应板块 · 原理 B + 案例】
五段式指令：是什么 / 给谁用 / 包含什么 / 长什么样 / 不能怎样
工具：一主两辅；对话派（WorkBuddy / 豆包） vs 工程派（Trae / 通义灵码 / CodeBuddy）
选型四问：演示一次还是迭代一周 / 愿不愿意装环境 / 页面展示还是数据流转 / 出问题谁来救
合格反馈 = 指出现象 + 给出方向
规则文件（AGENTS.md）四块：项目背景 / 技术约定 / 输出规范 / 红线
提示词即代码：五要素评分卡 = 编译器
金句：AI PM 的代码是提示词和工作流

【对应板块 · 实操】
电脑组：装工具 / 存规则 / 断网验证 / A-B 双栏（全步骤）

每题必带 ≥1 个当日术语

【对应板块 · 复盘验收】
三句收束 + 压轴金句

### 9.1 工具选型参考（原表保留）

| 任务场景 | 推荐选择 | 关键理由 |
|---|---|---|
| 周五路演前夜，5 分钟内要看到演示页 | WorkBuddy 或豆包 | 对话派零门槛，一句话到页面，不装环境 |

| 演示层与数据层都要覆盖 | 一主两辅组合 | 演示层用对话派，工程层用工程派，忌单打独斗 |

### 9.2 规则文件前三条参考（以「社区团购选品助手」为例，原表保留）

| 条目 | 示例 | 说明 |
|---|---|---|
| 项目背景 | 「本项目为社区团购选品助手 MVP，服务对象为团长，目标是输入食材清单输出选品建议与成本测算」 | 一两句话说清是什么、给谁用、做到什么程度 |
| 技术约定 | 「单文件 HTML，不引入外部依赖，配色统一用 #7C3AED」 | 定框架、定风格、定位置 |
| 红线 | 「不许调用未经验证的第三方接口；不许改动已验收的核心计算逻辑」 | 用「不许」开头，一条条列 |

### 9.3 【新增】对应板块术语小测参考答案（10 题，每题 1 分，≥8 分为达标）

| 题 | 考点 | 参考答案 | 评分标准 |
|---|---|---|---|
| 1 | Vibe Coding 定义 | 用自然语言说清需求、AI 生成代码、人负责验收与迭代 | 答出「人说清楚 + AI 生成 + 人验收」三要素得 1 分，缺「人验收」不得分 |
| 2 | 零依赖 ≠ 单文件页面 | 单文件讲文件数量，零依赖讲不靠外部资源；单文件也可能引在线字体 | 明确指出两者维度不同得 1 分 |
| 3 | 幻觉 | AI 编造不存在的接口 / 字段 / 事实，看似合理实则无中生有 | 答出「编造 / 无中生有」得 1 分，只答「出错」不得分 |
| 4 | 可验收 | 有可逐条对照的验收标准、有人确认才算完成 | 答出「有标准 + 有人确认」得 1 分 |
| 5 | 降级 | 主动换更轻路径达成目标，是计划内备选 | 答出「主动 / 备选 / 仍达成目标」得 1 分 |
| 6 | 五段式指令 | 是什么 / 给谁用 / 包含什么 / 长什么样 / 不能怎样 | 五段全对得 1 分，缺 1 段不得分 |
| 7 | 规则文件作用 | 项目宪法，管每一轮生成，跨工具跨天生效 | 答出「长期 / 每轮 / 跨工具」之一得 1 分 |
| 8 | 可用性 | 用户视角：看得懂、点得动、不溢出 | 答出「用户视角」得 1 分 |
| 9 | 外部依赖 | 需要联网 / 本地服务 / 特定字体才能跑的资源 | 举例正确得 1 分 |
| 10 | 国产大模型的约束 | 数据出境、内容安全、供应链自主、合规对标 | 答出任一合规维度得 1 分 |

### 9.4 【新增】对应板块面试评分示例（以「AI 生成的代码怎么验收」为例）

| 档位 | 表现 | 分值（满分 10） |
|---|---|---|
| 优秀 | 结论清晰 + 逐项对照五段式验收 + 点名防幻觉（查编造接口 / 字段）+ 跑起来亲眼验证 + 核心层设人工验收关 + 带出「可验收」「幻觉」术语 | 9–10 |
| 良好 | 有验收动作、提到人工验收关，但缺「防幻觉」或未用术语 | 7–8 |
| 合格 | 只说「我会看一眼 / 点一点」，缺机制、缺清单 | 5–6 |
| 失分 | 「AI 生成应该没问题」「出问题再说」，把验收责任推给 AI | 0–4 |

## 十、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 把 Vibe Coding 当「许愿机」 | 说一句话就想直接上线，生成失败就抱怨工具不行 | 用流程图强调五步是循环不是直线；现场演示「挑毛病—再说清楚」至少两轮【原有保留】 |
| 工具集邮 | 五款全部注册、每个都浅尝，最后一款用不深 | 讲「一主两辅」原则；实操第一题强制只选一款主力【原有保留】 |
| 生成失败就放弃或手工改代码 | 不会用自然语言描述差距，转而自己 debug（调试） | 演示合格反馈的公式：指出现象 + 给出方向；让学员现场练一句话反馈【原有保留】 |
| 跳过规则文件 | 直接开工，第二天发现输出风格全变、返工 | 现场展示「同一项目有无规则文件」两轮生成差异；实操第二题强制写三条【原有保留】 |
| 把「能跑」当「能交付」 | Demo 能演示就认为完工，不做验收 | 回扣 W2 评测集与 W6D4 测试验收安排；强调「演示层快跑，核心层慢验」【原有保留】 |
| 【新增·术语混淆】零依赖 / 单文件页面混用 | 认为「一个 HTML 文件就一定断网能开」，忽略在线字体、CDN（内容分发网络）脚本仍是外部依赖 | 用「带电源线的小家电」类比拆开；术语小测第 2、9 题当堂纠偏 |
| 【新增·术语混淆】幻觉当普通 bug | 看到 AI 编的接口名以为「只是没调通」，照着去联调半天 | 明确幻觉是「无中生有」，验收清单第一条就是查「这个接口 / 字段是否真实存在」 |
| 【新增·术语混淆】降级当放弃 | 手机 / 平板组同学一听「要装 IDE」就认为今天实操与自己无关 | 用「设备要求表」说明降级是计划内备选路径；结对补位，人人交齐三件套 |
| 【新增·面试失分】心虚或夸大 | 答「Demo 是不是你做的」时，要么反复说「我不会写代码」，要么说「全是我做的」 | 用 60 秒标准答法定调：逻辑 / 验收 / 迭代方向是我的，代码是 AI 按我的规矩写的；不卑不亢 |
| 【新增·面试失分】验收题只答「看一眼」 | 说不出验收机制、清单、人工验收关，也不带术语 | 用「逐项对照五段式 + 防幻觉 + 跑起来 + 人工验收关」四步模板反复两两模拟 |
| 【新增·面试失分】接不住追问 | 被追问「出事故谁负责」时愣住，或把责任推给 AI | 练 2–3 层追问链；统一口径「责任在 PM 不在 AI，靠规则文件红线 + 改动冻结 + 彩排提前防」 |
