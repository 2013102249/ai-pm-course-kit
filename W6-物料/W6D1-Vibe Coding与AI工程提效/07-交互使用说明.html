课堂交互使用说明 · 《提示词调试台》及本课交互资产（W6 周一专用 · 300 分钟版）

配套教学日：W6 周一《Vibe Coding 与 AI 工程提效》· 300 分钟（6 课时 × 50 分钟）。
用途：本课第 3 节「提示词即代码」（135–145 min，约 8 分钟）与第 4 节实操评分（158–190 min）核心教具。工具位置：02-交互工具/提示词调试台.html
本课语境：该工具在 W1D3 已作为「提示词五要素」教具使用；本课复用其五要素评分卡与 A/B 对比功能，升级为「提示词即代码」的演示台。
使用前请完成「课前检查」，故障处理见文末；300 分钟版另附《6 节使用时机表》与《设备要求表》。

一、何时用它：本课三个使用时点（原有保留，时间对齐 6 节）

时点用法时长
课前（可选）学员按导学案预习任务，把「开工指令」预填进去自测一次，带着问题上课学员自定
第 3 节（135–145 min，主用时点）讲师演示「提示词即代码」：五要素评分卡 = 提示词的编译检查器约 8 min
第 4 节（158–190 min，学员实操）学员现场改自己的开工指令，目标评分 5 分；手机 / 平板组由结对同学代跑并回读评分学员 32 分钟实操内完成

为什么本课用它演示「提示词即代码」：Vibe Coding 的全部产出，源头是给 AI 的指令。指令写得好不好，过去靠「感觉」，本工具把它变成可量化的评分——五个要素就是五条「编译规则」，缺哪条、掉几分，当场可见。学员由此建立认知：提示词是新的源代码，评分卡是新的编译器。

二、课前检查（开课前 10 分钟，原有保留）

检查项操作
投屏分辨率浏览器窗口 ≥1280px 宽，确保左右双栏不堆叠、五要素列表完整可见
模板切换先点一次「会议纪要总结」模板，确认四个场景模板均可正常载入
A/B 面板打开右上角「A/B 对比模式」开关，确认双配置面板正常显示
离线可用性本工具全部逻辑在浏览器本地运行，无外部请求；课前断网验证一次即可
备用方案提前对「完整版 / 删角色版 / 精简版」三屏截图，工具异常时直接放截图讲
学员端群里发布工具链接，提醒学员第 4 节实操时同步打开（手机端 ≤720px 自动单栏，可用，但 A/B 双栏看不全，见《设备要求表》）
结对准备本期 1 名学员仅持手机 / 平板，课前指定 1 名电脑组同学结对，确认屏幕共享方式

三、五步演示脚本（与讲课稿第 3 节对应，原有保留）

步骤讲师操作30 秒讲解要点提问
① 认识结构点击「会议纪要总结」模板，点「运行」提示词也有「语法结构」：角色 / 任务 / 约束 / 输出格式 / 示例；五项齐全 = 编译全过 = 5 分「这条提示词由哪几部分组成？」
② 缺一行删掉 System Prompt 里的角色描述，再点「运行」提示词「缺一行」就像代码「缺一个 import」——功能照跑，边界条件下崩「哪一项从已覆盖变成缺失？说明什么？」
③ 体验失控把 User Prompt 精简成「总结一下」，再运行模糊的需求描述 = 不可维护的代码；总分掉到 2 分，输出开始自由发挥「总分降到几分？缺了哪几项？」
④ 对照改进按评分卡的改进建议逐项补回提示词迭代 = 按编译错误逐行修；约束与输出格式是「生产环境关键行」「补哪一项对分数提升最明显？」
⑤ 理解参数打开 A/B 对比，A 保持完整提示词、温度 0.3；B 只留半句、温度拉到 0.9，点「对比运行」同一提示词不同温度、不同完整度的稳定性差异；结论：生产环境要「低温度 + 完整提示词」「两个回答差在哪？哪个更适合上线？」

四、两个关键演示动作（不可省略，原有保留）

  1. 必须让学员「看见掉分」：删角色描述后，手指沿五要素列表从上往下划，停在「角色设定 · 缺失」一行，再指向总分从 5 变 4。视觉冲击比讲解更有效。
  2. A/B 对比必须改两个变量中的一个先、再改另一个：先只改提示词（温度相同），让学员确认「差异全部来自提示词」；再拉温度，确认「温度放大发散」。一次只改一个变量，是 W5D2 AB 实验纪律的回扣。

五、常见故障处理（原有保留）

故障处理
页面打不开 / 白屏确认文件路径 02-交互工具/提示词调试台.html；用浏览器直接打开（file:// 协议即可，无需起服务）
点击「运行」无输出刷新页面重试；或改点其他场景模板，确认是否为单模板问题
流式回答中途停住刷新后重跑该步；讲解不中断，用「工具也会卡，产品要有兜底」带过
A/B 面板点了「对比运行」只有一侧出结果检查两侧文本框是否都有内容；任一侧为空时该侧无评分
投屏字太小浏览器 Ctrl / Cmd + 「+」放大至 125%
学员端打不开无需等待——本工具课后可自学；第 4 节实操改为纸上填写五要素自评，讲师投屏展示
手机 / 平板端 A/B 双栏退化单栏属「必须借电脑」四步之一：由结对同学代跑并回读两侧评分，手机组对照导学案验收清单签字

六、课后学员自学指引（发群文案，原有保留）

同学们，今天课的「提示词调试台」已发群。课后请大家完成三件事：① 把你的开工指令改到五要素 5 分，把改前改后两版都存下来；② 依次点开「客户意图分类 / 合同信息抽取 / 文案改写」三个模板，各评一次分，找出五要素里你最常缺的一项；③ 打开 A/B 对比，固定提示词只改温度（0.1 与 0.9），跑三次，记录输出差异。周二开发冲刺课前，助教会抽查开工指令评分——5 分是底线，不是目标。

「必须借电脑」四步的判定依据（供讲师巡场解释）

步骤为什么手机 / 平板做不了代跑后手机组要拿到什么
装工程派工具桌面 IDE / 编辑器插件无移动端形态一句「主力 / 备用工具已登录」的确认
保存 AGENTS.md无项目目录与文件管理能力结对回读的三条规矩原文，确认与口述一致
断网验证零依赖无法模拟「断网 + 本地双击打开」验收清单上「断网可开、字体正常、按钮可用」三项打勾
A/B 双栏对比窄窗口自动单栏，两个配置面板看不全、对比失真结对念出 A / B 两侧评分与「一次只改一个变量」的结论

三条巡场要点

  1. 结对不是「电脑组全包」：手机 / 平板组持有「五段式指令 + 挑毛病清单 + 验收清单」三样主导权，电脑组只代跑上述四步。
  2. 手机端「卡片溢出 / 点不动」这类可用性问题，往往只有手机视角看得见——手机组是挑毛病的主力，不是旁观者。
  3. 归档不能降级：三件套与验收截图确认收到后再打勾，产出可以借手，署名必须是自己。
