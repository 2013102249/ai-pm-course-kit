内容（节点文案，一字不改）

  1. 说清楚 —— 注解：需求写成五段式：是什么 / 给谁用 / 包含什么 / 长什么样 / 不能怎样
  2. 生成 —— 注解：AI 工具产出代码或页面
  3. 跑起来 —— 注解：本地运行，亲眼验证
  4. 挑毛病 —— 注解：对照预期找差距：样式 / 逻辑 / 报错
  5. 再说清楚 —— 注解：差距一句话描述给 AI，进入下一轮

循环箭头中部放轮次胶囊：「快速迭代 · 通常 3–10 轮」。

右下角边界提示条（白底紫字）：「边界口诀：演示层快跑，核心层慢验」。

验收标准

  1. 五步顺序与教案完全一致，箭头方向清晰、无交叉打结；
  2. 循环必须是闭环视觉（第五步有箭头回到第一步），不能画成直线流程；
  3. 中文标注无错别字，「说清楚 / 生成 / 跑起来 / 挑毛病 / 再说清楚」动词保持原样；
  4. 品牌色严格使用紫 #7C3AED 与蓝 #2563EB，不引入第三色系（灰阶除外）；
  5. 缩至 720px 宽仍可读（投屏备用机与学员手机场景）；
  6. 不含 emoji、不含任何国外工具名、不含价格数字。

讲法脚本

  • 使用时机：对应板块开场，投屏后停留约 8 分钟，是方法论部分的主视觉。
  • 讲法：分两段讲。第一段，从左上方「说清楚」起，沿箭头依次走完五步，每步念节点标题 + 一句注解，语速放慢；走完第五步时，手指沿循环箭头划回第一步，强调「这是循环不是直线——一个 Demo 通常三到十轮」。第二段，指向轮次胶囊提问「所以 Vibe Coding 的本质是什么」，引出「快速迭代」与金句「上限是提示词，下限是品味」。
  • 提问点：「这个箭头为什么是循环的？本质是什么？」（预期：本质不是一次生成对，是快速迭代）
  • 过渡话术：「循环讲完了，但哪些事能进这个循环、哪些不能，得划条线——看右边这条边界提示。」

验收标准

  1. 五款工具名称准确无错别字：WorkBuddy / 豆包 / Trae / 通义灵码 / CodeBuddy；
  2. 无任何具体价格数字、无参数数字（如准确率、支持语言数）——只允许「免费额度」这类公开口径，且必须带「以官网实时政策为准」；
  3. 与导学案「五工具对比记录表」五列结构一致（定位 / 擅长场景 / 上手难度 / 价格模式），学员可对照填写；
  4. 派别分组视觉清晰：前两行对话派（蓝）、后三行工程派（紫），组别标签不遮挡单元格文字；
  5. 1920px 宽下表格不换行、不溢出；品牌色与图 1 统一；
  6. 不含 emoji、不含国外工具名。

讲法脚本

  • 使用时机：对应板块开场，投屏后停留约 10 分钟，是选型环节的主视觉；学员对照导学案同步填写。
  • 讲法：先讲原则「不要当工具集邮党，要一主两辅」，再逐行讲五款工具，每款只讲定位一句话 + 擅长场景一句话，不展开参数。讲完后归纳派别：手指沿前两行划一下「对话派」，再沿后三行划一下「工程派」。最后给出选型四问（演示一次还是迭代一周 / 愿不愿意装环境 / 页面展示还是数据流转 / 出问题谁来救），让学员在导学案「我的项目选哪个」列写下答案。
  • 提问点：「五款工具能分几派？规律是什么？」（预期：对话派零门槛做演示，工程派项目级迭代）
  • 过渡话术：「工具选好只是开始——连续迭代三天，没有规矩 AI 每天给你不同的东西。下一招：规则文件。」

内容（示范题用对应板块题 1）

  • 题目：「你不会写代码，这个 Demo 到底是不是你自己做的？」
  • 第 1 层「那代码到底谁写的？」→ 应答要点：AI 出体力，我出判断；不心虚也不夸大。
  • 第 2 层「AI 写的你怎么保证没问题？」→ 应答要点：逐项对照五段式验收、跑起来亲眼验证、核心层人工验收关。
  • 第 3 层「出了事故谁负责？」→ 应答要点：责任在 PM 不在 AI；规则文件红线 + 改动冻结 + 彩排。
  • 底部横条：答题四件套「踩分点 → 追问链 → 失败答法 → 60 秒标准答法」；总纲「先给结论、中间带术语、结尾把责任收到人这边」。

讲法脚本

  • 使用时机：对应板块题型拆解 15 min 的主视觉，配合 8 张面试追问卡使用。
  • 讲法：先只露题目条，请学员答第一层；答完逐层下拉露出追问框，每露一层点一名学员接；三层走完，指底部总纲齐读一遍。强调「追问越深，越是在确认你是不是真做过」。
