## 第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错三种题型）

## 第 1 层 · 基础巩固（4 题）

> 用于对应板块随堂巩固。满分 20 分，达标线 ≥ 15 分。

**1-1（填空）** 补全三态「必备三要素」：
空态 = 图标／插图 + ________ + 下一步动作；错态 = 发生了什么 + 你能做什么 + ________（且已输入内容不丢）；加载态 = 即时反馈 + ________ + 防重复提交。

**1-2（简答）**「暂无数据」四个字为什么不合格？请把它改写成一条合格空态（写出插图、文案、按钮）。

**1-3（判断 + 理由）** 判断下列三个操作要不要做加载态，并各给一句理由：① AI 生成回答（约 10 秒）；② 本地折叠面板展开（< 0.2 秒）；③ 表单提交后等待约 2 秒。

**1-4（简答）** 某错态只弹了一句「出错了」，没有重试按钮、且把 200 字输入清空了。指出它违反了 22 项清单 B 组哪几项，并说明各应判什么级。

### 第 1 层 · 参考答案与评分标准

| 题 | 参考答案 | 评分标准 |
|---|---|---|
| 1-1 | 一句人话（说明）／重试或修改入口／进度感知 | 每空 1 分，共 3 分；本层按 5 分制折算见下 |
| 1-2 | 不合格：只说现状，缺图标、缺原因与建议、缺下一步动作。改写示例：放大镜插图 +「没有找到与『退款』相关的结果，试试更短的关键词，或更换同义词」+ 主按钮「清空重搜」 | 说出「缺下一步动作」2 分；改写含插图 / 人话 / 按钮三件套 3 分，共 5 分 |
| 1-3 | ① 要（远超 1 秒，必须给反馈 + 进度感知 + 防重复）；② 不要（纯本地瞬时切换，可标 N/A）；③ 要（超过 1 秒）；拿不准按「用户会不会怀疑坏了」判，不掐秒表 | 每判断正确 1 分 + 理由合理 0.5 分，共 4.5 分，四舍五入计入 5 分 |
| 1-4 | 违反 B1（暴露技术报错/不友好）、B2（缺「发生了什么 + 能做什么」两句）、B3（缺重试与「已输入不丢失」提示）、B5（输入未保留）。B3/B5 影响任务完成与信任，判 P1；若演示路径必现可升 P0 | 每指出 1 项 1 分（最多 4 分），分级与理由 1 分，共 5 分 |

> 折算：1-1 按 3 分记、1-3 按 5 分记，本层满分 20 分，≥15 分达标。

## 第 3 层 · 求职挑战（3 题）

> 用于对应板块前预热、对应板块复盘。满分 15 分，达标线 ≥ 11 分；答法须带当日术语。

**3-1（短答提纲）** 用 60 秒答法的「四段结构」，写出「异常态怎么设计」的提纲（每段一句话，标出会用到的术语）。

**3-2（情景简答）** 研发说「这个异常不用做，正常路径又不会出错」。写一段对齐话术，必须点名至少两件可交付物，并引用一个反面案例结论。

**3-3（复盘简答）** 结合「只做正常态、异常态一片空白导致用户流失」案例，用「状态机 / 可恢复 / 反馈闭环」三个术语写一段复盘（不编造数字，量化结论写「待教务补充」）。

### 第 3 层 · 参考答案与评分标准

| 题 | 参考答案 | 评分标准 |
|---|---|---|
| 3-1 | ① 结论定义（带术语）：错态是操作失败时给原因与恢复入口、且可恢复的状态；② 3 条动作：人话、重试 / 修改入口、输入不丢 + 超时兜底；③ 可交付物：状态清单 + 走查清单 B3/B5；④ 金句：错态的底线不是提示，是用户出问题时东西还在、还能接着来 | 四段各 1 分共 4 分、标出术语（错态 / 可恢复 / 兜底文案 任一）1 分，共 5 分 |
| 3-2 | 要点：用状态机把四态写成需求条目（交付物一）、用 22 项走查清单当共同验收物且助教按表核验（交付物二）、用 P0/P1/P2 排期先保演示路径；引用「异常态不是意外，是必达路径」与对应板块用户流失复盘；不靠「多沟通」 | 两件交付物各 1.5 分共 3 分、优先级 1 分、反面案例结论 1 分，共 5 分；只答「多沟通」最多 1 分 |
| 3-3 | 要点：状态机只写了正常态，漏空 / 错 / 加载；可恢复没做（断网后输入全丢）；反馈闭环在失败那一刻断线，用户「以为没保存 → 以为崩了 → 关掉去别家」，且不留反馈、后台难归因；量化结论「待教务补充」 | 三术语各 1 分共 3 分、流失链条 1 分、不编数字（写待教务补充）1 分，共 5 分 |

## 第 4 层 · 面试实战（6 题，每题含踩分点 / 追问链 / 参考答案 / 评分表）

> 用于对应板块两两模拟。每题满分 10 分，≥7 分达标；评分表由同桌填写，结果抄入《面试模拟记录表》。通用结构：① 带术语的结论 → ② 3 条可判分动作 → ③ 可交付物 → ④ 金句收口。

### 面试题 4-1 ·「三态是什么？为什么 AI 产品尤其要单独设计？」（技术理解）

- **踩分点**：① 说出空 / 错 / 加载三态及各自触发场景（3 分）；② 指出 AI 生成耗时长、结果不确定，等待与失败是高频路径（2 分）；③ 用「状态机」说明四态并存（2 分）；④ 上升「功能决定能不能用，三态决定敢不敢用」（1 分）。
- **追问链**：L1「最容易被漏的是哪一态？」→ 加载态；L2「怎么保证团队不漏？」→ 状态机四态清单 + 22 项走查清单；L3「研发说加载态不重要？」→ 用 badcase 与 P1 级别对齐，写进验收物。
- **参考答案（60 秒要点）**：三态逐态给触发场景与三要素 → 联系 AI 特性 → 状态机四态写全 → 走查清单验收 → 金句收口。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 定义完整 | 3 | 三态 + 触发场景齐全 | |
| AI 特性 | 2 | 点出耗时长 / 结果不确定 / 高频 | |
| 术语运用 | 2 | 用「状态机」且用对 | |
| 上升视角 | 1 | 说到信任 / 敢不敢用 | |
| 交付物与收口 | 2 | 落到清单 / 看板 + 金句 | |

### 面试题 4-2 ·「一个结果都没有的页面，空态怎么设计？现场说文案和结构。」（场景设计）

- **踩分点**：① 三件套齐全（图标 / 人话 / 下一步动作，2 分）；② 文案给原因 + 修改建议而非「暂无数据」（2 分）；③ 给可点击动作（清空重搜 / 换词，2 分）；④ 区分「首次无数据」与「搜索无结果」两种空态（2 分）。
- **追问链**：L1「未登录导致的空白算空态吗？」→ 算，给登录入口；L2「要不要放推荐内容？」→ 可放，但主目标仍是下一步动作；L3「怎么验证合格？」→ 清单 A 组 5 项 + 「用户看完知道点什么」。
- **参考答案（60 秒要点）**：先分类型 → 三件套逐项给具体文案 → 落到清单 A2 硬指标 → 「空态不是装饰，是反馈闭环一环」。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 三件套 | 2 | 图标 / 人话 / 动作齐全 | |
| 文案质量 | 2 | 有原因 + 建议，无裸词 | |
| 可点动作 | 2 | 至少 1 个明确按钮 | |
| 分类意识 | 2 | 区分两类空态 | |
| 验收落点 | 2 | 对清单 A 组 + 收口金句 | |

### 面试题 4-3 ·「异常态怎么设计，才能让用户有路可走、且不丢已输入内容？」（场景设计 / 项目深挖）

- **踩分点**：① 人话、不暴露 500 / undefined / 堆栈（2 分）；② 给重试 / 修改入口（2 分）；③ 保「可恢复」——提示写「已保留」、表单不清空（3 分）；④ 给超时兜底（如 30 秒重试 / 取消，1 分）。
- **追问链**：L1「重试又失败？」→ 次数上限 + 查看历史记录等替代路径，形成反馈闭环；L2「怎么和研发保证输入不丢？」→ 前端本地暂存 + 需求条目写明，用 B5 验收；L3「算 P0 还是 P1？」→ 按口诀，演示路径必现升 P0。
- **参考答案（60 秒要点）**：三条底线 + 一个兜底 → 写成需求条目与研发对齐 → B3/B5 验收 → 「底线不是提示，是东西还在、还能接着来」。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 人话 / 不暴露技术细节 | 2 | 明确禁用报错码 | |
| 恢复入口 | 2 | 重试 / 修改入口具体 | |
| 可恢复 | 3 | 提示语 + 表单不清空 + 本地暂存 | |
| 超时兜底 | 1 | 给时间点与选项 | |
| 交付物与收口 | 2 | 需求条目 / 清单编号 + 金句 | |

### 面试题 4-4 ·「加载态什么时候用骨架屏、进度条，什么时候做降级？怎么取舍？」（技术理解）

- **踩分点**：① 骨架屏用于结构可预期、进度条 / 百分比用于时长可估、流式输出用于生成类（3 分）；② 点明三者只是「进度感知」，替代不了即时反馈与防重复（2 分）；③ 降级用于主能力不可用保核心链路并配兜底文案（2 分）；④ 给出取舍依据：时长 / 结构 / 主链路（1 分）。
- **追问链**：L1「只有转圈够不够？」→ 不够；L2「降级会让用户觉得残缺吗？」→ 用兜底文案说明「当前为简化版」并给恢复后的完整结果；L3「按钮禁用会不会像卡死？」→ 禁用同时给文案 / 进度，形成反馈闭环。
- **参考答案（60 秒要点）**：先厘清「手段 ≠ 加载态全部」→ 按两条件选手段 → 降级场景 → 两条不变（即时反馈、防重复）→ 反馈闭环收口。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 手段辨析 | 3 | 三种手段各归位 | |
| 关系正确 | 2 | 明确骨架屏 ≠ 加载态全部 | |
| 降级理解 | 2 | 功能退让 + 兜底文案 | |
| 取舍依据 | 1 | 说清判据 | |
| 不变项与收口 | 2 | 即时反馈 / 防重复 + 金句 | |

### 面试题 4-5 ·「体验走查怎么做？怎么保证不走成走过场？」（项目深挖）

- **踩分点**：① 22 项五组结构（2 分）；② ✓/✗/N/A 打法 + 不通过写具体画面（2 分）；③ P0/P1/P2 分级 + 返工排序（2 分）；④ 跨项目配对 +「只对项目不对人」+ P0 讲师终审（2 分）。
- **追问链**：L1「检查方不好意思说问题？」→ 立规则、写不出画面视为没查、抽查询问；L2「两轮记录不一致听谁的？」→ 以检查方为准并标注，P0 终审；L3「怎么证明有价值？」→ 通过率 / 返工清零 / 周四试用反馈对照，细节是体验的复利。
- **参考答案（60 秒要点）**：清单五组 → 打勾写画面 → 分级排序 → 防走过场三条 → 三件可交付物 → 金句收口。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 清单结构 | 2 | 五组分布说对 | |
| 记录规范 | 2 | 打法 + 写具体画面 | |

### 面试题 4-6 ·「怎么和研发对齐兜底？研发说这个异常不用做你怎么办？」（项目深挖 / 行为题）

- **踩分点**：① 把兜底写成需求条目（状态清单四态 + 边界情况，3 分）；② 用走查清单当验收物而非口头约定（2 分）；③ 用 P0/P1/P2 对齐优先级、用 badcase / 演示风险说服（2 分）；④ 明确「可恢复、输入不丢」硬验收点（1 分）。
- **追问链**：L1「排期紧只能做一半？」→ 先保演示路径上的错态 / 加载态，P2 动效后置；L2「怎么避免上线后被砍？」→ 写进验收清单、助教按表核验、不达标打回；L3「你亲自写过兜底文案吗？」→ 给具体一句 + 三句结构。
- **参考答案（60 秒要点）**：三件可交付物对齐 → 硬验收点 → 优先级 → 反面案例结论「异常态不是意外，是必达路径」→ 亲写一句兜底文案收口。
- **评分表**

| 维度 | 分值 | 满分表现 | 得分 |
|---|---|---|---|
| 需求条目化 | 3 | 状态清单 + 边界情况 | |
| 验收物 | 2 | 走查清单 / 助教核验 | |
| 优先级与说服 | 2 | 分级 + badcase | |
| 硬验收点 | 1 | 可恢复 / 输入不丢 | |
| 反面案例与收口 | 2 | 引用结论 + 亲写文案 | |

### 二、功能完整度 4 条硬标准（全部满足才算过）

| # | 硬标准 | 验法（可打勾） | 判定规则 |
|---|---|---|---|
| 1 | 核心链路 100% 可跑通 | 从进入产品 → 主输入 → 处理 → 结果呈现，完整走一遍主路径 | 任何一步卡死、报错、无响应，即不通过；此项为 P0 级，当场记录 |

### 三、体验走查通过率（软标准）

- **工具**：导学案《体验走查清单》22 项（空态 5 / 错态 5 / 加载态 4 / 文案 4 / 一致性 4）。
- **算法**：通过率 = 通过项数（✓）÷（22 − N/A 项数）× 100%，保留整数。N/A 项须在周四前补说明，未补说明的 N/A 计为不通过。
- **判定档位**：

| 档位 | 条件 | 处理动作 |
|---|---|---|
| 通过 | 通过率 ≥ 80% 且无 P0 | 体验验收通过，进入周四测试验收 |
| 限期返工 | 通过率 60%–79%，或 ≥ 80% 但存在 P0 | 当晚按返工优先级排序抢修，周四测试验收前完成复走查 |
| 当晚必须返工到位 | 通过率 < 60% | 当晚 22:00 节点顺延至复走查通过为止；影响周四试用安排的，由讲师协调助教支援 |

- **数据来源**：22 项清单由「同组互查 + 自检」两轮记录合成——检查方填写的清单是主数据，被检查方自检是复核数据；两轮不一致的项，以检查方记录为准并标注。

### 四、返工优先级规则（P0 / P1 / P2）

| 级别 | 定义 | 判定口诀 | 时限 | 典型示例 |
|---|---|---|---|---|
| P0 · 翻车 | 阻断演示 / 数据错误 / 合规风险 | 「演示会不会断、数据对不对、有没有合规风险」三条占其一 | 当天清零，当晚 22:00 前复验 | 主路径点击报 500；AI 生成内容无标识；演示账号登不上；错误数据对外可见 |
| P1 · 明显 | 影响任务完成，或导致用户困惑 | 「用户会不会卡住、会不会看不懂」 | 当天返工，随今晚提交 | 搜索无结果是白屏；加载无反馈；按钮中英混杂；错误后输入被清空 |
| P2 · 优化 | 更好但非必须 | 「没有会不会死」 | 记入优化清单；周五路演前有余力则做，做不完带入 W7 复盘，不丢人 | 骨架屏动效；空态插画精致度；文案语气统一；图标替换 |

P0 的确认与撤销只有讲师有权，防止「大事化小」和「小题大做」两种极端。

#### 同级排序规则（先级别、后权重、再成本）

1. **先按级别**：P0 → P1 → P2，不同级别不混排。
2. **同级按演示路径权重**：路演 5 分钟会经过的界面 > 核心功能界面 > 后台 / 设置界面。评委只看前者。
3. **仍同级按修复成本升序**：5 分钟能修的先修，快速降风险、快速降焦虑。
4. **落到人**：每条问题对应唯一负责人和截止时间，写入小组返工看板，禁止「大家都负责 = 没人负责」。

### 讲稿原题（可作追问链）

- 我先问一个问题：昨天链路已经跑通了，今天最该补什么？
- 第一种状态，空态。什么叫空态？用户打开你的产品，里面什么都没有——第一次用，没有历史记录；搜了一个词，没有结果；功能开着开关，没填过资料。这时候你的页面长什么样？
- 如果你的产品搜索后一个结果都没有，页面应该说什么？
- 模型 30 秒没返回，用户盯着屏幕能做什么？
