二、教学目标（可测量）

  1. 能对照三态设计标准，指出任意界面在空态、错态、加载态上的缺陷，并写入走查清单（验证：导学案 22 项体验走查清单完成度 100%，A/B/C 三组 14 项逐条有结果）。
  2. 能按 P0 / P1 / P2 给问题分级，并给出本组返工的先后顺序（验证：问题清算与返工排序表，每条含级别、页面、负责人、截止时间）。
  3. 本组项目体验走查通过率达到 80% 以上且无 P0 遗留（验证：产出验收清单，为周四测试验收的前置条件）。
  4. 【术语目标】 能准确说出本日 12 个核心术语的一句话定义，并至少完成 8 组「易混辨析」的正确配对（验证：第 1 节《术语自测表》≥8 行自评 + 第 0 层术语辨析小测正确率 ≥ 80%，错态/空态/加载态/降级 四词零混淆）。
  5. 【面试目标】 能用 60 秒标准答法回答「三态是什么」「异常态怎么设计」「体验走查怎么做」「怎么和研发对齐兜底」四类问题，答法至少含 1 个当日术语并能扛住 2 层追问（验证：《面试模拟记录表》≥4 行，含追问记录与自评分，两两模拟互评 ≥ 达标）。
  6. 能把当日走查与返工成果，归整为可放入作品集的「三态设计标准 + 走查清单 + 返工前后对照」三块积木（验证：《本日作品集积木》表产出物 / 完成度 / 归档位置三列填写完整）。
  7. 能理解「细节是体验的复利」，并用一句反面案例说明「只做正常态、异常态一片空白」为什么会导致用户流失（验证：第 3 节讨论发言 + 第 6 节三句收束复述）。

六、三态设计标准表（本课核心）

状态触发场景必备三要素合格标准常见反例
空态首次进入无数据 / 搜索无结果 / 功能未开启① 图标或插图 ② 一句人话说明 ③ 下一步行动指引用户看完知道「现在做什么能得到内容」白屏；「暂无数据」四个字裸奔；无任何按钮
错态网络失败 / 服务超时 / 输入非法① 人话说明发生了什么 ② 用户能做什么 ③ 重试或修改入口不暴露技术细节；用户已输入内容不丢失；有路可走「Error 500」；「undefined」；alert 弹窗后清空表单
加载态任何超过 1 秒的操作① 即时反馈 ② 进度感知 ③ 防重复提交用户知道系统在干活、大约还要等多久点击后 3 秒无反应；按钮可重复点击；干等无进度

宣讲顺序建议：先空态（出现频率最高），再错态（最影响信任），最后加载态（最容易漏）。每讲一态，配一次课堂提问（见第七节）。三态之上补一层「状态机」视角：任何界面都不止「正常态」一个画面，而是「正常 / 空 / 错 / 加载」四态并存，四态都写完才算这个界面做完。

七、课堂提问设计（20 问）

分类：原理与走查（1–8）、术语辨析（9–14）、面试追问（15–20）。其中术语辨析 ≥6、面试追问 ≥6，满足 300 分钟版提问规范。

#类别提问提问时机预设答案 / 引导方向
1原理「昨天核心链路已经跑通，今天最该补什么？」第 2 节开场不是再加功能，是补体验细节——三态是用户看得见的部分
2原理「用户搜索后一个结果都没有，页面应该说什么？」第 2 节空态说人话 + 给建议 + 给动作：「没有找到相关结果，试试更短的关键词」+ 清空重搜按钮
3原理「模型 30 秒没返回，用户盯着屏幕能做什么？」第 2 节错态超时提示 + 重试按钮；输入内容保留；不暴露技术报错
4原理「点击生成按钮 3 秒没反应，用户第一反应是什么？」第 2 节加载态以为坏了，会重复点击——所以加载态要即时反馈 + 禁用按钮
5走查「互查发现问题一大堆，先修哪个？」第 3 节按 P0 → P1 → P2；同级先修演示路径上的
6走查「通过率多少算达标？有 P0 算不算达标？」第 6 节验收通过率 80% 以上且无 P0；有 P0 时通过率再高也不达标
7原理「为什么路演评委第一眼看到的常常不是核心功能？」第 2 节往往是某个白屏、报错或转不完的圈；功能决定能不能用，体验决定敢不敢用
8走查「同一条问题，检查方和你判断不一致，以谁为准？」第 3 / 4 节以检查方记录为准并标注，P0 由讲师终审，避免人情分
9术语辨析「空态和错态都『没有内容』，怎么一眼区分？」第 1 节看触发原因：无数据是空态，出问题才是错态；空态给「下一步」，错态给「恢复路径」
10术语辨析「骨架屏就是加载态吗？两者什么关系？」第 1 节骨架屏是加载态里「进度感知」的一种实现手段，不等于加载态全部（还有即时反馈、防重复）
11术语辨析「兜底文案和降级是一回事吗？」第 1 节兜底文案是给用户的说明文字；降级是功能层面的退让策略（如关掉非核心能力保主链路）
12术语辨析「容错和可恢复，哪个范围更大？」第 1 节容错是系统「扛住错误不崩」的能力；可恢复专指「用户能回到出错前的状态、输入不丢」
13术语辨析「体验走查和普通『试用一下』差在哪？」第 1 节走查有 22 项可勾选标准、分级和记录，是结构化验收；试用是主观感受
14术语辨析「状态机里的『状态』，和我们说的『三态』是不是同一个『态』？」第 1 节同源但层级不同：三态是「异常/等待类」界面状态的子集，状态机还含正常态与切换条件
15面试追问「你说要做三态，那三态分别是什么？为什么 AI 产品格外要讲？」第 5 节空/错/加载 + 生成耗时长、结果不确定 → 等待与失败高频，三态是信任底线
16面试追问「异常态怎么设计？说一个你写过的兜底文案。」第 5 节人话说明 + 可做什么 + 重试入口 + 输入不丢；文案要具体到字段与动作
17面试追问「体验走查怎么做？怎么保证不走成走过场？」第 5 节清单化 22 项 + 逐项打勾 + 问题写具体画面 + 分级 + 跨项目互查
18面试追问「怎么和研发对齐兜底？研发说『这个不用做』你怎么办？」第 5 节用状态清单把兜底写成需求条目，用走查清单当验收物，用 P0 级别对齐优先级
19面试追问「如果只能修一个，骨架屏动效和错态不丢输入，你先做哪个？」第 5 节先错态不丢输入（可恢复、影响信任，属 P1/P0），骨架屏动效是 P2 优化
20面试追问「你怎么证明这些细节真的有价值，不是自嗨？」第 5 节细节是体验的复利；用走查通过率、返工清零记录、周四试用反馈做对照基线

【第 2 节 · 原理 A】今天只做两件事：功能补全 + 三态打磨（禁止开新需求）
  空态   = 图标 + 人话 + 下一步动作
  错态   = 发生了什么 + 你能做什么 + 重试入口（已输入内容不丢）

  状态机 = 每个界面「正常 / 空 / 错 / 加载」四态都写完才算做完

  问题分级：P0 翻车当天清零 / P1 明显当天返工 / P2 优化周五前有余力再做
