AI 产品经理就业训练营 · 学员版 · 课上直接填写 · 姓名：____________ · 项目名：____________
本日任务是「走查」：你会拿到一张 22 项体验走查清单，先检查别人的项目，再被别人检查。清单打勾、问题记录、分级排序，全部可勾选、可互查、可排序。

一、课前预习（上课前完成，约 15 分钟）

预习任务 1：打开自己的项目，把 5 个关键页面各点一遍（首页 / 主功能页 / 结果页 / 历史记录页 / 设置页），用笔记下哪一处你觉得「用户可能懵」。

- 空态是：________________________________________________

预习思考题（课上会点名回答）：
1. 用户搜索后没有任何结果，你的页面现在是什么样？合格的样子应该包含哪三个要素？

  1. 网络断开时你的产品会显示什么？用户已经输入的内容还在不在？
  1. 你的项目里，哪个操作等待超过 1 秒却没有任何加载提示？

二、体验走查清单（22 项，课上作为检查方填写）

用法：对照被检查方的项目逐项验证。结果列打「✓」通过 /「✗」不通过 /「N/A」不适用；不通过时，问题记录列必须写清具体画面（在哪个页面、做了什么操作、看到什么），写不出画面视为没查。问题分级：P0 翻车（阻断演示 / 数据错误 / 合规风险）、P1 明显（影响任务完成或用户困惑）、P2 优化（更好但非必须）。

A 组 · 空态（5 项）

# 检查项 结果 问题记录（不通过必填，注明 P0/P1/P2）
A1 首次进入无数据时，页面有引导性空态，不是白屏，也不是「暂无数据」四个字了事 ✓ / ✗ / N/A
A2 空态包含「下一步动作指引」，用户看完知道现在做什么能得到内容 ✓ / ✗ / N/A
A3 空态有图标或插图，视觉上不裸奔 ✓ / ✗ / N/A
A4 搜索无结果时，空态给出可能原因与修改建议（如「试试更短的关键词」） ✓ / ✗ / N/A
A5 未登录 / 功能未开启时的空态有明确入口（登录按钮 / 开启开关），不是一句拒绝 ✓ / ✗ / N/A

B 组 · 错态（5 项）

# 检查项 结果 问题记录（不通过必填，注明 P0/P1/P2）
B1 网络错误有友好提示，不暴露技术报错（如 500、undefined、代码堆栈） ✓ / ✗ / N/A
B2 错误提示说人话：发生了什么 + 用户能做什么，两句齐全 ✓ / ✗ / N/A
B3 模型超时 / 生成失败有重试按钮，且提示「已输入内容不会丢失」 ✓ / ✗ / N/A
B4 表单校验错误定位到具体字段，提示写在出错位置，不弹窗后不清空 ✓ / ✗ / N/A
B5 错误发生后，用户已输入的内容完整保留，刷新前不丢失 ✓ / ✗ / N/A

C 组 · 加载态（4 项）

# 检查项 结果 问题记录（不通过必填，注明 P0/P1/P2）
C1 所有超过 1 秒的操作都有加载反馈（转圈 / 骨架屏 / 进度条任选其一） ✓ / ✗ / N/A
C2 AI 生成类操作用流式输出或分步进度展示，不是静止画面干等 ✓ / ✗ / N/A
C3 加载过程中触发按钮禁用，无法重复提交 ✓ / ✗ / N/A
C4 长时间无响应有超时兜底（如 30 秒后给出重试或取消选项） ✓ / ✗ / N/A

D 组 · 文案（4 项）

# 检查项 结果 问题记录（不通过必填，注明 P0/P1/P2）
D1 界面文案全部为中文，无中英混杂（API、JSON 等约定俗成的技术词除外） ✓ / ✗ / N/A
D2 按钮文案是「动词 + 名词」，无「确定 / 提交」裸词造成的歧义 ✓ / ✗ / N/A
D3 AI 生成的内容有「AI 生成」标识，符合合规要求 ✓ / ✗ / N/A
D4 无错别字、无未替换的占位文本（测试 / test / lorem / 某某某） ✓ / ✗ / N/A

E 组 · 一致性（4 项）

# 检查项 结果 问题记录（不通过必填，注明 P0/P1/P2）
E1 全站主按钮的颜色、圆角、字号统一，不存在两种主按钮样式 ✓ / ✗ / N/A
E2 相同操作在所有页面表现一致（如删除要么都二次确认，要么都不确认） ✓ / ✗ / N/A
E3 图标风格统一，线形与面性图标不混用 ✓ / ✗ / N/A
E4 页面跳转后返回，原状态保留（已输入的筛选、搜索词不清空） ✓ / ✗ / N/A
