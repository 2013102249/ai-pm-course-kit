早上好，欢迎回到《AI 产品经理课余充电》，我是你的讲师。

今天这期，聊一个面试里越来越常见的判断题——「这个需求，你做 Agent 还是做工作流？」我见过不少候选人，张口就是「当然是 Agent，越智能越好」。这一句话，基本就出局了。8 分钟后，你会拿到一把三刻度的尺子，任何场景丢过来，你都能十秒内给出判断和理由。课间、排队、睡前都能听，不用看屏幕。


先给结论。Agent 和固定工作流的本质区别，一句话——自主决策对比预定义路径。

工作流，像工厂流水线：开始、理解问题、查数据、判断、回复，每个节点做什么、顺序是什么，事先全部定死。它不聪明，但它确定——每一步可预期、可验证、可回溯。

Agent 呢，像派出去的一个靠谱同事：你只给目标，路线它自己规划。灵活，但每一单走的路都不一样，你没法提前保证它怎么走。

所以这不是「哪个更高级」的问题，是「拿什么换什么」的问题。Agent 用自主性换灵活性，工作流用确定性换可控性。产品经理的活儿，就是替用户选对这一边。


怎么选？三个维度，问自己三个问题。

第一问：这个任务的流程图，我画得出来吗？画得出，步骤和顺序都能预先定义——工作流。画不出，路径要模型现场规划——才考虑 Agent。这叫任务确定性。

第二问：步骤数得出来吗？三到八步、固定有限——工作流。数不出来、随输入动态伸缩——Agent。这叫步骤数。

第三问：出错的代价是什么？如果是钱、信任、不可逆操作——低容错，老老实实用工作流，还要加人工把关。如果错了重来就行——Agent 的多轮自我修正才是优势。这叫容错要求。

拿两个例子套一下。定时抓五个网站的新闻、摘要、发邮件——流程图画得出、五步数得清、错了重跑——工作流。帮用户安排出差，查日程、订票、订酒店、写行程，顺序取决于他的日程和偏好——流程图画不出——Agent。

再多给你一个自测技巧：拿到需求先画流程图，五分钟画得出来，就做工作流；画到一半发现「这步得看情况」，分支越画越多，那就是 Agent 的信号。别怕判断错，怕的是没量过就开做。

记住今天这句面试金句：能用工作流解决的事，别用 Agent——确定性是产品的好朋友。


选完形态，还有两件事决定产品生死。

第一件，人机接管点。高风险操作执行前，留一个审批型接管点——AI 准备做什么、依据是什么，人确认了再执行。模型输出存疑，设纠错型——低于置信度阈值就转人工复核。前面都失败，留兜底型——转人工，并且必须带着完整上下文，别让用户把问题重新讲一遍。

第二件，失败兜底三件套，顺序别乱：瞬时失败先重试，持续失败再降级——切备用方案或者礼貌拒答，都失败最后才转人工。很多产品的通病是：只设计了顺利的路径，一条不顺利的都没设计。工具一超时，用户端无限转圈——第二天投诉就来了。面试里被追问「降级降成什么样」，你就答：宁可选「结果不完整但明确告知」，也不要「结果漂亮但可能出错」，这是信任账。

再送你一句：兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。


收束成三句话：Agent 和工作流的本质区别是自主决策对比预定义路径；判断用三把尺子——任务确定性、步骤数、容错要求；形态定了之后，接管点和兜底三件套决定产品生死。

最后给你一个课余小任务：回想你主项目的核心任务，用三把尺子量一遍——流程图画得出吗？步骤数得清吗？错了代价大吗？量完你会发现，多数项目该从工作流起步，而不是 Agent。
