## 开场钩子（0:00–0:40）

早上好，欢迎回到《AI 产品经理课余充电》，我是你的讲师。

今天这期，聊一个面试里越来越常见的判断题——「这个需求，你做 Agent 还是做工作流？」我见过不少候选人，张口就是「当然是 Agent，越智能越好」。这一句话，基本就出局了。8 分钟后，你会拿到一把三刻度的尺子，任何场景丢过来，你都能十秒内给出判断和理由。课间、排队、睡前都能听，不用看屏幕。

## 第一部分：先分清两个东西（0:40–2:30）

先给结论。Agent 和固定工作流的本质区别，一句话——**自主决策对比预定义路径**。

工作流，像工厂流水线：开始、理解问题、查数据、判断、回复，每个节点做什么、顺序是什么，事先全部定死。它不聪明，但它确定——每一步可预期、可验证、可回溯。

Agent 呢，像派出去的一个靠谱同事：你只给目标，路线它自己规划。灵活，但每一单走的路都不一样，你没法提前保证它怎么走。

所以这不是「哪个更高级」的问题，是「拿什么换什么」的问题。【放慢】Agent 用自主性换灵活性，工作流用确定性换可控性。产品经理的活儿，就是替用户选对这一边。

## 第二部分：三刻度尺子（2:30–5:00）

怎么选？三个维度，问自己三个问题。

第一问：这个任务的流程图，我画得出来吗？画得出，步骤和顺序都能预先定义——工作流。画不出，路径要模型现场规划——才考虑 Agent。这叫任务确定性。

第二问：步骤数得出来吗？三到八步、固定有限——工作流。数不出来、随输入动态伸缩——Agent。这叫步骤数。

第三问：出错的代价是什么？如果是钱、信任、不可逆操作——低容错，老老实实用工作流，还要加人工把关。如果错了重来就行——Agent 的多轮自我修正才是优势。这叫容错要求。

拿两个例子套一下。定时抓五个网站的新闻、摘要、发邮件——流程图画得出、五步数得清、错了重跑——工作流。帮用户安排出差，查日程、订票、订酒店、写行程，顺序取决于他的日程和偏好——流程图画不出——Agent。

再多给你一个自测技巧：拿到需求先画流程图，五分钟画得出来，就做工作流；画到一半发现「这步得看情况」，分支越画越多，那就是 Agent 的信号。别怕判断错，怕的是没量过就开做。

【放慢】记住今天这句面试金句：**能用工作流解决的事，别用 Agent——确定性是产品的好朋友。**

## 第三部分：定了形态之后的两件事（5:00–7:00）

选完形态，还有两件事决定产品生死。

第一件，人机接管点。高风险操作执行前，留一个审批型接管点——AI 准备做什么、依据是什么，人确认了再执行。模型输出存疑，设纠错型——低于置信度阈值就转人工复核。前面都失败，留兜底型——转人工，并且必须带着完整上下文，别让用户把问题重新讲一遍。

第二件，失败兜底三件套，顺序别乱：瞬时失败先重试，持续失败再降级——切备用方案或者礼貌拒答，都失败最后才转人工。很多产品的通病是：只设计了顺利的路径，一条不顺利的都没设计。工具一超时，用户端无限转圈——第二天投诉就来了。面试里被追问「降级降成什么样」，你就答：宁可选「结果不完整但明确告知」，也不要「结果漂亮但可能出错」，这是信任账。

【放慢】再送你一句：**兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。**

## 结尾（7:00–8:00）

收束成三句话：Agent 和工作流的本质区别是自主决策对比预定义路径；判断用三把尺子——任务确定性、步骤数、容错要求；形态定了之后，接管点和兜底三件套决定产品生死。

【放慢】最后给你一个课余小任务：回想你主项目的核心任务，用三把尺子量一遍——流程图画得出吗？步骤数得清吗？错了代价大吗？量完你会发现，多数项目该从工作流起步，而不是 Agent。

## 附录一：本日术语速记（12 个术语，各一句话）

> 用途：配合 本课教学日对应板块术语精讲，通勤时顺一遍；每条一句话，不展开。

1. **工作流**：步骤与顺序预先定死、照着固定路径跑的流程。
2. **Agent（智能体）**：只给目标、由模型自主规划路径去完成的任务形态。
3. **三刻度尺**：任务确定性、步骤数、容错要求，判断「用 Agent 还是工作流」的三个维度。
4. **确定性**：输入相同、步骤与输出可预期、可复现的程度；不等于「结果一定对」。
5. **容错**：出错代价高低、允许多轮试错的程度；是尺子，不是动作。
6. **人机协同（Human-in-the-loop，人在回路）**：把人安排在流程关键节点参与判断与兜底的设计。
7. **人工确认**：高风险动作执行前展示依据、等人一键确认，属事前拦截。
8. **兜底（Fallback）**：主路径失败后仍让用户得到明确结果的备用设计。
9. **节点**：工作流里承担一步处理的最小单元，如开始、LLM、输出。
10. **分支**：按条件把流程引向不同路径的判断节点；失败分支专接异常，两者都要画。
11. **失败重试**：瞬时失败后自动再执行一到两次，前提是重跑无副作用（幂等）。
12. **边界条件**：超长、空值、无关问题等非常规输入；验收要跑正常 / 边界 / 异常三类。

一句话串起来：**能用工作流解决的事，别用 Agent——确定性是产品的好朋友。**

## 附录二：面试 30 秒口播（3 题，每题约 30 秒）

> 用途：配合对应板块「面试讲解与追问防御」，每题是一段可直接说出口的短稿；完整 60 秒版与追问链见 02-讲课稿对应板块、06-分层习题第 4 层。

**第 1 题 · 「这个需求，你做 Agent 还是工作流？」**
「我不会直接选，先用三刻度尺量：任务确定性、步骤数、容错要求。流程图画得出、步骤数得清、出错代价高，就做固定工作流，因为确定性是产品的好朋友；只有路径要模型现场规划、错了能重来，才考虑 Agent。我会再补一句风险：Agent 是拿可控性换灵活性，涉及钱和信任的环节，保留工作流和人工确认。」

**第 2 题 · 「工作流失败了你怎么办？」**
「先分类型：工具超时这类瞬时失败，自动重试一到两次，前提是幂等；主工具持续不可用就降级，切备用方案或礼貌拒答并明确告知结果可能不完整；都失败或涉及高风险，最后转人工，工单带上完整上下文、承诺响应时限。每一级都要有明确反馈，绝不能无限转圈——兜底设计是产品承诺，用户只在乎坏了之后谁负责。」

**第 3 题 · 「人机协同你怎么设计？」**
「按时间轴拆三型：审批型放事前，退款、发邮件、删数据执行前展示依据、人工确认；纠错型放事中，置信度低于阈值进复核队列；兜底型放事后，重试降级都失败才转人工，且必带完整上下文。原则是接管成本要对冲风险损失，每个点都回答：人工来了看什么、能改什么、改完流程怎么继续。」
