教案 · W3 周二《Agent 产品设计与工作流实操》

AI 产品经理就业训练营 · 第三周第二天 · 90 分钟（2 课时）· 讲师版
本课为实操课：讲授 30 分钟 + 实操陪跑 50 分钟 + 收尾 10 分钟，讲授让位于动手。

一、基本信息

项目 内容
所属阶段 阶段二 · AI 核心能力（Week 3）
本课主题 Agent 产品设计与工作流实操
课时 90 分钟（2 课时，实操环节不安排中间休息，靠步骤切换调节节奏）
授课对象 转行 / 进阶层学员（W2 周五已完成主项目立项，昨日已学 Agent 架构原理）
前置知识 Agent 四要素（规划 / 记忆 / 工具 / 执行）、ReAct 循环、提示词五要素
本课产出 主项目 Agent 工作流原型 V1（Dify 或 Coze 搭建，可实际运行）
教学场地 机房或自带电脑教室；学员人手一台电脑 + 可访问 Dify / Coze；投屏可用
教学红线 Dify / Coze 操作步骤一律用通用化描述（节点类型、连线逻辑），不绑定特定版本界面细节，统一口径「以当前版本界面为准」

二、教学目标（可测量）

  1. 能用「任务确定性、步骤数、容错要求」三个维度，对给定业务场景做出「该用 Agent 还是固定工作流」的判断，并说出至少两条理由（对应课堂决策练习 + 习题第一层）。
  2. 能在 Dify / Coze 中独立搭建一条含「LLM 节点 + 工具节点 + 条件分支」的工作流并运行成功（对应实操五步打卡 + 课后主项目工作流 V1）。
  3. 能为自己搭建的工作流补齐失败兜底三件套（重试 / 降级 / 转人工）中至少两件，并标注一个人机接管点（对应导学案自检表 + 习题兜底设计题）。

三、教学重难点

  • 重点一：「Agent vs 工作流」决策框架——学员普遍把 Agent 当万能解，需要建立「确定性是产品的好朋友」的判断意识。
  • 重点二：工作流实操——从零搭出一条可运行的工作流，是本周五原型评审 I（里程碑 ②）的直接前置。
  • 难点一：人机协同与接管点设计，学员容易走两个极端（全自动不敢上 / 全人工没用 AI）。
  • 难点二：失败兜底意识，学员默认「能跑就行」，不会为异常路径设计产品行为。

五、教学步骤与时间拆分（总和 = 90 分钟）

时间 环节 教学内容 教学方法 对应产出
0–3 min 导入 复习 Agent 四要素（30 秒）；抛出两难案例：同样「帮用户安排出差」，为什么有的产品做成 Agent、有的做成固定流程？ 提问 + 悬念 —
3–13 min 环节一：Agent vs 工作流决策框架 三维度决策表（任务确定性 / 步骤数 / 容错要求）逐维讲透；4 个场景现场快判；给出口诀「能用工作流解决的事，别用 Agent」 讲授 + 图示（工作流编排示意图） 导学案决策表第 1–2 行
13–30 min 环节二：人机协同与失败兜底 三类人机接管点（审批型 / 纠错型 / 兜底型）；失败兜底三件套（重试 / 降级 / 转人工）；失败案例：一个没有失败分支的客服工作流 讲授 + 案例 导学案接管点与兜底自检表
30–80 min 环节三：实操陪跑（50 min，核心） 五步搭建工作流：① 建应用（30–38）→ ② 加节点（38–48）→ ③ 配工具（48–58）→ ④ 调提示词（58–68）→ ⑤ 测运行（68–80）；每步「讲师投屏 3–5 分钟 + 学员动手 + 助教巡场」；第⑤步强制测异常输入 投屏演示 + 学员实操 + 巡场 导学案五步打卡 + 工作流设计表
80–90 min 收尾 作品快照分享（2–3 名学员投屏）；人机接管自查三问；布置课后作业（主项目工作流 V1 截图归档）；预告周五原型评审 I 分享 + 讲授 主项目工作流 V1 任务布置

六、「Agent vs 工作流」决策表（核心知识点）

决策维度 适合固定工作流 适合 Agent 判断要领
任务确定性 高：步骤与顺序可以预先定义，输入输出可预期 低：路径需要模型自主规划，事先无法穷举 问自己：能不能画出完整的流程图？画得出=工作流
步骤数 固定且有限（常见 3–8 步） 不定，随任务动态伸缩 步数能数出来=工作流；数不出来=Agent
容错要求 低容错：错一步代价高，需要可验证、可回溯 相对高容错：可多轮自我修正，试错成本低 出错的代价是钱、信任、不可逆操作 → 工作流 + 人审

一句话结论：Agent 用自主性换灵活性，工作流用确定性换可控性——产品经理的活儿，就是替用户选对这一边。

七、人机协同与接管点设计

接管点类型 触发时机 典型场景 设计要点
审批型（事前） 高风险 / 不可逆操作执行前 对外发邮件、下单付款、删除数据 展示「AI 准备做什么 + 依据」，人工一键确认或修改
纠错型（事中） 模型输出置信度低 / 两次输出不一致 信息抽取结果存疑、分类摇摆 设定置信度阈值，低于阈值转人工复核队列
兜底型（事后） 重试与降级均失败 工具连续超时、用户投诉升级 转人工时必须携带完整上下文，不让用户重复描述

设计原则：接管成本（人工介入的时延与人力）要对冲风险损失（出错的代价）；每个接管点都要回答「人工来了看什么、能改什么、改完流程怎么继续」。

八、失败兜底三件套

兜底手段 适用失败 通用做法 产品呈现
① 重试 瞬时失败：超时、网络抖动、限流 自动重试 1–2 次；确保节点幂等（重跑不产生副作用） 用户无感知或短暂等待提示
② 降级 持续失败：主模型 / 主工具不可用 切备用模型、退化为简化逻辑、返回缓存结果、礼貌拒答 明确告知「结果可能不完整」
③ 转人工 ①② 均失败，或涉及高风险决策 生成工单，携带对话上下文与已执行步骤，承诺响应时限 用户看到明确的下一步，不是无限转圈

课堂口径：兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。

九、课堂提问设计（7 问）

# 提问 提问时机 预设答案 / 引导方向
1 「让 AI 自由规划一次旅行行程可以放手，为什么让它审核报销单就不行？」 导入 行程错了代价低、可以重来；报销涉及钱与合规，错一步有真实损失，需要确定的路径与人工把关——引出容错维度
2 「Agent 和固定工作流的本质区别，一句话是什么？」 决策框架 自主决策 vs 预定义路径；本质是「自由度」与「可控性」的交换
3 「数步骤：这个任务的步骤能提前数出来吗？」 决策快判 能数出来（3–8 步固定）→ 工作流；数不出来、随输入变化 → Agent
4 「如果让 Agent 直接给用户发退款，你会在哪个点设人工接管？」 人机协同 审批型接管点：执行前展示金额与依据，人工确认；金额超阈值强制人审
5 「工作流里 LLM 节点的输出格式乱掉，下游会发生什么？怎么防？」 实操·加节点 下游解析失败、全链路中断；用提示词强约束输出格式 + 条件分支校验 + 失败分支
6 「工具调用超时，自动重试两次还失败，产品上用户应该看到什么？」 实操·测运行 走降级（备用方案 / 礼貌拒答）或转人工；不能无限转圈，要给明确反馈
7 「同一个任务，Agent 版和工作流版，哪个更省钱？为什么？」 收尾 工作流：步骤固定，Token 消耗可预估；Agent 多轮规划与反思，调用量成倍增加

十、板书要点

Agent vs 工作流：自由度 ↔ 可控性

三维度判断：任务确定性 / 步骤数 / 容错要求
口诀：能用工作流解决的事，别用 Agent——确定性是产品的好朋友

人机接管三型：审批（事前）/ 纠错（事中）/ 兜底（事后）
兜底三件套：重试（瞬时）→ 降级（持续）→ 转人工（最终出口）

实操五步：建应用 → 加节点 → 配工具 → 调提示词 → 测运行

十一、实操环节组织（与 07-交互使用说明配合）

步骤 讲师投屏 学员任务 完成标志
① 建应用（8 min） 通用化演示创建工作流应用的入口与基本信息配置 创建自己的工作流应用并命名（建议命名：主项目名-workflow-v1） 应用创建成功，进入编排画布
② 加节点（10 min） 演示「开始 → LLM → 条件分支 → 输出」的连线逻辑 按导学案设计表搭出主链路 4 类节点 画布上出现完整主链路连线
③ 配工具（10 min） 演示给节点挂载工具 / 插件（如联网搜索、知识库检索）的通用配置项 为至少 1 个节点配置工具调用 工具节点测试通过
④ 调提示词（10 min） 演示在 LLM 节点写「角色 + 任务 + 输出格式约束」提示词 完成自己 LLM 节点的提示词，明确输出格式 单节点试运行输出符合格式
⑤ 测运行（12 min） 演示整条运行 + 故意制造一次失败（断工具 / 乱输入） 跑通 3 类输入：正常 / 边界 / 异常；补失败分支 整条链路三类输入均可运行

巡场规则：讲师主投屏，助教按「卡壳优先级」巡场——账号登录问题 > 连线找不到节点 > 工具配置报错 > 提示词效果，见 07-交互使用说明。

十二、课堂练习参考答案（4 场景快判）

场景 判断 关键理由
每天定时抓取 5 个指定网站新闻，摘要后发邮件 固定工作流 步骤固定可数、顺序不变、出错重跑即可
用户一句话「帮我安排下周去上海出差」，需查日程、订票、订酒店、写行程 Agent 步骤数不定、路径依赖用户日程与偏好，需自主规划
客服工单按固定字段分类打标并路由到对应团队 固定工作流 分类规则明确、步骤 3 步以内、要求结果稳定可审计
开放式「帮我调研一个竞品并写分析报告」 Agent 子任务需动态拆解（搜索→阅读→取舍→成文），事先无法穷举路径

十三、学员易错点预判与应对

易错点 表现 应对
把所有场景都当 Agent 做 主项目一律「给 Agent 一个目标让它自己跑」 用决策表现场快判主项目场景；讲「确定性是产品的好朋友」；要求学员说出工作流判断理由才能动手
工作流一顺到底，没有失败分支 画布只有主链路，节点失败就整条断 实操第②⑤步强制要求：至少 1 个条件分支 + 1 条失败分支，列入导学案自检表
提示词不限输出格式，下游解析失败 LLM 节点输出自由文本，工具节点读不懂 第④步统一「输出格式约束」写法；现场演示乱格式导致下游报错的反面案例
工具节点不设超时与重试意识 前端无限转圈，用户流失 第⑤步演示「制造失败」；讲兜底三件套顺序：先重试、再降级、最后转人工
只顾搭流程不测异常输入 正常输入能跑就交差 第⑤步打卡要求跑 3 类输入（正常 / 边界 / 异常），异常输入不崩才算 V1
混淆「单节点试运行」与「整条运行」 只测了单个节点就以为完成 完成标志明确区分：单节点输出符合格式 ≠ 整条链路可运行，两种都要测
