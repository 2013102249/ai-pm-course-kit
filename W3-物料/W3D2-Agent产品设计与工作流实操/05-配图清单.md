## 制图规格（已制成） · 《工作流编排示意图》

### 一、画面内容（从左到右）

主链路（实线，从左到右一条直线）：

```
[开始节点] → [LLM 节点] → [工具节点] → [条件分支] → [输出节点]
   用户输入      理解与生成     调用外部能力     按条件走向      返回结果
```

条件分支向右分出两条路径：

- 上路（成立）：继续到「输出节点」，正常返回
- 下路（不成立）：进入失败分支，依次标注「重试 → 降级 → 转人工」三级兜底，最终到「人工接管点」

必须标注的三类信息：

| 标注项 | 画法要求 |
|---|---|
| 失败分支 | 从条件分支引出的虚线向下路径，逐级标「① 重试（瞬时失败）→ ② 降级（持续失败）→ ③ 转人工（最终出口）」 |
| 人机接管点 | 在「转人工」之后与「高风险操作执行前」各放一个人形图标，分别标注「兜底型接管（事后）」「审批型接管（事前）」 |
| 变量传递示例 | 任选一根连线标注「输出变量 → 输入参数」，体现连线即变量传递（对应实操第②步知识点） |

### 二、视觉规范

| 项目 | 规范 |
|---|---|
| 品牌主色 | 紫 #7C3AED（主链路节点、标题） |
| 品牌辅色 | 蓝 #2563EB（条件分支、失败分支虚线） |
| 辅助色 | 兜底与人机接管点用橙色警示（#F59E0B），灰 #7A7590 用于说明性小字 |
| 字体 | 中文黑体（PingFang SC / 思源黑体），节点名 ≥16px，标注字 ≥12px |
| 尺寸 | 画布 1600×700px，16:9，适配投屏与 PPT 全屏页 |
| 文案 | 全部中文标注，无错别字；节点名与教案术语严格一致（开始 / LLM / 工具 / 条件分支 / 输出） |
| 交付 | SVG 源文件 + 导出 PNG（2 倍图），文件名「工作流编排示意图」 |

### 三、验收标准

1. 主链路五节点齐全、顺序正确，与教案环节三实操五步的节点类型一一对应
2. 失败分支三级兜底顺序正确（重试 → 降级 → 转人工），与教案第八节表格一致
3. 人机接管点至少 2 处且有类型标注（审批型 / 兜底型）
4. 品牌色使用正确（紫 #7C3AED / 蓝 #2563EB），无第三方字体与素材
5. 投屏 1280px 宽度下所有文字可读；打印黑白稿层级仍可分辨

### 四、讲法脚本（讲师用）

- **环节一（3–13 min）讲法**：先只讲主链路五个节点——「这就是一条工作流，每一步事先定死」；再指着条件分支讲三维度决策的落点——「流程图画得出，就是工作流」；最后用手指沿失败分支走一遍，引出口诀。
- **提问点**：「如果工具节点超时，沿这条虚线走，用户最后看到什么？」（预期：降级或转人工，不是转圈）
- **过渡话术**：「这张图就是你们接下来 50 分钟要在 Dify / Coze 里搭出来的东西——现在它是一张图，下课之前它是你画布上能跑的原型。」
- **实操环节（30–80 min）挂屏讲法**：全程不关，作为「实操地图」。每进入一步，讲师指一下图上对应位置（第②步指节点、第③步指工具节点、第⑤步指失败分支），学员抬头即知进度。
- **金句落点**：讲完失败分支后放金句——「兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。」
