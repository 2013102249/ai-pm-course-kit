## 二、教学目标（可测量）

1. **术语目标**：能准确说出本日 12 个术语的一句话定义，重点能一句话讲清「Agent vs 工作流」的本质区别；完成《术语自测表》12 题，答对 ≥10 题。验证：第 1 节当堂小测（10 min）+ 03-导学案《术语自测表》批改。
2. **面试目标**：能用 60 秒标准答法回答「做 Agent 还是工作流」「工作流失败怎么办」「人机协同怎么设计」「要不要上多 Agent」四类题，每题命中 ≥3 个踩分点、能接住 2 层追问。验证：第 5 节两两模拟 + 03-导学案《面试模拟记录表》自评分与追问记录。
3. **决策目标**：能用「任务确定性、步骤数、容错要求」三刻度尺，对给定业务场景做出「该用 Agent 还是固定工作流」的判断，并说出至少两条理由。验证：课堂决策练习（4 场景快判）+ 06-分层习题第 1 层。
4. **实操目标**：能在 Dify / Coze 或扣子国内版 / 豆包中独立搭建一条含「LLM 节点 + 工具节点 + 条件分支」的工作流并运行成功；只有手机 / 平板的学员能完成替代动作并交出纸面设计。验证：第 4 节实操五步打卡 + 课后主项目工作流 V1 + 设备替代记录。
5. **兜底目标**：能为自己搭建的工作流补齐失败兜底三件套（重试 / 降级 / 转人工）中至少两件，并标注一个人机接管点。验证：03-导学案接管点与兜底自检表 + 06-分层习题第 2 层兜底设计题。
6. **验收目标**：跑通「正常 / 边界 / 异常」三类输入，异常输入不崩、用户端有明确反馈；能把本日产出按「产出物 / 完成度 / 归档位置」登记为作品集积木。验证：第 6 节当堂验收三条线 + 《本日作品集积木》表。

## 三、教学重难点

- **重点一**：「Agent vs 工作流」决策框架——学员普遍把 Agent 当万能解，需要建立「确定性是产品的好朋友」的判断意识。
- **重点二**：工作流实操——从零搭出一条可运行的工作流，是本周五原型评审 I（里程碑 ②）的直接前置。
- **难点一**：人机协同与接管点设计，学员容易走两个极端（全自动不敢上 / 全人工没用 AI）。
- **难点二**：失败兜底意识，学员默认「能跑就行」，不会为异常路径设计产品行为。
- **难点三（术语混淆）**：「Agent / 工作流」「确定性 / 准确率」「容错 / 兜底」「人工确认 / 转人工」「节点 / 分支」「失败重试 / 降级」六组相邻概念极易互串；零基础学员尤其会把「能自动跑」一律叫 Agent，把「条件分支」当「失败分支」。应对：第 1 节逐词给「易混辨析」，用《术语自测表》连线题与改错题当堂纠偏。
- **难点四（面试失分）**：学员答题容易「一开口就选 Agent」「只讲顺利路径」「把人机协同说成加个审核按钮」「被追问就改口」。应对：第 5 节用「踩分点 + 追问链 + 失败答法 + 60 秒标准答法」四件套做防御训练，两两模拟录进《面试模拟记录表》。

**本节附：核心知识点备查表（原有核心讲解按 6 节归入第 2 / 3 / 4 节，原样保留）**

> 下表四张为原有版本的核心讲解内容，分别落在第 2 节（决策表、4 场景答案）、第 3 节（接管点、兜底三件套）、第 4 节（实操五步组织），不得整段删除。

**决策表（第 2 节用）**

| 决策维度 | 适合固定工作流 | 适合 Agent | 判断要领 |
|---|---|---|---|
| 任务确定性 | 高：步骤与顺序可以预先定义，输入输出可预期 | 低：路径需要模型自主规划，事先无法穷举 | 问自己：能不能画出完整的流程图？画得出=工作流 |
| 步骤数 | 固定且有限（常见 3–8 步） | 不定，随任务动态伸缩 | 步数能数出来=工作流；数不出来=Agent |
| 容错要求 | 低容错：错一步代价高，需要可验证、可回溯 | 相对高容错：可多轮自我修正，试错成本低 | 出错的代价是钱、信任、不可逆操作 → 工作流 + 人审 |

一句话结论：**Agent 用自主性换灵活性，工作流用确定性换可控性——产品经理的活儿，就是替用户选对这一边。**

**人机接管点设计（第 3 节用）**

| 接管点类型 | 触发时机 | 典型场景 | 设计要点 |
|---|---|---|---|
| 审批型（事前） | 高风险 / 不可逆操作执行前 | 对外发邮件、下单付款、删除数据 | 展示「AI 准备做什么 + 依据」，人工一键确认或修改 |
| 纠错型（事中） | 模型输出置信度低 / 两次输出不一致 | 信息抽取结果存疑、分类摇摆 | 设定置信度阈值，低于阈值转人工复核队列 |
| 兜底型（事后） | 重试与降级均失败 | 工具连续超时、用户投诉升级 | 转人工时必须携带完整上下文，不让用户重复描述 |

设计原则：接管成本（人工介入的时延与人力）要对冲风险损失（出错的代价）；每个接管点都要回答「人工来了看什么、能改什么、改完流程怎么继续」。

**失败兜底三件套（第 3 节用）**

| 兜底手段 | 适用失败 | 通用做法 | 产品呈现 |
|---|---|---|---|
| ① 重试 | 瞬时失败：超时、网络抖动、限流 | 自动重试 1–2 次；确保节点幂等（重跑不产生副作用） | 用户无感知或短暂等待提示 |
| ② 降级 | 持续失败：主模型 / 主工具不可用 | 切备用模型、退化为简化逻辑、返回缓存结果、礼貌拒答 | 明确告知「结果可能不完整」 |
| ③ 转人工 | ①② 均失败，或涉及高风险决策 | 生成工单，携带对话上下文与已执行步骤，承诺响应时限 | 用户看到明确的下一步，不是无限转圈 |

课堂口径：**兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。**

**实操环节组织（第 4 节用，与 07-交互使用说明配合）**

| 步骤 | 讲师投屏 | 学员任务 | 完成标志 |

| ① 建应用（158–164 min，6 min） | 通用化演示创建工作流应用的入口与基本信息配置 | 创建自己的工作流应用并命名（建议命名：主项目名-workflow-v1） | 应用创建成功，进入编排画布 |

## 六、课堂提问设计（20 问）

> 分类：术语辨析 7 问（≥6）、原理与实操 7 问（原有 7 问保留）、面试追问 6 问（≥6）。

| # | 类别 | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|---|
| 1 | 术语辨析 | 「Agent 和固定工作流的本质区别，一句话是什么？」 | 第 1 节 | 自主决策 vs 预定义路径；本质是「自由度」与「可控性」的交换 |
| 2 | 术语辨析 | 「确定性高，等于结果一定对吗？」 | 第 1 节 | 不等；确定性说路径可预期、可复现，准确率说结果对错，别混 |
| 3 | 术语辨析 | 「容错和兜底，哪个是尺子、哪个是动作？」 | 第 1 节 | 容错是判断「错得起吗」的尺度，兜底是错之后的具体动作 |
| 4 | 术语辨析 | 「人工确认和转人工，都叫人介入，时点一样吗？」 | 第 1 节 | 不一样；人工确认是事前拦截，转人工是事后接盘 |
| 5 | 术语辨析 | 「节点和分支，哪个在做事、哪个在选路？」 | 第 1 节 | 节点是做事的工位，分支是决定往哪走的岔路；失败分支是专门接异常的那条 |
| 6 | 术语辨析 | 「失败重试和降级，先后能换吗？」 | 第 1 节 | 不能；重试治瞬时抖动，降级治持续不可用，顺序先重试再降级 |
| 7 | 术语辨析 | 「三刻度尺只量『任务复不复杂』够不够？」 | 第 1 节 | 不够；确定性、步骤数、容错要求三维要一起量 |
| 8 | 原理 | 「让 AI 自由规划一次旅行行程可以放手，为什么让它审核报销单就不行？」 | 第 2 节 导入 | 行程错了代价低、可以重来；报销涉及钱与合规，错一步有真实损失，需要确定的路径与人工把关——引出容错维度 |
| 9 | 原理 | 「数步骤：这个任务的步骤能提前数出来吗？」 | 第 2 节 快判 | 能数出来（3–8 步固定）→ 工作流；数不出来、随输入变化 → Agent |
| 10 | 人机协同 | 「如果让 Agent 直接给用户发退款，你会在哪个点设人工接管？」 | 第 3 节 | 审批型接管点：执行前展示金额与依据，人工确认；金额超阈值强制人审 |
| 11 | 实操 | 「工作流里 LLM 节点的输出格式乱掉，下游会发生什么？怎么防？」 | 第 4 节 加节点 | 下游解析失败、全链路中断；用提示词强约束输出格式 + 条件分支校验 + 失败分支 |
| 12 | 实操 | 「工具调用超时，自动重试两次还失败，产品上用户应该看到什么？」 | 第 4 节 测运行 | 走降级（备用方案 / 礼貌拒答）或转人工；不能无限转圈，要给明确反馈 |
| 13 | 收尾 | 「同一个任务，Agent 版和工作流版，哪个更省调用量？为什么？」 | 第 6 节 | 工作流：步骤固定，消耗可预估；Agent 多轮规划与反思，调用量更高（不写具体数值，口径「以官方当前说明为准」） |
| 14 | 面试追问 | 「你说这个需求用工作流，如果业务下周就要加三种新情况，你怎么答？」 | 第 5 节 | 追的是边界：先守住「路径能否预先穷举」，能穷举就扩分支，穷举不了才评估 Agent，并说清改造成本 |
| 15 | 面试追问 | 「你加了人工确认，那人工成本谁扛？阈值怎么定？」 | 第 5 节 | 追的是取舍：接管成本要对冲风险损失，按出错代价分档设阈值，高风险强审、低风险抽检 |
| 16 | 面试追问 | 「你设计的重试，会不会重复扣款？」 | 第 5 节 | 追的是幂等：重跑无副作用是底线，带唯一单号或改为状态查询 |
| 17 | 面试追问 | 「你说失败就转人工，转过去用户要重新描述一遍吗？」 | 第 5 节 | 追的是体验：必须携带完整上下文与已执行步骤，给明确下一步 |
| 18 | 面试追问 | 「为什么要上多 Agent？单 Agent 加工作流不够吗？」 | 第 5 节 | 追的是复杂度：先用三刻度尺量，多数需求单 Agent + 工作流够；多 Agent 是复杂度跃升，先问可控性与接管成本扛不扛得住 |
| 19 | 面试追问 | 「降级降成什么样算合格？」 | 第 5 节 | 追的是信任账：宁可「结果不完整但明确告知」，不要「结果漂亮但可能出错」 |
| 20 | 面试追问 | 「你搭的工作流只测了正常输入，敢上线吗？」 | 第 5 节 | 追的是验收：必须跑正常 / 边界 / 异常三类输入，异常不崩才算 V1 |

## 七、板书要点（按 6 节重排）

```
【第 1 节 0–50 术语精讲与零层入口】
12 术语：工作流 / Agent / 三刻度尺 / 确定性 / 容错 / 人机协同
        人工确认 / 兜底 / 节点 / 分支 / 失败重试 / 边界条件
六组易混：Agent↔工作流  确定性↔准确率  容错↔兜底
          人工确认↔转人工  节点↔分支  失败重试↔降级
重点辨析：Agent = 自主决策；工作流 = 预定义路径

【第 2 节 50–100 核心原理讲授 A】
Agent vs 工作流：自由度 ↔ 可控性
三刻度尺：任务确定性 / 步骤数 / 容错要求
口诀：能用工作流解决的事，别用 Agent——确定性是产品的好朋友

【第 3 节 100–150 核心原理讲授 B + 案例】
人机接管三型：审批（事前）/ 纠错（事中）/ 兜底（事后）
兜底三件套：重试（瞬时）→ 降级（持续）→ 转人工（最终出口）
反面案例：无限转圈的客服工作流

【第 4 节 150–200 实操演练与巡场】
实操五步：建应用 → 加节点 → 配工具 → 调提示词 → 测运行
双路径：A Dify / Coze 境外版   B 扣子国内版 / 豆包
手机 / 平板：纸面流程图 + 结对 + 课后补实操
三类输入：正常 / 边界 / 异常

【第 5 节 200–250 面试讲解与追问防御】
四主题：做 Agent 还是工作流 / 失败怎么办 / 人机协同 / 多 Agent
每题四件套：踩分点 → 追问链 → 失败答法 → 60 秒标准答法

【第 6 节 250–300 复盘 · 归档 · 验收】
三句收束 + 作品集积木归档 + 验收三条线
主链路跑通 / 失败分支存在 / 接管点明确
```

## 八、课堂练习参考答案

**（一）4 场景快判（原表保留）**

| 场景 | 判断 | 关键理由 |
|---|---|---|
| 每天定时抓取 5 个指定网站新闻，摘要后发邮件 | 固定工作流 | 步骤固定可数、顺序不变、出错重跑即可 |
| 用户一句话「帮我安排下周去上海出差」，需查日程、订票、订酒店、写行程 | Agent | 步骤数不定、路径依赖用户日程与偏好，需自主规划 |
| 客服工单按固定字段分类打标并路由到对应团队 | 固定工作流 | 分类规则明确、步骤 3 步以内、要求结果稳定可审计 |
| 开放式「帮我调研一个竞品并写分析报告」 | Agent | 子任务需动态拆解（搜索→阅读→取舍→成文），事先无法穷举路径 |

**（二）术语小测参考答案（第 1 节当堂小测 10 题，示例）**

| 题 | 答案 | 给分点 |
|---|---|---|
| 1 连线：自主决策 → ？；预定义路径 → ？ | Agent / 工作流 | 各 1 分 |
| 2 判断：确定性高就等于结果一定正确（×） | 错，确定性指路径可预期 | 判断 1 分 + 理由 1 分 |
| 3 改错：「出错代价大就叫兜底」 | 应为「容错要求低」；兜底是失败后的备用设计 | 改对 1 分 + 说明 1 分 |
| 4 选择：重试 2 次仍失败下一步？ | 降级 | 选对 2 分 |
| 5 改错：「人工确认就是转人工」 | 人工确认是事前拦截，转人工是事后接盘 | 改对 1 分 + 时点说明 1 分 |
| 6 连线：节点 / 分支 → 做事 / 选路 | 节点=做事，分支=选路 | 各 1 分 |
| 7 判断：三刻度尺只看任务复杂度（×） | 三维：确定性、步骤数、容错要求 | 判断 1 分 + 补两维 1 分 |
| 8 选择：边界条件指？ | 超长、空值、无关问题等非常规输入 | 选对 2 分 |
| 9 改错：「工作流路径由模型现场决定」 | 应为 Agent；工作流是预定义路径 | 改对 2 分 |
| 10 简答：转人工必须带什么？ | 完整上下文 + 已执行步骤 | 各 1 分 |

**（三）面试评分示例（第 5 节「做 Agent 还是工作流」题，三档 Rubric）**

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 结论明确不盲目选 Agent，给出至少两个维度的判断依据 | 24–31 |
| 良好 | 用三刻度尺逐场景拆解，区分「哪些子任务走工作流、哪些交给 Agent」，提到人工接管点 | 32–37 |
| 优秀 | 额外补风险提示：可控性代价、调用量差异或「工作流为主、Agent 局部嵌入」的架构建议，并能接住 2 层追问 | 38–40 |

## 九、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 把所有场景都当 Agent 做 | 主项目一律「给 Agent 一个目标让它自己跑」 | 用决策表现场快判主项目场景；讲「确定性是产品的好朋友」；要求学员说出工作流判断理由才能动手 |
| 工作流一顺到底，没有失败分支 | 画布只有主链路，节点失败就整条断 | 第 4 节第②⑤步强制要求：至少 1 个条件分支 + 1 条失败分支，列入导学案自检表 |
| 提示词不限输出格式，下游解析失败 | LLM 节点输出自由文本，工具节点读不懂 | 第④步统一「输出格式约束」写法；现场演示乱格式导致下游报错的反面案例 |
| 工具节点不设超时与重试意识 | 前端无限转圈，用户流失 | 第⑤步演示「制造失败」；讲兜底三件套顺序：先重试、再降级、最后转人工 |
| 只顾搭流程不测异常输入 | 正常输入能跑就交差 | 第⑤步打卡要求跑 3 类输入（正常 / 边界 / 异常），异常输入不崩才算 V1 |
| 混淆「单节点试运行」与「整条运行」 | 只测了单个节点就以为完成 | 完成标志明确区分：单节点输出符合格式 ≠ 整条链路可运行，两种都要测 |
| **（术语混淆）把 Agent 当「更聪明的升级版」** | 说「简单任务用工作流、难任务上 Agent」 | 第 1 节纠正：不是难度高低，是「路径能否预先定义」；三维一起量，难但确定的任务仍走工作流 |
| **（术语混淆）把条件分支当失败分支、把容错当兜底** | 设计表只填一条岔路、兜底栏写「容错低」 | 第 1 节六组易混对照 + 术语自测表连线 / 改错题；第 4 节设计表把「条件分支」「失败分支」「兜底」分列 |
| **（面试失分）一开口就选 Agent、被追问就改口** | 「当然上 Agent，越智能越好」，追问成本与可控性后立刻改答案 | 第 5 节 60 秒标准答法先给结论再给框架；追问链按「边界 → 取舍 → 幂等 / 体验」三层固定应答，模拟时录进记录表 |
| **（面试失分）人机协同只说「加个审核按钮」** | 答不出三型接管点、阈值、上下文携带 | 用「审批 / 纠错 / 兜底」三型 + 接管成本对冲风险损失 + 转人工必带上下文的标准句式反复演练 |
