## 第 0 层 · 术语辨析（12 题，共 60 分）

> 题型：选择题、连线题、改错题三种；配对应板块（0–50 min）当堂小测，名词均出自当日 12 术语。

**0-1（选择，5 分）** 关于「Agent 与固定工作流的本质区别」，最准确的说法是：
A. Agent 用的是更强的模型，工作流用的是更弱的模型
B. Agent 由模型自主规划路径，工作流按预定义路径执行
C. Agent 是新产品形态，工作流是过时技术
D. Agent 不需要提示词，工作流需要提示词

**0-2（选择，5 分）** 「确定性高」最准确的含义是：
A. 结果一定正确　B. 模型参数更大　C. 输入相同、步骤与输出可预期可复现　D. 跑得更快

**0-3（选择，5 分）** 工具节点超时，自动重试 2 次仍失败，按「兜底三件套」下一步应该：
A. 继续重试直到成功　B. 把报错原样抛给用户　C. 走降级：切备用方案或礼貌拒答，仍失败再转人工　D. 立即重启整条工作流

**0-4（选择，5 分）** 下列哪一组是「三刻度尺」的正确组成？
A. 准确率 / 速度 / 成本　B. 任务确定性 / 步骤数 / 容错要求　C. 模型大小 / 数据量 / 提示词长度　D. 节点数 / 分支数 / 工具数

**0-5（连线，5 分）** 把左侧概念与右侧含义连线：
① 工作流　② Agent　③ 容错　④ 兜底　　a. 错之后的具体动作　b. 步骤与顺序预先定死　c. 出错代价高低的尺度　d. 只给目标、模型自主规划

**0-6（连线，5 分）** 把左侧概念与右侧时点 / 职责连线：
① 人工确认　② 转人工　③ 节点　④ 分支　　a. 决定往哪走的岔路　b. 事前拦截　c. 做事的工位　d. 事后接盘

**0-7（连线，5 分）** 把左侧手段与右侧适用失败连线：
① 失败重试　② 降级　③ 转人工　　a. 持续失败（主工具不可用）　b. 最终出口 / 高风险　c. 瞬时失败（超时抖动）

**0-8（连线，5 分）** 把左侧输入类型与右侧例子连线：
① 正常输入　② 边界条件　③ 异常输入　　a. 完全无关的问题、故意断工具　b. 符合预期的常规提问　c. 超长文本、空字段

**0-9（改错，5 分）** 改错并说明理由：「Agent 是工作流的升级版，任务越难就越该上 Agent。」

**0-10（改错，5 分）** 改错并说明理由：「人工确认就是转人工，都是在流程里加个人审一下。」

**0-11（改错，5 分）** 改错并说明理由：「容错就是兜底，兜底就是容错，都是失败后的处理。」

**0-12（改错，5 分）** 改错并说明理由：「画了条件分支就等于有失败分支了，异常输入会自己走过去。」

## 第 2 层 · 进阶实操题（方案设计层，原第 8 题保留 + 新增 13、14 题）

**8. 兜底设计题（60 分，原题保留）**

你为主项目设计了一条「售后退款助手」工作流：开始 → LLM 节点（理解用户诉求）→ 工具节点（查询订单系统）→ 条件分支（金额 ≤ 500 元自动走退款流程；> 500 元需人工审核）→ 输出节点。

请回答：

1. 这条工作流里应设哪几类人机接管点？分别设在哪个节点之后、触发条件是什么？
2. 订单系统接口超时时的完整兜底链路：从第一次失败到最终出口，用户每一步看到什么？
3. 「自动退款 ≤ 500 元」这个分支，重试安全吗？如果不安全，需要补什么设计？

**13（新增，20 分）** 人机协同设计题：某「AI 外发营销邮件」工作流，LLM 节点生成邮件正文，工具节点调用发送接口。请设计三型接管点（审批 / 纠错 / 兜底）各一处，写明触发时机、人工「看什么 / 能改什么 / 改完怎么继续」，并说明为什么「外发邮件」属于低容错场景。

**14（新增，20 分）** 输出格式与分支题：你的 LLM 节点输出自由文本，下游条件分支读不懂字段而整条链路中断。请写出：① 提示词三段式（角色 / 任务 / 输出格式约束）里的「输出格式约束」怎么写；② 除了改提示词，还应补哪两类分支来防这类失败；③ 为什么「单节点试运行通过」不等于「整条链路可运行」。

## 第 3 层 · 求职挑战题（面试层，原第 9、10 题保留 + 新增 15、16 题）

**9. 面试真题：Agent 还是工作流？（40 分，原题保留）**

面试官：「我们想给电商客服升级 AI 能力，有人说直接上一个全能 Agent，有人说做成固定流程。你作为产品经理，怎么决策？」

要求：先给决策框架，再给判断路径，最后补一个「显专业」的风险提示。

**10. 案例分析：无限转圈事故（40 分，原题保留）**

某客服工作流上线三天后紧急下线：订单系统升级导致接口超时，工作流没有失败分支，用户端无限转圈，当天投诉翻倍。假如你是该产品经理，请给出：① 事故的根因（用本课术语表述）；② 修复后的兜底链路设计；③ 一条可写进产品文档的兜底设计原则。

**15（新增，20 分）** 多 Agent 判断题：业务方说「我们的客服太复杂，直接上多 Agent 分工吧」。请先用三刻度尺说明你会怎么量，再给出「什么信号才说明该评估多 Agent」，并指出多 Agent 带来的最大产品风险（用本课术语）。

**16（新增，20 分）** 验收与边界条件题：一条工作流「正常输入能跑出结果」就准备上线。请列出上线前必跑的三类输入，说明「边界条件」与「异常输入」的区别，并写出当堂验收的三条线。

## 第 4 层 · 面试实战（6 题，每题含踩分点、追问链、失败答法、评分表）

> 用法：配对应板块（200–250 min）两两模拟；每题先自己答 60 秒，再由同伴按追问链连追 2–3 层，最后用评分表互评。60 秒标准答法全文见 02-讲课稿对应板块。

**17. 「这个需求，你做 Agent 还是工作流？」（场景设计题）**
- 踩分点：① 不直接选，先亮三刻度尺；② 逐维给判断依据 ≥2 条；③ 说出「路径能否预先定义」是分界而非难度；④ 补风险提示（可控性 / 调用量 / 工作流为主）。
- 追问链：追问 1「下周要加三种新情况呢？」→ 能穷举扩分支，穷举不了再重评并说改造成本；追问 2「同事坚持要 Agent 怎么说服？」→ 用出错代价说话；追问 3「成本怎么算？」→ 步骤固定可预估 / 多轮规划调用量更高，具体「以官方当前说明为准」。
- 典型失败答法：「当然上 Agent，越智能越好。」失分原因：无框架、交出可控性、被追问即改口。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 结论明确不盲目选 Agent，给出至少两个维度依据 | 24–31 |
| 良好 | 用三刻度尺逐场景拆解，区分哪些子任务走工作流 / Agent，提到人工接管点 | 32–37 |
| 优秀 | 补风险提示（可控性代价、调用量差异或「工作流为主、Agent 局部嵌入」），且接住 2 层追问不改口 | 38–40 |

**18. 「工作流跑失败了你怎么办？」（项目深挖题）**
- 踩分点：① 先分失败类型（瞬时 / 持续 / 高风险）；② 兜底三件套顺序正确（重试 → 降级 → 转人工）；③ 说清每级用户看到什么；④ 主动补幂等与完整上下文。
- 追问链：追问 1「重试两次还失败？」→ 降级并明确告知；追问 2「降级降成什么样？」→ 宁可不完整但明确告知；追问 3「转人工要重新描述吗？」→ 不能，带上下文与已执行步骤，承诺时限。
- 典型失败答法：「报错就提示用户稍后再试。」失分原因：无失败分支、无产品承诺，是「无限转圈」的口头版。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 答出至少两级兜底，顺序基本正确 | 24–31 |
| 良好 | 三件套齐全且顺序正确，写到「用户每一步看到什么」 | 32–37 |
| 优秀 | 主动补「重试要幂等」「转人工必带完整上下文」，并提炼可复用原则 | 38–40 |

**19. 「人机协同你怎么设计？」（场景设计题）**
- 踩分点：① 三型接管点齐全（审批 / 纠错 / 兜底）；② 每型给触发时机；③ 讲「接管成本对冲风险损失」；④ 答全「看什么 / 能改什么 / 改完怎么继续」。
- 追问链：追问 1「人工成本谁扛？」→ 按出错代价分档设阈值；追问 2「阈值怎么定？」→ 由风险损失倒推；追问 3「不就是加个审核按钮？」→ 是三型不同时点的分工，人工确认事前、转人工事后。
- 典型失败答法：「在高风险步骤加个审核按钮让人点一下。」失分原因：只答一型、无阈值与上下文，把人机协同说成一个控件。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 说出至少两型接管点及其时点 | 24–31 |
| 良好 | 三型齐全、触发条件明确，提到接管成本 | 32–37 |
| 优秀 | 答全三问（看什么 / 改什么 / 怎么继续）并指出「转人工必带上下文」 | 38–40 |

**20. 「怎么判断要不要上多 Agent？」（技术理解 / 场景设计题）**
- 踩分点：① 不神化，先用三刻度尺量；② 说明多数需求「单 Agent + 工作流」已够；③ 指出多 Agent 是复杂度跃升不是能力升级；④ 用可控性、接管成本、失败路径作判据。
- 追问链：追问 1「单 Agent 加工流不够吗？」→ 够，先固化可确定部分；追问 2「什么信号该加？」→ 子任务目标不同且需动态拆解、失败可隔离；追问 3「上了最大风险？」→ 失败路径变多、接管点难定位，更要兜底与上下文传递。
- 典型失败答法：「任务复杂就多上几个 Agent 分工，效果更好。」失分原因：把复杂度当能力、无框架、未答可控性代价。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 不盲目附和，说出「先量再定」 | 24–31 |
| 良好 | 用三刻度尺说明「单 Agent + 工作流」通常够，并给出评估信号 | 32–37 |
| 优秀 | 指出复杂度跃升与可控性代价，答出失败隔离与接管成本，不引入课程外新概念 | 38–40 |

**21. 「你搭的工作流，重试会不会重复扣款？」（项目深挖题）**
- 踩分点：① 识别自动退款不幂等；② 解释幂等＝重跑无副作用；③ 给唯一单号或状态查询两种方案；④ 风险前置到设计与验收。
- 追问链：追问 1「哪些节点最危险？」→ 付款 / 发消息 / 删数据等写操作；追问 2「怎么验证？」→ 故意制造失败再重试，核对只执行一次；追问 3「边界条件怎么测？」→ 正常 / 边界 / 异常三类一起跑。
- 典型失败答法：「重试几次应该没事，平台会处理。」失分原因：把工程底线推给平台，暴露没搭过没测过。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 意识到重试有副作用风险 | 24–31 |
| 良好 | 说清幂等含义并给出至少一种方案 | 32–37 |
| 优秀 | 给出两种方案 + 验收方法（制造失败、三类输入），体现风险前置 | 38–40 |

**22. 「一条工作流上线前，你怎么验收？」（项目深挖 / 场景设计题）**
- 踩分点：① 三条线（主链路跑通 / 失败分支存在 / 接管点明确）；② 跑全正常 / 边界 / 异常三类输入；③ 区分单节点试运行与整条运行；④ 回答「任何节点失败，用户看到的最后一条消息是什么」。
- 追问链：追问 1「只测正常输入行不行？」→ 不行，边界与异常才暴露失败分支；追问 2「怎么算异常不崩？」→ 有降级或转人工的明确反馈，不无限转圈；追问 3「接管点怎么验？」→ 高风险步骤执行前有人确认且带上下文。
- 典型失败答法：「点一下运行，能出结果就上线。」失分原因：把「跑通」当「验收」，无失败路径意识。
- 评分表：

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 说出三类输入与「主链路跑通」 | 24–31 |
| 良好 | 三条线齐全，区分单节点与整条运行 | 32–37 |
| 优秀 | 提炼「上线前必答用户最后看到什么」的验收机制，并绑定人机接管自查三问 | 38–40 |

### 第 0 层 · 术语辨析（每题 5 分）

| 题 | 答案 | 给分点 |
|---|---|---|
| 0-1 | **B** | 选 B 满分；选 A 得 2 分（意识到模型差异但归因错误） |
| 0-2 | **C** | 选 C 满分；能口头补「不等于准确率」加 1 分（本层封顶 5 分） |
| 0-3 | **C** | 选 C 满分；口述「重试管瞬时、降级管持续、转人工是出口」加 1 分 |
| 0-4 | **B** | 选 B 满分 |
| 0-5 | ①-b ②-d ③-c ④-a | 每条连线 1.25 分 |

| 3 | **固定工作流** | 判断 8 分 + 理由 7 分（规则明确、步骤 3 步以内、要求结果稳定可审计——「可审计」是高分点） |
| 4 | **Agent** | 判断 8 分 + 理由 7 分（子任务需动态拆解：搜索 → 阅读 → 取舍 → 成文，事先无法穷举） |

### 第 2 层 · 进阶实操（三档 Rubric 见各题）

**第 8 题参考答案**：① 至少两处接管点——审批型：金额 > 500 元的条件分支后，人工审核（事前拦截高风险）；兜底型：转人工出口，携带对话上下文与已执行步骤；答出纠错型（LLM 意图理解置信度低时转复核）为加分项。② 兜底链路：首次超时 → 自动重试 1–2 次（用户看到短暂等待提示）→ 仍失败走降级（告知「系统繁忙，已为您创建人工工单」或返回缓存结果）→ 转人工，工单携带上下文，承诺响应时限；全程无无限转圈。③ 不安全——「自动退款」不是幂等操作，重试可能重复打款；需补幂等设计（请求带唯一退款单号，同一单号只执行一次）或把重试改为「状态查询」确认是否已退。

| 档位 | 标准 |
|---|---|
| 合格（36–47 分） | 答出至少两类接管点 + 兜底链路顺序正确（重试 → 降级 → 转人工） |
| 良好（48–54 分） | 接管点有明确触发条件，兜底链路写到「用户每一步看到什么」的产品呈现层 |
| 优秀（55–60 分） | 主动识别「自动退款不幂等」并给出幂等设计或状态查询替代方案，体现风险前置意识 |

**第 13 题参考答案**：审批型——邮件发送前展示收件人、正文、依据，人工一键确认 / 修改，超阈值或含敏感词强制人审（外发不可逆、错了直接损伤品牌与合规，属低容错）；纠错型——LLM 生成置信度低或同一收件人两次文案不一致，进人工复核队列；兜底型——发送接口连续超时、重试与降级都失败，转人工且携带已生成文案与收件人上下文，不让运营重填。每点都要答「看什么（收件人 / 正文 / 依据）、能改什么（改文案 / 改收件人 / 撤回）、改完怎么继续（回到发送节点或转工单）」。

| 档位 | 标准 |
|---|---|
| 合格（12–15 分） | 三型各设一处，位置大致正确 |
| 良好（16–18 分） | 三型触发时机明确，答出低容错理由 |
| 优秀（19–20 分） | 每型答全「看什么 / 能改什么 / 改完怎么继续」，并指出转人工必带上下文 |

**第 14 题参考答案**：① 输出格式约束写法示例——「严格按以下 JSON 结构输出，不要输出任何其他内容」，字段名列清楚，且至少有一个供条件分支读取的判断字段。② 除改提示词，还应补「条件分支校验」（格式不符时走校验失败路径）与「失败分支」（异常输入 / 解析失败的兜底去向）。③ 单节点试运行只验证该节点输出符合格式，不验证变量传递、工具调用、条件走向与整条链路的失败处理；必须再跑整条运行 + 正常 / 边界 / 异常三类输入。

| 档位 | 标准 |
|---|---|
| 合格（12–15 分） | 写出格式约束，知道要补分支 |
| 良好（16–18 分） | 分清条件分支与失败分支，说出变量传递 |
| 优秀（19–20 分） | 完整解释「单节点 ≠ 整条」，并绑定三类输入验收 |

### 第 3 层 · 求职挑战

**第 9 题参考答案**：决策框架 = 三刻度尺（任务确定性 / 步骤数 / 容错要求）。判断路径 = 逐个拆客服业务：工单分类打标（确定性高、步骤少、要可审计）→ 固定工作流；复杂纠纷协商、跨系统动态处理（路径不定）→ Agent，且 Agent 分支必须设审批型接管点（退款、补偿等执行前人工确认）。专业风险提示 = 「全能 Agent 意味着放弃可控性，客服出错直接损伤信任与资金，建议工作流为主、Agent 局部嵌入；Agent 多轮规划调用量更高，具体口径以官方当前说明为准。」

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 结论明确（不盲目选 Agent），给出至少两个维度的判断依据 |
| 良好（32–37 分） | 用三刻度尺逐场景拆解，区分「哪些子任务工作流、哪些 Agent」，提到人工接管点 |
| 优秀（38–40 分） | 额外补风险提示：可控性代价、调用量差异或「工作流为主、Agent 嵌入」的架构建议 |

**第 10 题参考答案**：① 根因 = 工作流一顺到底、没有失败分支；工具节点持续失败后无重试 / 降级 / 转人工路径，错误直接暴露给用户端（无限转圈）。② 修复链路 = 工具节点加重试（1–2 次，幂等）→ 失败走降级分支（返回缓存 / 简化答复并告知）→ 最终转人工（工单携带上下文与已执行步骤），每级都有用户可见的反馈文案。③ 原则示例 = 「兜底设计不是技术问题，是产品承诺——每条工作流上线前必须回答：任何节点失败后，用户看到的最后一条消息是什么。」

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 根因定位到「没有失败分支」，修复方案含至少两级兜底 |
| 良好（32–37 分） | 兜底三级齐全且顺序正确，根因用「主路径 / 失败路径」的产品语言表述 |
| 优秀（38–40 分） | 提炼出可复用的设计原则或验收机制，体现体系化思维 |

**第 15 题参考答案（新增）**：先用三刻度尺量——确定性（子任务流程图画得出吗）、步骤数（数得清吗）、容错要求（错了代价大吗）；多数客服子任务可固化成固定工作流，只把路径真不定的交给一个 Agent。评估多 Agent 的信号：子任务确实目标不同且需动态拆解、失败可隔离、且可控性与接管成本还扛得住。最大产品风险（用本课术语）：分支与失败路径变多、人机接管点难定位、兜底三件套与完整上下文传递更复杂；多 Agent 是复杂度跃升，不是能力升级。本题不引入课程外新技术概念。

| 档位 | 标准 |
|---|---|
| 合格（12–15 分） | 先量再定，不盲目附和 |
| 良好（16–18 分） | 用三刻度尺说明「单 Agent + 工作流」通常够，给出评估信号 |
| 优秀（19–20 分） | 指出复杂度跃升与可控性代价，答出失败隔离与接管成本 |

**第 16 题参考答案（新增）**：三类输入 = 正常 / 边界 / 异常。边界条件是输入端的极端取值（超长文本、空字段、无关问题），异常输入还包括链路中途的失败（故意断工具）；前者测「输入能不能接住」，后者测「失败分支接不接得住」。当堂验收三条线 = 主链路跑通 / 失败分支存在 / 接管点明确；并补「任何节点失败，用户看到的最后一条消息是什么」。

| 档位 | 标准 |
|---|---|
| 合格（12–15 分） | 写出三类输入与三条线 |
| 良好（16–18 分） | 说清边界条件与异常输入的区别 |
| 优秀（19–20 分） | 补出「最后一条消息」验收机制与人机接管自查三问 |

### 讲稿原题（可作追问链）

- 上课先抛一个两难案例：同样是「帮用户安排出差」，为什么有的产品做成 Agent，让模型自己规划；有的产品做成固定流程，一步步点下一步？
- 用这把尺子判断：让 AI 自由规划一次旅行行程可以放手，为什么让它审核报销单就不行？
- 选好了形态，下一个问题：哪些环节交给机器，哪些环节留给人？
- 如果让 Agent 直接给用户发退款，你会在哪个点设人工接管？
