# 分层习题 · W3 周二《Agent 产品设计与工作流实操》

> 三层难度：基础巩固（概念）→ 进阶实操（方案设计）→ 求职挑战（面试真题）。
> 本课考点：场景适配判断（4 场景选 Agent 或工作流）、兜底设计。
> 建议用法：基础层当堂测 10 分钟（实操结束后的收尾段可抽查口答）；进阶层当作业；求职挑战层自测，第八周面试课复用。
> 所有题目附参考答案与评分标准。

---

## 第一层 · 基础巩固题（概念层）

### 一、场景适配判断（每题 15 分，共 60 分）

**判断下列 4 个场景该用「固定工作流」还是「Agent」，各给一条关键理由。**

**1. 每天早上 8 点定时抓取 5 个指定财经网站的头条新闻，摘要后发送到订阅用户邮箱。**

**2. 用户说「帮我安排下周去上海的出差」，系统需要查他的日历、比价机票、订酒店、按他的饮食偏好推荐餐厅并生成行程单。**

**3. 客服系统收到工单后，按「订单 / 物流 / 退款 / 投诉」四个固定类别打标，并路由到对应处理团队，要求分类结果稳定、可审计。**

**4. 运营同学输入一个竞品名字，希望系统自动产出一份包含产品定位、功能对比、定价策略的分析报告，具体要查什么、读几篇资料事先无法确定。**

### 二、选择题（每题 10 分，共 20 分）

**5. 关于「Agent 与固定工作流的本质区别」，最准确的说法是：**
A. Agent 用的是更强的模型，工作流用的是更弱的模型
B. Agent 由模型自主规划路径，工作流按预定义路径执行
C. Agent 是新产品形态，工作流是过时技术
D. Agent 不需要提示词，工作流需要提示词

**6. 工作流中某工具节点调用超时，自动重试 2 次仍失败。按「兜底三件套」的正确顺序，下一步应该：**
A. 继续重试，直到成功为止
B. 直接把报错信息原样抛给用户
C. 走降级：切备用方案或礼貌拒答，仍失败再转人工
D. 立即重启整条工作流

### 三、简答题（20 分）

**7. 写出人机接管点的三种类型及其触发时机，并说明「转人工」时必须携带什么。**

---

## 第二层 · 进阶实操题（方案设计层）

**8. 兜底设计题（60 分）**

你为主项目设计了一条「售后退款助手」工作流：开始 → LLM 节点（理解用户诉求）→ 工具节点（查询订单系统）→ 条件分支（金额 ≤ 500 元自动走退款流程；> 500 元需人工审核）→ 输出节点。

请回答：

1. 这条工作流里应设哪几类人机接管点？分别设在哪个节点之后、触发条件是什么？
2. 订单系统接口超时时的完整兜底链路：从第一次失败到最终出口，用户每一步看到什么？
3. 「自动退款 ≤ 500 元」这个分支，重试安全吗？如果不安全，需要补什么设计？

## 第三层 · 求职挑战题（面试层）

**9. 面试真题：Agent 还是工作流？（40 分）**

面试官：「我们想给电商客服升级 AI 能力，有人说直接上一个全能 Agent，有人说做成固定流程。你作为产品经理，怎么决策？」

要求：先给决策框架，再给判断路径，最后补一个「显专业」的风险提示。

**10. 案例分析：无限转圈事故（40 分）**

某客服工作流上线三天后紧急下线：订单系统升级导致接口超时，工作流没有失败分支，用户端无限转圈，当天投诉翻倍。假如你是该产品经理，请给出：① 事故的根因（用本课术语表述）；② 修复后的兜底链路设计；③ 一条可写进产品文档的兜底设计原则。

## 参考答案与评分标准

### 第一层 · 基础巩固

| 题 | 答案 | 给分点 |
|---|---|---|
| 1 | **固定工作流** | 判断 8 分 + 理由 7 分（步骤固定可数、顺序不变、出错重跑即可；答「数得出来」「流程图画得出」均可） |
| 2 | **Agent** | 判断 8 分 + 理由 7 分（步骤数不定、路径依赖用户日程与偏好，需自主规划） |
| 3 | **固定工作流** | 判断 8 分 + 理由 7 分（规则明确、步骤 3 步以内、要求结果稳定可审计——「可审计」是高分点） |
| 4 | **Agent** | 判断 8 分 + 理由 7 分（子任务需动态拆解：搜索 → 阅读 → 取舍 → 成文，事先无法穷举） |
| 5 | **B** | 选 B 得满分；选 A 得 3 分（能意识到模型差异但归因错误） |
| 6 | **C** | 选 C 得满分；能口述「重试管瞬时、降级管持续、转人工是出口」额外加 5 分 |
| 7 | 审批型（事前：高风险 / 不可逆操作执行前）、纠错型（事中：置信度低或两次输出不一致）、兜底型（事后：重试与降级均失败）；转人工必须携带完整上下文（对话记录 + 已执行步骤） | 三类型各 5 分 + 触发时机各 1 分 + 携带上下文 2 分 |

### 第二层 · 进阶实操（三档 Rubric）

**第 8 题参考答案**：① 至少两处接管点——审批型：金额 > 500 元的条件分支后，人工审核（事前拦截高风险）；兜底型：转人工出口，携带对话上下文与已执行步骤；答出纠错型（LLM 意图理解置信度低时转复核）为加分项。② 兜底链路：首次超时 → 自动重试 1–2 次（用户看到短暂等待提示）→ 仍失败走降级（告知「系统繁忙，已为您创建人工工单」或返回缓存结果）→ 转人工，工单携带上下文，承诺响应时限；全程无无限转圈。③ 不安全——「自动退款」不是幂等操作，重试可能重复打款；需补幂等设计（请求带唯一退款单号，同一单号只执行一次）或把重试改为「状态查询」确认是否已退。

| 档位 | 标准 |
|---|---|
| 合格（36–47 分） | 答出至少两类接管点 + 兜底链路顺序正确（重试 → 降级 → 转人工） |
| 良好（48–54 分） | 接管点有明确触发条件，兜底链路写到「用户每一步看到什么」的产品呈现层 |
| 优秀（55–60 分） | 主动识别「自动退款不幂等」并给出幂等设计或状态查询替代方案，体现风险前置意识 |

### 第三层 · 求职挑战（三档 Rubric）

**第 9 题参考答案**：决策框架 = 三维度（任务确定性 / 步骤数 / 容错要求）。判断路径 = 逐个拆客服业务：工单分类打标（确定性高、步骤少、要可审计）→ 固定工作流；复杂纠纷协商、跨系统动态处理（路径不定）→ Agent，且 Agent 分支必须设审批型接管点（退款、补偿等执行前人工确认）。专业风险提示 = 「全能 Agent 意味着放弃可控性，客服出错直接损伤信任与资金，建议工作流为主、Agent 局部嵌入；并强调 Agent 多轮规划调用量大，成本也更高。」

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 结论明确（不盲目选 Agent），给出至少两个维度的判断依据 |
| 良好（32–37 分） | 用三维度框架逐场景拆解，区分「哪些子任务工作流、哪些 Agent」，提到人工接管点 |
| 优秀（38–40 分） | 额外补风险提示：可控性代价、成本差异（Agent 调用量成倍）或「工作流为主、Agent 嵌入」的架构建议 |

**第 10 题参考答案**：① 根因 = 工作流一顺到底、没有失败分支；工具节点持续失败后无重试 / 降级 / 转人工路径，错误直接暴露给用户端（无限转圈）。② 修复链路 = 工具节点加重试（1–2 次，幂等）→ 失败走降级分支（返回缓存 / 简化答复并告知）→ 最终转人工（工单携带上下文与已执行步骤），每级都有用户可见的反馈文案。③ 原则示例 = 「兜底设计不是技术问题，是产品承诺——每条工作流上线前必须回答：任何节点失败后，用户看到的最后一条消息是什么。」（原则表述不唯一，能体现「失败路径与主路径同等设计」即可）

| 档位 | 标准 |
|---|---|
| 合格（24–31 分） | 根因定位到「没有失败分支」，修复方案含至少两级兜底 |
| 良好（32–37 分） | 兜底三级齐全且顺序正确，根因用「主路径 / 失败路径」的产品语言表述 |
| 优秀（38–40 分） | 提炼出可复用的设计原则或验收机制（如「上线前必答用户最后看到什么」「失败分支列入评审清单」），体现体系化思维 |
