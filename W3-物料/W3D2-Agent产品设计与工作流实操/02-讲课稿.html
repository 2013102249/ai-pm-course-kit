讲课稿 · W3 周二《Agent 产品设计与工作流实操》（完整逐字稿）

AI 产品经理就业训练营 · 90 分钟 · 实操课口径：讲授段（0–30 分钟）可照读，实操段（30–80 min）为陪跑指令
标记说明：【问】课堂提问 【停】停顿等待 【操作】投屏操作指令 【巡场】巡场要点 【金句】面试金句（放慢语速重复一遍）
教学红线：所有 Dify / Coze 操作均为通用化描述（节点类型、连线逻辑），不绑定特定版本界面细节，统一口径「以当前版本界面为准」。

开场与导入（0–3 分钟）

大家好，昨天我们讲了 Agent 的架构原理——规划、记忆、工具、执行四要素，还有 ReAct 循环。今天不讲新概念，今天动手：用 Dify 或者 Coze（扣子），把你主项目的工作流原型搭出来。周五就是原型评审 I，里程碑 ②，今天是直接前置。

先花 30 秒复习。Agent 四要素，规划、记忆、工具、执行；ReAct 循环，思考、行动、观察，转圈直到完成任务。齐了，往下走。

【问】上课先抛一个两难案例：同样是「帮用户安排出差」，为什么有的产品做成 Agent，让模型自己规划；有的产品做成固定流程，一步步点下一步？【停，点 1–2 名学员】

有同学说到自由度，有同学说到可控——都对，但都不完整。今天的第一个任务，就是把这个「感觉」变成一把可以量化的尺子。

环节一：Agent vs 工作流决策框架（3–13 分钟）

【操作：打开配图《工作流编排示意图》，先只看主链路：开始 → LLM 节点 → 工具节点 → 条件分支 → 输出】

这就是一条最典型的工作流：五个节点，一条主链路，每一步做什么、输入输出是什么，事先全部定死。而 Agent 呢，只有一个起点和一个目标，中间怎么走，模型自己决定。

那产品经理怎么选？三个维度，一个一个过。

第一维，任务确定性。 问自己一个问题：这个任务的流程图，你画得出来吗？画得出、步骤和顺序都能预先定义——用工作流。画不出、路径要模型现场规划——才考虑 Agent。

第二维，步骤数。 数得出来的，常见三到八步，固定有限——工作流。数不出来、随输入动态伸缩的——Agent。

第三维，容错要求。 出错的代价是什么？如果是钱、信任、不可逆操作，低容错，用工作流，而且要加人工把关。如果是可以重来、试错成本低的事，Agent 的多轮自我修正反而是优势。

【问】用这把尺子判断：让 AI 自由规划一次旅行行程可以放手，为什么让它审核报销单就不行？【停】

对——行程错了代价低，重跑就是；报销涉及钱和合规，错一步有真实损失。这就是容错维度在说话。

好，现场快判四个场景，我说场景，你们喊答案。

每天定时抓取五个指定网站新闻，摘要后发邮件——【停】工作流，步骤固定可数。用户一句话「帮我安排下周去上海出差」，要查日程、订票、订酒店、写行程——【停】Agent，步骤数不定，路径依赖用户日程。客服工单按固定字段分类打标、路由到对应团队——【停】工作流，规则明确，要求稳定可审计。开放式「帮我调研一个竞品并写分析报告」——【停】Agent，子任务要动态拆解，事先无法穷举。

【金句】把这四题的判断逻辑收成一句话，今天最重要的一句：能用工作流解决的事，别用 Agent——确定性是产品的好朋友。 面试被问「什么场景该用 Agent」，先反问确定性，你就赢了一半。

环节二：人机协同与失败兜底（13–30 分钟）

选好了形态，下一个问题：哪些环节交给机器，哪些环节留给人？

人机接管点分三类，按时间轴记。

第一类，审批型，事前。 高风险、不可逆操作执行之前——对外发邮件、下单付款、删除数据。产品上要展示「AI 准备做什么、依据是什么」，人一键确认或修改。

【问】如果让 Agent 直接给用户发退款，你会在哪个点设人工接管？【停】

对，审批型：执行前展示金额和依据，人工确认；金额超阈值强制人审。

第二类，纠错型，事中。 模型输出置信度低、两次输出不一致的时候，转人工复核队列。设定一个置信度阈值，低于它就走人。

第三类，兜底型，事后。 重试和降级都失败了，转人工。注意一个细节：转人工必须携带完整上下文，不能让用户把问题重新描述一遍——那是最伤体验的一刀。

设计原则一句话：接管成本要对冲风险损失。每个接管点都要回答三个问题：人工来了看什么、能改什么、改完流程怎么继续。

再说失败兜底，三件套，顺序不能乱。

第一件，重试，管瞬时失败。 超时、网络抖动、限流，自动重试一到两次，前提是节点幂等——重跑不产生副作用。

第二件，降级，管持续失败。 主模型、主工具持续不可用，切备用模型、退化为简化逻辑、返回缓存结果，或者礼貌拒答，但要明确告知「结果可能不完整」。

第三件，转人工，是最终出口。 前两件都失败，或涉及高风险决策，生成工单，带上对话上下文和已执行步骤，承诺响应时限。

现在讲一个反面案例。【停，放慢】某团队做了一个客服工作流：用户提问，LLM 节点理解意图，工具节点查订单系统，输出节点回复。上线第一天跑得挺好。第三天，订单系统升级，接口超时。工作流里没有失败分支——工具节点一挂，整条链路中断，用户端的表现是：无限转圈。当天下午投诉翻倍，晚上产品被紧急下线。复盘报告就一句话：我们设计了所有顺利的路径，没有设计任何一条不顺利的。

【问】工具调用超时，自动重试两次还失败，产品上用户应该看到什么？【停】

对——降级或转人工，给明确反馈，不能无限转圈。

【金句】记住这句：兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。

好，前 30 分钟讲完，从现在开始，剩下 50 分钟全部动手。

环节三：实操陪跑（30–80 分钟，核心环节）

先说规矩：我投屏，大家跟做；每一步我演示三到五分钟，然后你们动手，助教巡场；每一步都有完成标志，卡住了举手，别自己耗。五步：建应用、加节点、配工具、调提示词、测运行。界面细节以你们手上当前版本为准，我讲的是节点类型和连线逻辑，产品思路不挑版本。

第①步 建应用（30–38 分钟）

【操作：投屏演示在 Dify 或 Coze 中创建工作流应用的通用入口：新建应用 → 选择「工作流」类型 → 填写名称与基本信息】

看投屏：新建一个应用，类型选工作流——注意，不是聊天助手、不是 Agent，选工作流。命名建议用「主项目名-workflow-v1」，比如「售后助手-workflow-v1」。创建成功后进入编排画布。

【巡场】这一步的典型卡点是找不到「工作流」类型入口，助教直接指。

完成标志：你的画布打开了。打开的举手，我扫一眼——好，全军过线，30 秒之内我们进第二步。

第②步 加节点（38–48 分钟）

【操作：投屏演示四类节点的连线逻辑：开始节点 → LLM 节点 → 条件分支节点 → 输出节点；演示从上游节点的输出变量连到下游节点的输入变量】

现在搭主链路，四类节点。开始节点，定义这条工作流的输入——比如用户的问题。LLM 节点，接大模型，理解和生成。条件分支节点，按条件走向不同路径。输出节点，把结果交给用户。

连线逻辑就一条：下游节点的输入，来自上游节点的输出变量。你在画布上连的每根线，本质都是一次「变量传递」。

【问】大家边连边想：如果 LLM 节点的输出格式乱掉，下游会发生什么？【停】

对——下游解析失败，全链路中断。所以这一步就埋下伏笔：等会儿第④步，我们会用提示词强约束输出格式，再补一条失败分支。

学员任务：按导学案的设计表，搭出主链路四类节点。硬性要求：至少一个条件分支。失败分支不急着连，第⑤步专门处理。

完成标志：画布上出现完整主链路连线。

第③步 配工具（48–58 分钟）

【操作：投屏演示给节点挂载工具或插件的通用配置：选择工具 → 填入 API 凭证或启用内置插件 → 配置输入参数映射 → 单节点试运行】

光有 LLM 不够，工作流的价值在「能干活」。给节点挂工具：联网搜索、知识库检索，或者你自己接的 API。通用配置四件事：选工具、填凭证或启用插件、把上游变量映射到工具的输入参数、单节点试运行一次。

【巡场】这一步报错最集中：凭证没填、参数没映射。助教优先处理「红色报错」，其次处理「跑通了但结果不对」。

学员任务：至少给一个节点配上工具调用。

完成标志：工具节点单独测试通过。

第④步 调提示词（58–68 分钟）

【操作：投屏演示在 LLM 节点内写提示词：角色 + 任务 + 输出格式约束；现场先演示一个不限格式的版本跑一次，再改成强约束版本跑一次，对比输出】

现在回到第②步埋的伏笔。LLM 节点的提示词，三段式：角色、任务、输出格式约束。格式约束怎么写？给它模板——「严格按以下 JSON 结构输出，不要输出任何其他内容」，字段名列清楚。

【操作：故意跑一次不限格式的版本，让下游条件分支报错】

看到了吗？输出是自由文本，条件分支读不懂字段，直接断。改完之后——跑通了。这就是「先制造失败，再修复失败」，比背十条最佳姿势都管用。

学员任务：完成自己 LLM 节点的提示词，明确输出格式。

完成标志：单节点试运行，输出符合你定义的格式。

第⑤步 测运行（68–80 分钟）

【操作：投屏演示整条工作流运行；然后故意制造一次失败——临时断开工具或输入乱码文本，展示失败分支如何接住】

最后一步，也是最容易被跳过的一步：测异常。跑三类输入——正常输入，验主链路；边界输入，比如超长文本、空字段；异常输入，比如完全无关的问题、故意断工具。硬性要求：补上失败分支，异常输入不崩，用户端要有明确反馈。

【问】如果你的工具节点超时、自动重试两次还失败，你的失败分支应该把用户引到哪？【停】

对，降级或转人工——就是第 13 分钟讲的兜底三件套，现在落到你自己的画布上。

完成标志：整条链路，三类输入均可运行。

收尾（80–90 分钟）

停下手里的活，我们收尾。

先看作品。请两到三位同学投屏自己的工作流，一分钟讲清楚：解决什么问题、几个节点、失败分支怎么设计的。【停，学员分享，讲师各点评一句：先肯定，再指出一个接管点建议】

分享完，做一个人机接管自查，三个问题：第一，我的工作流里，风险最高的那一步是什么？第二，它在执行前，有人确认吗？第三，它失败之后，用户看到的最后一条消息是什么？这三个问题答不上来，回去补。

【金句】最后再重复一遍今天的口诀，抄到导学案上：能用工作流解决的事，别用 Agent——确定性是产品的好朋友。

课后作业：完成主项目工作流 V1，把编排画布和三类输入的运行结果截图，归档到项目文件夹。周五原型评审 I，我们按今天的三条线验收：主链路跑通、失败分支存在、接管点明确。今天搭得越完整，周五越轻松。

下课。

附录：不懂技术也能问出口的 3 个问题（学员与研发对话专用）

使用说明：转行学员与技术同事对话，最怕「不知道该问什么」。下面 3 个问题不需要任何技术背景，但每一个都问在产品要害上——研发听完就知道你是内行。建议抄进笔记本，入职第一天就能用；本节供课下消化，不占用课堂时间。

问题一：「这条流程里，哪一步失败率最高？失败了用户会看到什么？」

  • 什么时候问：任何人展示「跑通了」的演示时。
  • 为什么好：我们设计了所有顺利的路径，也要设计不顺利的路径——用户不在乎错在哪个节点，只在乎坏了之后谁负责。

问题二：「能用固定工作流解决的部分，为什么还要交给 Agent 自主决定？」

  • 什么时候问：看到方案里「看起来很酷」的自主环节时。
  • 为什么好：能用工作流解决的事别用 Agent，确定性是产品的好朋友——这一问是复杂度过滤器。

问题三：「每个节点失败重试的时候，会不会重复扣款、重复发消息？」

  • 什么时候问：讨论重试策略和兜底方案时。
  • 为什么好：重跑无副作用（行话叫「幂等」）是工程底线；会问这个的 PM，研发会主动拉你进核心群。

附录一：巡场提问清单（助教用）

#巡场时机提问预设答案 / 判断标准
1第②步连线时「你这根线，传的是哪个变量？」能说出上游输出 → 下游输入的对应关系
2第②步收尾「你的条件分支，条件是什么？走两条路分别去哪？」条件明确，两条路径去向清晰
3第③步「这个工具的输入参数，来自哪个节点？」参数映射指向明确的上游变量
4第④步「你的输出格式约束，下游靠哪个字段做判断？」格式约束里有可供条件分支读取的字段
5第⑤步「你的失败分支，用户最后看到什么？」有明确反馈文案，不是转圈
6全程通用「这一步如果失败，重试安全吗？」知道幂等概念，重跑无副作用

附录二：本课面试金句汇总（建议学员抄录）

  1. 能用工作流解决的事，别用 Agent——确定性是产品的好朋友。
  2. Agent 用自主性换灵活性，工作流用确定性换可控性——产品经理的活儿，就是替用户选对这一边。
  3. 兜底设计不是技术问题，是产品承诺——用户不在乎错在哪个节点，只在乎坏了之后谁负责。
  4. 我们设计了所有顺利的路径，没有设计任何一条不顺利的——这就是没有失败分支的产品死法。
  5. 接管成本要对冲风险损失；每个接管点都要回答：人工来了看什么、能改什么、改完流程怎么继续。

附录三：防冷场话术库（讲师备用）

场景话术
提问后无人应答「提示一下——昨天讲的四要素里，哪个要素负责『自己决定下一步』？那不用它决定的东西叫什么？」
学员答非所问「这个角度先记下来。回到问题本身——它问的是确定性，你搭的这条流程，确定性在哪？」
学员答对但声音小「对，完全正确。大声再说一遍，让大家听到——这句面试能直接用。」
实操环节集体卡住「停一下手。我看至少一半同学卡在同一步，我统一讲——不是你的问题，是这一步确实有个坑。」
个别学员进度过快「快的人做加法：给你的工作流再补一个接管点，想想加在哪。」
