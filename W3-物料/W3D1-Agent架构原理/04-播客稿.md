## 开场钩子（0:00–0:40）

早上好，欢迎回到《AI 产品经理课余充电》，我是你的讲师。

今天这期，聊第三周的开篇词——Agent。这个词你肯定听腻了，但我先做个测试：如果面试官问「Agent 产品和普通 AI 对话产品的区别是什么」，你能用一句话答到点子上吗？很多人答「更智能」「能自主决策」，这些都不算答对。8 分钟后，你会有一句面试官点头的答案，还能接住他三个追问。

## 第一部分：从答题到办事（0:40–2:30）

先给结论。**答题是给答案，办事是拆任务、用工具、拿结果、担责任。**Agent，就是从答题走向办事的那一步。

你问 AI 要一份旅游攻略，它交付一份文本，对错你自己把关——这是答题。你说帮我把机票酒店订了，它得先拆任务、再调接口、再处理失败、最后交付一条真订单——这是办事。两者的差别不是「更智能」，而是交付物从信息变成了结果，责任主体从你变成了它。

责任一变，产品的设计重心就变了。一个 Agent 系统有四要素：规划，把大目标拆成步骤；记忆，短期上下文加长期存取；工具，接上外部能力；执行，真正动手。每个要素，产品经理都有一块自留地：规划管步数上限，记忆管记什么忘什么，工具管给哪几个、给多大权限，执行管哪些动作要人点头。注意，这四个要素里没有一个是「更聪明的模型」——Agent 的难点从来不是模型，是围绕模型的产品设计。

【放慢】这里给你今天的第一个面试答案：**Agent 就是长着四肢的大模型——模型是大脑，四要素是四肢，产品经理设计的是四肢的关节。**

## 第二部分：两个必考的产品设计（2:30–5:00）

四要素里，我挑两个面试最爱追问的展开。

第一个，ReAct。术语是「思考与行动交替」，但产品经理的答案是另一句：**把模型的思考过程摊开给用户看。**为什么要摊开？因为可观测带来三样东西——用户知道它在干嘛，这是信任；发现跑偏能随时叫停，这是可中断；出了错能定位到具体哪一步，这是可纠偏。反面教材就是那种只有转圈动画的 Agent：用户等三十秒就开始刷新页面，哪怕最后结果是对的，体验也崩了。所以步骤清单、进度可见、可展开细节，这些不是界面美化，是 Agent 产品的信任地基。

第二个，边界设计。记住今天的第二句金句：**没有步数上限的 Agent，是在拿用户的 token 赌运气。**Agent 每一步都在调模型、调工具，钱按步累加，所以最大步数是必填项，不是可选项。比步数更重要的，是另一条线：**Agent 产品经理的第一问题——这件事什么时候交还给人类？**三种时刻必须交还：模型没把握的时候、预算触顶的时候、碰到不可逆动作的时候。支付、发送、删除这类动作，做之前必须有人工确认，这是红线。

顺便答一个高频追问：「什么时候该用多个 Agent？」先泼冷水：多 Agent 是复杂度黑洞，Agent 之间的通信、消息损耗、失败传播，每个都是新的坑。只有任务真能并行、上下文真装不下、专业能力真需要隔离，三个信号占其一，才考虑多 Agent。顺序永远是：先问单 Agent 能不能解决，再问要不要 Agent。

## 第三部分：一个新杠杆（5:00–6:30）

第三个知识点，MCP，模型上下文协议，Anthropic 在 2024 年 11 月发布的开放标准。

它解决的是「M 个模型接 N 个工具」的适配爆炸问题——没有统一协议，要写 M 乘 N 套适配；有了统一协议，M 加 N 份工作就够。类比一句话：**MCP 就是 AI 时代的 USB 接口。**没有 USB 的年代，每个设备一种线；USB 一统天下，即插即用。

对产品经理的意义就一句：工具接入的成本在标准化中大幅下降，你设计 Agent 时的工具选择空间变大了。以前接一个新工具要评估两周开发排期，协议统一之后是分钟级配置——这意味着你在方案评审里可以更大胆地试错，也意味着「工具生态够不够丰富」会成为你选平台的正式考量项。面试聊到工具生态，能带出「工具侧有 MCP，Agent 互联侧有 A2A」，就够了。

## 结尾（6:30–8:00）

收束成三句话：Agent 和对话产品的区别，是答题和办事的区别；ReAct 的产品讲法是把思考摊开给用户看；三道闸门——接管点、步数上限、人工确认，是 Agent 产品的安全底线。

【放慢】最后给你一个课余小任务：打开你手机里任何一个 AI 助手，给它一个真正「办事型」的任务，盯着看——它拆了几步、用了什么工具、卡在哪。你盯着它跑完的那几分钟，比听十节理论课都管用。
