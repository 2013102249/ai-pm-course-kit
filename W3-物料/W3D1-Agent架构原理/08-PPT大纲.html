P06｜术语 1 · Agent（智能体） 🗣

  • 一句话定义：会自己拆任务、用工具、把事办完的 AI。
  • 生活类比：你交办给助理「帮我安排下周出差」，他自己去查、去订，回你一句「办好了」——你不用一步步盯着。
  • 易混辨析：最容易和普通 Chatbot（聊天机器人）混。Chatbot 你问一句它答一句，交付「答案」
  • 面试说法：「Agent 和对话产品的本质区别，是从答题走向办事——交付物从信息变成结果，责任主体从用户变成产品。」

P07｜术语 2 · 四要素（规划 / 记忆 / 工具 / 执行） 🗣

  • 一句话定义：让大模型能办事的四样零件。
  • 生活类比：开一家小餐馆：规划是排好做菜顺序，记忆是记住老客口味，工具是锅碗灶具，执行是真正把菜端上桌。
  • 易混辨析：容易和「模型能力」混。四要素不是更聪明的模型，是围着模型搭的产品设计——模型只是大脑，四要素是四肢。
  • 面试说法：「Agent 的难点从来不在模型，而在四要素的产品设计，每个要素产品经理都有一块自留地。」

P08｜术语 3 · ReAct（Reasoning + Acting，推理

  • 一句话定义：模型「想一步、做一步、看一眼、再想」的循环。
  • 生活类比：照着菜谱做没做过的菜：先看一步说明、动手、尝一口咸淡、再决定要不要加盐。
  • 易混辨析：容易和「一次性给答案」混。普通问答是一锤子买卖，ReAct 是「做一步看一步」的循环，跑偏了能中途调头。
  • 面试说法：「ReAct 对产品经理的意义，是把模型的思考过程摊开给用户看——换来信任、可中断、可纠偏。」

📍 原文出处：一句话定义：模型「想一步、做一步、看一眼、再想」的循环。（见讲稿「术语精讲与零层入口」）

P09｜术语 4 · 规划（Planning）

  • 一句话定义：把大目标拆成一串可执行的小步骤。
  • 生活类比：搬家前先列清单：装箱、叫车、搬运、拆箱，而不是想到哪件搬哪件。
  • 易混辨析：容易和「固定工作流」混。工作流是人提前把步骤写死、路径不变；规划是 Agent 自己临场拆，所以更要设步数上限。
  • 面试说法：「规划模块我一定配三样：任务边界、步数上限、重试策略——没有最大步数（max steps）的 Agent 是在拿用户 token（用量计费…

📍 原文出处：一句话定义：把大目标拆成一串可执行的小步骤。（见讲稿「术语精讲与零层入口」）

P10｜术语 5 · 记忆（Memory）

  • 一句话定义：Agent 记下的上下文与跨会话经验。
  • 生活类比：常去的理发店师傅记得你「两边推短、上面留长」，你不用每次重讲一遍。
  • 易混辨析：容易和「聊天记录」混。聊天记录是流水账全存；记忆要设计「记什么、忘什么」，用户还能查看和删除。
  • 面试说法：「记忆不是越多越好——会遗忘才是产品设计，长期记忆要白名单化、用户可见可删。」

📍 原文出处：一句话定义：Agent 记下的上下文与跨会话经验。（见讲稿「术语精讲与零层入口」）

P11｜术语 6 · 工具调用（Tool Use / Tool Callin

  • 一句话定义：Agent 借用外部能力去查数据、办事情。
  • 生活类比：自己不会修水管，但会打电话叫水电工——你不必会干，知道叫谁就行。
  • 易混辨析：容易和「模型自己算」混。模型硬答汇率往往是编的；调了查询工具拿回的才是真数据。
  • 面试说法：「工具给最小集、权限最小化，而且工具描述文案就是提示词的一部分——模型靠它决定何时调用、传什么参数。」

📍 原文出处：一句话定义：Agent 借用外部能力去查数据、办事情。（见讲稿「术语精讲与零层入口」）

P12｜术语 7 · MCP（Model Context Protocol，

  • 一句话定义：给模型和工具定统一插口，让接入即插即用。
  • 生活类比：以前打印机、鼠标、键盘各一种线；有了 USB，什么设备插上就能用。
  • 易混辨析：容易和「某一个工具或插件」混。MCP 不是工具本身，是工具与模型之间的接口标准，把 M×N 套适配降到 M+N。

P13｜术语 8 · Multi-Agent（多智能体）

  • 一句话定义：多个 Agent 分工协作，各管一段任务。
  • 生活类比：办一场婚礼，请了策划、摄影、司仪各管一摊——人多了，就得多一个人专门协调。
  • 易混辨析：容易和「把一个 Agent 拆成多个步骤」混。那是同一个 Agent 的规划
  • 面试说法：「多 Agent 是复杂度黑洞：两个 Agent 能做的事，别用五个；先问单 Agent 能不能解决。」

📍 原文出处：一句话定义：多个 Agent 分工协作，各管一段任务。（见讲稿「术语精讲与零层入口」）

P14｜术语 9 · 自主性（Autonomy）

  • 一句话定义：不用人一步步指挥、自己往下跑的程度。
  • 生活类比：定好目的地的代驾，你不用告诉他每个路口怎么拐；但过收费口、停车付钱，他还得问你一句。
  • 易混辨析：容易和「全自动」混。自主性要分档，不是越高越好；不可逆动作那一档，必须收回来交还人类。
  • 面试说法：「自主性我按动作可逆性分档：查询、草稿放手做；支付、发送、删除必须停下来等人点头。」

📍 原文出处：一句话定义：不用人一步步指挥、自己往下跑的程度。（见讲稿「术语精讲与零层入口」）

P15｜术语 10 · 边界（Boundary，产品边界）

  • 一句话定义：划清 Agent 该做什么、做到哪、何时停。
  • 生活类比：给家政阿姨列一张单子：打扫哪些房间、哪些柜子别动、拿不准的先打电话问。
  • 易混辨析：容易和「功能清单」混。功能清单说「能做什么」；边界更要说「不做什么」和「什么时候停」——任务边界、步数上限、接管点都算。
  • 面试说法：「我设计 Agent 先画边界：任务边界、最大步数、成本上限、人工接管点，四样缺一不可。」

📍 原文出处：一句话定义：划清 Agent 该做什么、做到哪、何时停。（见讲稿「术语精讲与零层入口」）

P16｜术语 11 · 幻觉（Hallucination）

  • 一句话定义：模型一本正经地编出不存在的内容。
  • 生活类比：问路碰到不熟路的人，他不好意思说不知道，随口给你指了个方向，听着还挺肯定。
  • 易混辨析：容易和「答错」混。答错是记岔了，幻觉是凭空造；Agent 里靠工具调用查证、靠执行日志留痕兜底，正好对上「办事要担责任」。
  • 面试说法：「答题型产品幻觉顶多被吐槽，办事型产品幻觉是真金白银的损失——关键数据必须工具查证、不可逆动作必须人工确认。」

📍 原文出处：一句话定义：模型一本正经地编出不存在的内容。（见讲稿「术语精讲与零层入口」）

P17｜术语 12 · 可观测性（Observability）

  • 一句话定义：用户能看见 Agent 在干什么、走到第几步。
  • 生活类比：外卖 App 上的「骑手已取餐、距您 1.2 公里」——看不见进度，你才会一遍遍刷新。
  • 易混辨析：容易和「运行日志」混。日志是给工程师排错用的；可观测性是给用户看的步骤清单，是信任设计，不是调试界面。
  • 面试说法：「可观测性不是 debug 界面，是信任地基：默认展示步骤清单，想看细节再点开——这叫可展开的透明。」

📍 原文出处：一句话定义：用户能看见 Agent 在干什么、走到第几步。（见讲稿「术语精讲与零层入口」）
