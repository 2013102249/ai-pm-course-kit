## 二、教学目标（可测量）

1. 能独立画出 Agent 四要素架构图（规划 / 记忆 / 工具 / 执行），并为每个要素写出一条「产品经理管什么」（对应作业：主项目 Agent 架构图）。
2. 能用「从答题到办事」的框架，向非技术同事讲清 Agent 与普通对话产品的区别（对应课堂提问 + 习题第一层）。
3. 面对给定场景，能初步判断「该不该上 Agent」，并给出接管点设计与步数上限两个产品决策（对应课堂练习 + 习题第二层，W3D2 深化）。

## 三、教学重难点

- **重点**：四要素的产品视角解读——每个要素「是什么、产品经理管什么、常见坑是什么」，而不是技术实现细节。
- **难点一**：ReAct 的讲法。学员容易把它背成术语。正确讲法：把模型的思考过程「摊开给用户看」，这是信任设计，不是 debug 界面。
- **难点二**：Multi-Agent 复杂度警告。学员看过 Manus 等产品后容易「言必称多 Agent」，必须用「复杂度黑洞」压回去。
- **难点三**：MCP 协议。用「USB 接口」类比落到「工具接入成本」这一产品视角，避免讲成协议规范课。

## 五、教学步骤与时间拆分（总和 = 90 分钟）

| 时间 | 环节 | 教学内容 | 教学方法 | 对应产出 |
|---|---|---|---|---|
| 0–8 min | 导入：从答题到办事 | 对比「让 AI 写旅游攻略」与「让 Agent 订好机票酒店」：答题给答案，办事拆任务、用工具、拿结果、担责任；以 Manus 的公开产品形态（任务拆解、过程可见）做客观描述 | 类比 + 提问 1 | — |
| 8–15 min | 环节一：Agent 是什么 | 「长着四肢的大模型」：W1D2 讲的大脑（LLM）+ 今天装的四肢（四要素）；展示四要素架构图总览 | 回顾 + 图示 | 导学案画骨架 |
| 15–42 min | 环节二：四要素逐个精讲（核心） | 规划（7 min）：拆任务、步数上限、可观测；记忆（6 min）：短期上下文与长期记忆、遗忘与隐私；工具（7 min）：最小工具集、权限最小化、描述文案；执行（7 min）：不可逆动作、人工确认、回滚留痕；每要素按「是什么 → 产品经理管什么 → 常见坑」三段推进，对应交互工具节点点击 | 交互演示 + 讲授 + 提问 2–5 | 四要素笔记表 |
| 42–55 min | 环节三：ReAct 与反思机制 | ReAct = 思考—行动—观察循环；核心讲法：把思考过程摊开给用户看（步骤列表、进度可见、失败重试可见）；反面案例：黑箱转圈 3 分钟用户流失；反思机制 = 失败后自动调整下一步 | 讲授 + 对比案例 + 提问 6 | ReAct 三句话笔记 |
| 55–65 min | 环节四：MCP 协议 | 「USB 接口」类比：没有 USB 前每个设备一种接口（M×N 适配），MCP 统一协议（M+N）；客观介绍 MCP 为 Anthropic 于 2024 年 11 月发布的开放协议、已被多家主流厂商跟进；产品含义：接工具成本下降，是产品经理的新杠杆；A2A 一句话前瞻 | 类比 + 讲授 + 提问 7 | MCP 一句话笔记 |
| 65–75 min | 环节五：Multi-Agent 复杂度警告 | 多 Agent 分工形态；三个隐藏成本：协作协议、消息格式、失败传播；决策原则：先问「单 Agent 能不能解决」；点击交互工具「多 Agent 协作」节点 | 交互演示 + 讲授 + 提问 8 | Multi-Agent 判断笔记 |
| 75–85 min | 环节六：产品边界与主项目草图 | 三道闸门：人工接管点（金句：这件事什么时候交还给人类）、步数与成本上限、安全闸门；学员在导学案画主项目 Agent 架构草图 8 分钟，讲师巡视 | 讲授 + 现场作画 + 巡视 | 主项目架构草图 |
| 85–90 min | 总结与作业 | 三句话收束 + 作业布置 + 预告 W3D2 工作流实操 | 讲授 | — |

## 六、课堂提问设计（8 问，附预设答案）

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 「让 AI 写一份旅游攻略，和让 AI 直接把机票酒店订好，这两件事的本质差别在哪？」 | 导入 | 前者交付「答案」，对错由你自己判断；后者交付「结果」，要拆任务、调工具、处理失败，还要担责任——引出「从答题到办事」 |
| 2 | 「Agent 拆完任务后，为什么还会一步错、步步错？」 | 规划环节 | 没有重试策略与步数上限：失败后不停重试或硬着头皮往下跑；规划必须设计「重试几次、何时放弃」 |
| 3 | 「Agent 的记忆是不是越多越好？」 | 记忆环节 | 不是。记太多有隐私风险且干扰判断；该忘的忘（遗忘策略），且用户要能查看、删除自己的记忆 |
| 4 | 「为什么说工具的描述文案是提示词的一部分？」 | 工具环节 | 模型靠工具描述决定「用什么、怎么用」，描述含糊就会调错工具或传错参数；写工具描述等于在写提示词 |
| 5 | 「执行环节，哪些动作必须有人工确认？」 | 执行环节 | 不可逆动作：支付、发送、删除、对外承诺；可逆动作可以放手，不可逆动作必须设闸门 |
| 6 | 「为什么要把 Agent 的思考过程展示给用户？直接给结果不是更快吗？」 | ReAct 环节 | 可观测带来三样东西：信任（知道它在干嘛）、可中断（发现跑偏能叫停）、可纠偏（看到错在哪一步）；黑箱转圈是体验杀手 |
| 7 | 「没有 MCP 之前，3 个模型接 10 个工具要写多少套适配？有了 MCP 之后呢？」 | MCP 环节 | 没有 MCP 是 3×10=30 套适配，有统一协议是 3+10=13 套——M×N 变 M+N，接入成本大幅下降 |
| 8 | 「什么时候才真的需要多 Agent？」 | Multi-Agent 环节 | 先问单 Agent 能不能解决；只有任务可并行、上下文塞不下、专业需要隔离时才拆——两个 Agent 能做的事，别用五个 |

## 七、板书要点

```
Agent = 长着四肢的大模型 = 大脑（LLM）+ 四肢（四要素）

四要素：规划（拆任务·步数上限） 记忆（短期上下文·长期存取·会遗忘）
        工具（最小集·权限最小化） 执行（不可逆=人工确认·留痕）

ReAct：思考 → 行动 → 观察 → 再思考（把思考摊开给用户看）
MCP：工具的 USB 接口，M×N 变 M+N

产品三道闸门：接管点（何时交还人类） 步数上限（防烧钱） 安全闸门（不可逆必确认）
```

## 八、课堂练习参考答案（主项目草图巡视要点）

| 检查项 | 合格线 | 常见问题 |
|---|---|---|
| 四要素标全 | 图上有规划 / 记忆 / 工具 / 执行四个模块 | 只画了「LLM + 工具」，漏记忆与执行 |
| 接管点 | 至少标出 1 个「交还人类」的位置 | 全自动闭环，无人接管点 |
| 步数上限 | 标注最大步数或成本上限 | 没有任何上限标注 |
| 工具清单 | 列出 3–5 个具体工具及权限 | 只写「调用工具」四个字 |

## 九、学员易错点预判与应对（6 条）

| 易错点 | 表现 | 应对 |
|---|---|---|
| 把 Agent 当万能药 | 「我们项目全用 Agent 做」 | 用场景适配判断压回：任务结构固定用工作流，开放式才用 Agent；W3D2 专门练判断，今天先记「先问单 Agent，再问要不要 Agent」 |
| 忽视步数与成本上限 | 架构图里没有任何上限设计 | 讲金句「没有步数上限的 Agent 是在拿用户的 token 赌运气」；要求草图必须标注最大步数 |
| 忘记设计人工接管点 | 画成全自动闭环 | 讲金句「Agent 产品经理的第一问题：这件事什么时候交还给人类」；要求草图至少标 1 个接管点 |
| 把四要素背成技术名词 | 只会复述 Planning/Memory/Tools/Action | 每要素强制回答「产品经理管什么」，笔记表按此设计，答不出就现场追问 |
| 一上来就设计多 Agent | 简单需求拆 5 个 Agent | 讲「复杂度黑洞」金句与三个隐藏成本；决策原则：两个 Agent 能做的事，别用五个 |
| 把 ReAct 讲成纯技术 | 认为「思考过程展示」是 debug 信息 | 对比黑箱转圈与步骤可见两种体验，落点：思考透明化是信任设计，不是技术日志 |
