## 二、教学目标（可测量）

1. 能独立画出 Agent 四要素架构图（规划 / 记忆 / 工具 / 执行），并为每个要素写出一条「产品经理管什么」（验证：导学案四要素笔记表 4 行填满 + 主项目架构草图四框齐全）。
2. 能用「从答题到办事」的框架，向非技术同事讲清 Agent 与普通对话产品的区别（验证：课堂提问 1 口头作答 + 习题第一层第 6 题达 20 分以上）。
3. 面对给定场景，能初步判断「该不该上 Agent」，并给出接管点设计与步数上限两个产品决策（验证：习题第二层第 8 题四场景判断 ≥3 个正确 + 草图含 1 个接管点与 1 个上限标注）。
4. **（术语目标）** 能准确说出当日 12 个术语的一句话定义，并辨析至少 3 组易混概念（验证：《术语自测表》12 行自评 ≥10 行达标 + 第 0 层术语辨析题 10 题答对 ≥8 题）。
5. **（面试目标）** 能对 4 道核心面试题给出 60 秒标准答法，并接住至少 2 层追问（验证：《面试模拟记录表》≥4 行含追问记录与自评分 + 第 4 层面试实战题评分表达「良好」档）。
6. 能说出英文缩写首次出现时的全称与中文（ReAct、MCP、API、LLM、A2A、RAG 等）（验证：对应板块术语小测「缩写全称连线」全对）。
7. 能完成本日作品集积木归档，说清每份产出放在哪、周五评审怎么用（验证：《本日作品集积木》表 3 行填全，含归档位置）。

## 三、教学重难点

- **重点**：四要素的产品视角解读——每个要素「是什么、产品经理管什么、常见坑是什么」，而不是技术实现细节；全课用生活类比，不讲代码。
- **难点一**：ReAct 的讲法。学员容易把它背成术语。正确讲法：把模型的思考过程「摊开给用户看」，这是信任设计，不是 debug（调试）界面。
- **难点二**：Multi-Agent 复杂度警告。学员看过通用 Agent 产品后容易「言必称多 Agent」，必须用「复杂度黑洞」压回去。
- **难点三**：MCP 协议。用「USB 接口」类比落到「工具接入成本」这一产品视角，避免讲成协议规范课。
- **难点四（术语混淆）**：零基础学员最容易把三组词混成一团——Agent 与普通 Chatbot（聊天机器人）、规划与固定工作流、可观测性与运行日志；另有「自主性越高越好」「记忆越多越好」两个直觉误区。对应板块用「易混辨析 + 当堂连线改错」专门拆。
- **难点五（面试失分）**：学员答题爱说「更智能」「能自主决策」这类空话，一被追问「那怎么落地」就卡住。对应板块用「先结论 → 三条踩分点 → 一个当日术语 → 一个自己项目的例子」的骨架统一纠正，并做两两模拟与追问防御。

## 六、课堂提问设计（20 问，附预设答案）

| # | 类别 | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|---|
| 1 | 导入 | 「让 AI 写一份旅游攻略，和让 AI 直接把机票酒店订好，这两件事的本质差别在哪？」 | 对应板块导入 | 前者交付「答案」，对错由你自己判断；后者交付「结果」，要拆任务、调工具、处理失败，还要担责任——引出「从答题到办事」 |
| 2 | 原理理解 | 「Agent 拆完任务后，为什么还会一步错、步步错？」 | 对应板块规划 | 没有重试策略与步数上限：失败后不停重试或硬着头皮往下跑；规划必须设计「重试几次、何时放弃」 |
| 3 | 原理理解 | 「Agent 的记忆是不是越多越好？」 | 对应板块记忆 | 不是。记太多有隐私风险且干扰判断；该忘的忘（遗忘策略），且用户要能查看、删除自己的记忆 |
| 4 | 原理理解 | 「为什么说工具的描述文案是提示词的一部分？」 | 对应板块工具 | 模型靠工具描述决定「用什么、怎么用」，描述含糊就会调错工具或传错参数；写工具描述等于在写提示词 |
| 5 | 原理理解 | 「执行环节，哪些动作必须有人工确认？」 | 对应板块执行 | 不可逆动作：支付、发送、删除、对外承诺；可逆动作可以放手，不可逆动作必须设闸门 |
| 6 | 原理理解 | 「为什么要把 Agent 的思考过程展示给用户？直接给结果不是更快吗？」 | 对应板块 ReAct | 可观测带来三样东西：信任（知道它在干嘛）、可中断（发现跑偏能叫停）、可纠偏（看到错在哪一步）；黑箱转圈是体验杀手 |
| 7 | 原理理解 | 「没有 MCP 之前，3 个模型接 10 个工具要写多少套适配？有了 MCP 之后呢？」 | 对应板块 MCP | 没有 MCP 是 3×10=30 套适配，有统一协议是 3+10=13 套——M×N 变 M+N，接入成本大幅下降 |
| 8 | 原理理解 | 「什么时候才真的需要多 Agent？」 | 对应板块 Multi-Agent | 先问单 Agent 能不能解决；只有任务可并行、上下文塞不下、专业需要隔离时才拆——两个 Agent 能做的事，别用五个 |
| 9 | **术语辨析** | 「Agent 和普通 Chatbot（聊天机器人）都叫 AI 产品，分界线到底画在哪？」 | 对应板块 | 交付物与责任主体：Chatbot 给「答案」、责任在你；Agent 给「结果」、责任在它。不是「更智能」 |
| 10 | **术语辨析** | 「『规划』和『固定工作流』听起来都是把事拆成步骤，差在哪？」 | 对应板块 | 工作流是人提前把步骤写死、路径固定；规划是 Agent 自己临场拆，所以必须配步数上限与接管点 |
| 11 | **术语辨析** | 「『可观测性』和工程师看的『运行日志』是不是一回事？」 | 对应板块 | 不是。日志给工程师排错；可观测性给用户看步骤清单，是信任设计，不是调试界面 |
| 12 | **术语辨析** | 「『自主性』是不是越高越好？为什么『全自动』反而要警惕？」 | 对应板块 | 自主性按动作可逆性分档；查询、草稿可放手，支付、发送、删除必须收回来交还人类 |
| 13 | **术语辨析** | 「『幻觉』和『答错了』有什么区别？办事型产品为什么更怕它？」 | 对应板块 | 答错是记岔了，幻觉是凭空编；答题型顶多被吐槽，办事型是真金白银的损失，要靠工具查证与人工确认兜底 |
| 14 | **术语辨析** | 「ReAct（Reasoning + Acting，推理与行动交替）和『一次性给答案』差在哪？『反思机制』又算哪一拍？」 | 对应板块 | ReAct 是「做一步、看一眼、再决定」的循环；反思是失败后换方式再来的一次额外推理，仍要受步数上限约束 |
| 15 | **面试追问** | 「你说 Agent 比 Chatbot 强，强在哪？如果我这个场景只需要查一条退款政策呢？」 | 对应板块题 1 追问 | 不能泛说「强」，要回到「交付物 + 责任」；单一知识查询用不上 Agent，用检索问答即可，顺势引出「什么时候不该用 Agent」 |
| 16 | **面试追问** | 「ReAct 把思考摊开给用户看，会不会信息过载？你怎么设计？」 | 对应板块题 2 追问 | 分层呈现：默认只给步骤清单，一行一句；想看细节再点开——「可展开的透明」，不是事无巨细的汇报 |
| 17 | **面试追问** | 「你说不该上 Agent，那业务方就要『全自动』，你怎么说服他？」 | 对应板块题 3 追问 | 全自动的隐含代价是「错误也全自动」；接管点不是能力不足，是把责任留在该在的位置——可靠性优先于自动化率 |
| 18 | **面试追问** | 「多 Agent 复杂度怎么控？如果一定要拆，你先定哪三件事？」 | 对应板块题 4 追问 | 先问单 Agent 能不能解决；真要拆，先定协作协议、消息格式、失败传播的定位与兜底，能不拆就不拆 |
| 19 | **面试追问** | 「你画的架构图里，步数上限设成多少？凭什么？」 | 对应板块题 6 追问 | 给出具体数字与依据（任务复杂度、单步成本），并说明「超限即暂停并交还人类」，不是随口一个数字 |
| 20 | **面试追问** | 「讲一个你把某件事『交还人类』的设计，当时怎么权衡效率和安全？」 | 对应板块题 8 追问 | 用自己主项目的真实动作（如对外发送前确认）讲权衡：接管不是弹窗打断，而是「暂停 + 选项」，用户保有控制感 |

> 分布：原理理解 8 问（原 8 问完整保留）+ **术语辨析 6 问** + **面试追问 6 问** = 20 问，满足 ≥18、术语辨析 ≥6、面试追问 ≥6。

## 七、板书要点（按 6 节重排）

```
【对应板块 · 术语精讲与零层入口】
Agent = 会办事的 AI ｜ 四要素 = 规划 · 记忆 · 工具 · 执行
ReAct（Reasoning + Acting，推理与行动交替）：想 → 做 → 看 → 再想
MCP（Model Context Protocol，模型上下文协议）：工具的统一插口
易混三组：Chatbot（聊天机器人）≠ Agent ｜ 规划 ≠ 固定工作流 ｜ 可观测性 ≠ 运行日志
两个直觉误区：自主性越高越好 ✗ ｜ 记忆越多越好 ✗

【对应板块 · 核心原理讲授 A】
Agent = 长着四肢的大模型 = 大脑（LLM，大语言模型）+ 四肢（四要素）
答题给答案 ｜ 办事拆任务 · 用工具 · 拿结果 · 担责任
规划：拆任务 · 任务边界 · 步数上限 · 重试策略（金句：拿 token 赌运气）
记忆：短期上下文 · 长期存取 · 写入与遗忘 · 隐私可见可删（金句：会遗忘才是产品设计）
工具：最小集 · 权限最小化 · 描述文案 = 提示词的一部分
执行：不可逆 = 人工确认 · 回滚补偿 · 日志留痕

【对应板块 · 核心原理讲授 B + 案例】
ReAct：把思考摊开给用户看 → 信任 / 可中断 / 可纠偏；默认步骤清单 + 可展开细节
反思机制：失败后换方式再来，反思几次也要有上限
MCP：M×N 变 M+N；USB 类比；工具生态成为选型考量
Multi-Agent：三个隐藏成本（协作协议 · 消息损耗 · 失败传播）；先问单 Agent
三道闸门：接管点（何时交还人类）· 步数与成本上限 · 安全闸门（不可逆必确认）

【对应板块 · 实操演练与巡场】
任务五步：读场景 → 画四框 → 标接管点与上限 → 列工具清单 → 自查
巡场三看：四要素是否标全 / 有无接管点 / 上限与工具是否具体
手机 · 平板替代：纸质四框图 + 拍照归档；口头复述代替点节点

【对应板块 · 面试讲解与追问防御】
四道必答：Agent vs Chatbot ｜ ReAct 怎么工作 ｜ 什么时候不该用 Agent ｜ 多 Agent 复杂度怎么控
答法骨架：先给结论 → 三条踩分点 → 一个当日术语 → 一个自己项目的例子
追问防御：被追「那怎么落地」就回到接管点 / 步数上限 / 人工确认

【对应板块 · 复盘 · 作品集归档 · 当堂验收】
三句收束 + 三张表归档（术语自测表 / 面试模拟记录表 / 本日作品集积木）
验收四条：四要素标全 · 接管点明确 · 步数上限标注 · 工具清单具体
决策三问：单 Agent 能不能解决 → 要不要 Agent → 要不要多个 Agent
```

## 八、课堂练习参考答案

### 8.1 主项目草图巡视要点（原表保留）

| 检查项 | 合格线 | 常见问题 |
|---|---|---|
| 四要素标全 | 图上有规划 / 记忆 / 工具 / 执行四个模块 | 只画了「LLM + 工具」，漏记忆与执行 |
| 接管点 | 至少标出 1 个「交还人类」的位置 | 全自动闭环，无人接管点 |
| 步数上限 | 标注最大步数或成本上限 | 没有任何上限标注 |
| 工具清单 | 列出 3–5 个具体工具及权限 | 只写「调用工具」四个字 |

### 8.2 对应板块术语小测参考答案（示例 6 题）

| 题 | 答案 | 给分点 |
|---|---|---|
| 缩写全称连线：ReAct | Reasoning + Acting，推理与行动交替 | 全称 2 分 + 中文 2 分 |
| 缩写全称连线：MCP | Model Context Protocol，模型上下文协议 | 全称 2 分 + 中文 2 分 |
| 缩写全称连线：API | Application Programming Interface，应用程序接口 | 全称 2 分 + 中文 2 分 |
| 改错：「Agent 的记忆越多越好」 | 错。记忆要设计写入与遗忘策略，用户可见可删；「会遗忘才是产品设计」 | 判错 2 分 + 说出遗忘策略 3 分 + 说出隐私可见可删 3 分 |
| 改错：「可观测性就是给工程师看的运行日志」 | 错。可观测性是给用户看的步骤清单，属信任设计，不是 debug 界面 | 判错 2 分 + 说出「给用户看」3 分 + 说出「信任设计」3 分 |
| 辨析：「规划」与「固定工作流」 | 工作流路径写死；规划由 Agent 临场拆，故须配步数上限与接管点 | 说出「谁拆步骤」4 分 + 说出「要设上限」4 分 |

### 8.3 对应板块面试评分示例（以「什么时候不该用 Agent」为例）

| 档位 | 标准 | 分值 |
|---|---|---|
| 合格 | 结论明确（不全自动），能说出「路径固定用工作流」「高风险不可逆要人工确认」两条理由 | 18–23 |
| 良好 | 理由含「不可逆动作需人工确认」框架，并给出「AI 建议、人类拍板」的可落地折中方案 | 24–27 |
| 优秀 | 把任务拆成「分析 / 建议 / 决策」三段明确人机分工，或补出成本上限、执行日志留痕与可靠性表述 | 28–30 |

## 九、学员易错点预判与应对（10 条）

| 易错点 | 表现 | 应对 |
|---|---|---|
| 把 Agent 当万能药 | 「我们项目全用 Agent 做」 | 用场景适配判断压回：任务结构固定用工作流，开放式才用 Agent；W3D2 专门练判断，今天先记「先问单 Agent，再问要不要 Agent」 |
| 忽视步数与成本上限 | 架构图里没有任何上限设计 | 讲金句「没有步数上限的 Agent 是在拿用户的 token（用量计费单位）赌运气」；要求草图必须标注最大步数 |
| 忘记设计人工接管点 | 画成全自动闭环 | 讲金句「Agent 产品经理的第一问题：这件事什么时候交还给人类」；要求草图至少标 1 个接管点 |
| 把四要素背成技术名词 | 只会复述 Planning / Memory / Tools / Action | 每要素强制回答「产品经理管什么」，笔记表按此设计，答不出就现场追问 |
| 一上来就设计多 Agent | 简单需求拆 5 个 Agent | 讲「复杂度黑洞」金句与三个隐藏成本；决策原则：两个 Agent 能做的事，别用五个 |
| 把 ReAct 讲成纯技术 | 认为「思考过程展示」是 debug 信息 | 对比黑箱转圈与步骤可见两种体验，落点：思考透明化是信任设计，不是技术日志 |
| **（术语混淆）把 Agent 和 Chatbot 混为一谈** | 面试答「Agent 就是更智能的聊天机器人」 | 对应板块用「交付物 + 责任主体」两栏对比，强制改成「从答题到办事」；术语小测改错题专门考 |
| **（术语混淆）把「规划」说成「固定工作流」、把「可观测性」说成「日志」** | 连线题连错、把用户可见的步骤清单说成给工程师排错用 | 用「谁拆步骤」「给谁看」两个追问当场拆；板书列「易混三组」反复齐读 |
| **（面试失分）答空话、一被追问就卡** | 「更智能」「能自主决策」，追「怎么落地」时沉默 | 统一答法骨架「先结论 → 三踩分点 → 一术语 → 一项目例」；每题都练 2–3 层追问链，落回接管点 / 步数上限 / 人工确认 |
| **（面试失分）英文缩写只背字母、说不出全称与中文** | 说 ReAct、MCP 却答不出全称，显得只会背名词 | 对应板块每个缩写首次出现即给全称 + 中文，术语卡正面只印「全称 + 中文 + 一句话」，小测做连线 |
