## 图 1 · 评审三维评分卡（原有 · 制图规格，已制成）

### 用途与使用方式

- **投屏版**：对应板块讲授三档档位时展示版式，让学员 5 分钟内看懂怎么打分；本课版另在对应板块实操前回切一次。
- **打印版**：A4 横版，每张含 1 个被评组记录区，人手 4 份（3 轮 + 1 份补评 / 备用）；边距 ≥15mm，方便现场快写。
- **数字版**：导出 PNG（Portable Network Graphics，便携式网络图形）附到导学案附录，缺打印件的学员在平板或手机上照填。

### 版式要求

| 区域 | 内容 | 版式说明 |
|---|---|---|
| 顶部 | 标题「评审三维评分卡」+ 被评组编号 + 评审人签名栏 | 标题左对齐，编号与签名右对齐一行排开 |
| 主体 | 三行三列核心区：三个维度 × 「评分框 + 打分依据线」 | 每行左侧维度名，中间 0–5 分勾选框（六个空心方框），右侧一条书写线（≥120mm） |
| 辅助 | 每个维度名下附一行小字追问清单 | 用户价值：谁在用 / 解决什么 / 现在怎么解决；技术可行：数据从哪来 / 调什么能力 / 多久能做；体验：第一次用会不会懵 / 错了怎么办 |
| 底部 | 两条填写区：「我的追问」与「一句话建议」 | 各留两行书写线；行尾小字标注「全员满分 = 评审失败」 |

### 三维度 × 三档描述（打印版卡背附档位说明，投屏版随卡展示）

| 维度 | 2 分及以下 | 3 分 | 4–5 分 |
|---|---|---|---|
| 用户价值 | 答不清谁在用、解决什么，或「所有人都是用户」 | 人群与问题明确，但答不出「用户现在怎么解决」 | 人群具体、问题高频，且能对比现有解法说出差异 |
| 技术可行 | 数据来源说不清，或架构图无四要素标注（画成功能清单） | 调用路径清楚（API / 工作流），但估时缺失或不合理 | 数据来源、调用能力、估时三者齐全且口径合理（按天估） |
| 体验 | 无引导无兜底，演示依赖提前写死的输入 | 有引导或兜底之一，但错误路径未设计 | 首次使用有引导 / 示例 / 默认值，错误有兜底且结果可溯源 |

### 视觉规范

| 项目 | 要求 |
|---|---|
| 品牌色 | 主色紫 #7C3AED（标题、维度名、勾选框描边）；辅色蓝 #2563EB（追问清单小字、底部填写区标签） |
| 底色 | 白底，维度行间隔用 #F1EBFD 浅紫条带；书写线 #A5A1B8 细线 |
| 字体 | 标题 22–24px 加粗，正文与追问小字 12–14px；中文标注无错别字 |
| 禁用项 | 禁 emoji；禁阴影渐变装饰，保持打印黑白复印后仍可辨识 |

### 验收标准

- 三维度齐全，每维度附追问清单小字，与 01-教案提问设计逐字一致。
- 三档描述具体可操作（见上表），复印 grayscale 后文字与勾选框仍清晰。
- A4 横版单页放下，含底部两条填写区，不出现第二页。
- 投屏 720p 下最小字号可读；导出 PNG（Portable Network Graphics，便携式网络图形）≤1MB。

### 讲法脚本（原有，对应板块 / 对应板块任务说明时配合投屏，约 90 秒）

「这张卡就是你们今天的评审工具。三个维度从上到下：用户价值、技术可行、体验。每个维度 0 到 5 分，六个格子，你在对应分数上打勾，右边必须写一句打分依据——只打勾不写依据的，表不算交。卡背有三档描述，打分前先对一眼：比如用户价值那行，答不出『用户现在怎么解决』的，最高 3 分。最底下两条必填：一条追问、一句话建议。建议禁写『继续完善』——要写到能直接进对方的迭代计划里。」

### 图 2 · Agent 四要素架构图（原有 · 复用）讲法脚本

「对照这张图看刚才那组的『架构图』：规划、记忆、工具、执行四个要素，缺一个都不叫架构图，叫功能清单。反例点评时用这张图做对照标尺，一句话即可，不展开讲。」

- 结论前置：原型评审 I 不是「演示好不好看」，而是「这套设计能不能安全进入 PRD 阶段」的门禁。评审只问三件事——流程是否闭环、异常是否有去处、代价是否算得清。
- 里程碑 ② 定位表：
- | 项 | 结论 |
