## 二、原型 V1.5 验收清单（学员自查表）

> 用法：周末提交综合输出前逐项自查；助教按「核验方式」列逐项复核。任何一项不通过，V1.5 不算提交。

### 1. 架构图完整（四要素标注）

| 验收要求 | 核验方式 |
|---|---|
| Agent 架构图标注规划 / 记忆 / 工具 / 执行四要素，每个要素写明产品职责一句话 | 助教对照 Agent 四要素架构图逐格指认，四格齐全且各有职责说明；缺任一格 = 不通过 |
| 图中体现「用 Agent 还是用工作流」的判断依据（哪里需要自主规划、哪里固定流程） | 学员口头 30 秒说明判断依据，助教记录；答不出 = 不通过 |

### 2. 工作流可运行

| 验收要求 | 核验方式 |
|---|---|
| Dify / Coze 工作流可实际运行，非截图壳 | 助教提供一条非演示用真实输入，学员现场执行，端到端出结果；中途断链 = 不通过 |
| 失败路径有兜底（错误提示或降级话术，不白屏不静默） | 助教故意输入一条超出知识范围的问题，验证兜底表现；白屏或硬编 = 不通过 |

### 3. 知识库非空壳（≥20 份真实文档）

| 验收要求 | 核验方式 |
|---|---|
| 知识库文档数 ≥20 份，且与项目主题真实相关 | 助教进入后台清点文档数；随机抽 3 份打开核对内容与主题相关性；凑数文件（无关 / 重复 / 空文档）不计入 |
| 文档有生效日期与责任人字段（更新机制雏形） | 抽查任 1 份查看元信息；无字段 = 不通过 |

### 4. 迭代计划含推翻项与时间点

| 验收要求 | 核验方式 |
|---|---|
| 推翻项 ≥1 条，写明「推翻什么、为什么」 | 助教逐条核对；推翻项缺失或只写「继续完善」 = 不通过 |
| 本周改 ≤3 条，每条带具体日期（精确到日） | 逐条查日期字段；「下周」「尽快」字样 = 不通过 |
| 保留项 ≥1 条（这版要守住的判断） | 有记录即可，无字数要求 |

## 三、验收档位与处理

| 档位 | 判定标准 | 处理 |
|---|---|---|
| 通过（里程碑 ② 达成） | 四大项全部通过 | 进入周末综合输出打包；优秀计划可作下期范本 |
| 有条件通过 | 仅第 3 项文档份数 15–19 份，其余全过 | 周一 12:00 前补齐到 20 份，逾期按未提交计 |
| 退回 | 第 1、2、4 项任一不通过 | 按迭代计划返工，助教周一跟进，重验时间由讲师指定 |
