四、设计背景学员转译提示

  • 视觉传达同学：PRD 的「功能描述 + 状态说明」就是设计规范文档（Design Spec）的产品版——你写过按钮的 normal / hover / disabled 三态，PRD 里写的是功能的三种情况。
  • 环境设计同学：PRD 的异常兜底 ≈ 施工图的节点大样图——正常做法之外，还要交代特殊情况怎么处理。你早就有「画大样」的思维。
  • 动画同学：分镜脚本的「帧间过渡」就是 PRD 的「状态流转」——A 状态到 B 状态之间发生什么，你写过成百上千次。
  • 共同提示：面试官常问「你的 PRD 被评审挑战过哪一条」——P4 的意见闭环表就是直接答案，这正是设计评审（design review）教过你的生存技能。

五、手机 / 平板可行路径（🟡 归档动作移动端可完成）

  1. PRD 长文档在 W4 课内已用电脑完成——归档不需要重写 PRD。
  2. 手机动作：复制 PRD 链接进 P4、截 PRD 结构截图（用手机放大文档逐屏截图或直接用目录页截图）、填写意见闭环表（手机表格）。
  3. 四段式「方案」段更新：手机文档改 150 字。
  4. 罗思蕊通道：本块全部归档动作手机可完成；唯一建议是用平板预览一遍 PRD 排版在手机上的显示效果。

六、常见问题

  • Q：PRD 评审被批得最狠的一页要不要放出来？ A：要。「被批 → 修改 → 通过」的闭环是 P4 最有说服力的部分；只放光鲜版本反而显得没经历过真实评审。
  • Q：用户研究报告和 PRD 都放会不会太长？ A：P4 只放链接和摘要卡，全文在附件层——作品集页面保持 3 分钟可读完，深度材料供面试官自愿下钻。
