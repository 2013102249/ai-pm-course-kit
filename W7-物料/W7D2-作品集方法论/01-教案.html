教案 · W7 周二《作品集方法论》

AI 产品经理就业训练营 · 第七周第二天 · 90 分钟（2 课时）· 讲师版

一、基本信息

项目 内容
所属阶段 阶段四 · 实战与就业（Week 7）

二、教学目标（可测量）

  1. 能说出作品集三种形态（项目复盘文档 / 在线演示 / 产品分析集）的定位差异，并根据自身背景在决策表上选定「一主一辅」组合，且给出两条理由（对应课堂决策表 + 习题第一层）。
  2. 能将一段平庸项目经历改写为符合 STAR 法则且含对比数字的版本：S 一句话、T 可量化、A 写决策、R 有基准值到结果值（对应课堂改写练习 + 习题第二层改写题）。
  3. 能按六节模板（背景 / 目标 / 我的角色 / 关键决策与取舍 / 数据结果 / 反思与迭代）完成主项目深度复盘文档初稿，数据结果节含至少 3 组「基准值→结果值」数字并标注来源（对应写作工作坊产出）。

三、教学重难点

  • 重点：STAR 逐字母写作规范——Situation 一句话、Task 可量化、Action 写决策不写流水账、Result 必须有数字。
  • 难点一：Action 与「岗位说明书」的边界。学员默认写「负责了什么」，正确写法是「决策了什么、放弃了什么、为什么」。
  • 难点二：数据呈现的对比意识。学员易只写绝对值（「引用正确率 90%」），缺基准值后数据失去说服力；本课用三原则（对比才有意义 / 图表选型 / 标注来源）纠正。

六、作品集三种形态选择决策（教案重点）

6.1 三形态定位表

形态 定位 核心内容 阅读者是谁 最佳使用场景
项目复盘文档 深度证明 背景 / 目标 / 我的角色 / 关键决策与取舍 / 数据结果 / 反思与迭代 面试官、内推人 面试前置材料；项目深挖环节的追问防御；简历项目段的弹药库
在线演示 直接证明 可访问的 MVP 链接 + 30 秒演示脚本 + 引导语 HR、面试官 简历作品集链接；面试现场「打开看看」；降低「描述与实物不符」的怀疑
产品分析集 思维证明 2–3 篇结构化产品拆解（目标用户 / 核心场景 / 关键功能 / 数据表现 / 我的改进假设） 面试官、行业同行 项目经验不足时的补充；证明方法论可迁移；建立行业话语权

6.2 按背景选型的决策表

学员背景 主形态 辅形态 决策理由
应届 / 学生 项目复盘文档 产品分析集 项目数量少，用单项目深度补经验短板；分析集展示潜力与思维结构，弥补「没上过岗」的信任缺口
转行 项目复盘文档 + 产品分析集 在线演示 面试官最大疑虑是「能不能干产品的活」：复盘证明闭环能力，分析集证明原行业经验可迁移；演示链接作为第三方佐证
在职 / 进阶 在线演示 项目复盘文档 有真实业务与在职背书，可访问的演示最直接可信；复盘文档用于面试深挖时展示决策深度

6.3 一句话决策口诀

应届靠深度，转行靠迁移，在职靠实物——每种背景都要有「一份主形态 + 一份辅形态」，单选是赌运气。

七、STAR 逐字母教学要点（教案重点）

字母 写作规范 合格标准 典型错误
S · Situation 一句话背景，只交代约束条件 ≤40 字，含「行业 / 场景 / 核心矛盾」三要素 写成 200 字创业故事；背景讲 5 分钟还没到自己
T · Task 可量化的目标与范围 含「从几到几 / 多大规模 / 什么周期 / 什么指标」 「负责知识库产品」——无范围无目标，无法推出可验证的 R
A · Action 写决策不写流水账 每条能回答「为什么这么做、放弃了什么」；写 2–3 条关键决策而非 8 条日常工作 写成岗位说明书（负责调研、写 PRD、跟开发）；全是「我们」看不到「我」
R · Result 必须有数字，且必须有对比 「基准值→结果值 + 时间范围」，如「引用正确率从 71% 提升至 90%」 形容词堆砌（效果显著、广受好评）；只有绝对值没有基准；把团队成果写成个人成果不注明角色

改写前后对比（教学示例，学员改写时替换为真实数据）

版本 内容 问题诊断
平庸版 「负责了知识库产品的设计和开发，学到了很多。」 无 S（什么场景）、无 T（什么目标）、A 是职责罗列、R 是感受不是结果
优秀版 「主导 XX 知识库从 0 到 1：完成 32 次用户访谈定位答非所问主因，设计分块+重排方案使引用正确率从 71% 提升至 90%，上线两周服务 340 次真实咨询。」 S 藏在一句话里，T 是「从 0 到 1」，A 是两个关键决策，R 有三组带基准的数字

八、数据呈现三原则（教案重点）

原则 规范 反例 改法
① 对比才有意义 任何数字必须带基准值、竞品值或目标值 「引用正确率 90%」——高还是低无从判断 「引用正确率从 71% 提升至 90%（上线两周）」
② 图表选型 一图一结论；趋势用折线、对比用条形、构成用堆叠；不使用立体与 3D 效果 立体饼图 12 个分块，读者找不到重点 横向条形图，只保留 Top 5，结论写在标题里
③ 标注来源 每个数字可被追问：写在哪个图表、哪份报告、什么时候测的 数字凭空出现，面试官一问「怎么测的」就卡壳 数字后加来源脚注，如「数据来源：W6 测试报告 · 12 人三轮评测」

九、课堂提问设计（7 问）

# 提问 提问时机 预设答案 / 引导方向
1 「屏幕上这两段复盘写的是同一个项目，为什么面试官只会约谈第二个？」 导入 第二段有数字、有决策、有角色、可验证；第一段只有职责和感受，面试官无法判断能力，也无法追问
2 「三种形态里，哪一种最能让面试官在 3 分钟内判断你的产品能力？」 环节一 复盘文档——信息密度最高，同时看到思路、动作、数据、反思；但要强调三形态是组合不是单选
3 「STAR 四个字母里，哪两个最容易被写废？」 环节二开头 A 和 R——A 写成流水账或岗位说明书，R 写成形容词没有数字
4 「Situation 为什么必须压到一句话？」 S 卡片 背景只用来交代约束条件，不是讲故事；背景冗长会挤占 A 和 R 的空间，面试官 3 分钟看不到重点就翻页了
5 「『负责知识库产品』这个 T 为什么不合格？」 T 卡片 不可量化——没有范围、规模、周期、指标，推不出可验证的 Result；改法：「从 0 到 1 主导 8 周上线，目标引用正确率 85% 以上」
6 「如果 Result 的数字不好看，比如正确率只从 68% 提到 74%，还能写吗？」 R 卡片 能写——有诚实基准的改进也是结果，可补一条「归因 + 迭代计划」体现思考深度；一票否决的是造假，不是数字小
7 「把团队成果写成个人成果，最大的风险是什么？」 A 卡片 面试官追问细节立刻穿帮（「这个方案当时谁提的？为什么不用另一条路？」）；正确做法是写清角色：「团队 4 人，我负责检索与重排方案」

十、板书要点

作品集 = 让能力可验证
三种形态：复盘文档（深度）+ 在线演示（实物）+ 产品分析集（思维）
选型口诀：应届靠深度，转行靠迁移，在职靠实物

S 一句话：行业 + 场景 + 核心矛盾（≤40 字）
T 可量化：从几到几 / 多大规模 / 什么指标
A 写决策：为什么这么做，放弃了什么（不写岗位说明书）
R 有数字：基准值 → 结果值 + 时间范围

数据三原则：对比才有意义 / 一图一结论 / 数字可追问

十一、学员易错点预判与应对（5 条）

# 易错点 典型表现 应对动作
1 Result 写了形容词没写数字 「效果显著」「广受好评」「学到了很多」 强制规则：每条 Result 必须含「基准值→结果值」；互审环节专查数字，无数字直接打回重写
2 Action 写成岗位说明书 「负责需求调研、PRD 撰写、跟进开发上线」 教「决策过滤器」：每条 Action 必须能回答「为什么这么做、放弃了什么」；删掉所有换个人也能写的句子
3 把团队成果写成个人成果不注明角色 全篇「我们」，或把 4 人团队的指标写成个人成绩 六节模板强制设「我的角色」节；用追问测试：面试官问「这个数字里你贡献了哪部分」你答得上吗
4 数据只有绝对值没有对比基准 「引用正确率 90%」 三原则第一条当堂纠正；要求全部改写为「从 X% 提升至 Y%」格式，并列出基准来源
5 复盘写成工作总结，只有成功没有取舍 通篇「完成了什么」，没有「放弃了什么、哪里做错了」 模板中「关键决策与取舍」「反思与迭代」两节强制填写；提醒学员：面试官最想看的就是这两节，全是成功叙事反而显得没做过事
