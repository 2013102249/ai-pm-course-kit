## 二、教学目标（可测量）

1. 能用三维定题法把选题表述为「行业 × 场景 × 人群」的一句话，三环均有明确限定词，不带「万能」「所有」「一站式」类泛化词。**验证**：导学案《选题卡》三环格均填入具体名词，讲师逐环点检通过。
2. 能用四维评分卡（技术 / 数据 / 合规 / 竞争，各 0–5 分，单维 ≥3 分且总分 ≥12 分为及格线）给自己选题打分，且每一维至少写出 1 条扣分理由。**验证**：立项报告第五章贴入四分数 + 总分 + 每维扣分理由，数据维写明具体来源。
3. 能按六章结构完成立项报告并通过讲师评审；未过者按返工机制当天修订重交。**验证**：里程碑 ① 验收表「三环 / 指标 / 自评 / 风险」四项均判「通过」。
4. **（术语目标）** 能准确复述并辨析本日 12 个核心术语的一句话定义，且能指出每个术语最易混淆的相邻概念。**验证**：《术语自测表》≥10/12 填写正确，能口头说清「Scope 与功能清单」「MVP 与半成品」「里程碑与验收标准」三组区别。
5. **（Scope 目标）** 能用 Scope 边界把三环锁死的选题再砍一刀，圈出 MVP 首版范围。**验证**：立项报告「核心场景 1–3 个」之外，另写出 ≥2 条「首版不做」清单，每条附「为什么暂不做」的理由（优先级 / 资源约束 / 风险）。
6. **（面试目标）** 能就「你怎么立的项」「为什么先做这个功能」「Scope 怎么砍」「可行性怎么评估」四类问题做 60 秒标准答法，并扛住 2 层追问。**验证**：两两模拟后《面试模拟记录表》自评 ≥及格，答法含 ≥1 个当日术语，且不出现「老板定的 / 随便排的 / 感觉能做」等失败答法特征。
7. **（作品集目标）** 能把当日立项报告归档进作品集 P2 页，并说清它与 W1（P1 起点页）、W6（P6 成品页）的衔接关系。**验证**：《本日作品集积木》表填全产出物 / 完成度 / 归档位置，归档位置写明 `W2-P2-立项页-姓名` 与草稿文档 `姓名-AI产品作品集-V1`。

## 三、教学重难点

- **重点一**：三维定题法——「行业 × 场景 × 人群」三环交集，好选题是交集里长出来的，不是脑子里想出来的。
- **重点二**：可行性四维评分卡——用打分把「感觉靠谱」变成「有据可查」。
- **重点三（新增）**：Scope 边界与 MVP 首版——三环锁死只说明「题目清楚了」，还要用范围边界把「能做的」收成「首版只做的」，用优先级给出「暂不做」的判据。
- **难点一**：三环收缩。学员第一反应几乎都是大而全（「万能 AI 助手」），要学会用限定词逐环收缩。
- **难点二**：诚实自评。学员倾向四维全打 5 分回避问题，要强制「每维至少扣 1 分并写理由」。
- **难点三（术语混淆）**：12 个术语里「Scope / MVP / 里程碑 / 验收标准」四词连环混——学员把「范围」当成「功能清单」，把「MVP（最小可行产品）」当成「做一半的半成品」，把「里程碑」和「验收标准」前后颠倒。第 1 节须用生活类比 + 易混辨析逐组拆开。
- **难点四（面试失分）**：面试答立项只讲结果、不讲取舍，被追问「为什么先做这个功能」「Scope 怎么砍」时答「老板定的」「先做简单的」「随便排的」，直接丢掉「产品判断力」这一得分点。第 5 节须用追问链与失败答法对照纠正。

## 六、课堂提问设计（22 问：核心 7 + 术语辨析 8 + 面试追问 7）

### 甲 · 原核心提问（7 问，保留）

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 「往届那个『万能 AI 助手』为什么失败？」 | 第 2 节导入 | 没有具体人群和场景，三环全是空气：做不完、评不了、卖不动；好选题要把三环全部锁死 |
| 2 | 「行业、场景、人群三环里，哪一环最先收缩？」 | 第 2 节三维定题 | 通常先锁行业（学员在 W1D5 已定主赛道），行业定了场景和人群的搜索空间立刻缩小 |
| 3 | 「为什么选题必须绑定自己的主赛道，不能随便挑个热门方向？」 | 第 2 节三维定题 | 项目要贯穿 W3–W6 直到面试：赛道一致才有行业纵深，简历、作品集、面试谈资才是一个整体；换热门赛道等于放弃已积累的行业认知 |
| 4 | 「四维里哪一维打不及格，必须换题或改题，不能带病立项？」 | 第 3 节四维评分 | 合规维。技术弱可以降范围，数据缺可以自建，但合规硬伤（如无资质做医疗诊断建议）没有补救空间，国内上线直接过不了备案 |
| 5 | 「及格线为什么定单维 ≥3、总分 ≥12，而不是鼓励越高越好？」 | 第 3 节四维评分 | 评分目的是暴露短板不是追求完美分；单维 <3 说明有致命短板，总分低说明整体存疑；诚实的 13 分比虚高的 20 分更有价值 |
| 6 | 「『用户很喜欢我们的产品』算成功指标吗？怎么改？」 | 第 3 节立项报告 | 不算，不可测量。改成可量化表述，如「试用用户 7 日留存 ≥40%」「答疑准确率 ≥90%（评测集 ≥50 条）」 |
| 7 | 「3 分钟陈述里，最不该被省掉的是哪一部分？」 | 第 4 节评审工作坊 | 风险与对策。评审官最想听的不是你多有信心，而是你知不知道自己会死在哪、怎么不死 |

### 乙 · 术语辨析提问（8 问，第 1 节）

| # | 提问 | 预设答案 / 辨析方向 |
|---|---|---|
| 8 | 「立项和『想个点子』最大的区别是什么？」 | 立项是把想法写成经得起质询的承诺：要有目标用户、成功指标、风险对策并过评审；点子只是想法 |
| 9 | 「Scope（范围边界）和『功能清单』是同一件事吗？」 | 不是。功能清单只列「做什么」，Scope 还要写清「不做什么」和边界在哪；本日首版不做清单就是 Scope 的落地 |
| 10 | 「MVP（最小可行产品）是『做一半的半成品』吗？」 | 不是。MVP 是能完整跑通核心场景、可交付可验证的最小版本，不是没做完；判断标准是「能不能拿去验证成功指标」 |
| 11 | 「里程碑和验收标准，哪个在前、哪个在后？」 | 里程碑是时间点 / 阶段节点（本日是里程碑 ①），验收标准是该节点「做到什么才算过」的判据；先有节点，再给判据 |
| 12 | 「风险清单和『问题清单』有什么区别？为什么每条风险必须配对策？」 | 风险是「还没发生但可能发生」的坏事，问题是「已经发生」的；清单必须配对策，否则只是担忧不是预案 |
| 13 | 「资源约束里，时间、设备、数据三样，哪一样最容易被零基础学员忽略？」 | 数据。学员常写「用公开数据」却指不出具体来源；数据维在评分卡里有硬规则：写不出具体来源该维最高 2 分 |
| 14 | 「『目标用户』和『问题陈述』，为什么都不能写成『所有人』？」 | 目标用户要「可触达的一类人」，问题陈述要落在具体场景的具体痛点；写成「所有人」等于没有画像、没有痛点，后续评测集与试用都建不起来 |
| 15 | 「优先级和三维定题的『人群环』有什么关系？」 | 优先级是给同类需求排序，判据来自人群痛点强度与资源约束；人群环锁得越死，优先级越容易排，因为只服务一类人的一类痛 |

### 丙 · 面试追问提问（7 问，第 5 节）

| # | 提问 | 预设答案 / 引导方向 |
|---|---|---|
| 16 | 「面试官问『你怎么立的项』，第一句该给结论还是过程？」 | 先给结论框架（三环 / 四维 / 报告六章三选一），再展开判据，最后补一句成熟观点；不要从「我当时先想了很久」讲起 |
| 17 | 「被追问『为什么先做这个功能而不是别的』，你拿什么当判据？」 | 拿优先级判据：人群痛点强度 × 高频 × 可验证 × 资源约束；并说清「暂不做的」为什么排后 |
| 18 | 「『Scope 怎么砍』被连追两层：砍掉的功能以后怎么向用户交代？」 | 第一层答砍的依据（MVP 只保留跑通核心场景的最小集）；第二层答砍后的交代：写进「首版不做清单」、给触发条件（何时补）、给兜底话术 |
| 19 | 「『可行性怎么评估』答完四维后，追问『合规不达标你怎么办』？」 | 合规是硬门槛，没有补救空间：换题或改题，不能带病立项；技术弱可降范围、数据缺可自建，唯独合规不行 |
| 20 | 「问『这个选题为什么是现在做』，答『技术成熟了』够不够？」 | 只算及格。要补行业层面的时机证据：用户习惯被教育完成、新的合规要求或成本压力出现、大模型能力刚好跨过门槛 |
| 21 | 「行为题『立项被否你怎么改的』，失败答法是什么？」 | 失败答法：说「评审没眼光 / 我随便改了改」；正确答法是给「被否的具体一项 → 我怎么收缩 / 补数据来源 → 复审通过」的可验证链条，返工记录本身就是作品集素材 |
| 22 | 「『成功指标怎么定的』被追问『没达标算不算失败』？」 | 不算失败，算「暴露短板」；指标要可测量、有数字、有期限，未达标要有归因（提示词 / 资料 / 模型 / 需求四类）与下一步，诚实的未达标比「效果很好」值钱 |

          PRD=Product Requirements Document 产品需求文档

【第 2 节 · 核心原理讲授 A】
选题定生死：方向错了，执行越快死得越快
三维定题 = 行业 × 场景 × 人群（三环交集）
  行业：我懂的赛道（W1D5 已锁）  场景：高频 · 具体 · 有痛点  人群：可触达的一类人

Scope 边界：三环锁死后再砍一刀 → MVP 首版只做 1 个核心场景
  首版不做清单 = 写清「暂不做什么」+ 为什么 + 何时补

【第 3 节 · 核心原理讲授 B】
四维评分卡（各 0–5 分，满分 20）
  技术：现有模型能力够不够  数据：训练 / 评测数据从哪来（写不出来源 ≤2 分）
  合规：备案 · 内容安全 · 个人信息（硬门槛）  竞争：差异化在哪
  及格线：单维 ≥3 且总分 ≥12

评审工作坊：3 分钟陈述 + 2 分钟质询，重点压「指标」与「风险」
Scope 砍范围实操：把「首版不做清单」写进报告
手机 / 平板替代：一段一屏写六章、逐条文字互评、录音替代陈述

【第 5 节 · 面试讲解与追问防御】
四问：你怎么立的项 / 为什么先做这个功能 / Scope 怎么砍 / 可行性怎么评估
每题 5 项：题目+题型 · 踩分点 · 追问链 · 失败答法 · 60 秒标准答法
防御原则：先结论框架，再判据，最后补成熟观点

【第 6 节 · 复盘 · 作品集归档 · 当堂验收】
三句收束：三环锁题 / 四维验题 / 六章写下来并砍出 Scope

### 3. 术语小测参考答案（第 1 节当堂小测，新增）

| 题 | 参考答案 | 给分点 |
|---|---|---|
| 填「一句话定义」：Scope | 项目「做什么、不做什么」的边界 | 出现「不做什么 / 边界」即满分；只写「功能列表」不给分 |
| 填「一句话定义」：MVP | 能跑通核心场景、可验证的最小版本 | 出现「最小 + 可验证」满分；答「半成品」不给分 |
| 辨析：里程碑 vs 验收标准 | 里程碑是阶段节点，验收标准是该节点「算不算过」的判据 | 说出「节点 / 判据」前后关系满分 |
| 辨析：风险清单 vs 问题清单 | 风险未发生、问题已发生；风险必须配对策 | 两点各半分 |

| 缩写：写出 MVP 全称与中文 | Minimum Viable Product，最小可行产品 | 全称、中文各半分 |
| 连线：合规维 ↔ 硬门槛 | 合规低于 3 分必须换题 / 改题 | 连对并说出「无补救空间」加分 |
| 简答：优先级判据从哪来 | 人群痛点强度 × 高频 × 可验证 × 资源约束 | 写出 ≥2 个判据满分 |

## 九、学员易错点预判与应对（10 条：原 6 + 术语混淆 2 + 面试失分 2）

| 易错点 | 表现 | 应对 |
|---|---|---|
| 选题太大 | 「万能助手」「一站式 AI 平台」类表述，三环全空 | 用第八节收缩演示现场改一例；要求学员逐环加限定词，每个环至少 1 个具体名词 |
| 选题没有数据来源 | 说不出训练 / 评测数据从哪来，写「用公开数据」却指不出哪个公开数据集 | 给数据三来源清单：公开数据集、业务方 / 自建整理、模型合成；要求数据维打分时必须写明具体来源，写不出即视为该维 ≤2 分 |
| 选题与赛道脱节 | W1D5 定了金融赛道，今天突然想做教育选题（觉得「更好做」） | 回扣主线项目逻辑：项目贯穿到面试，赛道一致才有行业纵深；确需调整的，须说明在主赛道内的关联理由并由讲师单独确认 |
| 成功指标写成感觉 | 「用户很喜欢」「体验好」 | 提问 6 现场改写；给 SMART（具体 / 可衡量 / 可达成 / 相关 / 有时限）口诀：可测量、有数字、有期限；模板中指标栏预置示例格式 |
| 四维自评全打满分 | 规避短板，评分卡写不出扣分理由 | 强制规则：每维至少写 1 条扣分理由，写不出扣分理由的维度由讲师默认按 5 分重审其选题难度 |
| 忽视合规维 | 认为合规是「上线以后的事」 | 回扣 W2D4 合规检查清单；用提问 4 讲清合规是硬门槛：备案、内容安全、个人信息三查不过，项目直接不可立项 |
| **（术语混淆）把 Scope 当功能清单 / 把 MVP 当半成品** | 报告里列了 8 个功能却写不出「首版不做」；说「MVP 就是先做个半成品」 | 第 1 节用「装修合同写明不含哪些房间」类比 Scope；用「先上一道能完整点单结账的菜，不是端半盘菜」类比 MVP；要求报告必附 ≥2 条首版不做清单 |
| **（术语混淆）里程碑与验收标准颠倒** | 把「W6 上线」当成验收标准，把「准确率 ≥90%」当成里程碑 | 板书并列两列：里程碑=节点（里程碑 ① 今天 / W6 上线），验收标准=判据（三环锁死 / 指标可测 / 四维诚实 / 风险有对策）；用提问 11 当场对调纠正 |
| **（面试失分）只讲结果不讲取舍** | 答「你怎么立的项」只说「我做了个招生答疑知识库」，被追问「为什么先做这个功能」答不上来 | 第 5 节强制「结论框架 + 判据 + 成熟观点」三段式；用面试评分示例逐项打分，逼出优先级判据 |
| **（面试失分）用「老板定的 / 随便排的」答排序题** | 「Scope 怎么砍」答「先做简单的」「老板让做啥做啥」 | 用失败答法对照 + 追问链示范：砍的依据是「MVP 只保留跑通核心场景的最小集」，并给砍后的触发条件与兜底话术 |
