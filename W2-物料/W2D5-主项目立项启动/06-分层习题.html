分层习题 · W2 周五《主项目立项启动（里程碑 ①）》

AI 产品经理就业训练营 · 第二周第五天 · 300 分钟（6 课时 × 50 分钟）· 习题册
五层难度：第 0 层 术语辨析（概念入口）→ 第 1 层 基础巩固 → 第 2 层 进阶实操 → 第 3 层 求职挑战 → 第 4 层 面试实战。
本课考点：选题可行性评估 + 三维定题 + Scope 边界 + 立项报告六章 + 面试防御。
建议用法：第 0 层随第 1 节当堂测 10 分钟；第 1 层当堂测；第 2 层作第 4 节实操与周末作业；第 3 层自测、第八周面试课复用；第 4 层随第 5 节两两模拟使用。
所有题目附参考答案与评分标准；题干中的选题、学员、数据均为教学示例，不出现真实学员姓名，不编造 offer / 薪资 / 就业率数据（涉及处写「待教务补充」）。
手机 / 平板：第 0、1 层可直接在手机上作答；第 2 层第 13 题本身就是设备替代方案设计题，按导学案第 4 节「设备档位与替代动作」执行即可。

第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错 / 填空四种题型）

一、选择题（每题 5 分，共 20 分）

T1. 关于「立项」，下列说法正确的是：
A. 立项就是想出一个好点子
B. 立项是把想法写成经得起质询的书面承诺，含目标用户、成功指标、风险对策并过评审
C. 立项等于开工，通过就可以直接写 PRD
D. 立项只是上线前补的一份文档

T2. 关于「Scope（范围边界）」，最准确的是：
A. 把所有要做的功能列成一张清单
B. 只写「做什么」，不写「不做什么」
C. 同时写清「做什么」和「不做什么」，并给圈外需求一个去处与回来的条件
D. 范围列得越大越显专业

T3. 判断一个版本是不是 MVP（最小可行产品），唯一标准是：
A. 功能数量最少
B. 开发时间最短
C. 能不能完整跑通一个核心场景、并拿去验证成功指标
D. 界面做得最简

T4. 关于里程碑与验收标准，正确的是：
A. 里程碑是「算不算过」的判据，验收标准是「到哪一站」
B. 里程碑是阶段节点，验收标准是该节点「做到什么才算过」的判据
C. 两者是同一个词的两种说法
D. 成功指标就是验收标准

配合第 5 节「面试讲解与追问防御」两两模拟使用。每题评分表合计 10 分；参考答案见文末「第 4 层参考答案」。

M1 · 你怎么立的项？从头讲一遍。（项目深挖）

项目内容
题目 + 题型「你怎么立的项？从头讲一遍。」（项目深挖）
踩分点① 先给结论框架（三维定题 / 四维评分 / 六章报告任一，说得出名字）3 分；② 展开 ≥2 条可验证判据（行业锁主赛道、人群可触达、数据有来源）3 分；③ 提到评审、里程碑 ① 锁定、此后不换题 2 分；④ 用上 ≥1 个当日术语且 60 秒内收口 2 分
追问链L1「三环里你先锁哪一环，为什么？」→ 先锁行业（W1D5 已定），搜索空间立刻缩小；L2「人群可触达，今天能约到几个访谈？」→ 给具体渠道与数量，说不出就承认短板并给补齐动作；L3「被评审打回过吗？改了什么？」→ 给被否的具体一项 + 修改动作 + 复审通过，返工记录进作品集复盘段
评分表框架 3 □ / 判据 3 □ / 里程碑 2 □ / 术语与收口 2 □ = ____ /10
失败答法「我先是想了很多方向，后来觉得教育好做就定了，做着做着就清楚了。」失分原因：无框架、无判据、全是感觉，坐实「不会提需求」

M2 · 为什么先做这个功能，而不是别的？（场景设计 / 项目深挖）

项目内容
题目 + 题型「首版为什么先做这个功能，而不是别的？」（场景设计 / 项目深挖）
踩分点① 先亮优先级判据（痛点强度 × 高频 × 可验证 × 资源约束）3 分；② 说明首版功能能跑通核心场景并验证一条成功指标 3 分；③ 说清「暂不做的」为什么排后 2 分；④ 用上 Scope / MVP 术语 2 分
追问链L1「换一个功能先做，差在哪？」→ 差在验证不了核心指标、拉长反馈周期；L2「老板坚持先做另一个呢？」→ 用判据对齐、给最小试错成本、保留兜底，不硬顶也不盲从；L3「数据不好，怎么判断是功能选错还是指标定错？」→ 先回看指标是否可测量，再按提示词 / 资料 / 模型 / 需求四类归因
评分表判据 3 □ / 核心场景与指标 3 □ / 暂不做的理由 2 □ / 术语 2 □ = ____ /10
失败答法「先做简单的，复杂的留给后面 / 老板让做啥做啥 / 随便排的。」失分原因：把优先级等同于开发难度或行政指令，没有自己的产品判断

M3 · Scope 怎么砍？砍掉的功能以后怎么交代？（项目深挖 / 场景设计）

项目内容
题目 + 题型「Scope 怎么砍？砍掉的功能以后怎么向用户交代？」（项目深挖 / 场景设计）
踩分点① 定义 Scope = 做什么 + 不做什么 2 分；② 砍的判据是「只保留跑通核心场景的最小集（MVP）」3 分；③ 落地成首版不做清单并给触发条件 3 分；④ 给砍后交代（兜底话术 / 何时补 / 进需求池 / 变更记录）2 分
追问链L1「砍到什么程度算到位？」→ 以「能否验证成功指标」为界；L2「被砍的功能用户点名要？」→ 记录进需求池、给兜底话术与触发条件，不临时加塞破坏时间盒；L3「六周里 Scope 会变吗？」→ 会，但每次变更留记录，回扣立项报告与 W6 回填
评分表定义 2 □ / 判据 3 □ / 清单与触发条件 3 □ / 交代机制 2 □ = ____ /10
失败答法「能砍多少砍多少，先上线再说 / 全砍到只剩一个按钮 / 没想过砍。」失分原因：要么把砍范围当偷工减料，要么没有边界意识

M4 · 可行性怎么评估？合规不达标怎么办？（技术理解）

项目内容
题目 + 题型「可行性怎么评估？合规不达标你怎么办？」（技术理解）
踩分点① 四维名称与各自判据（技术 / 数据 / 合规 / 竞争）3 分；② 及格线数字（单维 ≥3、总分 ≥12）2 分；③ 数据来源硬规则（写不出具体来源该维 ≤2）2 分；④ 合规是硬门槛、无补救空间、必须换题或改题 3 分
追问链L1「技术维只有 2 分，还立不立？」→ 不能带病，先缩小 Scope 或回三维收缩重打分；L2「写『用公开数据』够吗？」→ 不够，要指名具体数据集 / 自建 / 合成，否则压到 ≤2；L3「四维都过了就一定做成？」→ 不保证，评估是暴露短板不是发奖状，后续靠评测集与里程碑持续验
评分表四维 3 □ / 及格线 2 □ / 数据规则 2 □ / 合规硬门槛 3 □ = ____ /10
失败答法「四维都打 5 分，说明选题完美 / 合规上线前再补就行。」失分原因：全满分暴露自评不诚实，把合规当可补项直接踩红线

M5 · 这个选题为什么是现在做？为什么用 AI？（场景设计）

第 4 层 · 面试实战（每题 60 秒标准答法要点 + 评分表用法）

评分表用法：按每题 4 个踩分点逐项打勾计分，合计 10 分；≥8 分优秀、6–7 分良好、5 分及格、≤4 分需重练。两两模拟时，答完先自评，再由同伴按踩分点复评，差异处回看「失败答法」。

M1 参考答案要点（60 秒）：「三步：三维定题锁行业 × 场景 × 人群，三环都带具体名词；可行性四维打分，技术 / 数据 / 合规 / 竞争各 0–5 分，单维 ≥3、总分 ≥12，数据维必须指名来源，合规是硬门槛；写成六章立项报告，过评审锁定里程碑 ①，此后不换题。体会：评估是暴露短板不是发奖状，诚实的 13 分比虚高的 20 分值钱。」（含术语：三维定题、可行性四维、里程碑、合规硬门槛）

M2 参考答案要点（60 秒）：「排优先级用四个判据：痛点强度 × 高频 × 可验证 × 资源约束。首版只做能跑通核心场景、能挂评测集验证一条成功指标的那个功能；其余写进首版不做清单，注明优先级低 / 合规风险未摸清，等触发条件满足再补。Scope 不是列功能，是敢写清这一版不做什么。」（含术语：优先级、Scope、MVP、成功指标）

M3 参考答案要点（60 秒）：「砍的判据只有一条：MVP 必须完整跑通一个核心场景并验证一条成功指标，达不到这个最小集就不能再砍。砍掉的进首版不做清单，写清为什么和什么条件下补；对用户给兜底话术、记进需求池、留变更记录，不临时加塞破坏时间盒。范围可以变，但每次变更 W6 回填时能对得上账。」（含术语：Scope、MVP、首版不做清单、变更记录）
