### 〇.2《设备要求表》（手机 / 平板 / 电脑三档）

> 原则：**「填初选卡 + 五问自查 + 互查 + 面试模拟 + 术语自测」在手机 / 平板上可完整完成**；仅「三窗口平铺同屏对比」需电脑，且非必做，用单档轮流测替代即可，不阻塞任何产出。

| 设备档 | 可完成任务 | 受限任务 | 替代动作 | 适用板块 |
|---|---|---|---|---|

## 一、课前检查（开课前 15 分钟）

| 检查项 | 操作 |
|---|---|
| 账号与登录 | 在讲师电脑浏览器打开 3 个各模型官方对话产品的网页版（对应通用旗舰 / 轻量快速 / 推理增强三档），逐一确认已登录、可对话、无限流提示 |
| 档位确认 | 逐个确认三档档位确实已选中（部分产品需在设置或输入框旁手动切换） |
| 新对话 | 三个窗口各开一个全新对话，避免历史上下文污染实验 |
| 秒表就绪 | 手机秒表或系统秒表放在手边，实验需现场计时 |
| 投屏分辨率 | 三个窗口平铺（左右各一 + 下方一），确认投屏后三个窗口文字末排可读；必要时用系统分屏或浏览器多窗口排列 |
| 备用方案 | 提前用三个档位各跑一遍任务包并截图（见对应板块预案 C），存入相册可快速投屏 |
| 学员端 | 本实验为讲师演示型，学员只需在导学案上同步记录；无需学员登录任何工具 |
| 设备分档确认（本课版新增） | 按〇.2《设备要求表》确认手机 / 平板 / 电脑三档人数，混编三人互查小组，并提前把「默认档 / 深度思考档」切换路径发给手机端学员 |

## 二、统一测试任务包（与导学案记录表对应）

三个任务覆盖三条能力线，提示词可直接复制使用（场景为概括性通用场景，均为**教学示例**，不涉及具体品牌、不含任何跑分与价格数字）：

| 任务 | 直接发送的提示词 | 考察点 |
|---|---|---|
| 任务 A · 简单摘要 | 「请把下面这段产品说明概括成一句话，不超过 30 字：〈现场贴入一段约 300 字的通用产品说明文本〉」 | 基础能力线；三类档位预期都能过 |
| 任务 B · 多步逻辑推理 | 「三个人参加比赛：甲比乙快，丙比甲慢但比乙快，请按从快到慢排出三人名次，并写出推理过程。」 | 多步推理；预期轻量档可能出错且不报错 |
| 任务 C · 带约束写作 | 「写一条 50 字以内的中秋促销文案，必须包含『满减』这个词，最后以一个礼貌收尾语结束。」 | 约束遵循；预期档位间遵守度有差异 |

## 三、怎么读结果：四个观察维度

向学员明确并同步记录到导学案记录表：

| 维度 | 怎么读 | 记录方式 |
|---|---|---|
| 正确性与完整性 | 任务 A 看是否抓住核心信息；任务 B 看推理步骤与结论是否正确；任务 C 逐条核对约束（字数、关键词、收尾语） | 勾选 + 一句话描述 |
| 响应速度 | 发送后开始计时，回答结束停止；对比三档秒数 | 记录约几秒（如「约 3 秒 / 约 10 秒」，为教学示例读数，非固定值） |
| 消耗 | 回答长度肉眼可比；界面显示 Token（词元）数或字数的产品顺带记录 | 记录相对关系（长 / 中 / 短） |
| 失败方式 | 重点维度。区分三种：报错或拒答 / 谨慎带保留 / **一本正经地给错答案**。第三种最危险，用户无法识别 | 一句话描述错误形态 |

## 四、讲师演示脚本（5 步 · 本课版按对应板块实验段 25 分钟重排）

| 步骤 | 讲师操作 | 时长 | 要点 |
|---|---|---|---|
| ① 讲规则 | 投屏实验任务卡，念三个任务与四个观察维度，学员在导学案记录表上先建好表头 | 3 min | 强调「我们不背跑分，我们只记录今天亲眼所见」 |
| ② 跑任务 A | 三窗口同时发送摘要任务，掐秒表，展示三档回答 | 5 min | 预期都能过——引出「简单任务用贵档是浪费」 |
| ③ 跑任务 B | 发送逻辑题，等回答完成后逐个核对 | 8 min | 重点引导看轻量档「错得理直气壮」；推理增强档的思考等待时间让学员体感 |
| ④ 跑任务 C | 发送带约束写作，给学员 1 分钟自己逐条核对约束 | 6 min | 让学员自己发现约束遵循差异，讲师不下结论 |
| ⑤ 收敛记录 | 留 3 分钟让学员补全记录表并写 2 条自己的结论；讲师巡场后点 1–2 人分享 | 3 min | 收敛到板书口诀；衔接后续正反案例与决策树环节 |

> 合计 25 分钟，落在对应板块（100–150 min）的实验段；对应板块（）另有学员实操 32′，用主项目真实任务按〇.2《设备要求表》的设备档位重跑。

## 五、网络故障预案

| 预案 | 触发条件 | 处理动作 |
|---|---|---|
| 预案 A：单档限流或未响应 | 某一档发送后长时间无响应或弹出限流提示 | 讲解不中断——「正好，这就是真实接入会遇到的限流，产品要有兜底」；切备用窗口或用该档预跑截图继续对比，秒数改用截图预跑记录并注明「预跑数据」 |
| 预案 B：现场网络整体缓慢 | 多窗口均明显卡顿 | 只保留任务 B（教学价值最高的一个任务）现场跑，任务 A、C 改用预跑截图讲解；把省下的时间让给学员讨论 |
| 预案 C：现场完全不可用（断网） | 无法访问任何模型产品 | 全程改用课前预跑的三档截图：按任务逐张投屏，讲法不变（对照记录表逐维度读），并向学员说明「回放中会补现场实跑版本」；课后在社群补发现场实跑的录屏；手机 / 平板学员同样可看截图完成记录 |
| 预案 D：结果与预期不符 | 例如轻量档在任务 B 也答对 | 不掩盖——当场改写结论：「这恰恰证明不能靠别人的结论选型，必须自己测」；这正是本课方法论的最佳 live 佐证，按预案 D 话术自然接住 |

## 六、课后学员自学指引（发群文案）

> 同学们，今天课上「同任务 × 3 档模型」的实验请课后自己做一遍升级版：用你主项目的真实任务，分别用你常用产品的三个档位各跑 3 次，按四个维度（正确性 / 速度 / 消耗 / 失败方式）记录到导学案表格里。周五立项报告的技术可行性一节要用。注意两点：一是同一任务多跑几次再看，单次结果有运气成分；二是只记录现象和自己的归因，不要背任何跑分，单价一律「以官网实时价格为准」。
> **只有手机 / 平板的同学**：按《设备要求表》的替代动作做——切「默认档 / 深度思考档」轮流问同一任务、各掐一次秒表，把快 / 慢、长 / 短、答没答到点记进导学案；初选卡五问用备忘录逐条填完整即可，不影响周五立项。对应板块《术语自测表》与对应板块《面试模拟记录表》也请在手机上补完，对应板块归档时一并登记。

### 常见问题（答疑口径）

- 1. 上下文窗口越来越大，是不是就不用 RAG 了？ 结论：仍要。窗口管「一次能塞多少」，RAG 管「知识从哪来、能不能更新、能不能溯源」，两者不互相替代。
- 2. 幻觉能不能靠换模型根治？ 结论：不能。只能靠检索溯源、护栏拦截、引用标注和兜底话术把风险压到可接受。
- 3. 评分表里的分数哪里来？ 结论：来自你自己的评测集（见 W2D3）；本章分值是教学假设，禁止照搬。
