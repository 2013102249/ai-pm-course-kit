## 二、教学目标（可测量）

1. 能用「能力-成本-延迟」三角，对给定业务场景从三类模型（通用旗舰 / 轻量快速 / 推理增强）中做出初选，并说出至少两条权衡理由（对应课堂决策树填写 + 分层习题基础层）。
2. 能现场完成「同一组任务 × 3 类模型」对比实验，按「正确性 / 响应速度 / 消耗 / 失败方式」四个维度如实记录结果，并归纳出至少一条自己验证的结论（对应导学案模型对比记录表 + 课后实验记录作业）。
3. 能用选型决策树为自己的主项目完成模型初选，产出「首选模型 + 两条理由 + 一个备选方案」，直接用于 W2 周五立项报告（对应导学案主项目选型初选卡）。

## 三、教学重难点

- **重点一**：能力-成本-延迟三角——学员必须建立「选型是三维权衡，不是单向比强弱」的产品视角。
- **重点二**：选型决策树——五问顺序不可乱，先场景后模型，先「够用」后「更强」。
- **难点一**：学员容易「唯榜单论」，把跑分排名当选型依据。应对：用现场实验让学员亲手验证「榜单第一不等于你的场景最优」。
- **难点二**：成本与延迟意识缺失。学员默认「选最聪明的准没错」。应对：用「10 倍调用量」的成本放大提问，让学员自己算出后果；价格一律用「以官网实时价格为准」口径，教方法不背数字。
- **难点三**：模型信息动态变化，学员容易把本课的横评结论当永久事实。应对：反复强调「横评表会过期，方法不会」，教的判断框架可长期复用。

## 六、「能力-成本-延迟」三角讲解设计（重点环节教学设计）

**讲解目标**：让学员离开教室时能脱口而出「选型不是选最强，是三维权衡」。

**讲解顺序（先建立冲突，再给框架）**：

1. **先给一个单维判断题制造冲突**：「模型 A 能力最强、模型 B 便宜三倍、模型 C 快三倍，你的产品该选谁？」让学员发现——这个问题没法回答，因为缺了场景。由此引出：能力、成本、延迟三个角，缺一个角都没法做决策。
2. **逐角讲解（每角配一个产品经理视角的追问）**：
   - **能力角**：不是「哪家最强」，是「这个场景需要的最低能力线在哪」。低于这条线的产品不合格，高于这条线的部分要花真金白银买。追问：「能力线以上多出来的聪明，用户愿意付钱吗？」
   - **成本角**：三类成本——调用成本（按 token 计费，以各官网实时价格为准）、接入与运维成本、切换成本。追问：「如果你的产品日调用 1 万次和 100 万次，同样的单价意味着什么？」
   - **延迟角**：用户体感。对话类产品超过数秒用户就开始流失，批处理类产品可以等。追问：「你的场景里，用户等 10 秒会发生什么？」
3. **三角的用法（板书收束）**：先按场景定「能力线」，再在能力线之上的模型里比「成本 × 延迟」，最后用合规与部署做一票否决。**顺序不可反**——先看便宜再补能力，是新手最常见的返工原因。
4. **即时检验**：给两个概括场景（离线批量摘要 / 在线实时客服），让学员口头用三角说一遍初选逻辑，确认全班掌握后再进对比实验。

## 七、选型决策树教学设计（重点环节教学设计）

**决策树五问（板书与导学案一致）**：

```
第 1 问：任务类型是什么？（问答摘要 / 创意生成 / 多步推理 / 结构化抽取）
第 2 问：质量底线在哪？（错了的代价：可接受 / 需人工兜底 / 不可接受）
第 3 问：延迟容忍多少？（实时对话 / 几秒可等 / 离线批处理）
第 4 问：预算与调用量？（日均量级 × 官网实时单价估算）
第 5 问：合规与部署约束？（数据是否可出域 / 是否要求国产与备案 / 私有化需求）
```

**教学设计要点**：

1. **先错后对**：先给一个「反例决策」——某团队所有场景无脑上最强模型，成本失控后被迫全线降级重测。让学员指出错在哪一问没问。
2. **五问顺序即板书顺序**：强调第 1、2 问定「能力线」，第 3、4 问定「档位」，第 5 问是「一票否决」，与三角讲解的顺序互相印证。
3. **小模型专属强调**：在第 2 问分支上重点讲「什么时候用小模型」——任务简单且量大、失败可兜底、需要极速响应时，小模型是正解不是妥协。
4. **课堂落地**：环节五学员把五问逐条套自己的主项目，产出写在导学案初选卡上；讲师巡视时只追问「你的第 5 问答案是什么」，用合规问倒逼真实思考。

## 八、课堂提问设计（7 问）

| # | 提问 | 提问时机 | 预设答案 / 引导方向 |
|---|---|---|---|
| 1 | 「同一个问题，两个模型的回答差这么多，如果你是老板，你给哪个发工资？为什么？」 | 导入 | 引出分歧点：回答好的可能更贵更慢；发工资的标准不是「好」而是「够用且划算」——自然过渡到选型方法论 |
| 2 | 「同样是 pretrain 出来的模型，为什么能力差别这么大？」 | 环节一 | 训练数据、规模、对齐与后训练策略不同；回扣 W1D2「超级接话员」类比——不同接话员读过的书和训练方式不同 |
| 3 | 「海外模型与国产模型，在国内做产品时真正拉开差距的是什么维度？」 | 环节一 | 不只是能力，还有合规备案、国内访问与接入便利、中文场景适配、私有化部署支持；能力之外的因素常是决定项 |
| 4 | 「你的产品日调用量涨 100 倍，你还敢用最贵的模型吗？」 | 环节二成本角 | 多数场景不敢——成本随调用量线性放大；引出「量大且简单的任务应该交给便宜档位」，以官网实时单价为准现场估一估 |
| 5 | 「实验里轻量模型哪个任务掉链子了？掉链子的方式是什么？」 | 环节三 | 预期：多步推理或带约束任务出错率升高，且错得「理直气壮」（不报错、直接给错答案）；强调「失败方式」比「失败次数」更值得关注 |
| 6 | 「推理增强模型回答前先『想』很久，什么场景这个等待花得值？」 | 环节三 | 数学、逻辑、代码、复杂决策类任务值；闲聊、摘要类任务不值——等待是用户体感的直接损失 |
| 7 | 「决策树五问里，哪一问的答案可能直接否决前面四问的所有结论？」 | 环节四 | 第 5 问合规与部署——数据不能出域时，再强的海外模型也不可选；一票否决项必须最先确认或最后兜底检查 |

## 九、板书要点

```
选型不是选最强，是选最合适

能力-成本-延迟三角：
  能力线 = 场景能接受的最低质量
  成本   = 调用（token，以官网实时价格为准）+ 运维 + 切换
  延迟   = 用户体感；实时场景以秒计

选型五问（顺序不可乱）：
  ① 任务类型 ② 质量底线 ③ 延迟容忍 ④ 预算量级 ⑤ 合规部署（一票否决）

三类模型档位：通用旗舰（能力全） / 轻量快速（快且省） / 推理增强（先想后答）
一句话：先定能力线，再比成本与延迟，最后合规兜底。
```

## 十、课堂练习参考答案（主项目选型练习示例）

以概括示例「面向中小商家的智能客服问答产品」为参照（学员按各自项目作答，结构一致即可）：

| 决策树五问 | 示例回答 |
|---|---|
| ① 任务类型 | 售后政策问答为主，属知识问答与摘要类 |
| ② 质量底线 | 答错会引发客诉，需人工兜底机制 |
| ③ 延迟容忍 | 在线对话，需秒级响应 |
| ④ 预算量级 | 中小商家付费意愿有限，成本敏感，量大 |
| ⑤ 合规部署 | 面向国内商家，数据不可随意出域，倾向国产已备案模型 |

**示例结论**：首选国产主流对话模型的标准档位（具体以官网实时信息与自测为准）；备选轻量档处理高频简单问题以压成本；复核项：接入的模型须已完成生成式 AI 服务备案。**给分点**：五问齐全（50%）、结论与五问自洽（30%）、给出备选与复核项（20%）。

## 十一、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 唯榜单论 | 引用某榜单排名作为选型唯一依据 | 现场实验反证：让榜单结论在自己的任务上失效一次；强调榜单是通用能力参考，不是你的场景评测 |
| 只看能力不看成本与延迟 | 方案里永远写「接入最强模型」 | 用「调用量 × 100」提问逼学员算账；作业要求初选卡必须含成本估算框架（以官网实时价格为准） |
| 把本课横评结论当永久事实 | 一周后引用「课上说某模型更强」 | 每次提到横评表都补一句「以官网实时信息为准」；教方法不教死结论 |
| 忽略合规一票否决 | 初选卡直接写海外旗舰模型，不谈数据出域 | 巡视时只问第 5 问；结合 W2 周四合规课预告——备案与数据出域将决定主项目的模型池 |
| 认为换模型是零成本 | 说「先随便选一个，不好再换」 | 讲清切换成本：提示词重调、输出格式回归测试、评测集重跑；预告 W2D3 评测集正是「敢换模型」的底气 |
