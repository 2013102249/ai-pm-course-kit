# 教案 · W2 周四《AI 合规与安全（国内岗刚需）》

> AI 产品经理就业训练营 · 第二周第四天 · 300 分钟（6 课时 × 50 分钟）· 讲师版
> 主题：AI 合规与安全——生成式 AI 管理办法、算法备案、内容安全、数据合规

> **本课合规口径声明（讲师每引用一次法规名称都要带出）**：本课只做产品认知与流程框架教学，帮助产品经理「知道该问什么、该找谁确认」，不构成任何法律意见。凡涉及条款编号、适用范围、办理要求、时限与结论，一律「以现行法规与法务意见为准」；课堂、案例与习题中的示例均为概括性教学情境，不指向具体企业，不设处罚金额，不作违规定性。产品经理的职责是把合规变成产品动作与待确认项，而不是自己下法律结论。

## 二、教学目标（可测量）

1. **术语目标**：能用自己的话说清当日 12 个术语（生成式 AI 服务、算法备案、内容安全、数据合规、个人信息、训练数据合法性、标识义务、幻觉风险、人工审核、红线、免责声明、投诉通道）的一句话定义，并至少辨清 6 组易混对；验证方式：第 1 节当堂术语小测 10 题答对 ≥8 题、《术语自测表》12 行填满。
2. **手续认知目标**：能说清「算法备案 / 大模型备案 / 应用登记」三者是不同动作、能复述「两端一门」定位，并能在不给出法律结论的前提下说明「该找谁确认」；验证方式：课堂快答 3/3 + 导学案对比表填写完整。
3. **清单应用目标**：能对照《AI 产品合规检查清单》五模块，给主项目逐项标注「已具备 / 待补齐 / 不适用」，标「不适用」必须写理由；验证方式：第 4 节产出清单预填版，周五立项报告合规章节直接引用。
4. **场景判断目标**：给定 5 个产品功能场景，能判断合规风险点并给出至少 1 条产品侧整改动作，且动作与风险对应；验证方式：习题第三层场景判断 ≥4/5 达标。
5. **面试目标**：面对「上线要不要备案 / 训练数据合规怎么判断 / 生成内容出事谁负责 / 合规怎么写进 PRD」四类高频题，能给出含术语、含「拉法务确认而非自己下结论」的 60 秒结构化答法，并扛住 2 层追问；验证方式：第 5 节两两模拟 +《面试模拟记录表》≥4 行、自评分与讲师抽评误差 ≤1 档。
6. **案例迁移目标**：能从一线案例 / 公示材料拆解中提炼 ≥3 条对主项目的启发，并对应到清单模块；验证方式：导学案「案例记录区」≥3 条要点。
7. **作品集目标**：能把当日产出整理成可归档的作品集积木（清单、术语卡笔记、面试答法稿）；验证方式：第 6 节《本日作品集积木》表填齐「产出物 / 完成度 / 归档位置」三列并通过当堂验收。

## 三、教学重难点

- **重点**：合规检查清单五模块（算法备案 / 内容安全 / 数据合规 / 未成年人保护 / 责任标识）——不是背法条，而是把每条要求翻译成产品动作与待确认项。
- **难点一（概念）**：算法备案、大模型备案、应用登记三个概念极易混淆，学员会以为「备案 = 一个动作」；用对比表 + 一句话口诀 + 「以现行法规与法务意见为准」的口径区分，强调这只是帮助记忆的简化框架。
- **难点二（边界）**：合规与产品创新的边界感。学员容易走两个极端——要么「合规吓得不敢做」，要么「上线再说」；用「合规是立项四维之一，不是立项阻碍」的框架纠偏。
- **难点三（口径）**：学员容易把课堂框架当成法律结论去背、去面试里下判断；反复纠偏为「产品经理提出待确认项、推动法务确认」，具体一律「以现行法规与法务意见为准」。
- **难点四（术语混淆，新增）**：12 个术语里，「内容安全 ↔ 数据合规」「标识义务 ↔ 免责声明」「机器审核 ↔ 人工审核」「个人信息 ↔ 匿名化数据」「幻觉风险 ↔ 内容安全」「红线 ↔ 风险」六组最易混；用「一句话定义 + 生活类比 + 易混辨析」三连 + 连线/改错练习解决。
- **难点五（面试失分，新增）**：面试里两类典型失分——① 把「要不要备案」答成一句「要 / 不要」的法律结论，越界且经不起追问；② 只讲原则不给产品动作，或漏掉「拉法务确认」与「待确认项写进 PRD」；用踩分点拆解 + 失败答法对照 + 60 秒标准答法 + 两两模拟解决。
- **难点六（节奏）**：一线案例环节（嘉宾连线）冷场或超时会挤压清单精讲与面试讲解时间；按 `07-交互使用说明` 三段计时与冷场预案控制。

### 附 5-1：第 2 / 3 节核心讲解要点（本课核心产出，保留原「合规检查清单五模块设计」）

> 下表「法规依据」一栏只写名称与一句话管什么，不写条款编号、不写施行日期、不作适用结论；每讲完一模块讲师补一句「具体是否适用、如何办理，以现行法规与法务意见为准」。

| 模块 | 法规依据（公开事实 · 名称） | 产品动作示例 | 主项目自查问题 |
|---|---|---|---|
| 一、算法备案 | 《互联网信息服务算法推荐管理规定》等，涉及算法推荐服务的备案公示要求（以现行法规与法务意见为准） | 确认所用模型是否已履行相应手续；查产品官网 / 应用商店详情页的公示信息；基于已完成手续的模型做应用时，把「是否需登记」列为待确认项 | 我的产品要走哪条手续？用谁的模型？谁去确认？ |
| 二、内容安全 | 《生成式人工智能服务管理暂行办法》等，强调生成内容合法合规、防歧视、尊重知识产权、投诉举报机制（以现行法规与法务意见为准） | 上线前把安全评估列为待确认项；接入机器审核 + 人工审核；设计拒答与转人工兜底；产品内提供投诉通道 | 我的评测集里有没有内容安全负例？投诉通道放哪？ |
| 三、数据合规 | 《个人信息保护法》等，强调合法性基础、最小必要、保障个人权利（以现行法规与法务意见为准） | 梳理数据清单（收什么、存多久、给谁用）；训练用途单独授权；提供删除与注销通道；调用外部模型前签数据协议 | 我收集了哪些个人信息？能不能不收集？ |
| 四、未成年人保护 | 《未成年人保护法》网络保护专章等，强调网络产品对未成年人的保护义务（以现行法规与法务意见为准） | 判断目标用户是否含未成年人；含则增加适龄提示与内容分级；对易沉迷形态设置防沉迷机制；未成年人信息处理从严 | 我的目标用户里有未成年人吗？有就要多做什么？ |
| 五、责任标识 | 《人工智能生成合成内容标识办法》等，涉及 AI 生成合成内容添加显式或隐式标识（以现行法规与法务意见为准） | AI 生成内容打显式标签 / 水印；对话界面标注「内容由 AI 生成」；保留隐式标识（元数据）不被去除；配免责声明与投诉通道 | 我的产品每个 AI 输出都有标识吗？标在哪？ |

**访谈提纲 5 问**（提前 3 天发嘉宾确认，均以「做法与经验」为限，不问法律结论）：
1. 您所在团队的产品上线前，合规相关手续是怎么组织推进的？产品经理承担哪部分？
2. 内容安全审核在真实产品里怎么落地？机器审核和人工审核怎么分工，出现漏判后怎么补救？
3. 产品会收集用户对话数据，团队怎么做授权、脱敏和最小必要？踩过什么坑？
4. 您印象最深的一次「因合规被要求调整」是什么情况？产品经理当时应该做什么？
5. 您面试或带教 AI 产品经理时，最希望候选人在合规上具备什么能力？

**学员提问规则**：① 先举手或递麦，被点到先报「代称 + 一句话背景」；② 一人一问、不超过 40 秒，先复述问题再等回答；③ 优先问「流程、做法、坑」，不问薪资、不问未公开信息、不追问法律结论；④ 一次一问，追问不超过一轮；⑤ 导学案「案例记录区」边听边记，课后至少整理 3 条要点。

## 七、板书要点（按 6 节重排）

```
【第 1 节 · 语言系统】
12 术语：生成式AI服务 · 算法备案 · 内容安全 · 数据合规 · 个人信息
        训练数据合法性 · 标识义务 · 幻觉风险 · 人工审核 · 红线 · 免责声明 · 投诉通道
六组易混：内容安全↔数据合规 / 标识义务↔免责声明 / 机器审核↔人工审核
          个人信息↔匿名化 / 幻觉风险↔内容安全 / 红线↔风险

【第 2 节 · 原理 A】
合规 = 上线门槛，不是上线之后的事
一张地图（名称）：网安法 · 数安法 · 个保法 · 未成年人保护法
                  算法推荐规定 · 深度合成规定 · 生成式AI办法 · 标识办法
                （先后出台，具体时间 / 适用 / 条款一律「以现行法规与法务意见为准」）
两端一门：数据进模型=数据合规  内容出模型=内容安全  备案手续=开门营业
三道手续（简化框架）：自己训模型→大模型备案  用别人模型→应用登记  算法推荐→上系统备案
内容安全三防线：机器审核 → 人工审核 → 拒答兜底
生成标识：显式（标签 / 水印）+ 隐式（元数据）

【第 3 节 · 原理 B + 案例】
合规清单五模块：备案 · 内容安全 · 数据合规 · 未成年人 · 责任标识
最小必要：每收一个字段，都回答「不收集行不行」
责任边界：面对用户，产品方是责任第一排
一线案例 → 三句话：手续是流程活 / 内容安全是规则活 / 数据合规是授权活

【第 4 节 · 实操】
五步：填清单 → 标状态写理由 → 做习题 → 场景快答 → 同桌互查
设备替代：手机口述 + 同伴代填 / 平板截屏批注 + 拍照归档

【第 5 节 · 面试】
四主题：要不要备案 / 训练数据怎么判 / 出事谁负责 / 怎么进 PRD
万能起手：先给判断维度 → 再给产品动作 → 边界交给法务 → 落进待确认项
口诀：不下结论 · 给动作 · 留确认 · 可验收

【第 6 节 · 收束】
三句：合规是门槛 / 落在产品动作 / 产品方是责任第一排
口诀：备得上 · 审得出 · 收得少 · 护得住 · 标得清
作品集积木：清单 · 术语卡笔记 · 面试答法稿 · 案例要点 → 明天进立项报告

## 八、课堂练习参考答案（含术语小测与面试评分示例）

**场景快答（取自习题第三层场景 1，第 4 节用）**
场景：客服机器人直接回答用户医疗用药建议。
风险点：内容安全（医疗属高风险领域，无资质输出用药建议风险极高）；叠加幻觉风险；责任边界不清；缺免责声明与投诉通道。
整改动作：高风险话题设拒答与转人工 / 就医提示；答案来源限定为已审核知识库；输出加「内容由 AI 生成，不构成医疗建议」标识与免责声明；提供投诉通道。具体合规判断以现行法规与法务意见为准。

**术语小测（第 1 节，示例 3 题）**
- 改错：「只要写了免责声明，AI 生成内容出事就与产品方无关。」→ 错。免责声明不能替代内容安全设计，也不是责任挡箭牌；具体效力以现行法规与法务意见为准。
- 连线：数据进模型 → 数据合规；内容出模型 → 内容安全；标身份 → 标识义务；划责任范围 → 免责声明。
- 选择：机器审核拿不准的高风险输出应 → 进人工审核队列复核（不是直接放行、也不是全量人工重看）。
- 评分：10 题每题 1 分，≥8 分为达标；错题当日回填《术语自测表》「易混辨析」列。

**面试评分示例（第 5 节第 1 题「上线要不要备案」，10 分制）**

| 档位 | 表现 | 分 |
|---|---|---|
| 合格（6–7） | 不直接下「要 / 不要」结论，能说出「面向公众提供生成内容」等判断维度，并提到找法务确认 | 6–7 |
| 良好（8–9） | 上述 + 给出产品动作（核对公示、选已履行手续的模型）+ 把结论写进 PRD 待确认项（确认人 / 时间 / 上线门槛） | 8–9 |
| 优秀（10） | 上述 + 补「面对用户产品方是第一责任人」+ 主动说明「这是简化框架，具体以现行法规与法务意见为准」 | 10 |
| 失分 | 张口就答「要备案」并背条款 / 日期，或答「这是法务的事跟我无关」 | 0–3 |

## 九、学员易错点预判与应对

| 易错点 | 表现 | 应对 |
|---|---|---|
| 把合规当成「上线前一次性动作」 | 立项报告里合规只写一句「我们保证合法合规」 | 反复强调：清单贯穿主项目每个版本自查；用第 20 问把「保证合法合规」改写成可验收字段 |
| 混淆三类备案概念 | 把「算法备案」「大模型备案」「应用登记」说成一件事 | 用对比表 + 口诀区分；强调是简化记忆框架，具体以现行法规与法务意见为准 |
| 把课堂框架当法律结论背 | 面试里脱口而出具体条款、日期、「必须罚多少」 | 全课统一免责口径；示例不设处罚金额；用第 14 / 15 问纠偏为「提待确认项」 |
| 以为「套壳境外模型就不用管国内合规」 | 选型时只看效果与价格 | 用第 11 问纠偏：把「模型是否已履行相应手续」列为待确认项，判断交给法务 |
| 只盯内容安全，忽视数据合规 | 清单只填了审核模块 | 数据合规模块单独精讲 + 第 13 问用最小必要原则拷问每个字段 |
| 认为合规是法务的事，产品经理无事可做 | 「等法务审完再说」 | 指出产品是合规第一落点：拒答、标识、投诉通道、PRD 待确认项全是产品设计工作 |
| 一线案例环节学员被动听讲 | 记录区空白，提问环节冷场 | 规则提前投屏；助教预收问题纸条；讲师在每答完一问后提示「记录区记一条」 |
| **术语混淆（新增）** | 把「标识义务 = 免责声明」「内容安全 = 数据合规」「幻觉 = 违规」画等号 | 第 1 节六组易混三连讲 + 连线 / 改错练习；错题回填《术语自测表》 |
| **术语混淆（新增）** | 把「个人信息」当成只有姓名手机号，忽略对话里夹带的信息 | 用生活类比（快递面单）+ 第 5 问 + 训练前脱敏要求纠偏 |
