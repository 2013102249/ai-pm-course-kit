教案 · W2 周二《训练与微调原理（够用原则）》

AI 产品经理就业训练营 · 第二周第二天 · 90 分钟（2 课时）· 讲师版

一、基本信息

项目 内容
所属阶段 阶段一 · 认知筑基（Week 2：模型边界 · 微调原理 · 评测体系 · AI 合规）
本课主题 训练与微调原理（够用原则）
课时 90 分钟（2 课时，中间休息 5 分钟）
授课对象 转行 / 进阶层学员（W1 已完成大模型原理通识与提示词工程，周一已完成模型选型）
前置知识 大模型基本原理（Token / 上下文 / 幻觉）、模型选型决策树、提示词五要素
本课产出 微调必要性判断清单（五问逐项过）+ 一次 LoRA 旁观实验记录
课程衔接 昨天：模型选型（挑一个现成的）→ 今天：模型是怎么训练出来的（知道它从哪来）→ 明天：模型评测（判断它好不好）
教学红线 不讲数学与代码；微调流程用「旁观实验」呈现（讲师演示、学员观察记录），不让学员亲手跑训练

二、教学目标（可测量）

  1. 能用「实习生入职培训」类比，向非技术同事讲清预训练、SFT、LoRA、RLHF 四个阶段各自解决什么问题（对应导学案填空 + 习题第一层）。
  2. 能对任意给定场景，用「微调必要性判断清单」五问逐项过一遍，得出「该微调 / 不该微调」的结论并说明理由（对应课堂练习 + 习题实操题）。
  3. 能说清产品经理在一个微调项目里交付什么、验收什么，并用评测集验收而非看 Demo（对应环节四笔记 + 习题第三层）。

三、教学重难点

  • 重点：微调必要性判断清单（五问）——本课的落点不是「怎么微调」，而是「多数场景不该微调」，五问清单是学员带走的核心工具。
  • 难点一：SFT / LoRA / RLHF 三个概念的区分，学员容易混为一谈。用「实习生入职培训」类比逐段锚定：岗位培训（SFT）、便利贴改习惯（LoRA）、师傅带教打分（RLHF）。
  • 难点二：「微调能提升模型智力」的错误期待。要反复纠偏：微调主要改行为、风格、格式，不改变模型能力上限；补知识用 RAG。

五、教学步骤与时间拆分

时间 环节 教学内容 教学方法 对应产出
0–8 min 导入：从「挑人」到「培养」 回顾周一选型决策树；抛出问题：这些模型出厂前经历了什么；用 LLM 原理架构图定位本课位置；给出全程类比「实习生入职培训」 提问 + 图示 学员在导学案写下「想微调的场景」初判
8–26 min 环节一：模型培养四步全链路 用待制流程图讲四段：预训练=读完全部教科书（数以万亿计 Token、以月计）→ SFT=岗位培训（数以千计到万计的高质量示范）→ LoRA=贴便利贴（原模型不动，只加一小片可训练增量）→ RLHF=师傅带教打分（人类偏好对齐）；每段只讲「产品经理需要懂的部分」 讲授 + 类比 + 提问 导学案「四步类比表」填写
26–46 min 环节二：多数场景不该微调——五问判断清单（核心） 逐问讲清单：① 提示词真试到头了吗 ② 补的是知识还是行为 ③ 拿得出数以百计的高质量示例吗 ④ 需求会频繁变吗 ⑤ 说得清怎么算调好了吗；现场用 2 个场景逐项过清单 讲授 + 板书 + 现场演练 五问清单理解到位
46–62 min 环节三：LoRA 旁观实验 讲师演示：在开源小模型上用少量示例做一次风格微调，展示数据准备→训练过程→前后输出对比；学员只观察、记录，不动手 讲师演示 + 学员观察记录 导学案「LoRA 旁观实验记录表」
62–78 min 环节四：与算法团队的协作接口 产品经理在微调项目里交付什么（需求文档、评测集、示例数据验收标准、badcase 回流）、验收什么（评测集跑分、对比基线、上线门槛，不看 Demo 拍板） 讲授 + 案例（一次微调返工的故事） 导学案「协作接口笔记」
78–86 min 环节五：小组判断练习 4 个场景小组过五问清单（讨论 5 分钟 + 汇报），讲师点评 小组讨论 + 汇报 导学案「场景判断表」
86–90 min 总结与作业 三句话收束 + 布置作业 + 预告周三评测 讲授 —

（时间拆分总和 = 90 分钟）

六、微调必要性判断清单（五问）设计说明

本清单是本课的核心交付物，需在教案、讲课稿、导学案、习题四处保持措辞一致。

# 问题 考察什么 答「否」/「是」的走向
一 提示词真试到头了吗？ 是否穷尽了提示词工程与少样本示例这条低成本路径 没试到头 → 不微调，回去改提示词
二 要补的是知识还是行为？ 需求本质：知识（事实、政策、文档）→ RAG；行为（风格、格式、口吻、流程习惯）→ 才轮到微调 补知识 → 不微调，走 RAG
三 拿得出数以百计的高质量示例吗？ 数据工程能力：示例是否有代表性、标注是否一致、负面案例是否覆盖 拿不出 → 不微调，先补数据（而补数据的成本往往比想象高）
四 需求会频繁变吗？ 时效性：需求每个迭代都变，微调周期跟不上变化 频繁变 → 不微调，用提示词或 RAG
五 说得清「怎么算调好了」吗？ 评测先行：有没有可复跑的评测集与上线门槛 说不清 → 不微调，先建评测（预告明天课程）

结论规则：五问中任何一问得到「不利答案」，就不该微调。五问全过，才进入与算法团队的需求沟通——这也是「多数场景不该微调」的判断依据。

七、课堂提问设计（7 问）

# 提问 提问时机 预设答案 / 引导方向
1 「昨天我们做选型，像是在挑人。那一个模型被『造』出来之前，到底经历了什么？」 导入 海量阅读打底 + 岗位示范培训 + 反馈打磨；引出四步链路
2 「预训练读完了全部教科书，为什么它还是不会干你们岗位的活？」 预训练段 会「写」不等于会「做」；缺岗位示范——引出 SFT
3 「SFT 和预训练都在喂数据，差别在哪？」 SFT 段 规模量级不同（万亿级 Token vs 千到万级示范）；目的不同（学通识 vs 学行为规范）
4 「LoRA 为什么是贴便利贴，而不是重写一整本笔记？」 LoRA 段 只训练一小部分新增参数、原模型不动、数据和算力开销小、可插拔
5 「师傅带教打分（RLHF），模型到底学到了什么？」 RLHF 段 人类偏好——什么样的回答算「好」：有用、诚实、无害
6 「你的产品想让模型『说话更像你们公司的人』，该走微调还是 RAG？」 五问清单后 行为特征 → 优先 LoRA 微调；若是「掌握公司知识」→ RAG。借机回扣 W3D3 将学的口诀
7 「算法同学问你要多少示例数据、要什么样的，你怎么回答？」 协作接口段 先问清任务类型；数以百计起步、质量大于数量；必须覆盖负面案例与边界 case

八、板书要点

模型培养四步 = 实习生入职培训
预训练：读完全部教科书   → 通识打底（我们不参与，选型即可）
SFT：岗位培训           → 学会「像样地干活」（行为差异的来源）
LoRA：贴一张便利贴       → 习惯微调（原模型不动，性价比方案）
RLHF：师傅带教打分       → 对齐人类偏好（有用 / 诚实 / 无害）

微调必要性五问：
① 提示词到头了吗  ② 知识还是行为  ③ 有数据吗
④ 需求常变吗      ⑤ 说得清验收吗
→ 任何一问不过 = 不该微调

协作接口：产品经理交付「需求 + 评测集 + 数据标准」；验收「评测分」不看 Demo

九、「与算法团队协作的接口」：产品经理在微调项目里交付什么、验收什么

9.1 产品经理交付的四件东西

交付物 内容 常见缺失后果
微调需求文档 目标行为描述（要什么样）、负面清单（不要什么样）、典型输入输出示例 3–5 组 算法按自己的理解调，方向跑偏，返工以周计
评测集 与明天评测课同一套方法：覆盖正例、负例、边界 case，可复跑 没有评测集 = 验收凭感觉，Demo 惊艳上线即翻车
示例数据验收标准 数据量级预期（数以百计起步）、标注一致性规则、负面案例占比 数据质量参差，模型学到坏习惯
badcase 回流机制 上线后差评样本定期回流训练数据与评测集 效果上线即巅峰，之后持续衰减无人管

9.2 产品经理验收的三道关

验收关 做法 红线
对比基线 微调版必须与「提示词优化版」同题对比，赢在评测集上才算赢 只看微调版自我陶醉，不看基线
评测集跑分 用事前冻结的评测集出分，达标才验收 现场挑几个好例子跑 = 自欺欺人
上线门槛 事前约定：核心指标达到什么数值、负面案例不超过什么比例才上线 门槛事后定 = 门槛随便过

9.3 一句话原则

产品经理不碰训练代码，但要管住「定义问题、供给数据、主持验收」三件事——这三件事恰好是微调项目失败率最高的三处。

十、课堂练习参考答案（4 场景判断，环节五用）

场景 五问结论 判断与关键理由
让客服机器人回答每月更新的售后政策 ② 知识 → 否 不微调，用 RAG：知识会过期，微调灌知识等于过时就重训
让模型输出严格符合内部系统的 JSON 字段格式 ① 可能不到头 先提示词 + 输出校验；反复不稳且失败代价高才考虑微调
让模型用公司品牌口吻写推广文案 五问可全过 该微调（LoRA）：典型行为特征，示例可得，需求相对稳定
老板拍板「我们也微调一个自己的大模型」 ③⑤ 大概率不过 不微调：无数据、无评测标准、目标模糊；先用选型 + 提示词跑通业务

十一、学员易错点预判与应对（5 条）

易错点 表现 应对
把微调当万能药 「效果不好就微调一遍」脱口而出 用五问清单逐项过现场场景，让学员亲口说出「不过」；回扣「多数场景不该微调」
以为微调能「灌知识」 想把产品手册微调进模型 讲清知识会过期：微调灌知识 = 文档一改就重训；知识走 RAG
认为微调 = 模型更聪明 「微调后推理能力会变强」 纠偏：微调改行为、风格、格式，不提升智力上限；能力上限在预训练就基本定了
把 LoRA 理解成「小模型」 说「LoRA 是个轻量模型」 纠正：LoRA 是一种训练方法，产物仍是原模型加一小片可插拔增量
验收看 Demo 不看评测 「效果看起来不错就上线」 讲返工案例；与明天评测课衔接：评测集是产品经理在微调项目里最有分量的武器

十二、作业与衔接

  1. 完成导学案课后判断题自测（10 题）。
  2. 把课上五问清单套用到自己主项目的候选场景，写一段 100 字以内的「该不该微调」论证（周五立项评审可用）。
  3. 预习：明天讲模型评测体系，想一想「微调完了，怎么证明它真的变好了」。
