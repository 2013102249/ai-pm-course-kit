教案 · W2 周二《训练与微调原理（够用原则）》

AI 产品经理就业训练营 · 第二周第二天 · 300 分钟（6 课时 × 50 分钟）· 讲师版
本课为 300 分钟版（6 节课 × 50 分钟），在原版基础上新增「术语精讲」（第 1 节）与「面试讲解」（第 5 节）两大增量；中间每两节之间休息 10 分钟，不计入 300 分钟教学时长。第 1 节对「完全不了解技术」的学员须先走 W1-物料/W1D2-大模型原理通识/00-技术零层.md。

二、教学目标（可测量）

  1. 【术语目标】能用自己的话说清本日 12 个术语（预训练、微调、SFT、LoRA、RLHF、提示词工程优先、标注数据、训练集、过拟合、灾难性遗忘、五问清单、成本），英文缩写首次出现能写出全称与中文；在《术语自测表》12 题上答对 ≥10 题。（验证：第 1 节当堂小测 + 导学案《术语自测表》自评）
  2. 能用「实习生入职培训」类比，向非技术同事讲清预训练、SFT、LoRA、RLHF 四个阶段各自解决什么问题。（验证：导学案「四步类比表」+ 习题第 0 层辨析题）
  3. 能对任意给定场景，用「微调必要性判断清单」五问逐项过一遍，得出「该微调 / 不该微调」的结论并说明理由。（验证：课堂练习四场景 + 习题第 2 层实操题）
  4. 能说清产品经理在一个微调项目里交付什么、验收什么，并用评测集验收而非看 Demo。（验证：导学案「协作接口笔记」+ 习题第 3 层）
  5. 【面试目标】面对「什么时候该微调」「微调和提示词工程怎么选」「微调和 RAG 区别」「怎么判断微调有没有效果」四类高频题，能给出含当日术语的 60 秒标准答法，并扛住 2–3 层追问。（验证：第 5 节两两模拟 +《面试模拟记录表》自评分达「达标」档）
  6. 能完成一次 LoRA 旁观实验的三幕观察记录，写出「变了什么 / 没变什么 / 副作用」的一句话结论。（验证：导学案《LoRA 旁观实验记录表》）
  7. 能把当日产出归入《本日作品集积木》，标明产出物、完成度与归档位置，形成周五立项评审与第八周面试课可复用的材料。（验证：第 6 节当堂验收逐项打勾）

三、教学重难点

  • 重点：微调必要性判断清单（五问）——本课的落点不是「怎么微调」，而是「多数场景不该微调」，五问清单是学员带走的核心工具。
  • 难点一：SFT / LoRA / RLHF 三个概念的区分，学员容易混为一谈。用「实习生入职培训」类比逐段锚定：岗位培训（SFT）、便利贴改习惯（LoRA）、师傅带教打分（RLHF）。
  • 难点二：「微调能提升模型智力」的错误期待。要反复纠偏：微调主要改行为、风格、格式，不改变模型能力上限；补知识用 RAG。
  • 难点三【术语混淆】：本日 12 个术语多为「听过名词」级，学员极易把「微调」与「SFT」「LoRA」混为一谈、把「训练集」与「评测集」混为一谈、把「过拟合」与「灾难性遗忘」混为一谈、把「标注数据」当成「随便找一批文本」。用第 1 节逐词 5 项精讲 +「易混辨析」逐对拆开 + 习题第 0 层连线 / 改错题巩固。
  • 难点四【面试失分】：学员懂原理却不会「翻译」成面试语言——答「什么时候该微调」时脱口而出「看情况」，缺框架、缺术语、缺追问防御，被连追两层就乱。用第 5 节题型拆解 + 踩分点 + 60 秒标准答法 + 追问链演练 + 失败答法对照逐项纠偏。

六、微调必要性判断清单（五问）设计说明

本清单是本课的核心交付物，需在教案、讲课稿、导学案、习题四处保持措辞一致。

#问题考察什么答「否」/「是」的走向
一提示词真试到头了吗？是否穷尽了提示词工程与少样本示例这条低成本路径没试到头 → 不微调，回去改提示词
二要补的是知识还是行为？需求本质：知识（事实、政策、文档）→ RAG；行为（风格、格式、口吻、流程习惯）→ 才轮到微调补知识 → 不微调，走 RAG
三拿得出数以百计的高质量示例吗？数据工程能力：示例是否有代表性、标注是否一致、负面案例是否覆盖拿不出 → 不微调，先补数据（而补数据的成本往往比想象高）
四需求会频繁变吗？时效性：需求每个迭代都变，微调周期跟不上变化频繁变 → 不微调，用提示词或 RAG
五说得清「怎么算调好了」吗？评测先行：有没有可复跑的评测集与上线门槛说不清 → 不微调，先建评测（预告明天课程）

结论规则：五问中任何一问得到「不利答案」，就不该微调。五问全过，才进入与算法团队的需求沟通——这也是「多数场景不该微调」的判断依据。

七、课堂提问设计（24 问：术语辨析 7 + 面试追问 8 + 原理 / 导入 / 实操 9）

#类型提问提问时机预设答案 / 引导方向
1导入「昨天我们做选型，像是在挑人。那一个模型被『造』出来之前，到底经历了什么？」第 2 节导入海量阅读打底 + 岗位示范培训 + 反馈打磨；引出四步链路
2术语辨析「『微调』和『SFT』是同一个东西吗？谁是大类、谁是一种做法？」第 1 节微调是「不动整体、只改具体行为」的大类；SFT（监督微调）是微调的一种做法，用成对示范教模型听指令
3术语辨析「LoRA 是一种比大模型更轻的『小模型』，还是一种训练方法？它的产物到底是什么？」第 1 节LoRA（低秩适配）是训练方法；产物是「原模型 + 一小片可插拔增量」，不是独立小模型
4术语辨析「『训练集』和『评测集』能不能用同一批数据？为什么？」第 1 节不能；训练集是「教」，评测集是「考」，同一批等于考前泄题，分数虚高
5术语辨析「『标注数据』和『随便找一批文本』差在哪？为什么脏数据比没数据更糟？」第 1 节标注数据带标准答案且口径一致；脏数据让模型学到坏习惯，比不会更难改
6术语辨析「『过拟合』和『灾难性遗忘』都是『变笨』，区别在哪？」第 1 节过拟合=死记示例、换个问法就不会；灾难性遗忘=学了新风格丢了通用能力；一个「太死」，一个「顾此失彼」
7术语辨析「『知识』和『行为』怎么分？为什么这一问决定走 RAG 还是微调？」第 1 节 / 第 3 节内容 vs 方式；补知识走 RAG（改文档即生效），改行为才微调
8术语辨析「『提示词工程优先』是不是等于『永远不微调』？它的边界在哪？」第 1 节 / 第 3 节不是；它是「先试低成本路径」，边界是三种结构 + 三组少样本横向比过仍不达标、且属行为型需求
9原理「预训练读完了全部教科书，为什么它还是不会干你们岗位的活？」第 2 节会「写」不等于会「做」；缺岗位示范——引出 SFT
10原理「SFT 和预训练都在喂数据，差别在哪？」第 2 节规模量级不同（万亿级 Token vs 千到万级示范）；目的不同（学通识 vs 学行为规范）
11原理「LoRA 为什么是贴便利贴，而不是重写一整本笔记？」第 2 节只训练一小部分新增参数、原模型不动、数据和算力开销小、可插拔
12原理「师傅带教打分（RLHF），模型到底学到了什么？」第 2 节人类偏好——什么样的回答算「好」：有用、诚实、无害
13原理「你的产品想让模型『说话更像你们公司的人』，该走微调还是 RAG？」第 3 节行为特征 → 优先 LoRA 微调；若是「掌握公司知识」→ RAG
14实操「微调前后对比，变了什么、没变什么？有没有变得更差的地方？」第 4 节变口吻 / 用语，不变知识与推理；留意「灾难性遗忘」的温和版副作用
15实操「算法同学问你要多少示例数据、要什么样的，你怎么回答？」第 3 / 4 节先问清任务类型；数以百计起步、质量大于数量；必须覆盖负面案例与边界 case
16实操「验收那天全场合掌通过，为什么上线第一周还是翻车？」第 3 / 4 节验收没打开评测集、只看 Demo；评测集要冻结、要含通用回归题
17面试追问「『什么时候该微调』——面试官问这句，你第一句答什么？」第 5 节先给框架：不是拍脑袋，用五问清单逐项过，任何一问不过就不调
18面试追问「追问：提示词优化到什么程度才算『试到头』？」第 5 节三种结构不同提示词 + 每方案三组以上少样本 + 同一批测试题横向比过仍不达标
19面试追问「追问：老板坚持要微调，你怎么回应？」第 5 节不盲从不硬顶；把「要不要微调」转译成「先回答数据 / 评测 / 目标行为三个问题」
20面试追问「『微调和 RAG 有什么区别』——一句话讲清，你怎么说？」第 5 节补知识走 RAG（外挂资料、改文档即生效），改行为才微调；把知识微调进脑子等于把「会过期」印进去
21面试追问「追问：有没有既该补知识、又该改行为的情况？怎么排优先级？」第 5 节先拆开：知识部分走 RAG 当天生效，行为部分再单独评估微调；不要一锅端
22面试追问「『怎么判断微调有没有效果』——不看 Demo 看什么？」第 5 节事前冻结的评测集跑分 + 与提示词优化版基线同题对比 + 上线门槛；Demo 是演员，评测集是考卷
23面试追问「追问：评测集应该怎么建？只测口吻够不够？」第 5 节正例 + 负例 + 边界 + 与风格无关的通用能力回归题，防顾此失彼
24面试追问「追问：上线一个月效果掉了，你怎么排查？」第 5 节按优先级：通用能力变差→副作用；口吻下滑→badcase 未回流；需求漂移→规范被频繁改动

九、「与算法团队协作的接口」：产品经理在微调项目里交付什么、验收什么

9.1 产品经理交付的四件东西

交付物内容常见缺失后果
微调需求文档目标行为描述（要什么样）、负面清单（不要什么样）、典型输入输出示例 3–5 组算法按自己的理解调，方向跑偏，返工以周计
评测集与明天评测课同一套方法：覆盖正例、负例、边界 case，可复跑没有评测集 = 验收凭感觉，Demo 惊艳上线即翻车
示例数据验收标准数据量级预期（数以百计起步）、标注一致性规则、负面案例占比数据质量参差，模型学到坏习惯
badcase 回流机制上线后差评样本定期回流训练数据与评测集效果上线即巅峰，之后持续衰减无人管

9.2 产品经理验收的三道关

验收关做法红线
对比基线微调版必须与「提示词优化版」同题对比，赢在评测集上才算赢只看微调版自我陶醉，不看基线
评测集跑分用事前冻结的评测集出分，达标才验收现场挑几个好例子跑 = 自欺欺人
上线门槛事前约定：核心指标达到什么数值、负面案例不超过什么比例才上线门槛事后定 = 门槛随便过

9.3 一句话原则

产品经理不碰训练代码，但要管住「定义问题、供给数据、主持验收」三件事——这三件事恰好是微调项目失败率最高的三处。

十一、学员易错点预判与应对

易错点表现应对
把微调当万能药「效果不好就微调一遍」脱口而出用五问清单逐项过现场场景，让学员亲口说出「不过」；回扣「多数场景不该微调」
以为微调能「灌知识」想把产品手册微调进模型讲清知识会过期：微调灌知识 = 文档一改就重训；知识走 RAG
认为微调 = 模型更聪明「微调后推理能力会变强」纠偏：微调改行为、风格、格式，不提升智力上限；能力上限在预训练就基本定了
把 LoRA 理解成「小模型」说「LoRA 是个轻量模型」纠正：LoRA 是一种训练方法，产物仍是原模型加一小片可插拔增量
验收看 Demo 不看评测「效果看起来不错就上线」讲返工案例；与明天评测课衔接：评测集是产品经理在微调项目里最有分量的武器
【术语混淆】把微调 / SFT / LoRA 当成三个并列阶段「先微调、再 SFT、再 LoRA」用包含关系图讲清：微调是大类，SFT 与 LoRA 是其中两种做法；四步链路是「预训练→SFT→LoRA→RLHF」的产出顺序，不是并列定义
【术语混淆】把训练集当评测集、把标注数据当原始文本「拿训练用的示范直接验收就行」用「教与考」「泄题」类比；强调评测集须事前冻结、独立建、含通用回归题
【面试失分】答「什么时候该微调」只说「看情况」无框架、无术语，被追问即卡壳第 5 节强制套「五问清单」框架开口，先给结论再展开；用 60 秒标准答法反复跟读
【面试失分】把「微调 vs RAG」答成技术名词堆砌说一堆参数、显卡、训练细节拉回产品语言：「补知识走 RAG、改行为才微调」，一句话讲清再补一句边界，不引入公式与数字
