分层习题 · W2 周二《训练与微调原理（够用原则）》

AI 产品经理就业训练营 · 第二周第二天 · 300 分钟（6 课时 × 50 分钟）· 分层习题
五层难度：第 0 层术语辨析 → 第 1 层基础巩固 → 第 2 层进阶实操 → 第 3 层求职挑战 → 第 4 层面试实战。
建议用法：第 0 层随第 1 节当堂测（术语精讲配套）；第 1 层当堂测 10 分钟；第 2、3 层当作业；第 4 层配第 5 节两两模拟演练，第八周面试课复用。
全部题目附参考答案与评分标准。考点主线：微调必要性判断与面试得分；涉及数据一律写「待教务补充」，不编造成本与效果数字。

第 0 层 · 术语辨析（12 题，含选择 / 连线 / 改错 / 简答四种题型）

一、选择题（0-1 ~ 0-4，每题 5 分）

0-1. 关于「微调 / SFT / LoRA」的关系，正确的是：
A. 微调是 SFT 的一种做法
B. SFT 和 LoRA 都是微调这个大类下的具体做法
C. LoRA 是一种比大模型更轻量的独立小模型
D. 微调就是预训练的另一种叫法

0-2. 关于「训练集」与「评测集」，正确的是：
A. 用同一批数据最省事，结果也最准
B. 训练集负责「教」、评测集负责「考」，两者必须分开且评测集事前冻结
C. 评测集可以上线后再补
D. 训练集越大，验收分数一定越高

0-3. 关于「过拟合」与「灾难性遗忘」，正确的是：
A. 两者都是「模型变笨了」，没有区别
B. 过拟合是死记示例、换个问法就不会；灾难性遗忘是学了新风格、丢了通用能力
C. 灾难性遗忘是训练数据太多造成的
D. 过拟合指模型体积变大

0-4. 「提示词工程优先」的边界是：
A. 等于永远不微调
B. 三种结构提示词 + 三组以上少样本 + 同一批测试题横向比过仍不达标，且确属行为型需求，才算试到头
C. 提示词改一版没效果就该微调
D. 预算够就直接微调

二、连线题（0-5，6 组，每组 2 分）

0-5. 把左侧术语与右侧「生活类比 / 一句话」用线连起来：

左侧 · 术语右侧 · 类比 / 一句话（打乱）
① 预训练A. 岗位培训，成对的高质量示范教「这样问就这样答」
② SFTB. 读完全部教科书，先攒一身通识底子
③ LoRAC. 师傅带教打分，学出「什么算好答案」的尺子
④ RLHFD. 贴三张便利贴改习惯，原笔记一页没动
⑤ 标注数据E. 装修前先比「刷墙」和「砸墙重装」哪个划算
⑥ 成本F. 每篇都由同一位老师按同一把尺子批过、还附了范文

三、改错题（0-6 ~ 0-9，每题先判断再改正，共 5 分）

0-6. 「LoRA 是一种比大模型更轻量的小模型，产物是一个独立的小模型。」

0-7. 「把产品手册微调进模型以后，文档更新了也不用重训，很省事。」

0-8. 「拿训练用的那批示范直接当评测集验收就行，反正都是同一批好例子。」

0-9. 「微调之后模型推理能力明显变强，智力上限也跟着提高了。」

四、简答辨析（0-10 ~ 0-12）

0-10. 写出 SFT、LoRA、RLHF 三个缩写的英文全称与中文。

0-11. 「知识」和「行为」怎么分？各举一个产品例子，并分别说明走哪条技术路径。

0-12. 五问清单的结论规则是什么？为什么说「任何一问不过就不该微调」？

A. 读完全部教科书
B. 岗位培训

1-3. 关于 LoRA，理解正确的是：
A. LoRA 是一种比大模型更轻量的模型
B. LoRA 会改动原模型的全部参数
C. LoRA 只训练一小片新增参数，原模型不动，可插拔

1-4. 关于 RLHF，理解正确的是：
A. 它让模型学到大量新知识

C. 它替代 SFT，是训练的第一步

1-5. 以下最适合用微调解决的是：
A. 让客服机器人回答每周更新的售后政策
B. 让模型掌握行业报告里的最新数据
C. 让模型用公司品牌口吻写推广文案
D. 让模型联网查今天的天气

1-6.【新增】 关于「产品经理在微调项目里的协作接口」，正确的是：
A. 验收时看现场 Demo 效果惊艳就可以上线
B. 产品经理交付需求文档、评测集、示例数据验收标准、badcase 回流机制
C. 评测集可以等上线后再补
D. 上线门槛事后按结果再定更灵活

1-7.（原第 6 题）用「实习生入职培训」类比，向非技术同事讲清预训练、SFT、LoRA、RLHF 各自解决什么问题（每个一句话）。

1-8.（原第 7 题）写出微调必要性判断清单的五问，并说明为什么「任何一问不过就不该微调」。

1-9.【新增】 写出产品经理验收微调成果的「三道关」，并说明为什么「门槛事后定，就等于没有门槛」。

第 2 层 · 进阶实操题（方案设计层，4 题：原有 2 题保留 + 新增 2 题）

2-1、2-2 为原有题目（原第 8、9 题），内容保留；2-3、2-4 为新增。

2-1.（原第 8 题，60 分）四个场景判断：该不该微调？
对下列 4 个场景，逐个给出结论（微调 / RAG / 提示词优化 / 不做），并按五问清单说明卡在哪一问或五问为何全过：

  • 场景 A：让客服机器人准确回答公司每月更新的报销政策。
  • 场景 B：让模型输出的工单摘要严格符合内部系统的字段格式（现有提示词已试过三种结构仍偶发出错，出错会导致下游系统报错，失败代价高）。
  • 场景 C：让模型用公司「专业但不端着」的口吻写对外推文，口吻规范已沉淀为一份内部文档，需求预计一年内稳定。
  • 场景 D：老板要求微调一个自有大模型以「全面超越通用模型」，目前没有标注团队，也没有评测集。

2-2.（原第 9 题，40 分）微调需求文档写作。
针对场景 C（假设五问已全过、决定用 LoRA），为算法团队写一份微调需求文档，需包含：目标行为描述、负面清单、3 组典型输入输出示例（可用一句话概括）、验收方式。

2-3.【新增，30 分】 两个新场景过五问，给出结论、卡在第几问、两条理由：

  • 场景 E：让模型按固定模板生成部门周报，模板每季度会调整一次措辞。
  • 场景 F：让客服机器人掌握本月刚上线的三条促销活动规则。

2-4.【新增，30 分】 为「品牌口吻 LoRA 微调」设计一份评测集：分别写出正例、负例、边界 case、通用能力回归题各一条（可用一句话概括），并说明为什么必须保留「与风格无关的通用问题」。

第 3 层 · 求职挑战题（面试层，4 题：原有 2 题保留 + 新增 2 题）

3-1、3-2 为原有题目（原第 10、11 题），内容保留；3-3、3-4 为新增。

3-1.（原第 10 题，30 分）面试真题：老板要求微调，你怎么应对？
面试官：「你们产品效果没达预期，老板拍板说『别人都微调了，我们也微调一个』，你作为产品经理怎么办？」
要求：先表态（不盲从也不硬顶），再给出处理路径（五问清单 / 数据 / 评测），最后说明什么情况下你会同意微调。

3-2.（原第 11 题，30 分）案例分析：微调项目上线即巅峰。
某团队完成一次品牌口吻 LoRA 微调，上线首周口碑很好，一个月后效果明显下滑，且通用问题的回答质量也在变差。请给出你的排查思路（按优先级）和对应的产品改进动作。

3-3.【新增，25 分】 面试真题：「微调和 RAG 有什么区别？」要求：先一句话讲清分界，再补机制差异与时效；并回答追问「有没有既该补知识、又该改行为的情况，怎么排优先级？」

3-4.【新增，25 分】 案例分析：某团队五问全过后启动 LoRA 微调，验收当天只看现场 Demo 输出惊艳、全票通过，既没做基线对比，也没打开评测集，上线门槛是事后才定的。请指出至少 3 处违反「协作接口」的地方，并逐条给出改进动作。

第 4 层 · 面试实战（7 题，每题含踩分点 / 追问链 / 参考答案 / 评分表）

配套第 5 节「面试讲解与追问防御」与《面试模拟记录表》。每题先给题目与题型，再给踩分点、追问链、参考答案要点，最后给评分表（含一票失分项）。60 秒口播全文见 02-讲课稿 第 5 节。

4-1 · 什么时候该微调？（题型：技术理解）

  • 踩分点（每条 2 分，共 8 分）：① 先给框架、点名「五问清单」，不拍脑袋；② 完整复述五问；③ 结论规则「任何一问不过就不该微调、多数场景不该微调」；④ 补边界「补知识走 RAG、改行为才微调」。
  • 追问链：第 1 层「提示词到什么程度算试到头？」→ 三种结构 + 三组以上少样本 + 同一批测试题横向比过仍不达标；第 2 层「老板坚持要微调怎么回应？」→ 转译成「数据从哪来、怎么算调好、要改什么行为」三问；第 3 层「五问全过是不是一定成功？」→ 只是允许开工，还要冻结评测集、做基线对比、留通用回归题。
  • 参考答案要点：五问全报 → 结论规则 → 补 RAG / 行为分界 → 落到「评测集说话，不看 Demo」。
  • 评分表：
档位表现得分
优秀（8 分）四条全中，含术语「五问清单 / RAG / 评测集 / 基线」，被追 3 层仍稳8
良好（5–7 分）报出五问与结论规则，缺边界或追问层答得略薄5–7
待改进（≤4 分）只答「看情况 / 数据够多就调」，无框架无术语≤4
一票失分「预算够就直接微调」——判 0 分0

4-2 · 微调和提示词工程怎么选？（题型：场景设计）

  • 踩分点：① 顺序「提示词工程优先」；② 成本对比（只用相对量级，不写数字）；③「试到头」可操作判据；④ 什么情况才升级到微调；⑤ 升级后提示词版留作基线。
  • 追问链：第 1 层「是不是提示词永远优先？」→ 不是排位是门槛；第 2 层「改了十版都不稳算不算试到头？」→ 看结构差异与横向比，不看版本数；第 3 层「升级后提示词还留吗？」→ 留，且做基线。
  • 参考答案要点：先便宜后贵 → 三种结构判据 → 行为 / 稳定 / 数据 / 评测四条件 → 基线对比验收。
  • 评分表：
档位表现得分
优秀（8 分）五条全中，说清「重武器不该第一个上」并给出判据与基线8
良好（5–7 分）说出顺序与成本，判据或缺基线5–7
待改进（≤4 分）只说「微调更高级」，无视成本顺序≤4
一票失分「微调效果肯定比提示词好」——判 0 分0

4-3 · 微调和 RAG 有什么区别？（题型：技术理解）

  • 踩分点：① 一句话分界「补知识走 RAG、改行为才微调」；② 机制差异（外挂资料即时生效 vs 写进参数要重训）；③ 时效「知识会过期，微调灌知识等于把『会过期』印进脑子」；④ 边界「二者可叠加，先拆需求」。
  • 追问链：第 1 层「既补知识又改行为怎么办？」→ 拆开做，知识走 RAG、行为单独评估；第 2 层「RAG 答不准是不是该改微调？」→ 先查检索与文档质量，是应用层问题；第 3 层「微调能不能顺带补点知识？」→ 能塞但代价高、会过期、可能灾难性遗忘，不推荐。
  • 参考答案要点：给分界 → 讲机制与时效 → 举例（手册 / 口吻）→ 补可叠加边界。
  • 评分表：
档位表现得分
优秀（8 分）四条全中，含「会过期」表述与叠加边界8
良好（5–7 分）给对分界与机制，缺时效或边界5–7
待改进（≤4 分）只做名词解释「一个是外挂、一个是训练」≤4
一票失分「两个差不多，哪个好用哪个」——判 0 分0

4-4 · 怎么判断微调有没有效果？（题型：项目深挖）

  • 踩分点：① 事前冻结评测集（正 / 负 / 边界 / 通用回归）；② 与提示词优化版基线同题对比；③ 上线门槛事前约定；④ 金句「Demo 是演员，评测集才是考卷」+ badcase 回流。
  • 追问链：第 1 层「评测集只测口吻够不够？」→ 不够，四类题都要，尤其通用回归题；第 2 层「上线一个月掉了怎么排查？」→ 副作用 / badcase 未回流 / 需求漂移；第 3 层「老板只看 Demo 拍板怎么办？」→ 补一场同题对比 + 评测集跑分。
  • 参考答案要点：冻结考卷 → 验收三关 → 金句 → 回流防衰减 → 「没有评测集一律不签字」。
  • 评分表：
档位表现得分
优秀（8 分）四条全中，主动提通用回归题与 badcase 回流8
良好（5–7 分）说出评测集 + 基线对比，缺回归题或门槛5–7
待改进（≤4 分）「看用户反馈 / 现场跑几个例子」≤4
一票失分「现场挑几个好例子演一下就行」——判 0 分0

4-5 · 老板要求微调，你怎么应对？（题型：行为题 / 场景设计）

  • 踩分点：① 表态「不盲从也不硬顶」；② 五问清单定位真问题；③ 补条件（数据与评测不具备先补）；④ 低成本替代 + 验证周期；⑤ 说清「什么情况下同意微调」。
  • 追问链：第 1 层「别家都微调了怎么接？」→ 不比动作比问题，先说清要改的具体行为；第 2 层「老板仍要微调版成果？」→ 先做提示词 + RAG 基线，把对比与五问结论一起汇报；第 3 层「真同意了第一件事做什么？」→ 冻结评测集、写死目标行为与负面清单。
  • 参考答案要点：表态 → 三问转译 → 五问定位 → 补条件 + 低成本路径 → 同意条件 → 先有考卷再开枪。
  • 评分表：
档位表现得分

4-6 · 「为什么你们当时没有选择微调？」（题型：行为题 / 项目深挖）

  • 踩分点：① 不答「觉得没必要」空话，先给框架；② 复盘卡在哪一问；③ 说明低成本替代路径与验证思路（定性、不编数字）；④ 补「什么信号出现会重新评估」。

  • 参考答案要点：框架 → 卡点（知识 / 无标注数据 / 无评测集）→ 低成本路径 → 补评测集 → 重评信号；数据写「待教务补充」。

4-7 · 微调项目上线一个月效果下滑，怎么排查？（题型：项目深挖）

  • 踩分点：① 按优先级排查三条线（副作用 / badcase 未回流 / 需求漂移）；② 对应到评测集设计缺陷（缺通用回归题）；③ 机制性改进（回流、规范冻结、基线验收）；④ 点出「灾难性遗忘」并解释「温和版、偏科不是变笨」。
  • 追问链：第 1 层「怎么区分副作用还是数据脏？」→ 看掉的是通用问题还是目标口吻；第 2 层「现在补评测集来得及吗？」→ 来得及，先补回归题和边界 case 再决定要不要重训；第 3 层「怎么避免下次再犯？」→ 写进上线门槛作验收三关固定项。
  • 参考答案要点：三条线优先级 → 评测集缺陷 → 四个动作 → 写进门槛 → 「先有考卷，再谈重训」。
